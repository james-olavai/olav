## 1. 问题清单

测试中发现的工具链问题：

1. ❌ `DataGateway.search_similar_cases()` - 参数错误 (got an unexpected keyword argument 'keyword')
2. ❌ `Cache storage failed` - HumanMessage对象序列化失败
3. ⚠️ `Database query` - Table 'devices' 不存在（LLM生成SQL错误）

## 2. 修复详情

### 2.1 search_similar_cases参数不匹配 ✅

**问题根因**:
- `data_gateway.py`定义参数为 `symptom: str`
- `expert_tools.py`和`analyzer.py`调用时使用 `keyword=value`

**修复代码**:
```python
# expert_tools.py (Line 445)
# 修复前:
similar = gw.search_similar_cases(
    skill_name=skill_name, keyword=keyword, max_age_days=90, limit=max_results
)

# 修复后:
similar = gw.search_similar_cases(
    skill_name=skill_name, symptom=keyword, max_age_days=90, limit=max_results
)

# analyzer.py (Line 424)
# 修复前:
cases = _gw.search_similar_cases(skill_name, keyword, max_age_days=30, limit=2)

# 修复后:
cases = _gw.search_similar_cases(skill_name, symptom=keyword, max_age_days=30, limit=2)
```

**测试结果**: ✅ 无更多参数错误

---

### 2.2 HumanMessage序列化失败 ✅

**问题根因**:
- `orchestrator.py`缓存`result["messages"]`时，包含LangChain消息对象
- `json.dumps()`不支持HumanMessage/AIMessage等对象

**修复代码**:
```python
# orchestrator.py (Line 365+)
# 修复前:
cache_result = {
    "messages": result["messages"],  # ❌ 包含LangChain对象
    "performance": {...}
}

# 修复后:
# Convert messages to serializable format
serializable_messages = []
for msg in result["messages"]:
    if hasattr(msg, "content"):
        serializable_messages.append({
            "type": msg.__class__.__name__,
            "content": msg.content,
        })
    else:
        serializable_messages.append(str(msg))

cache_result = {
    "messages": serializable_messages,  # ✅ 可序列化字典
    "performance": {...}
}
```

**测试结果**: ✅ 无更多缓存序列化错误

---

### 2.3 datetime序列化失败 ✅

**问题根因**:
- `search_similar_cases`返回包含`created_at`等datetime字段的案例
- `json.dumps()`默认不支持datetime对象

**修复代码**:
```python
# expert_tools.py (Line 459)
# 修复前:
return json.dumps(result, indent=2, ensure_ascii=False)

# 修复后:
return json.dumps(result, indent=2, ensure_ascii=False, default=str)
```

**测试结果**: ✅ 无更多datetime序列化错误

---

### 2.4 orchestrate_query final_answer提取失败 ✅

**问题根因**:
- 缓存序列化后，`result["messages"]`中的消息变成了字典格式
- 原代码只处理`isinstance(last_msg, AIMessage)`，不处理字典

**修复代码**:
```python
# orchestrator.py (Line 491+)
# 修复前:
if isinstance(last_msg, AIMessage):
    final_answer = last_msg.content

# 修复后:
if isinstance(last_msg, AIMessage):
    final_answer = last_msg.content
elif isinstance(last_msg, dict) and "content" in last_msg:
    # Handle serialized message format
    final_answer = last_msg["content"]
elif hasattr(last_msg, "content"):
    final_answer = last_msg.content
else:
    final_answer = str(last_msg)
```

**测试结果**: ✅ 场景2成功返回VLAN配置方案

### 2.5 devices表不存在 ⚠️ 增强错误提示

**问题根因**:
- LLM生成的SQL查询引用了不存在的`devices`表
- 数据库可能使用`v_system`或其他视图名

**修复策略**: 增强错误提示（非阻塞问题）
```python
# data_gateway.py (Line 575+)
except Exception as e:
    # Provide helpful error messages for common issues
    error_msg = str(e)
    if "Table with name" in error_msg and "does not exist" in error_msg:
        # Extract table name and list available tables
        try:
            available_tables = conn.execute(
                "SELECT table_name FROM information_schema.tables WHERE table_schema = 'main'"
            ).fetchall()
            
            table_list = ", ".join([t[0] for t in available_tables])
            raise RuntimeError(
                f"Table '{table_name}' does not exist in database. "
                f"Available tables: {table_list}. "
                f"Please check your SQL query or database schema."
            ) from e
        except RuntimeError:
            raise
        except Exception as list_err:
            logger.debug(f"Could not list available tables: {list_err}")
    
    raise RuntimeError(f"Database query error: {str(e)}") from e
```

**测试结果**: ⚠️ LLM仍可能生成错误SQL，但现在提供可用表列表
