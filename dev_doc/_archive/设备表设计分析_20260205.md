# 设备表设计分析与建议

**日期**: 2026-02-05  
**议题**: 是否需要一个devices表维护设备基本信息 (Hostname, 版本, 模型, 厂商, 管理地址)

---

## 1. 现状分析

### 当前数据库设计

**主数据库**: `.olav/config/nornir/inventory/` (Nornir Inventory)

```yaml
groups:
  - name: "cisco"
    connection_options:
      netmiko:
        extras:
          device_type: "cisco_ios"
      nornir:
        username: "***"
        password: "***"

hosts:
  R1:
    hostname: 192.168.100.101
    groups: ["cisco"]
  R2:
    hostname: 192.168.100.102
    groups: ["cisco"]
  ...
```

**虚拟视图**: `.olav/config/nornir/nornir_data.yaml`

```yaml
v_system:  # 系统信息视图
  - device: R1
    hostname: 192.168.100.101
    role: core
    platform: cisco_ios
    site: lab
    ...

v_interfaces:  # 接口视图
v_lldp:        # LLDP邻居
v_bgp_neighbors:  # BGP邻居
v_ospf_neighbors: # OSPF邻居
```

### 问题观察

从测试发现的问题：

1. **LLM生成了错误的SQL**:
   ```sql
   -- LLM尝试查询这个不存在的表
   SELECT * FROM devices WHERE hostname IN ('R1', 'R2', 'R3', 'R4')
   ```

2. **虚拟视图结构不明确**:
   - LLM不知道有哪些视图可用
   - LLM不知道各视图的字段和用途
   - LLM倾向于自己"创造" devices表

3. **信息分散**:
   - 设备基本信息分散在多个地方
   - Nornir Inventory中的yaml格式
   - 虚拟视图中的嵌入式数据
   - 运行时show命令输出

## 3. 设计方案对比

### 方案A: ❌ 不建立devices表（现状）

**优点**:
- 实现简单，当前已正常运作
- 减少维护负担

**缺点**:
- ❌ LLM会自己"创造"devices表，导致SQL错误
- ❌ 查询分散，无统一数据源
- ❌ 无法快速列出所有设备及其属性
- ❌ 新手用户难以理解数据结构

**影响**:
```
uv run olav "列出所有Cisco设备"
→ LLM尝试: SELECT * FROM devices WHERE vendor='Cisco'
→ 错误: Table devices does not exist
```

---

### 方案B: ✅ 建立devices表（推荐）

**优点**:
- ✅ LLM有明确的数据源
- ✅ SQL查询准确无误
- ✅ 支持快速设备查询和过滤
- ✅ 为future功能铺路（配置管理、合规检查等）
- ✅ 与行业最佳实践一致

**缺点**:
- 需要初始化表结构
- 需要导入现有设备数据
- 需要维护同步逻辑

**实现成本**: 
- 建表: 30分钟
- 数据导入: 15分钟
- 同步机制: 可选（后续）

---

## 4. 推荐实现方案

### 4.1 建立devices表

```sql
CREATE TABLE IF NOT EXISTS devices (
    device_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    hostname VARCHAR(255) NOT NULL UNIQUE,
    ip_address VARCHAR(15) NOT NULL,
    device_type VARCHAR(50) NOT NULL,  -- cisco_ios, juniper_junos, etc
    vendor VARCHAR(50),                  -- Cisco, Juniper, Arista
    model VARCHAR(100),                  -- ISR4321, EX4300
    ios_version VARCHAR(50),             -- 16.12.03, 20.3.1
    serial_number VARCHAR(100),
    device_role VARCHAR(50),             -- core, distribution, access
    site VARCHAR(100),                   -- lab, dc1, branch
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_active BOOLEAN DEFAULT TRUE
);

CREATE INDEX idx_devices_hostname ON devices(hostname);
CREATE INDEX idx_devices_vendor ON devices(vendor);
CREATE INDEX idx_devices_role ON devices(device_role);
```

### 4.2 数据导入策略

**初始导入** (来自Nornir + show命令):


## 9. 参考实现框架

### 表结构
```sql
-- devices 表
CREATE TABLE devices (...)

-- 联合视图示例: v_devices_extended
CREATE VIEW v_devices_extended AS
SELECT 
    d.hostname,
    d.ip_address,
    d.vendor,
    d.device_role,
    COUNT(DISTINCT CASE WHEN lldp.neighbor IS NOT NULL THEN 1 END) as neighbor_count
FROM devices d
LEFT JOIN v_lldp lldp ON d.hostname = lldp.device
GROUP BY d.hostname, ...
```

### LLM提示
```python
"""
You have access to these database tables:

1. devices (primary device catalog)
   - hostname VARCHAR: Device unique name (e.g., R1, SW1)
   - vendor VARCHAR: Vendor name (Cisco, Juniper, Arista)
   - device_role VARCHAR: core, distribution, access
   - ios_version VARCHAR: Software version
   
2. v_lldp, v_bgp_neighbors, v_ospf_neighbors (network relationships)

Always query 'devices' FIRST for device information!

Example:
  Query: "List all Cisco routers"
  SQL: SELECT hostname, model FROM devices WHERE vendor='Cisco' AND device_type LIKE '%router%'
"""
```
