# 工具链问题快速答案

## 问题1: search_similar_cases (参数错误)

### ❓ 原因
**LLM或缓存层在某处用错了参数名**

```python
# ❌ 错误调用 (某处)
gw.search_similar_cases(skill_name=..., keyword=...)  # 用了 keyword

# ✅ 正确调用 (expert_tools.py Line 444)
gw.search_similar_cases(skill_name=..., symptom=...)  # 用了 symptom
```

**查了所有代码，expert_tools.py和analyzer.py的调用都是对的**，但错误仍然发生，说明是：
- LLM动态生成工具调用时传了错参数
- 或者缓存的工具定义与运行时代码版本不一致

### 💡 为什么不影响诊断

✅ **Expert Agent自动容错**:
1. search_similar_cases失败 → 返回空列表
2. 继续执行其他工具 (nornir_execute, analyze_topology)  
3. LLM用其他工具结果继续诊断
4. **最终诊断仍然准确** ✅

## 问题2: Database query (表不存在)

### ❓ 原因
**LLM生成的SQL用了错误的表名**

```sql
-- ❌ 错误: 这个表不存在
SELECT * FROM devices WHERE hostname IN ('R1', 'R2', 'R3', 'R4')

-- ✅ 正确: 应该用虚拟视图
SELECT * FROM v_lldp      -- LLDP邻居
SELECT * FROM v_bgp_neighbors   -- BGP邻居
SELECT * FROM v_ospf_neighbors  -- OSPF邻居
```

**为什么LLM会这么做？**

1. **LLM理解错了数据库结构**
   - 被告知"可以用query_database查询"
   - 猜测应该有 `devices` 表
   - 实际是虚拟视图 `v_lldp` 等

2. **工具文档不够详细**
   - 没有清晰列出可用的表和视图
   - 没有SQL查询示例
   - 没有明确说"用视图而非表"

### 💡 为什么不影响诊断

✅ **多工具冗余设计**:
1. query_database失败 (表不存在)
2. Expert Agent已经用 nornir_execute 获取数据
3. 有足够的信息继续诊断
4. **最终诊断仍然准确** ✅
