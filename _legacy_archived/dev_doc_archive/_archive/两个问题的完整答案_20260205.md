## 问题2: 是否需要一个设备表维护基本信息？

### ✅ 答案: 强烈建议建立devices表

**现状问题**:

测试发现LLM生成了错误的SQL:
```sql
SELECT * FROM devices WHERE hostname IN ('R1', 'R2', 'R3', 'R4')
❌ 错误: Table with name devices does not exist!
```

**根本原因**: 
- 没有明确的设备表，LLM"幻觉"出来的
- LLM被告知可以query_database，但不知道有哪些表
- 虚拟视图结构不明确，LLM倾向于自造一个devices表

---

### 建议的设备表结构

```sql
CREATE TABLE devices (
    device_id UUID PRIMARY KEY,
    hostname VARCHAR(255) UNIQUE,      -- R1, R2, SW1, SW2
    ip_address VARCHAR(15),            -- 192.168.100.101
    device_type VARCHAR(50),           -- cisco_ios, juniper_junos
    vendor VARCHAR(50),                -- Cisco, Juniper, Arista
    model VARCHAR(100),                -- ISR4321, Catalyst 3750
    ios_version VARCHAR(50),           -- 16.12.03, 20.3.1
    serial_number VARCHAR(100),        -- FCW2222L1234
    device_role VARCHAR(50),           -- core, distribution, access
    site VARCHAR(100),                 -- lab, dc1, branch1
    created_at TIMESTAMP,
    last_updated TIMESTAMP,
    is_active BOOLEAN
);

INDEX: hostname, vendor, device_role (性能优化)
```

### 为什么需要这个表？

1. **解决LLM幻觉问题**: 
   - LLM不再需要"猜测"表名
   - 明确的devices表让SQL生成更准确

2. **支持更多查询**:
   ```
   "哪些设备运行的iOS版本低于16.12?"
   "列出所有思科核心路由器"
   "显示所有分支站点的设备"
   ```

3. **为未来功能铺路**:
   - 配置备份管理
   - 合规性检查
   - 变更影响分析
   - 自动化补丁管理

4. **与行业最佳实践一致**:
   - 所有网络管理系统都有设备表
   - 标准化数据模型
   - 便于集成第三方工具
