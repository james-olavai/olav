🎯 开发阶段规划 (Phase 0-7)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Phase 0: 基础架构 (Foundation)
├─ 目标: 建立核心架构和数据层
├─ 里程碑:
│  ├─ ✅ 统一配置管理 (Settings + pydantic-settings)
│  ├─ ✅ DuckDB 数据库架构设计
│  ├─ ✅ Data Gateway 统一数据访问层
│  └─ ✅ 日志系统配置
└─ 验收: test_database_schema, test_config_loading

Phase 1: 网络数据采集 (Network Data Collection)
├─ 目标: 实现设备连接和快照采集
├─ 里程碑:
│  ├─ ✅ Nornir inventory 管理
│  ├─ ✅ Netmiko 设备连接
│  ├─ ✅ 命令执行框架 (白名单 + 黑名单)
│  ├─ ✅ 快照采集脚本
│  └─ ✅ 快照存储 (exports/snapshots/{date}/)
└─ 验收: test_device_connectivity, test_snapshot_collection
   要求: ≥3 台真实设备连接成功

Phase 2: 数据解析与存储 (Data Parsing & Storage)
├─ 目标: 解析快照数据并导入数据库
├─ 里程碑:
│  ├─ ✅ TextFSM 模板集成
│  ├─ ✅ 解析器框架
│  ├─ ✅ 数据导入器 (raw_importer.py)
│  ├─ ✅ 拓扑发现 (CDP/LLDP)
│  └─ ✅ 数据验证
└─ 验收: test_snapshot_parsing, test_data_import
   要求: 成功解析 ≥5 种 show 命令

Phase 3: Query Agent (结构化查询)
├─ 目标: 实现自然语言到 SQL 的查询功能
├─ 里程碑:
│  ├─ ✅ SQL 生成器 (NL → SQL)
│  ├─ ✅ 安全检查 (SQL 注入防护)
│  ├─ ✅ 查询执行器 (DuckDB)
│  ├─ ✅ 结果格式化 (Markdown table)
│  └─ ✅ 缓存机制 (精确匹配)
└─ 验收: test_simple_query_real_llm, test_query_cache
   要求: ≥10 个真实查询成功 (真实 LLM)

Phase 4: Expert Agent (诊断专家)
├─ 目标: 实现复杂故障诊断和根因分析
├─ 里程碑:
│  ├─ ✅ 知识库架构 (.olav/knowledge/)
│  ├─ ✅ 向量化索引 (Embedding)
│  ├─ ✅ RAG 检索 (知识库 + 历史案例)
│  ├─ ✅ ReAct Agent (推理 + 工具调用)
│  └─ ✅ 案例自动记录
└─ 验收: test_bgp_diagnosis_real_llm_real_device
   要求: ≥5 个真实故障场景诊断成功

Phase 5: Orchestrator (统一协调)
├─ 目标: 实现智能路由和质量评估
├─ 里程碑:
│  ├─ ✅ 路由决策 (Query vs Expert)
│  ├─ ✅ 执行计划缓存
│  ├─ ✅ 质量评估机制
│  ├─ ✅ 升级策略 (Query → Expert)
│  └─ ✅ Markdown 输出格式化
└─ 验收: test_routing_to_query_agent, test_quality_evaluation
   要求: 路由准确率 >95%

Phase 6: CLI 集成 (Command Line Interface)
├─ 目标: 实现用户友好的 CLI 界面
├─ 里程碑:
│  ├─ ✅ 交互式 REPL
│  ├─ ✅ 命令补全
│  ├─ ✅ 历史记录
│  ├─ ✅ 输出美化 (Rich)
│  └─ ✅ 错误处理
└─ 验收: test_cli_single_query, test_cli_interactive_mode

Phase 7: 端到端生产验收 (Production Acceptance)
├─ 目标: 生产级别功能完整性验证
├─ 场景测试:
│  ├─ ✅ 场景 1: 设备查询 (真实 LLM + 真实设备)
│  ├─ ✅ 场景 2: 故障诊断 (真实 LLM + 真实设备)
│  ├─ ✅ 场景 3: 性能分析 (真实 LLM + 真实设备)
│  └─ ✅ 可靠性测试 (连续执行 10 次)
└─ 最终验收指标:
   ├─ 查询成功率: ≥95%
   ├─ 诊断成功率: ≥85%
   ├─ 简单查询延迟 (P95): <5s
   ├─ 复杂诊断延迟 (P95): <30s
   ├─ 缓存命中延迟: <0.5s
   └─ 连续查询成功率: ≥90%
