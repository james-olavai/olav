## 🎓 关键学习和决策

### 1. 为什么是"能力验证"而不是"自动化测试"?

**决策依据**:
- ✅ Query Agent是AI系统，输出不确定性较高
- ✅ 需要人工判断"理解正确"vs"理解偏差"
- ✅ 自动化测试难以验证"中间步骤"的合理性
- ✅ 能力验证能够发现更多有价值的缺陷

**本次发现的例子**: 数据生成脚本的datetime bug就是手工验证时发现的

### 2. 为什么用100+个测试用例?

**覆盖度分析**:
- 20个L1用例 → 覆盖9个SQL基础维度
- 40个L2用例 → 覆盖时间、聚合、多表等中级特性
- 40个L3用例 → 覆盖5个真实网络运维场景

**预期缺陷发现**: 每增加20个用例可多发现1-2个基础缺陷

### 3. 为什么分P0/P1/P2优先级?

**优先级权重**:
- P0 (必做): 如果通不过，说明基本功能有问题 → 影响可用性
- P1 (应做): 常见场景，影响用户体验
- P2 (可选): 增强功能/边界情况，可以延后优化

**结果分布预期**:
```
通过L1 (P0全过) 
→ 95% 概率Agent基础功能正常
→ 进入L2

通过L2 (70%)  
→ Agent对中等复杂度有较好支持
→ 继续L3

通过L3 (30-45%)
→ 高级功能部分缺陷
→ 针对性改进
```
