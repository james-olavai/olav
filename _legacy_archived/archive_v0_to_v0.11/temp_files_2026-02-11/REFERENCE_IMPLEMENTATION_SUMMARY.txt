================================================================================
                      KEY REFERENCE RULES
================================================================================

🔴 RULE #1 (Most Important - Fixes 3-4 tests):
    Date/Time Type Conversions
    
    ❌ WHERE created_at > CURRENT_DATE - 30
    ✅ WHERE created_at > CURRENT_DATE - INTERVAL '30 days'
    
    Why: CURRENT_DATE returns DATE, 30 is INTEGER → cannot mix types
         INTERVAL '30 days' is proper DATE arithmetic

🟠 RULE #2 (Fixes 1-2 tests):
    Keep CASE Simple (Max 2-3 Conditions)
    
    ❌ CASE WHEN col1 = 'a' AND col2 = 'b' AND col3 IN (...) THEN ...
    ✅ CASE WHEN col1 = 'a' THEN ... ELSE ... END
    
    Why: Complex nested CASE confuses LLM column references
         Use CTE to separate logic

🟡 RULE #3 (Fixes 2-3 tests):
    Use CTE for 3+ Stacked Operations
    
    ❌ SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... (all at once)
    ✅ WITH step1 AS (...), step2 AS (...), step3 AS (...)
       SELECT ... FROM step3
    
    Why: Breaking into steps makes each part clear and correct
         LLM can generate each step accurately

🟢 RULE #4 (Fixes 1 test):
    All Columns in GROUP BY
    
    ❌ SELECT col1, COUNT(*) FROM t GROUP BY col2
    ✅ SELECT col1, col2, COUNT(*) FROM t GROUP BY col1, col2
    
    Why: GROUP BY must include all non-aggregated columns
         Otherwise DuckDB throws Binder error
