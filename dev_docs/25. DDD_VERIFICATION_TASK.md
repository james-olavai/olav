## 执行规则

1. **严格按 Claim ID 顺序验证**，不跳号
2. **每条 Claim 三步走：**
   - CLI 执行 → 记录实际输出到 `dev_docs/24. CLI_VERIFICATION_LOG.md`
   - 通过 → 写 E2E 测试追加到 `tests/00_e2e_acceptance_test.py`
   - 失败 → 不改文档、不跳过，先修代码，修完重验
3. **三种结果处理：**
   - ✅ Pass → Claim 保留，标记 Verified + 版本号
   - ⚠️ Partial → 收窄声明范围（在 claim-registry.md 和对应文档页标注条件）
   - ❌ Fail → 记录失败原因，创建 bugfix 任务，Claim 暂留但标记 ❌
4. **不允许修改 `docs/` 中的功能描述来适配代码行为** — 文档是合同，代码必须匹配
