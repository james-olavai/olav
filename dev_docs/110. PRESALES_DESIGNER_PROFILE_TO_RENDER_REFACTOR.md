# 110. Presales `designer` — profile→render refactor (minimize LLM authoring calls)

> Status: design + rollout. Supersedes the authoring model of dev_docs/107 §7 and
> dev_docs/109 for the HLD path. Builds on 108 (profile/constraints/lifecycle) and
> 109 (minimal-tool facade). ADR-0016 (presales domain).

## 1. Why (the concrete reliability cause, measured)

Real-agent e2e (gemma4-31b-agent) of the profile-first `designer` produced genuine
bid-grade HLDs that PASS the deterministic gates — but only **~1/3 of runs**. The
cause is **not** a "small-model ceiling"; it is **call count**, and it is measurable:

| Flow | LLM tool calls | Who authors the content | Reliability |
|---|---|---|---|
| `generate_change_plan` (netops) | **1** | Python fat-tool (all N devices in one call; "LLM sees only the final result") | stable |
| `audit` report | **few** | Python `render_report.py` renders the WHOLE report from the profile+data | stable |
| `designer` HLD (before this doc) | **~15–58** | LLM authors each of ~10 narrative chapters + each of 4 clause responses, individually | ~1/3 |

`loop_breaker` hard-stops after **4 consecutive** `execute_skill_script` failures.
Reliability ≈ `P(no 4-in-a-row failure across K calls)`. With `K≈1` (change_plan) or
`K≈4` (audit) a 4-streak is nearly impossible; with `K≈20–58` (designer, inflated by
retries — one run made **12** `profile_add(response)` calls for only **4** clauses) a
4-streak is nearly inevitable. Every extra LLM call is a fresh arg-construction dice
roll (the exact "60–80 per-device calls → overflow" anti-pattern `generate_change_plan`
was built to kill).

**The fix is structural: collapse K.** Make `designer` a real profile→render flow like
`audit` — the LLM populates a small profile and calls render; **Python authors
everything derivable**.

## 2. Key insight — deterministic ≠ "less narrative"

The bid-grade requirement (dev_docs/107, user: "写实、可溯源，不能拍脑门") is BETTER
served by deterministic rendering. `doc_renderers.py` already emits grounded prose
(`_frame`: **Purpose** → **Design principle** → **why**, with `[D:]/[R:]` citations)
from the RECORDED decisions/constraints/topology — i.e. the narrative is traceable to
what the analyst captured, not invented per-chapter by the model. Moving a chapter from
"LLM-authored" to "`render:`" **raises** groundedness and removes a hallucination
surface. The LLM keeps only the chapters that are genuine synthesis.

## 3. Target chapter classification (HLD)

Every HLD chapter is exactly one of three kinds (the profile YAML declares which):

- **computed (`render:`)** — Python renders grounded prose+table from `ctx`
  (decisions/constraints/topology/sizing/bom). No LLM authoring.
- **content-spec (`content:`)** — mixed: computed elements + a short model prose slot
  (kept for logical-topology, where the tier/routing facts are computed but the
  "why this shape" sentence is synthesis).
- **narrative (neither)** — LLM-authored. **Kept to a MINIMUM.**

### Reclassification (dc-fabric + campus)

| Chapter | Before | After | Renderer |
|---|---|---|---|
| Executive Summary | narrative | **narrative** (kept — the pitch/synthesis) | — |
| Business Requirements | narrative | **computed** | `requirements_summary` (new) |
| Design Options Considered | computed | computed | `options_considered` |
| Logical Topology | content-spec | content-spec (kept) | `render_section_content` |
| Physical Topology | narrative+mermaid | **content-spec** (mermaid computed + 1 prose slot) | + `topology_mermaid` |
| Routing & Protocol Design | narrative | **computed** | `routing_design` (new; wraps `config_intent`) |
| Redundancy & HA | narrative | **computed** | `redundancy` (new) |
| Failure-Domain Analysis | computed | computed | `failure_domain` |
| Capacity & Scalability | computed | computed | `capacity` |
| Address Planning | narrative | **computed** | `addressing_plan` (new) |
| Security & Segmentation | narrative | **computed** | `security_zoning` (new) |
| Wireless (campus) | narrative | **computed** | `wireless_design` (new) |
| Management & Operations | narrative | **computed** | `management_ops` (new) |
| Migration & Cutover | narrative | **computed** | `migration_plan` (new) |
| Assumptions/Risks/Constraints | narrative | **computed** | `assumptions_risks` (new; from constraints + open gaps) |
| BOM / Compliance appendices | computed | computed | `bom` / `compliance_matrix` |

**Result:** the LLM authors **only Executive Summary + the two topology prose slots** —
≈ **1–2 authoring calls** (batchable), down from ~10.

## 4. Clause responses — auto-derived, not an LLM step

The 4–12 `profile_add(response)` calls are removed. In `generate_hld`, before building
the compliance matrix, `derive_responses(project_id, run_id, chapters, db_path)` runs:

- for each **mandatory** requirement item **without an adequate response**, scan the
  assembled chapter bodies for a citation to it (`[R:clause_ref]` or `[R:item_id]`);
- if found, create a response: `compliance="comply"`, `section_ref = that chapter's
  title`, `narrative = the sentence(s) carrying the citation` (grounded, already cited);
- `_is_adequate` (compliance + narrative + section_ref) then passes deterministically.

This is the fat-tool principle applied to coverage: the LLM writes chapter prose that
references the clauses; Python folds that into per-clause compliance responses. The
model still MAY set an explicit response (e.g. `partial`/`non-comply` with an exception
narrative) — auto-derivation only fills the gaps, never overwrites an explicit verdict.

## 5. The new loop (designer HLD)

```
profile_view                      # read requirements/decisions/constraints/devices
create_design_run(doc_type=hld)
compute_sizing(...)               # 1 call, [Calc:]-cited
author_hld(exec_summary=…, topology_narrative=…)   # ONE call, 1–2 prose slots
render_document(doc_type=hld, sizing=…)   # Python: computed chapters + auto-derived
                                          # responses + gates. STOP on graded.passed.
```

`K ≈ 5`. If a gate still reports a gap (a computed renderer degraded to a neutral line
because its input is genuinely missing), the fix is to record the missing
decision/constraint (analyst) — not to hand-author prose. `render_document` remains the
one render/grade verb; `author_hld` is a thin `profile_add(kind=chapter)` batch (still
persisted in `design_chapters`, still accumulate-able).

## 6. Non-goals / preserved invariants

- LLD is unchanged here (already a fat tool: `generate_lld` authors+writes in Python —
  dev_docs/106; the memory records LLD 3/3).
- Gates unchanged (content-completeness / coverage / constraint-honoured / citation /
  placeholder). They now pass because the content is computed, not because the bar moved.
- Provenance contract unchanged: every computed sentence cites `[D:]/[R:]/[Spec:]/[Calc:]`
  resolved by id OR human handle (dev_docs/109 §4).
- 3-way workspace sync (authoritative + skillpack + runtime) for any SKILL.md/script edit.

## 7. Rollout (TDD, each RED→GREEN)

1. `derive_responses` + wire into `generate_hld` before `build_matrix`. Test: chapters
   citing `[R:x]` → adequate auto-response; explicit response not overwritten.
2. New renderers in `doc_renderers.py` (`requirements_summary`, `routing_design`,
   `redundancy`, `addressing_plan`, `security_zoning`, `wireless_design`,
   `management_ops`, `migration_plan`, `assumptions_risks`), each grounded + degrading
   to a neutral line. Register in `_HLD_RENDERERS`. Test each.
3. Update `hld_dc-fabric` + `hld_campus` profiles: `render:` on the reclassified
   chapters; keep exec-summary narrative + topology content-spec. Test: a run with only
   exec-summary + topology prose authored → `graded.passed=True`, all mandatory covered.
4. `author_hld` batch script + designer SKILL.md loop rewrite (STOP-on-pass kept).
   3-way sync. Reachability + drift gates green.
5. Behavioural e2e N≥3 (same harness): target ≥ 3/3 now that K≈5. Report the honest rate.

## 8. Success criterion

`designer` HLD reliability approaches `audit`/`change_plan` (near-deterministic) because
the LLM's authoring surface is ~1 call, not ~15. The doc is bid-grade because the
structured design is expanded deterministically (dev_docs/107 depth principle), and the
few genuine-synthesis chapters remain LLM-authored.
