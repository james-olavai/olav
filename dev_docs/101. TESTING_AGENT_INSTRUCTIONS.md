# 101. Testing Agent Instructions

**For:** Claude Code / AI Testing Agent
**Scope:** OLAV platform v0.18.0+ CI testing
**Reference:** `dev_docs/100. CI_TEST_PLAN.md` (100 test cases, 3 tiers)

> **v0.18.0 Agent Architecture:** 3 top-level agents only: `core`, `ops`, `audit`.
> Core has 4 subagents: `db_query`, `api_query`, `remote`, `admin`. Orchestrator sees 5 tools (4 direct + olav_delegate).
> Old agents (`ops-lab`, `audit-auditor`, `audit-designer`, `config`, `devops`, `infra`) are now subagents.
> Use `olav --agent ops "deploy lab"` instead of `olav --agent ops-lab "deploy lab"`.
> See `dev_docs/46. AGENT_BOUNDARY_v0.18.md` for full boundary specification.

## Execution Protocol

### Phase 1: Verify Tier 0

```bash
uv build
bash tests/ci/tier0_packaging.sh
```

**If all 25 pass:** Move to Phase 2.
**If any fail:** Diagnose → fix code → rebuild → re-run. Record the bug in `dev_docs/00. issues.md` with:
- Issue ID: `ISSUE-T0-{number}-{short-name}`
- Severity: P0 (blocks commit)
- Include the exact error output
- Fix the code, not the test (unless the test expectation is wrong)

### Phase 2: Implement & Run Tier 1

Implement `tests/ci/tier1_functional.sh` following the 50 test cases (T1-01 through T1-50) in `dev_docs/100. CI_TEST_PLAN.md`.

**Structure each test as:**

```bash
echo -n "[T1-XX] Description... "
# command
if [ condition ]; then
    echo "OK"; PASS=$((PASS+1))
else
    echo "FAIL"; FAIL=$((FAIL+1))
fi
```

**Test groups and their prerequisites:**

| Group | Tests | Prerequisites |
|---|---|---|
| LLM Queries | T1-01~T1-05 | `OLAV_API_KEY` set, seed data loaded |
| Cache | T1-06~T1-08 | T1-01 must run first (populates cache) |
| Memory | T1-09~T1-11 | T1-01 must run first (triggers AutoCapture) |
| KB CLI | T1-12~T1-17 | `olav init` done |
| Audit CLI | T1-18~T1-23 | At least one LLM query done (creates audit entries) |
| Auth | T1-24~T1-29 | Web service running |
| Web API | T1-30~T1-35 | Web service running |
| Core Tools | T1-36~T1-40 | Python direct invocation, no LLM needed |
| Workspace | T1-41~T1-45 | Skill installed |
| Security | T1-46~T1-50 | Web service running |

**Cache isolation for Tier 1:**
```bash
# Before T1-01 (LLM group): clean memory/cache for fresh baseline
rm -rf .olav/databases/memory.lance .olav/databases/memory.lancedb

# Before T1-06 (cache group): DO NOT clean — T1-06 tests cache from T1-01
# Before T1-08 (invalidation): seed new data to trigger invalidation
```

**When a test fails:**
1. Record in issues: `ISSUE-T1-{number}-{short-name}`
2. Diagnose: Is it a code bug or a test setup issue?
3. If code bug: fix in `src/olav/` or `olav-netops/`, rebuild wheel, re-run
4. If test setup: fix in the test script
5. After fix: re-run the **entire tier** (not just the failed test) to catch regressions

### Phase 3: Implement & Run Tier 2

Same pattern as Tier 1 but with real device requirements:

```bash
# Tier 2 requires:
export OLAV_API_KEY="sk-or-v1-..."
export OLAV_TEST_HOSTS_YAML="/path/to/real/hosts.yaml"
# Real SSH-reachable devices at 192.168.100.101-106
```

For T2-15~T2-18 (Lab Agent): requires ContainerLab. Skip with `SKIP` status if not available.
For T2-11~T2-14 (Agent Quality): output results for human review, mark as `REVIEW`.

## Decision Rules

| Situation | Action |
|---|---|
| Test fails due to code bug | Fix code → rebuild → re-run entire tier |
| Test fails due to missing prerequisite | Fix test setup, not the test expectation |
| Test fails due to LLM non-determinism | If output has data but format differs, mark PASS. If empty/error, mark FAIL |
| Test needs real device but unavailable | Mark SKIP, document in results |
| Test takes >60s | Mark SLOW, investigate if it's a performance bug |
| Safetensors shard noise | Always WARN, never FAIL |
| Cache test ambiguous | Check for `🔧` (tool call) presence, not timing |
| New bug found outside test plan | Add to issues, create new test case in the plan |
