### 7.5.1 `entvenv` 顺带给出了第 4 步的一半答案

`entvenv` 是干净 venv 装 olav + olav-ent wheel 的产物，即**改动前**
（sentence-transformers 仍是核心依赖）的状态，所以它的构成就是体积基线：

```
site-packages 合计                                        5.8 G
  nvidia (CUDA 运行时)                                    2.7 G
  torch                                                   1.1 G
  triton                                                  689 M
  nvidia+torch+triton+transformers+sentence_transformers
    +sklearn+scipy 合计                                   4.6 G   ← 79%
  ── 以下是留下来的 ──
  lance 193M / pyarrow 152M / lancedb 152M / _duckdb 58M
```

**挪进 extra 的预期收益 ≈ 4.6 G**，且印证了 pyproject 注释里
「linux-x86_64 上 PyPI 默认 torch 是 CUDA 构建」的说法 —— 单是 `nvidia/`
就 2.7 G，比 torch 本体还大。

这不能替代第 4 步的 A/B 实测（core wheel vs core+extra 两个干净 venv），
但已经是同一台机器上的真实数字，可以作为交叉校验。**记完这笔账就可以删
`entvenv`**，它是可重建的一次性产物。

**对第 4 步的修正：这台机器上体积对比 venv 绝不能建在 `/tmp`。** tmpfs 是
RAM 支撑的，当前 `Shmem` 已经 3.9 GB（占 15.6 GB 内存的 25%）。在 `/tmp` 里
装带 CUDA 的 torch 等于把几个 GB 直接压进内存 —— 这多半也是上个会话「并行跑
两个全量 pytest 就 OOM」的真实背景：不是两个 pytest 本身多重，而是内存已经
被 tmpfs 吃掉了一大块。改用 `/home/yhvh/` 下或 `/mnt/data` 的路径。

## 8. §7.7 两个缺陷的修复（2026-08-04）

### 8.1 修 ①：`olav init` 现在收敛平台镜像

`cli/commands/init.py::_deploy_platform_workspaces` 的 `elif not dst.exists()`
改为按**字节比较**：不同则刷新。

判定依据不是主观取舍，而是仓库内部的自相矛盾：`olav skill install`
（`cli/commands/skill.py:570`）对 netops 镜像**早就是无条件 `shutil.copy2`**。
两条部署路径面对同一个「generated mirror」模型给出相反行为，init 是异类。
原先「不覆盖以保住用户自定义」的理由早于 WORKSPACE-DUAL-COPY-DEBT Phase 3——
那次 dedup 之后 `.olav/workspace/*` 已是 git-ignore 的生成镜像，唯一权威是
wheel 源，此时「保住镜像里的自定义」等于保住漂移。

刷新是**非破坏性**的：被替换的文件先复制到
`.olav/backups/workspace/<timestamp>/<agent>/<rel>`，并在 init 输出里**逐个列名**
（不只给计数——刷新可能替掉别人正在改的东西，必须能从输出直接复核）。
备份**刻意放在 `.olav/workspace/` 之外**：`tools/` 池会按 `*.py` 加载，
备份文件掉进去会被当成真的 `@tool`。逃生阀 `OLAV_INIT_PRESERVE_WORKSPACE=1`
恢复旧的全跳过行为。

比较用字节而非 mtime：editable 安装与 wheel 安装对同一内容给出无关的时间戳，
用 mtime 会每次 init 都无谓刷新。

`.olav/backups/**` 在 `ownership_manifest.yaml` 里补了独立规则
（`class/status: generated`）——否则会被 `.olav/**` 兜底规则标成
`authoritative runtime-workspace`，而它是可丢弃产物。`.gitignore` 已按流程
用 `gen_gitignore.py --write` 重新生成。

### 8.2 修 ②：drift 脚本补齐漏检

`scripts/workspace_drift.py` 两处漏洞叠加，才让「改了 admin 工具却报
ALL COPIES IN SYNC」成为可能：

1. **`admin` 与 `services` 根本不在 `DOMAINS` 里**（只有 core/audit/netops/
   devops/ops）。已补，`source = src/olav/data/workspace/<name>`。
2. **比较范围排除 `tools/` 与 `scripts/`**，而漂移的 5 个文件全在 `scripts/` 下
   ——即便 domain 在列表里也照样看不见。新增 per-domain `compare_code`：
   wheel 源的平台域（core/admin/services）比较 metadata + Python；
   netops 源的域保持 metadata-only，因为那 4 个 netops 工具有**刻意**的
   `@tool`↔script 双版本分裂（`test_tool_dedup_phase2._DELIBERATE_DIVERGENCE`
   allowlist）。`apply_sync` 同步用同一 scope，否则 `--apply` 修不了
   `--check` 刚报的东西。

并加了**两条守卫盯这个 gate 自己的覆盖面**（原缺陷本质是「手维护的清单漏了一项，
没人守清单」）：

- `test_every_platform_agent_is_a_declared_domain` —— 从文件系统推导
  `src/olav/data/workspace/*` 下的目录，断言全部出现在 `DOMAINS` 里。
- `test_wheel_sourced_domains_compare_python_too` —— wheel 源的域必须
  `compare_code=True`。

三条 gate 都**实测过会红**（按 CLAUDE.md「prove the grader fires」）：删掉
`admin` domain → 第一条红；把 core 的 `compare_code` 改 False → 第二条红；
往 `.olav/workspace/core/api-query/scripts/api_request.py` 注入一行 → 主 gate
报 `DIFFER` 并 exit 2。
