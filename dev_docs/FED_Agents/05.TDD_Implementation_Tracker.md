# 🎯 TDD Implementation Tracker (FED Agents Architecture)

This document tracks the execution of the Federated Agents (4-Agent) architecture through a rigorous **Test-Driven Development (TDD)** methodology.

## 🔴 Green-Red-Refactor Loop

Before writing any feature code, the developer MUST write an E2E acceptance test or an integration test that fails.

---

## Phase 1: Core CLI & Agent Router (The Skeleton)

**Goal:** Implement the 4-Agent entry points and bypass the global Orchestrator loop.

- [ ] **Test 1:** `olav --agent quick "show me devices"` bypassing ReAct loops (Max iterations = 1).
  - *Dev action:* Modify `cli_main.py` to accept `--agent` arg. Update `QuickAgent` graph initialization.
- [ ] **Test 2:** `olav --agent ops "troubleshoot R1"` triggering the full ReAct loop.
  - *Dev action:* Connect the `ops` agent CLI branch.

---

## Phase 2: Skill Decomposition (The Muscle)

**Goal:** Break `olav-ops` into reading experts (Read-only skills).

- [ ] **Test 3:** The `execute_sql` tool in the `skill-topology` folder can ONLY access `topology_links` and `interfaces` tables.
  - *Dev action:* Create `.olav/workspace/olav-topology/SKILL.md` with limited schema exposure. Move corresponding scripts.
- [ ] **Test 4:** The `execute_sql` tool in the `skill-routing` folder can ONLY access `bgp_routes` and `routes`.
  - *Dev action:* Create `.olav/workspace/olav-routing/SKILL.md`.

---

## Phase 3: Config Pipeline Upgrades (The Bloodline)

**Goal:** Implement the data ingestion and normalization fixes.

- [ ] **Test 5:** (Snapshot Cleanup) Injesting 3 snapshots when retention is configured as `2` successfully deletes the oldest snapshot from the DuckDB and the file system.
  - *Dev action:* Write `clean_historical_snapshots.py` and hook it into the end of `take_snapshot`.
- [ ] **Test 6:** (Fuzzy Mapping) Feeding Huawei BGP JSON and Cisco BGP JSON to the system results in unified, Cisco-compliant rows in the DB. Ensure `schema_mappings` table caches the mapping.
  - *Dev action:* Develop the `fuzzy_map_schema` tool and standard Pydantic schema validator.
- [ ] **Test 7:** (Topology Generation) Providing a complex multi-vendor lab snapshot successfully generates bidirectional, deduplicated physical and logical edges in `topology_links`.
  - *Dev action:* Refactor the core `generate_topology` algorithm to rely on the sanitized fuzzy-mapped tables.

---

## Phase 4: Diff Analytics Tools (The Brain)

**Goal:** Implement the advanced state comparison tools for the `skill-diff` subagent.

- [ ] **Test 8:** Calling `diff_sql_state('ospf_neighbors', T1, T2)` returns JSON accurately showing exactly 1 missing neighbor.
  - *Dev action:* Write `.olav/scripts/diff_sql_state.py` leveraging DuckDB `EXCEPT`.
- [ ] **Test 9:** Calling `diff_topology_drift(T1, T2)` returns exactly which physical links went down and up.
  - *Dev action:* Write `.olav/scripts/diff_topology_drift.py`.
- [ ] **Test 10:** Calling `diff_routing_drift(T1, T2)` successfully highlights shifted `next_hop` paths without overwhelming the context window (limit < 20 rows).
  - *Dev action:* Write `.olav/scripts/diff_routing_drift.py`.
- [ ] **Test 11:** Calling `diff_raw_configs` correctly locates the raw text files for two snapshots and returns a GNU diff.
  - *Dev action:* Refactor `.olav/scripts/diff_configs.py` using the new `snapshot_id` FS layout.

---

## ✅ Definition of Done for Federation
1. All 11 tests pass in the standard CI pipeline (`uv run pytest tests/`).
2. The global Orchestrator from v0.9.x is successfully deleted.
3. The single `olav-ops` SKILL folder is deleted and replaced by specialized folders.
