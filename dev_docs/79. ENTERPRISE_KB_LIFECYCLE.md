# 79. Enterprise KB Lifecycle — Source-Tier Priority, Tombstones, Removal CLI

**Date**: 2026-05-15
**Status**: Design + initial implementation
**Supersedes parts of**: `dev_docs/70. R102_CONVERSATIONAL_MEMORY_INGESTION_SUBAGENT.md` (R102 commit semantics)
**Related**: `dev_docs/61. MEMORY_DRIVEN_USAGE_GUIDES.md`, `dev_docs/66. MEMORY_AS_PROMPT_PROGRAMMING_LANGUAGE.md`

---

## 1. Problem

Today's KB (LanceDB `usage_guide` category) has three injection paths:

| Path | Trigger | Authoring surface | Audit chain |
|---|---|---|---|
| Declarative | `*.guide.yaml` in workspace + `olav kb import-guides` | Git PR | Full (commit + reviewer + diff) |
| R102 conversational | NL → `memory_curator` sub-agent → HITL turn 2 | Chat | Single `audit_tool_calls` row; body in LanceDB only |
| L1 implicit | `OperationalEventCapturePlugin` after every write tool call | Automatic | `operational_event` category (weight 0.5, doesn't compete with guides) |

For a workspace operated by a single user / lab, this is fine. For an
enterprise (multi-tenant, change-controlled, regulated), R102 has four
audit gaps the design conversation surfaced 2026-05-15:

1. **Provenance break** — Git PR has author/reviewer/approver/diff/commit
   message; R102 commit only persists a `commit_to_memory(...)` row in
   `audit_tool_calls`, with body truncated to ~80 chars. The full body
   lives in LanceDB (binary store), unreachable from SQL reports like
   "show every guide alice committed in Q3".
2. **Reproducibility drift** — "Same rule said differently" → LLM
   produces different intent / keywords / scope → AutoRecall behaves
   differently across dev/stage/prod, silently.
3. **Attack surface** — A prompt injection in a pasted runbook could
   trick the LLM into emitting a guide that bypasses review. Git PR
   review + branch protection sits in front of the declarative path
   and the LLM cannot reach it.
4. **No source weighting** — R102 commit doesn't set `priority`, so
   user-spoken rules score the same as the platform's bundled
   guides (both default to `priority: 5 → weight: 1.0`). A whispered
   "alice prefers tenant=acme" outranks an architectural invariant
   in retrieval just because of recency / semantic similarity to the
   query.

Plus a fifth gap that surfaced during the same conversation:

5. **No first-class deletion** — Removing a committed memory entry is
   side-effectful (delete the YAML, hope the next `kb import-guides`
   prunes the LanceDB row). No `olav kb remove` CLI. No tombstone
   trail recording who deleted what and why.

This doc specifies the lifecycle changes that close these five gaps
without removing R102 (it stays as a UX affordance — but as a
**drafter**, not a committer-with-equal-weight).

## 2. Source tiers + canonical priority

Every guide gets a `source_tier` field. Tiers map to priorities by a
constant table — the field carries the trust hierarchy and the
priority is derived.

```yaml
# Tier definitions (constant, lives in olav.core.memory.guide_kb)
SOURCE_TIERS = {
    "vendor":   {"priority": 10, "weight": 2.0},   # Vendor/upstream docs (Cisco, Junos)
    "platform": {"priority":  8, "weight": 1.67},  # OLAV-bundled architectural invariants
    "team":     {"priority":  6, "weight": 1.33},  # Org-wide policy (NetBox naming, AS allocation)
    "user":     {"priority":  3, "weight": 0.83},  # Individual operator preference / scratch
}
```

Why these numbers: existing `priority → weight` math in
`olav.core.memory.guide_kb._priority_to_weight()` is
`0.5 + (priority - 1) * (1.5 / 9.0)`. The four tiers fan out across
the 0.5–2.0 weight band without collision; team-tier (priority 6,
weight 1.33) outranks the legacy un-tiered default (priority 5,
weight 1.0) so as we migrate, **un-tagged guides become the lowest
trusted tier** by default — caller knows it's untagged because the
field is missing in the YAML.

YAML schema addition:

```yaml
# .olav/workspace/<agent>/guides/<intent>.guide.yaml
schema_version: 2          # bump from 1; v1 files still load, treated as untagged
intent: netbox_naming_convention
agent: services
source_tier: team          # NEW — required for schema_version 2
keywords: [...]
body: |
  ...
```

`source_tier: user` is what R102 `commit_to_memory()` writes
automatically — the conversational path can never produce
`source_tier: vendor|platform|team`. To promote a user-tier guide
to team-tier, an operator must edit the YAML in git and PR it
through the declarative path.

### Backward compatibility

Schema v1 guides (no `source_tier` field) load successfully but log
a warning and default to `source_tier: user` (lowest trust). The
governance test `test_skill_llm_override_schema.py`-style gate will
later be tightened to require `source_tier` once the platform guides
have all been migrated.

## 3. Draft directory rename + persistence model

Today: `<workspace>/.curator_drafts/<intent>.draft.json` (dot-prefix,
gitignored).

New convention: keep the dot-prefix (it's still ephemeral) but
**publish a parallel commit log** that survives ingestion:

```
<workspace>/
├── .curator_drafts/                                  ← R102 in-flight HITL
│   ├── <intent>.draft.json
│   └── committed/
│       └── <intent>.draft_<unix-ts>.json             ← post-commit archive (existing)
├── <agent>/guides/
│   └── <intent>.guide.yaml                           ← committed (gitignored unless team promotes)
└── kb_audit/                                         ← NEW — tracked in git
    ├── 2026-05-15T12-51-43_commit_netbox_sync_defaults.yaml
    └── 2026-05-15T13-08-22_remove_old_tenant_rule.yaml
```

Each commit / remove action writes one `kb_audit/<iso-ts>_<verb>_<intent>.yaml`
row with:

```yaml
action: commit | remove
intent: netbox_sync_defaults
agent: services
actor: yhvh                       # OS user / OLAV user
source_tier: user                 # for commits
reason: ""                        # operator-supplied, required for remove
timestamp: 2026-05-15T12:51:43+10:00
body_sha256: a8f23c...            # commits: fingerprint of body+keywords
session_id: ...                   # CLI session if available
```

This file IS the audit chain — git-tracked, PR-reviewable, diff-able,
six-month-late-grep-able. Distinct from `audit.duckdb`
`audit_tool_calls` (which captures the tool invocation but not the
semantic intent).

## 4. Removal CLI

New top-level subcommand:

```
olav kb remove <intent> [--agent <name>] [--reason "<text>"] [--keep-yaml]
```

Behavior:

1. Locate `<workspace>/<agent>/guides/<intent>.guide.yaml`. If `--agent`
   omitted, error if multiple matches (forces caller to disambiguate).
2. Read it → compute body sha256 (for audit row).
3. **Without `--keep-yaml`** (default):
   - Move source YAML to `<workspace>/<agent>/guides/<intent>.guide.yaml.removed`
     (the **tombstone**). Tombstones have the same filename pattern
     so `git status` shows the diff; they're not invisible deletes.
   - `prime_guides_from_dir` skips files ending in `.removed`, so
     the next reprime will not resurrect.
4. **With `--keep-yaml`**:
   - YAML stays; only LanceDB entry removed. Useful when the operator
     wants to edit + re-prime (effectively "evict from cache").
   - This is a footgun in audit terms — `--reason` is required to
     leave a trail.
5. Delete LanceDB row by id (`guide_<agent>_<intent>`).
6. Write `kb_audit/<iso-ts>_remove_<intent>.yaml` with `action: remove`,
   `reason`, body_sha256, actor.
7. Print summary + exit 0.

Reason field is **required** (CLI errors without `--reason`). Suppression
escape hatch via `OLAV_KB_REMOVE_ALLOW_NO_REASON=1` for batch scripts.

## 5. R102 demotion (minimum-surgery change)

`commit_to_memory.py` change:

```python
# BEFORE
payload = {
    "schema_version": 1, "intent": intent, "agent": agent,
    "keywords": list(keywords), "body": body.strip() + "\n",
}

# AFTER
payload = {
    "schema_version": 2,
    "intent": intent,
    "agent": agent,
    "source_tier": "user",      # ← NEW; R102 always writes user-tier
    "keywords": list(keywords),
    "body": body.strip() + "\n",
}
if scope and scope != "global":
    payload["scope"] = scope
```

Then `prime_guides_from_dir` looks up `SOURCE_TIERS[tier]["priority"]`
and uses that to compute `weight`. The hardcoded priority/weight on
the LanceDB row reflects the tier.

R102 commit also writes one `kb_audit/<iso-ts>_commit_<intent>.yaml`
row alongside the LanceDB write — same audit format as kb remove.

### Operator promotion path

User-tier guide gets promoted to team-tier by:

1. `olav kb show <intent>` → prints the YAML
2. Operator copies into their team's git repo, edits `source_tier:
   team`, opens PR
3. CI merges + reploys `kb import-guides` on the operator workspaces
4. The old user-tier row is automatically prune-evicted by
   orphan-prune (the new YAML has the same intent + agent so writes
   to the same `id`, the user-tier row's content gets overwritten;
   priority updates from 3 → 6 on rewrite)

No `olav kb promote` CLI needed — git PR IS the promotion mechanism,
which preserves the audit chain. Implementing a promote CLI would
re-open the audit-bypass loophole.

## 6. CLI surface (final)

```
olav kb import-guides [<dir>]           # existing — primes from disk
olav kb remove <intent> --reason "..."  # NEW
olav kb show <intent> [--agent <name>]  # NEW — print YAML (for promotion)
olav kb list [--tier <tier>] [--agent <name>]  # NEW — table of active guides
```

`olav kb list` becomes the first-class "what's in my KB" report,
groupable by `source_tier`, replacing the ad-hoc `lancedb` Python
snippet from the runsheet.

## 7. Backward compatibility + migration

1. **Schema v1 YAML files** load successfully — treat as
   `source_tier: user` (most conservative). Log a warning at prime
   time.
2. **5 bundled guide files** in `olav-netops/.olav/workspace/netops/guides/`
   (the schema guides shipped 2026-05-15 commit 7f1ae71d) get
   `source_tier: platform` + `schema_version: 2` migration in the
   same PR as this work. Other bundled guides follow case-by-case.
3. **Per-skill `references/*.guide.yaml`** files (per-skill
   migration commit 1b964d29) get `source_tier: platform` blanket
   migration.
4. R102 v1 commits already in the wild stay v1 (warning logged) until
   operator runs `olav kb remove --keep-yaml <intent>` + rewrites.

No flag-day. No forced migration. Old YAML works, just with weaker
trust ranking.

## 8. What this DOESN'T solve

Out of scope (separate ADRs / follow-ups):

* **Multi-tenant scope isolation** — `scope: global | agent | team:X`
  is already a YAML field but the enforcement is best-effort. A real
  enterprise deployment needs per-tenant LanceDB tables, not just
  scope filtering.
* **Cryptographic provenance** — body_sha256 in `kb_audit/` is
  tamper-evident under git but not signed. A regulated environment
  would want GPG-signed audit rows.
* **R102's bare-confirmation gap** (ISSUE-R102-BARE-CONFIRMATION-LOSES-DRAFT-CONTEXT,
  P2) — orchestrator forgets pending draft between CLI turns. Fixed
  separately via guide / session-id, orthogonal to lifecycle work.
* **Embedder dim migration** — un-related, see ISSUE-CAB-EMBED-DIM-MIGRATION-DESTRUCTIVE.

## 9. Implementation plan

Single PR, four commits:

1. **schema + tier mapping** — `guide_kb.py` learns `source_tier`
   field; `UsageGuide` dataclass adds `source_tier: str = "user"`;
   prime path computes weight from tier table; YAML schema v2
   accepted alongside v1 with deprecation warning.
2. **R102 emits user-tier** — `commit_to_memory.py` writes
   `source_tier: user` + `schema_version: 2`; tests updated.
3. **kb remove + audit** — `olav kb remove` CLI + `kb_audit/` writer
   + tombstone handling in `prime_guides_from_dir`.
4. **kb list + kb show** — read-only inspection CLIs.

Tests added in `tests/governance/test_kb_lifecycle.py`:
* tier → priority → weight math
* R102 round-trip emits user-tier
* `kb remove` writes tombstone + audit row + LanceDB delete
* reprime skips tombstoned intents
* `kb show` round-trips identical YAML

Demo verification on `olav-demo-2026-05-15`:
* Existing `guide_services_netbox_sync_defaults` (R102-committed)
  re-prime with v2 → `source_tier: user`, priority 3, weight 0.83
* `olav kb remove netbox_sync_defaults --reason "moved to git repo"`
  → tombstone YAML, LanceDB row gone, `kb_audit/` entry written
* `olav kb list --tier user` → shows demoted guides only
