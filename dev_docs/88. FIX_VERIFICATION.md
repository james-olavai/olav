## Additional Observations

1. **T3 runner returns empty content:** The audit runner sub-agent calls `execute_skill_script` (map_engine.py, render_report.py) but the outer orchestrator receives `content=''` from the task tool. The runner's output is not being propagated back. This may be a separate bug from the recall_memory fix.

2. **T2 root cause:** The `<|tool_call>call:default_api:check_health{}</tool_call|>` format suggests the LLM is using a Gemma-specific tool-call syntax that the deepagents runtime doesn't parse. The ops sub-agent profile may need a different tool-call parsing configuration for this LLM.

3. **T4 LLM 503 on first call:** The local llama.cpp server returns 503 "Loading model" on the first request after a cold start. The runtime propagates this as a hard exception rather than retrying. This is a resilience concern for production demos.
