# 35. NetOps Doc-Driven Development Plan

**Date:** 2026-04-06
**Status:** Design — Pending Implementation
**Scope:** olav-netops 用户文档 + DDD Claim 验证
**Driver:** M2 发布前 netops 功能需要文档化、可验证

---

## 1. 原则

1. **文档是合同** — 先写文档声明功能，再验证代码是否匹配。不允许修改文档来适配代码行为
2. **按用户心智模型组织** — 用户想的是"我要做什么"，不是"哪个模块负责"
3. **Claim 可执行** — 每条 Claim 必须有对应的 CLI 验证指令
4. **双语同步** — 每个 `.en.md` 必须有对应 `.zh.md`
5. **平台文档不改** — netops 是扩展，只新增 `netops/` 节

**采集类（C-NE-01, 03, 04, 18）— 必须验证完整管道输出：**
```python
class TestNE03NetopsInitPopulatesDB:
    """C-NE-03: /netops_init → parsed_outputs 有数据"""
    def test_netops_init_produces_real_data(self):
        # 执行完整管道（不是检查 DB 里有没有旧数据）
        result = subprocess.run([OLAV, "--agent", "ops", "/netops_init"], ...)
        assert result.returncode == 0

        with duckdb.connect(str(MAIN_DB_PATH), read_only=True) as con:
            rows = con.execute("""
                SELECT device_name, command, parsed_data, snapshot_id
                FROM netops.parsed_outputs
                WHERE snapshot_id = (SELECT MAX(snapshot_id) FROM netops.parsed_outputs)
            """).fetchall()

        # 生产要求：≥6 设备 × ≥5 命令 = ≥30 行
        assert len(rows) >= 30, f"Expected ≥30 rows, got {len(rows)}"
        # 生产要求：parsed_data 是有效 JSON 数组，非空
        for device, cmd, parsed, snap in rows:
            data = json.loads(parsed) if isinstance(parsed, str) else parsed
            assert isinstance(data, list), f"{device}/{cmd}: parsed_data 不是 list"
            assert len(data) > 0, f"{device}/{cmd}: parsed_data 为空数组"
```
