### ISSUE-P2-OPS-WORKSPACE-BLOAT

**优先级**: 🟡 P2
**状态**: Open
**影响阶段**: Phase 2（ops agent 日常使用）
**发现日期**: 2026-04-03

#### 问题描述

`ops` workspace 存在三类臃肿：

**① ops/netbox 与 workspace/netbox 重复**

`.olav/workspace/ops/netbox/SKILL.md` 和 `.olav/workspace/netbox/SKILL.md` 描述同一批 NetBox 工具，维护两份。ops orchestrator 内嵌的 `netbox` subagent 与独立 `netbox` workspace 在功能上完全重合。

**② sim + topology 拆分过细**

`ops/sim/SKILL.md`（BGP/OSPF/路由分析）和 `ops/topology/SKILL.md`（MAC 表/ARP/物理链路）均为**纯本地计算**（networkx + DuckDB，无外部网络），拆成两个独立 subagent 导致 orchestrator 需要多一次 LLM 路由决策才能触达计算能力。

**③ workspace tools/ 与 olav-netops Python 包重复**

`.olav/workspace/ops/tools/` 下的脚本（`diff_configs.py`、`execute_cli.py`、`take_snapshot.py` 等）与 `olav-netops` Python 包中的工具存在功能重叠。`core/SKILL.md` 全局继承机制本可让所有 subagent 自动获得这些工具，无需在每个 workspace 下重复放置。

#### 影响

| 问题 | 影响 |
|------|------|
| netbox 重复 | 修改需同步两处；ops orchestrator 工具列表膨胀 |
| sim/topology 拆分 | 6 subagent → 需要多跳 LLM 路由；启动时多加载 2 个 LangGraph 图 |
| tools/ 重复 | olav-netops 更新时 workspace 脚本不会自动同步，存在版本漂移风险 |

#### 建议修法

1. **移除 `ops/netbox/SKILL.md`**，ops orchestrator 改为通过 `olav_delegate("netbox", ...)` 委托独立 `netbox` workspace — semantic router 已能跨 workspace 路由，无需内嵌。
2. **合并 `ops/sim` + `ops/topology` → `ops/analysis` subagent**，单一 SKILL.md 描述所有本地计算能力（路由分析 + 图拓扑分析），减少 1 个 subagent 和 1 次 LLM 路由跳。
3. **清理 `ops/tools/` 中已被 `core/SKILL.md` 覆盖的脚本**，只保留 ops 专属工具（`diff_configs.py` 等），通用工具删除。

#### 里程碑 3 扩展（olav-ent）

当 `async_subagents` 接入远程 LangGraph 部署后，sim/topology/analysis 可进一步卸载到高算力节点，ops orchestrator 退化为纯调度层（只需 LLM + olav_delegate，无本地重计算）。

#### 解除门禁条件

- `ops` workspace AGENT.md 中 subagent 数量 ≤ 4（当前 6）
- `ops/netbox/SKILL.md` 删除后，`olav --agent ops "查询 NetBox 中 R1 的接口"` 仍正常工作（通过 delegate 路由）
- `olav-netops` 工具列表与 workspace tools/ 无重复（通过 `core/SKILL.md` 继承验证）

**优先级**: 🟢 P2
**状态**: Open
**影响范围**: 纯 API 查询型 agent（netbox-circuits 等 Creator 生成的 workspace）
**发现日期**: 2026-04-02

#### 问题描述

`create_deep_agent()` 无参数可禁用 `FilesystemMiddleware`，导致所有顶层 agent（包括纯 API 查询型）都会被注入 `ls/read_file/write_file/edit_file/glob/grep` 等文件系统工具。

对 netbox-circuits 类型的 agent：工具列表 = 24 NetBox GET 工具 + 9 个框架工具（fs + task + run_python_code），LLM 上下文噪音增加约 40%。

**不影响功能**：agent 仍能正确查询 NetBox，文件系统工具不会被误触发。

#### 根本原因

deepagents `create_deep_agent()` 硬编码 `FilesystemMiddleware` 注入（graph.py L197/237/275），无 `no_filesystem` 参数。

#### 建议修法（低优先级）

在 SKILL.md frontmatter 增加 `agent_type: api` 或 `no_filesystem: true`，OLAV 据此调用 `create_agent()`（ReAct）而非 `create_deep_agent()`：

```yaml
metadata:
  agent_type: api     # → OLAV uses create_agent() instead of create_deep_agent()
```

#### 解除门禁条件

- `olav --agent netbox-circuits` 工具列表中不再出现 ls/write_file/edit_file
- 其他 deepagents 功能（todo tracking 等）保持可用
