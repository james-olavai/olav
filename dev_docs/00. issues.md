### ISSUE-P2-AUDIT-PROFILE-HYPHEN-UNDERSCORE-MISMATCH

**优先级**: P2
**状态**: ✅ Closed (2026-04-10)
**发现日期**: 2026-04-10

### ISSUE-P2-NETOPS-INIT-DB-SCHEMA-WRONG

**优先级**: P2
**状态**: ✅ Closed (2026-04-10)
**发现日期**: 2026-04-10
**来源**: C-NE-03 手动测试 — `run.py` 直接执行

#### 问题描述

`.olav/workspace/ops/netops_init/run.py` 中的 DuckDB 写入逻辑存在两个 bug：

1. **VIEW 冲突**：`CREATE TABLE IF NOT EXISTS parsed_outputs` 在 `main` schema 执行，但 `main.parsed_outputs` 是指向 `netops.parsed_outputs` 的 VIEW。IF NOT EXISTS 看到 VIEW 已存在便跳过建表，随后 `INSERT INTO parsed_outputs` 尝试向 VIEW 写入，报 `Catalog Error: parsed_outputs is not an table`。

2. **列顺序错误**：`INSERT INTO parsed_outputs VALUES (?,?,?,?,?,?,...)` 使用位置参数，但脚本中列顺序与 `netops.parsed_outputs` 实际列顺序不符（实际列：`device_name, command, parsed_data, snapshot_id, raw_output, raw_output_hash, ingested_at`），导致 `Conversion Error: Malformed JSON`。

**影响：** `run.py` 每次运行 SSH 采集均成功，但所有结果均无法写入 DB，84 条写入失败（14 命令 × 6 设备）。

#### 修复

`.olav/workspace/ops/netops_init/run.py`：
- 移除 `CREATE TABLE IF NOT EXISTS`（表已存在）
- 改为 `INSERT OR IGNORE INTO netops.parsed_outputs (device_name, command, parsed_data, snapshot_id, raw_output, ingested_at) VALUES (?, ?, ?, ?, ?, current_timestamp)`，使用显式列名和 schema 前缀。

### ISSUE-P2-NETOPS-INIT-JUNIPER-COMMAND-TIMEOUT

**优先级**: P2
**状态**: ✅ Closed (2026-04-10)
**发现日期**: 2026-04-10
**来源**: C-NE-03 手动测试 — R1 为 juniper_junos 平台

#### 问题描述

`DISCOVERY_COMMANDS` 列表为纯 Cisco IOS 命令（如 `show ip interface brief`）。在混合平台 inventory（含 Juniper 设备 R1）中，Juniper 不支持 IOS 命令，netmiko 触发 `ReadTimeout`，导致该设备 SSH 会话断开，后续命令全部跳过 R1，最终 R1 只写入 2 行而非 14 行。

**影响：** Juniper 设备无法完整采集；exit code 2（有失败）；R1 丢失 12 个命令的采集结果。

#### 修复

`.olav/workspace/ops/netops_init/run.py`：
- 将命令列表拆分为 `DISCOVERY_COMMANDS_UNIVERSAL`（2 条，兼容所有平台）和 `DISCOVERY_COMMANDS_IOS`（12 条，仅 Cisco）
- 引入 `_JUNOS_PLATFORMS` 集合和 `junos_hosts` 过滤集
- 对 IOS-only 命令使用 `ios_target`（排除 Juniper 主机），对 universal 命令使用全量 `target`
- 结果：72/72 成功，exit code 0

### ISSUE-P2-NETBOX-V2-TOKEN-AUTH-FORMAT

**优先级**: P2
**状态**: ✅ Closed (2026-04-10)
**发现日期**: 2026-04-10
**来源**: Demo runsheet Chapter 7 infra agent — NetBox 403 Forbidden

#### 问题描述

NetBox 5.2.x 引入了 v2 token 格式（HMAC peppered token）。存储在 `.olav/services/netbox/env/netbox.env` 中的 `NETBOX_TOKEN` 是陈旧的 v1 明文 token，NetBox 5.2 返回 `403 Invalid v1 token`。

NetBox v2 token 认证格式：`Authorization: Bearer nbt_<key>.<plaintext>`（非 `Token <value>`）。v2 token 不在 DB 中存储明文，只存 HMAC digest + pepper_id，因此 token 轮换后旧值永久失效。

#### 修复

通过 Django shell 重新生成 v2 token 并更新 env 文件：

```bash
docker exec netbox-netbox-1 python3 /opt/netbox/netbox/manage.py shell -c "
from users.models import Token
from django.contrib.auth import get_user_model
User = get_user_model()
admin = User.objects.get(username='admin')
Token.objects.filter(user=admin).delete()
t = Token(user=admin)
t.save()
print('NETBOX_TOKEN=nbt_' + t.key + '.' + str(t._token))
"
```

然后将输出的 `NETBOX_TOKEN=nbt_<key>.<plaintext>` 写入 `.olav/services/netbox/env/netbox.env`。

`services.yaml` 中 `auth.type: bearer` 配置正确（OLAV 发送 `Authorization: Bearer <token>`）。

#### 注意

此 token 仅在当前 NetBox 实例有效。如重建 NetBox 容器需重新生成。pepper 密钥 (`API_TOKEN_PEPPER_1`) 也需与 env 文件保持一致。

### ISSUE-P2-TOPOLOGY-LINKS-ETL-MISSING

**优先级**: P2
**状态**: Open
**发现日期**: 2026-04-10
**来源**: 测试团队 — LLDP/CDP 数据采集后 topology_links 表为空

#### 问题描述

`netops_init` 成功采集 `show cdp neighbors detail` / `show lldp neighbors detail`，数据以 TextFSM JSON 存入 `parsed_outputs.parsed_data`。但 **`parsed_outputs → topology_links` 的 ETL 步骤未实现**，导致 `topology_links` 表始终为空，所有依赖视图（`v_topo_links_clean`、`v_l2_topology_summary`、`v_device_neighbors_summary`）返回零行。

管道断裂点：
- `olav-netops/scripts/netops_init.py:566-572` 尝试 `from olav.core.topology_engine import extract_lldp_topology`
- **`src/olav/core/topology_engine.py` 文件不存在**
- import 被 try/except 包裹为 non-blocking warning，静默失败

#### 解决方案

创建 `src/olav/core/topology_engine.py`，实现 `extract_lldp_topology(con)` 函数：

1. **读取**：`SELECT device_name, command, parsed_data FROM netops.parsed_outputs WHERE command IN ('show cdp neighbors detail', 'show lldp neighbors detail')`
2. **解析**：遍历 `parsed_data` JSON 数组，提取邻居条目中的：
   - `source_device` = 当前 `device_name`
   - `source_interface` = 本端接口（TextFSM 字段 `local_interface` / `LOCAL_INTERFACE`）
   - `destination_device` = 邻居主机名（TextFSM 字段 `neighbor` / `NEIGHBOR`）
   - `destination_interface` = 对端接口（TextFSM 字段 `neighbor_interface` / `NEIGHBOR_INTERFACE`）
3. **生成 link_id**：确定性哈希 `hashlib.md5(f"{sorted_pair}:{sorted_intf}".encode()).hexdigest()`，确保 A→B 和 B→A 生成同一 link_id
4. **写入**：`INSERT OR IGNORE INTO netops.topology_links` 设置：
   - `discovery_protocol` = `'CDP'` / `'LLDP'`（根据原始 command 判断）
   - `link_type` = `'L2'`
   - `link_status` = `'up'`（从 parsed_data 可达即为 up）
   - `first_seen` / `last_seen` = `current_timestamp`
   - `snapshot_id` = 当前 snapshot_id

目标表 schema 已定义在 `olav-netops/src/olav_netops/core/tables.py:79-105`，视图已就绪，仅差 ETL 填充。

### ISSUE-P2-DIFF-E2E-NETMIKO-INJECTION

**优先级**: P2
**状态**: Open
**发现日期**: 2026-04-10
**来源**: 测试团队 — C-NE-26 diff 功能需要真实设备 E2E 验证

#### 问题描述

C-NE-26（`diff_topology_drift` 检测链路状态变化）当前仅有 gated 测试桩，未执行真实设备上的变更检测。需要端到端验证：在真实 CLAB 设备上注入配置变更，执行两次 snapshot，验证 diff 工具能检出变化。

#### 解决方案

使用 netmiko 注入变更 + 自动回滚的完整 E2E 流程：

```python
# tests/e2e/test_diff_netmiko_e2e.py

_DIFF_E2E_ENABLED = (
    os.environ.get("DIFF_E2E_ENABLED", "").strip() == "1"
    and _LLM_ENABLED
)

@pytest.mark.skipif(not _DIFF_E2E_ENABLED,
                    reason="Diff E2E: set DIFF_E2E_ENABLED=1 + LLM API key")
class TestDiffNetmikoE2E:

    def test_diff_detects_interface_change(self, clab_device):
        """C-NE-26: 真实设备 diff 检测"""
        host = clab_device["host"]
        # Step 1: 基线快照
        take_snapshot(snapshot_id="before", commands=[
            "show interfaces", "show ip interface brief",
            "show lldp neighbors detail",
        ])

        # Step 2: netmiko 注入变更
        changes = [
            "interface Loopback99",
            "description OLAV-DIFF-TEST",
            "ip address 10.255.255.99 255.255.255.255",
            "no shutdown",
        ]
        netmiko_configure(host, changes)

        try:
            # Step 3: 变更后快照
            take_snapshot(snapshot_id="after", commands=[
                "show interfaces", "show ip interface brief",
                "show lldp neighbors detail",
            ])

            # Step 4: 验证 diff 检出
            result = diff_sql_state("interfaces", "before", "after")
            assert any("Loopback99" in r for r in result), \
                "diff 未检出 Loopback99 变更"

        finally:
            # Step 5: 回滚（无论测试成功失败）
            rollback = [
                "no interface Loopback99",
            ]
            netmiko_configure(host, rollback)
```

关键设计决策：
1. **try/finally 保证回滚**：即使 assertion 失败也会执行 `no interface Loopback99`，不影响 CLAB 环境
2. **环境变量门控**：`DIFF_E2E_ENABLED=1` 防止 CI 中意外执行
3. **可扩展变更类型**：除 loopback 外，还可测试 VLAN 增删、接口 description 修改、BGP neighbor 变更等
4. **snapshot_id 隔离**：`before` / `after` 独立 snapshot，diff 工具按 snapshot_id 对比
