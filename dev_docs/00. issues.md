### ISSUE-TRACE-LEARNER-NOT-IMPLEMENTED

**状态**: Open
**发现日期**: 2026-04-10
**影响测试**: 16 个 (tests/unit/)

`trace_learner.py` 文件缺失，导致 `/trace-review` slash command 在生产中静默返回 `{"status": "error"}`，功能完全失效。

**根因**: `_handle_trace_review()` 在 `src/olav/cli/commands/trace_review.py` 中动态 import `trace_learner.py`，文件不存在时直接返回 error dict，所有断言 `status == "success"` 的测试失败。

**预期路径**: `olav-netops/.olav/workspace/config/sync/tools/trace_learner.py`

**失败测试**:

| 文件 | 数量 | 代表失败 |
|------|:----:|---------|
| `tests/unit/test_trace_learner.py` | 6 | `test_trace_learner_importable` — FileNotFoundError |
| `tests/unit/test_trace_learner_learn.py` | 8 | `test_run_learn_cycle_with_failures_writes_to_store` |
| `tests/unit/test_trace_review_slash.py` | 2 | `test_handle_trace_review_empty_db` — status='error' |

**需实现的契约**:
```python
# trace_learner.py 必须暴露：
_run_learn_cycle(hours, limit, db_path, store, llm) -> dict
# 返回：{status, total_failures, total_ok, failures, window_hours,
#        constraints_extracted, learn_count}
# - 读取 audit.duckdb error/cancelled runs
# - 为每个失败 run 收集 tool_call_failed / run_error events
# - LLM 通过 llm= 参数注入（unit test 中 mock）
```
