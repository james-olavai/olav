### ISSUE-P2-OC-NETCONF-LEGACY-CLEANUP

**状态**: Open
**发现日期**: 2026-04-11
**影响测试**: 12 FAIL（gate tests 引用已废弃的 OC/NETCONF 架构）

#### 问题描述

v0.11.0 的实际数据管道是 **SSH → TextFSM → JSON → DB → sandbox**，但代码库中残留了早期 OpenConfig/NETCONF 架构的代码和测试。这些遗留物没有任何调用者，导致 12 个 gate 测试 FAIL（测试引用了不存在的表/列/功能）。

#### 遗留清单

**死代码（应删除）：**

| 文件 | 行数 | 说明 |
|------|:----:|------|
| `src/olav/services/netconf_collector.py` | 281 | NETCONF 采集器 — 无 workspace/agent 调用它 |
| `tests/unit/test_netconf_collector.py` | 234 | 上述采集器的测试 |
| `ncclient>=0.7.1` in `pyproject.toml` | — | 死依赖，仅被 netconf_collector 引用 |

**死测试（应删除或重写）：**

| 文件 / 测试 | 引用的死概念 | 处置 |
|------|------|------|
| `test_gate_phase1::test_r2_has_netconf_domains` | NETCONF domains（采集不存在） | 删除 |
| `test_gate_phase2_normalization.py` **整个文件**（330 行, 11 tests） | `mapping_rules` 表（OC 规范化未实施） | 删除整文件 |
| `test_gate_phase4::test_p4_2_mapping_rules_is_ground_truth` | `mapping_rules` 表 | 删除 |
| `test_gate_phase4::test_nl_bgp_down_query` | `v_bgp_neighbors.prefixes_received` 列（不存在） | 修正为实际列名或删除 |
| `test_gate_phase4::test_nl_r2_neighbors_query` | 同上 | 同上 |

**死 DB 对象（可选清理）：**

| 表 | 行数 | 说明 |
|------|:----:|------|
| `yang_leaves` | 60 | 无消费者 — mapping_rules 不存在所以 yang_leaves 也没用 |
| `oc_outputs`（netops schema） | 0 | 空表 — OC 规范化未实施 |
| `mapping_table` | ? | 疑似遗留 |
| `oc_transforms` | ? | 疑似遗留 |
| `schema_catalog` | ? | 疑似遗留 |
| `pending_schema_evolutions` | ? | 疑似遗留 |

#### 解决方案

**Step 1 — 删除死代码：**
```bash
rm src/olav/services/netconf_collector.py
rm tests/unit/test_netconf_collector.py
# pyproject.toml 移除 ncclient>=0.7.1
```

**Step 2 — 删除死测试：**
```bash
rm tests/gates/test_gate_phase2_normalization.py
# test_gate_phase1: 删除 test_r2_has_netconf_domains
# test_gate_phase4: 删除 test_p4_2_mapping_rules_is_ground_truth
# test_gate_phase4: 修正 test_nl_bgp_down_query（移除 prefixes_received 列引用）
```

**Step 3 — 清理死 DB 对象（可选，下次 lab session）：**
```sql
DROP TABLE IF EXISTS yang_leaves;
DROP TABLE IF EXISTS netops.oc_outputs;
DROP TABLE IF EXISTS mapping_table;
DROP TABLE IF EXISTS oc_transforms;
DROP TABLE IF EXISTS pending_schema_evolutions;
```

**验证：** 清理后 `pytest tests/unit/ tests/gates/ -q` 应 0 FAIL。

### ISSUE-P1-SCHEMA-ENGINE-MODULE-MISSING

**状态**: Open
**发现日期**: 2026-04-11
**影响**: 4 个 workspace 工具 + 1 个 CLI 命令运行时崩溃

`src/olav/core/schema_engine.py` **不存在**，但 5 个文件在运行时 import 它：

| 文件 | import |
|------|------|
| `.olav/workspace/config/discovery/tools/classify_field.py:36` | `from olav.core.schema_engine import SchemaEngine` |
| `.olav/workspace/config/discovery/tools/trigger_schema_evolve.py:37` | `from olav.core.schema_engine import SchemaEngine` |
| `.olav/workspace/config/discovery/tools/create_unified_view.py:31` | `from olav.core.schema_engine import create_unified_view, build_mutation_request` |
| `.olav/workspace/config/discovery/tools/register_api_schema.py:272` | `from olav.core.schema_engine import SchemaEngine` |
| `src/olav/cli/commands/config_evolve.py:233` | `from olav.core.schema_engine import get_domain_collection` |

这些工具属于 OC 规范化架构（Phase 2），该架构已被 SSH → TextFSM → JSON 管道取代，但工具代码未清理。

#### 解决方案

**config/discovery 的 4 个工具全部是死代码** — 它们的唯一目的是 OC schema mapping，当前架构不需要：

```bash
# 删除 4 个死工具
rm .olav/workspace/config/discovery/tools/classify_field.py
rm .olav/workspace/config/discovery/tools/trigger_schema_evolve.py
rm .olav/workspace/config/discovery/tools/create_unified_view.py
rm .olav/workspace/config/discovery/tools/register_api_schema.py
# 更新 SKILL.md 移除这些工具引用
```

`config_evolve.py` 的 schema_engine import 在 try/except 内（动态 import），不影响启动，但 `olav config evolve` 命令会失败 — 需要决定是删除该命令还是实现 schema_engine。
