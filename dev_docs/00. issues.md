## P1 — 高优先级

### ISSUE-P1-E2E-CLAIMS-RUBBER-STAMPED

**状态**: Open
**发现日期**: 2026-04-10
**来源**: 测试审计 — C-NE claim 覆盖率交叉验证

`olav-netops/tests/test_e2e_claims.py` 号称 E2E claim 验证，实际 **24/25 个测试类是橡皮图章**：只检查文件存在、DB schema 列名、字符串匹配，零 agent 调用、零功能验证。

典型伪造：C-NE-15 "NL 查询返回数据" → 实际 `SELECT count(*) > 0`；C-NE-33 "审计报告" → `map_engine.py` 文件存在。

**35 个 C-NE claim 实况：** genuine 12 / gated 5 / fake 8 / 无测试 11 / 弱断言 8

**修复：** 伪测试迁移到 `tests/gates/`，为每个 claim 建立真正的功能断言（见 `38. NETOPS_DDD_PLAN.md` §6.2 生产质量断言标准）。

---

### ISSUE-P1-CI-RUNS-ZERO-TESTS

**状态**: Open
**发现日期**: 2026-04-10

GitHub Actions 无任何 workflow 运行 pytest。3 个现有 workflow（release.yml / deploy-olav-web.yml / olav-doc deploy.yml）只做 build/deploy。

**后果：** ~150 测试从未在 CI 执行，代码合并前无质量门。

**修复：** 新增 `test.yml` workflow — push/PR 时运行 `pytest tests/unit/ tests/gates/`，nightly 运行 gated E2E。

---

### ISSUE-P1-PHASE-TESTS-MASQUERADE-AS-E2E

**状态**: Open
**发现日期**: 2026-04-10

`tests/e2e/test_phase{1,2,3,4}*.py` 共 ~86 测试，全是静态 DB 查询（`SELECT count > 0`），零 agent 调用。放在 `tests/e2e/` 暗示 E2E 但实际是前置条件检查。`test_phase3` 末尾 xfail 自承 "GATE-BYPASS-1"；`test_phase4` 名含 "nl_acceptance" 但零 NL 查询。

**修复：** 迁移到 `tests/gates/test_gate_phase*.py`，为每个 Phase 建立真正 E2E（调用 agent/管道 → 验证输出）。
