### 6. ISSUE-P2-RECALL-NO-ACCESS-COUNT-BUMP

**状态**: Open

`AutoRecallMiddleware.enrich()` 搜索到 memories 并注入 prompt 后，**不更新 `access_count`**。导致：
- `access_count` 全为 0（1535 条无一被标记为已召回）
- C-KB-08（高频 recall 衰减减半）永远不触发
- 知识质量反馈闭环断裂

**修复：** `enrich()` 在 `_format_memory_block()` 后，对命中的 memories 批量 bump：

```python
# middleware.py enrich() — 在 return 前追加
for mem in memories:
    try:
        self._store.update_memory(
            mem["id"],
            access_count=(mem.get("access_count", 0) or 0) + 1,
        )
    except Exception:
        pass  # non-blocking
```

### 7. ISSUE-P2-TIME-DECAY-NEVER-SCHEDULED

**状态**: Open

`apply_time_decay()` 从未被任何调度器调用。`schedule_time_decay()` 需要 `apscheduler` 但未配置。weight 全 1.0 → agent memory 永不衰减 → 旧知识与新知识同权重。

**修复两个选项：**

**A（推荐）：`olav service daemon start` 时自动调度**
```python
# daemon.py 启动时
from olav.core.memory.middleware import schedule_time_decay
scheduler = schedule_time_decay(store, interval_hours=24, half_life_days=60)
```

**B：cron 方式**
```bash
olav --agent config "add cron: apply_time_decay every 24h"
```
