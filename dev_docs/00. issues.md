### ISSUE-TRACE-LEARNER-NOT-IMPLEMENTED

**状态**: ✅ Closed (2026-04-10)
**发现日期**: 2026-04-10
**影响测试**: 16 个 (tests/unit/)

`trace_learner.py` 文件缺失，导致 `/trace-review` slash command 静默返回 `{"status": "error"}`。

**根因**: `src/olav/cli/commands/trace_review.py` 动态 import `trace_learner.py`（搜索 `olav-netops/.olav/workspace/config/sync/tools/` 和 `.olav/workspace/config/sync/tools/`），文件不存在时返回 error dict。

#### 解决方案

在 `olav-netops/.olav/workspace/config/sync/tools/trace_learner.py` 实现 ~150-200 行，4 个函数：

```
_analyze_failures(hours, limit, db_path) → dict
  查 audit_runs WHERE status='error' + JOIN audit_events
  WHERE event_type IN ('tool_call_failed', 'run_error')
  → {status, total_failures, total_ok, failures: [{run_id, agent_id, error_events}]}

_extract_constraints(report, llm=None) → list[str]
  total_failures==0 → [] 不调 LLM
  否则 LLM 提取约束，处理 markdown fence（```json...```）

_write_constraints_to_memory(constraints, store, scope="global") → int
  调用 olav.core.memory.guardrails.store_failure_memory()
  跳过空字符串，返回写入数量

_run_learn_cycle(hours, limit, db_path, store=None, llm=None) → dict
  编排 1→2→3，store/llm 允许 None（lazy-load），测试中 mock 注入
  → 合并 dict + constraints_extracted + learn_count
```

16 个测试已定义完整契约，纯实现任务。

### ISSUE-TRACKING-DOC-CONSISTENCY-STALE

**状态**: ✅ Closed (2026-04-10)
**发现日期**: 2026-04-10
**影响测试**: 1 个 (tests/unit/)

`test_tracking_doc_consistency.py::test_tracking_uses_current_cli_module_paths` 断言 `"olav-netops" in tracking_text`，但 tracking.md 已切换为 M3 UKS 聚焦。

#### 解决方案

**删除该测试文件。**

理由：
1. 原始意图是防止 tracking.md 引用已废弃的内部路径（`admin_cmd.py`, `onboard.py`）— tracking.md 内容已从 CLI 路径跟踪变为功能 TDD 跟踪，意图已失效
2. tracking.md 内容由业务决策驱动，不应被测试锁定为必须包含特定字符串
3. 硬塞 "olav-netops" 只为让测试通过属于本末倒置

```bash
rm tests/unit/test_tracking_doc_consistency.py
```
