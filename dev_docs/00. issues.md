## 🟡 活跃 Issues

### ISSUE-P1-DEEPAGENTS-TOOL-ISOLATION

**优先级**: 🟡 P1
**状态**: 部分缓解，根本修复待定
**影响阶段**: 所有 Agent（Creator / Ops / Quick / Config）
**发现日期**: 2026-04-02

#### 问题描述

deepagents 框架与 OLAV 的 SKILL.md 工具声明模型之间存在结构性冲突，导致：

1. **SKILL.md 被忽略**：`SkillsMiddleware` 只把 SKILL.md 内容追加到 system prompt（文档化），不会限制实际可用工具。deepagents 仍为每个 agent 自动注入 `FilesystemMiddleware`（`ls / read_file / write_file / edit_file / glob / grep / execute`）和 `TodoListMiddleware`（`write_todos`），无论 SKILL.md 是否声明。

2. **task() 子 agent 工具集不可控**：通过 `task()` 委托启动的子 agent，除自身声明工具外，还会收到 deepagents 默认全工具栈。在 Creator E2E 测试中，子 agent 使用了 `run_python_code / glob / web_search` 等 SKILL.md 中未声明的工具，绕过了平台管道（`register_api_service` 等 bridge 工具未被调用）。

3. **父 agent 状态传递给子 agent**：`SubAgentMiddleware` 在调用子 agent 时，将父 agent 的完整状态（files 积累、skills metadata、所有 state keys 除 messages 外）复制给子 agent。父 agent 若 context 已膨胀（如大量工具返回值），子 agent 一开始就在高负载 context 下运行。

4. **工具返回值无边界 → context 膨胀 → task() 逃跑**：当工具返回大量无截断数据（如 `execute_sql` 的大型 JSON 字段、`run_shell` 的完整日志），LLM 因 context 接近上限倾向于调用 `task()` 委托，而委托出去的子 agent 缺乏专用工具，进一步降级处理。

#### 已缓解措施（2026-04-02）

- ✅ `read_api_schema`：改为返回紧凑 `tags_summary`（13 tags + 计数），不再返回 1166 条完整 endpoint + 参数（原始 ~500KB → 现在 ~2KB）
- ✅ `execute_sql`（4个workspace）：`_sanitize_value()` 增加字段截断（>800字符截断 + `…[truncated]` 标记）
- ✅ `run_shell`：stdout 截断至 10KB，stderr 截断至 2KB，增加 `truncated` 标记
- ✅ Creator system prompt：明确禁止使用 `task()` 委托，要求 agent 直接执行全部 6 步
- ✅ Creator E2E 验证通过：agent 正确调用 6 步 bridge 工具，生成 24 个 circuits 函数文件

#### 架构结论（2026-04-02 深入调查）

**迁移到 deepagents 原生架构不能解决此问题**，原因：
- `FilesystemMiddleware` 在 deepagents `graph.py` 中为硬编码强制注入，无任何参数可禁用
- deepagents 原生无 workspace/SKILL.md 系统，迁移将丢失 OLAV 60% 的核心价值（工具自动发现、插件注册、审计、LLMFactory）
- 全量迁移工作量 15-20 天，且根本问题依然存在

**真正的根本修复：`olav_delegate()` 自定义委托工具（3-5 天）**

```python
@tool
def olav_delegate(subagent_name: str, task_description: str) -> str:
    """绕过 deepagents SubAgentMiddleware，以 ONLY 声明工具启动子 agent。"""
    tools = discover_tools(workspace / subagent_name / "tools")
    runnable = create_agent(llm, tools=tools, middleware=[TodoListMiddleware()])
    return runnable.invoke({"messages": [HumanMessage(task_description)]})
```

- 完全绕过 `SubAgentMiddleware`，不注入 `FilesystemMiddleware`
- 不需要 fork deepagents，纯 layering
- 子 agent 只有 SKILL.md 声明的工具

#### 根本修复待定

| 修复项 | 难度 | 优先级 | 说明 |
|--------|------|--------|------|
| `olav_delegate()` 工具实现 | 中（3-5天） | P1 | 真正隔离的子 agent 调用，完全绕过 SubAgentMiddleware |
| 无工具 subagent 也走 CompiledSubAgent | 低（1天） | P1 | 当前只有有工具的 subagent 才编译，无工具走默认全栈 |
| 高风险工具补充返回上限 | 低（1天） | P2 | `take_snapshot` / `diff_configs` 待补截断 |

#### 解除门禁条件

`olav_delegate()` 实现并替换主 agent 中对 deepagents `task()` 的依赖；CompiledSubAgent 覆盖所有 subagent（含无工具）；task() 委托不再作为 LLM 逃跑路线被触发。
