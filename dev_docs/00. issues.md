### ISSUE-P1-SKILL-INSTALL-NO-CORE-INJECTION

**状态**: Open
**发现日期**: 2026-04-12

`olav skill install olav-netops/` 安装 ops workspace，但不注入任何工具到 core agent。用户必须知道 `--agent ops` 才能做网络查询。

#### 设计方案

**skill 包的 `workspace.yaml` 声明注入策略：**

```yaml
# olav-netops/workspace.yaml
name: olav-netops
kind: SkillPack

# 日常工具 → 注入 core（用户不需要 --agent）
inject_into_core:
  tools:
    - search_commands      # 命令搜索
    - execute_cli          # SSH 单设备执行
    - take_snapshot        # 快照采集
    - diff_configs         # 配置对比
  references:
    - SCHEMA_REFERENCE.md  # DB schema 参考

# 专业 agent → 独立注册（需要 --agent）
agents:
  - ops                    # 深度分析 orchestrator
  - ops-lab                # 数字孪生
  - audit-designer         # 审计设计
  - audit-auditor          # 审计执行
  - devops                 # 脚本生成
  - infra                  # API 查询

# slash commands → 全局注册
slash_commands:
  - /netops_init
```

**`olav skill install` 行为变化：**

```python
def _install(source):
    decl = _read_workspace_yaml(source)
    
    # 1. 部署独立 agents（现有行为）
    for agent in decl.agents:
        _copy_agent_workspace(source / agent, target / agent)
    
    # 2. 新增：注入工具到 core
    if decl.inject_into_core:
        core_tools = target / "core" / "tools"
        for tool_name in decl.inject_into_core.tools:
            # 符号链接：core/tools/search_commands.py → ops/tools/search_commands.py
            src = _find_tool_source(source, tool_name)
            dst = core_tools / src.name
            if not dst.exists():
                dst.symlink_to(src.resolve())
        
        core_refs = target / "core" / "references"
        for ref_name in decl.inject_into_core.references:
            src = _find_reference_source(source, ref_name)
            dst = core_refs / src.name
            if not dst.exists():
                dst.symlink_to(src.resolve())
        
        # 更新 core/SKILL.md tools 列表
        _append_to_core_skill_md(decl.inject_into_core.tools)
    
    # 3. olav refresh（现有行为）
    _platform_refresh()
```

**不声明 `inject_into_core` 的 skill：** 只注册独立 agent，不碰 core。这是安全默认。

**卸载时：** `olav skill remove olav-netops` 删除符号链接 + 从 core SKILL.md 移除工具名。

#### 实施步骤

**Phase 1 — workspace.yaml 扩展**
1. `WorkspaceDeclaration` dataclass 新增 `inject_into_core` 字段
2. `skill.py::_install()` 读取并执行注入
3. `skill.py::_uninstall()` 清理符号链接

**Phase 2 — olav-netops workspace.yaml 更新**
1. 添加 `inject_into_core` 声明
2. 测试：全新 venv → `olav init` → `olav skill install olav-netops/` → `olav "R1 show version"` → core agent 直接执行（无需 `--agent`）

**Phase 3 — 代码清理**
1. 删除 `.olav/workspace/quick/`（工具已合并入 core）
2. `cli/main.py:195` 删除 `agent = "quick" if ws == "core" else ws` 硬编码
3. core AGENT.md 更新：从"平台开发 agent"变为"统一运维助手"
4. core/prompts/system.md 重写：加入"你有 SQL、CLI、KB、日志、写作能力"

### ISSUE-P1-AGENT-ARCHITECTURE-FRAGMENTED

**状态**: Open
**发现日期**: 2026-04-12

当前 13 个 workspace agent 职责碎片化严重，用户需要记忆 `--agent` 名称：

```
用户实际需求                     需要输入的命令
"R1 有几个 BGP 邻居?"          olav "..."              → quick agent（自动）
"模拟 R3 断开的影响"            olav --agent ops "..."   → ops agent（手动）
"生成 BGP 健康检查报告"         olav --agent audit "..." → audit agent（手动）
"写一个备份脚本"               olav --agent devops "..."→ devops agent（手动）
"润色这份报告"                 olav --agent writer "..." → writer（不存在）
"NetBox 有几台设备?"           olav --agent infra "..." → infra agent（手动）
```

#### 设计方案：合并为 3 层

```
Layer 1: core agent（默认，用户不需要指定 --agent）
  ├── 快速查询：execute_sql, search_commands（原 quick 的工具）
  ├── 知识搜索：recall_memory, search_logs, web_search
  ├── 写作润色：writer skill（新增，doc 44）
  ├── 平台管理：deploy_service, manage_cron, run_shell
  └── 自动路由：问题超出 core 能力 → 建议用户使用专业 agent
  
Layer 2: 领域 agent（需要 --agent 或 core 推荐）
  ├── ops     — 深度分析 + 模拟 + lab（有子 agent：analysis/probe/diff/lab）
  ├── audit   — 合规审计（designer + auditor）
  └── devops  — 脚本生成

Layer 3: 基础设施 agent（按需注册）
  ├── infra   — NetBox/InfluxDB API 查询
  └── gitea   — Git 仓库管理
```

**关键变化：**
1. **quick 合并入 core** — quick 的 4 个工具（execute_cli, search_commands, diff_configs, take_snapshot）移入 core，quick workspace 废弃
2. **writer 放入 core** — 是常用能力不是独立 agent
3. **core 成为默认入口** — `olav "任何问题"` 都先到 core，core 能解决的直接解决，不能的推荐 `--agent ops/audit/devops`
4. **SemanticRouter 接入** — core 内部用路由判断是否需要 escalate

**好处：**
- 用户 90% 的操作不需要 `--agent`
- core 有 SQL + CLI + KB + 日志搜索 + 写作能力 → 覆盖日常运维
- 只有深度分析（ops）、合规审计（audit）、脚本生成（devops）需要专业 agent
- 与 doc 44 Writer 设计一致：writer 不是独立 agent，是 core 的一个能力

#### 实施步骤

**Phase 1 — core agent 升级**
1. core/AGENT.md `description` 改为："统一运维助手 — SQL 查询、CLI 执行、知识搜索、日志分析、报告写作"
2. core/prompts/system.md 重写：
   - 删除"你是平台开发 agent"的定位
   - 加入："你是日常运维助手，能直接回答网络查询、执行 CLI、搜索知识库、分析日志、润色报告"
   - 加入 escalation 规则："如果用户需要多步骤故障分析 → 建议 `--agent ops`；合规审计 → `--agent audit`；批量脚本 → `--agent devops`"
3. core/SKILL.md 合并 quick 的 4 个工具 + writer references

**Phase 2 — quick workspace 废弃**
1. `cli/main.py:195` 删除 `agent = "quick" if ws == "core" else ws`
2. 默认 agent 永远是 `core`（`get_active_workspace()` 返回 "core"）
3. `.olav/workspace/quick/` 标记 DEPRECATED（保留一个版本周期）
4. `src/olav/data/workspace/` 不再包含 quick 模板

**Phase 3 — 代码清理**
1. 删除 `src/olav/data/workspace/quick/`（打包模板）
2. 删除 `.olav/workspace/olav/`（空壳 main agent，被 core 替代）
3. 删除 `.olav/workspace/venv-test-skill/`（测试残留）
4. 删除 `.olav/workspace/labs/`（空目录）
5. 删除 `.olav/workspace/gitea/`（如无使用者）
6. `olav refresh` 后验证 `olav list` 只显示有用的 agent
7. 更新 `42. DEMO_RUNSHEET.md` — 移除所有 `--agent quick` 引用

**Phase 4 — SemanticRouter 接入（ISSUE-P1-SEMANTIC-ROUTER-NOT-WIRED）**
1. `olav refresh` 调用 `initialize_router()` 建 `agent_intent_index`
2. `cli/main.py` 用 `route_query()` 结果决定 agent（不仅审计）
3. 路由逻辑：score > 0.85 → 直接路由到专业 agent；score < 0.85 → 默认 core
