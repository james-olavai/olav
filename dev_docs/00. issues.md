### ISSUE-T3-01-RELOAD-CONFIGLOADER-SINGLETON

**状态**: ✅ Fixed in `src/olav/api/server.py`
**发现日期**: 2026-04-14
**修复日期**: 2026-04-14
**类型**: P2 — 平台 bug

`POST /reload` 只重置了 `_agent_instance`，未重置 `ConfigLoader` 单例。`ConfigLoader._loaded = True` 导致后续请求始终读取首次加载的配置快照。写入 `api.json`（例如修改 `auth.mode`）后调用 `/reload` 不会生效，必须重启服务才能应用更改。

**影响**：`/reload` 的 config 热重载功能完全失效，包括 auth.mode、llm、embedding 等所有配置项。

**Fix**: 在 `reload_agent()` 中加入 `ConfigLoader._loaded = False; ConfigLoader._instance = None`，使下次请求重新从磁盘读取 `api.json`。

### ISSUE-T1-01-PID-REUSE-RACE


**状态**: ✅ Fixed in `src/olav/cli/commands/services/web.py`
**发现日期**: 2026-04-14
**修复日期**: 2026-04-14
**类型**: P2 — 平台 bug

`WebService._is_running()` used `os.kill(pid, 0)` which only confirms a PID exists in the process table — not that it is our uvicorn process. When killed externally, the stale PID file was left behind. If the old PID was reused by another OS process before the next `start()` call, `_is_running()` returned `True` → uvicorn never spawned → port 2280 empty.

**Fix**: Added `_is_our_process(pid)` module-level helper that reads `/proc/<pid>/cmdline` (Linux) or `ps -p` (macOS) and checks for `"uvicorn"` or `"olav.api.server"`. Updated `_is_running()` to call it after `os.kill(pid, 0)` succeeds — if the process identity check fails, the stale PID file is deleted and `False` is returned. Returns `True` conservatively when identity cannot be determined (e.g. PermissionError) to avoid accidental double-starts.

### ISSUE-P1-SERVICE-REFERENCES-GO-TO-DOMAIN-NOT-CORE

**状态**: ✅ Fixed — default output_dir changed to core/references/services (v0.17.2)
**发现日期**: 2026-04-15
**类型**: 架构 — infra 是平台能力不是域功能

`olav registry register` 生成的 API reference 文档写入 `workspace/infra/references/`（netops 域路径）。core agent 无法加载这些 references → 用户问 "NetBox 里 R1 的信息" 时 core 不知道怎么构造请求。

**services.yaml** 中所有 `output_dir` 都指向 `workspace/infra/references`：
```yaml

  output_dir: .olav/workspace/infra/references   ← netops 域路径
```

**本质问题：** infra 能力（注册 API 服务 + schema-aware 查询）是**平台级功能**，不是网络域功能。任何 OLAV 用户（不只是网络运维）都应该能：
1. `olav registry register jira http://jira:8080`
2. `olav "Jira 上有多少 open tickets?"`
3. core agent 用 api_request 查 Jira

**修复方向：**
- `output_dir` 默认改为 `workspace/core/references/services/`
- core SKILL.md 声明 `static_context` 加载服务 references
- 域扩展（netops）可以 symlink 或共享读取 core 的 references

### ISSUE-P1-EXECUTE-SQL-SYNTAX-ERROR

**状态**: ✅ Fixed — stray `)` removed (2026-04-15)
**发现日期**: 2026-04-15
**修复日期**: 2026-04-15
**类型**: P1 — 平台 bug（tool 完全不加载）

`execute_sql.py` 第 450 行有一个多余的 `)`，导致 SyntaxError。`discover_tools()` 加载模块失败 → execute_sql 工具不注册 → orchestrator 只有 3 个 tools（缺少最关键的查询工具）。

**影响：** v0.17.2 wheel 中的 execute_sql 完全不可用。用户无法执行任何 SQL 查询。

**根因：** 之前编辑 SCHEMA_HINT 赋值时遗留的括号。此外，ternary 表达式的优先级也需要额外括号确保正确求值。

**修复：**
```python
# Before (broken):
SCHEMA_HINT = "Schema: " + " | ".join(_hint_parts) if _hint_parts else "..."
)  # ← stray paren

# After (fixed):
SCHEMA_HINT = ("Schema: " + " | ".join(_hint_parts)) if _hint_parts else "..."
```

**修复范围：** `core/tools/execute_sql.py` + `core/query/tools/execute_sql.py`（两份拷贝）
