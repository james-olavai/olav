### ISSUE-RAW-01: Topology ETL 缺少 raw fallback — Gitea #10

**状态**: Open → P1
**发现日期**: 2026-04-17
**设计文档**: `dev_docs/50. DATA_PIPELINE_SELF_HEALING.md`

`topology_engine.py:74` 只从 `parsed_outputs` 的 LLDP/CDP JSON 提取链接。Junos `show lldp neighbors` TextFSM 解析失败 → R1 链接丢失 → 拓扑图不完整。

**raw_output_store 中有完整数据**（LLDP raw text），但 Topology ETL 不读 raw。

**修复:** Topology ETL 检测缺失设备 → fallback 到 `raw_output_store` 的 LLDP/CDP raw text → regex 提取邻居。

**验证:** `olav "网络拓扑"` 应包含 R1 的 LLDP 链接。

### ISSUE-RAW-02: execute_sql 不引导查询 raw_output_store

**状态**: Open → P1
**发现日期**: 2026-04-17

`execute_sql` docstring 和 schema hints 只提及 `parsed_outputs`，不提 `raw_output_store`。当 LLM 查询 "R1 BGP 状态" 时，只查 parsed（为空）→ 报告 "无数据"，不 fallback 到 raw。

**修复:**
1. `execute_sql` docstring: common tables 添加 `raw_output_store`
2. `ops/SKILL.md` Database Schema: 添加 `raw_output_store` 表 + fallback SQL pattern
3. `core/prompts/system.md`: 添加 fallback 查询规则

**验证:** `olav "R1 的 BGP 邻居"` → 应从 raw 获取 2 peers (3.3.3.3, 10.1.12.2)
