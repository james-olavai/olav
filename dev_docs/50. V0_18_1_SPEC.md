## 1. Top-level agents (4)

```
.olav/workspace/
├── audit/       — offline analysis / anomaly detection / reporting
├── core/        — platform control plane; orchestrator + admin
├── ops/         — live network operations (ex-ops-lab now lives at ops/lab)
└── services/    — NEW: service-shaped integrations (deploy/stop/registry)
```

`ops-lab/` folds into `ops/lab/` in Sprint 3. `audit/learner` stays but
merges cosmetically with `audit/designer` under the `auditor` brand.

**Governance:** `test_top_level_is_exactly_four_agents`

---

## 2. core tool budget

`core/SKILL.md` declares **at most 7 tools**, selected from:

1. `execute_sql`
2. `recall_memory`
3. `web_search`
4. `tool_help`
5. `get_static_context`
6. `olav_delegate` (to sub-agents)
7. `run_shell`  *(reserved; drop when admin agent picks it up)*

Everything else the model wants — `execute_cli`, `take_snapshot`,
`diff_configs`, `api_request`, `deploy_service`, … — goes through
`olav_delegate("<target-agent>", ...)`. Small models (8K window) cannot
afford the ambient list otherwise.

**Governance:** `test_core_agent_has_at_most_7_tools`

## 5. `services/` top-level agent

New dir `.olav/workspace/services/`:

```
services/
├── AGENT.md
├── SKILL.md
└── tools/
    ├── deploy_service.py
    ├── stop_service.py
    ├── register_service.py      # NEW
    └── api_request.py
```

Rationale: `services.yaml` + service-shaped integrations (NetBox,
InfluxDB, Gitea, CLAB, etc.) deserve a dedicated agent instead of
bloating `core/` or `ops/`. Discoverable via `olav --agent services`.

**Governance:** `test_services_agent_exists_as_top_level`

## 7. 小模型档位约束（ties into Sprint 0b）

Under `model_tier=small`:

* `core` agent ambient prompt ≤ **2,500 tokens** (measured via
  `TokenUsageCallback`).
* `static_context_mode` for the core / ops orchestrators must be
  `on_intent` or `lazy` (never `always`).
* Every sub-agent's SKILL.md lists at most **5 tools** (matches
  `tier_default("small", "core_tool_budget", 5)` from Sprint 0b).

**Governance:**
- `test_core_prompt_within_small_tier_budget`
- `test_static_context_modes_honor_small_tier`

## 10. Sprint 3 order-of-work

Recommended execution sequence (independent slices; pick up in this
order to preserve CI greenness):

1. `services/` agent scaffold (+ move `deploy_service`, `stop_service`,
   `api_request` from core; un-xfail
   `test_services_agent_exists_as_top_level`).
2. Merge `audit/designer` into `audit/auditor` as a skill.
3. Merge `ops/{analysis,diff}` → `ops/analyze`.
4. Fold `ops-lab/` into `ops/lab/` and merge with `ops/probe` → `ops/collect`.
5. Trim `core/SKILL.md` to ≤7 tools; rest routed via `olav_delegate`.
6. Run the small-tier budget audit (Sprint 0a token_meter emits
   measurements; compare to 2.5K target).

Rollback: every step is an isolated git commit; revert the one that
breaks.
