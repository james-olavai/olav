# 100. OLAV Demo Runsheet V3 — pip-install + zero-config + full-capability sweep

**Date**: 2026-07-05
**Version**: v0.22.1 (public PyPI: `olav` + `olav-netops`; software-understands-human UX + local-embedding fix)
**Duration**: ~30 min headline sweep / ~50 min full sweep
**Supersedes**: `dev_docs/67. DEMO_RUNSHEET_V2.md` (v0.19.0, source-install, manual init)
**Audience**: screen-recording demo — a viewer who has never seen OLAV should
go from "never installed it" to "it understands me and runs my network" without
watching anyone read a manual.

> **Why V3** (what changed since V2):
> 1. **Public pip install** — `pip install olav olav-netops` from PyPI
>    (0.22.1). No source checkout, no editable install, no `olav agent
>    install /path/`. `olav skill install olav-netops` now resolves the
>    installed package's bundled workspace.
> 2. **Zero-config onboarding is the opening act** — bare `olav` bootstraps
>    itself and asks once for the LLM key. `olav init` is no longer step 1.
>    The new "software understands the human" layer (dev_docs/99) becomes
>    Ch0/Ch1 headline material, not an afterthought.
> 3. **New capability chapters**: `olav doctor` / `/doctor` (Ch1), state-aware
>    welcome screen + returning-user continuity (Ch1), conversational
>    self-configuration + rollback (Ch8), generalized undo (Ch8),
>    runtime-failure recovery hints (Ch8).
> 4. **Data**: `tmp/anon/` — 16 weekly anonymized OLAV-canonical archives
>    (2025-11-02 → 2026-02-15) from a **339-device, 13-site** campus network.
>    36 command types. This is the scale story; no live devices required.
> 5. Chapter order re-sequenced for a recording arc: **hook (onboarding) →
>    data → intelligence → self-management/self-config → depth**.

## LLM backend for the recording

Use whatever the dev box is pinned to (`api.json` `llm.model`); the demo
narration never names the model. If asked, OLAV is model-agnostic and
small-model-first (runs on local qwen3-class 27B). Keep embedding on
`local` unless you specifically want to show cloud embedding — the
welcome-screen finding in Ch1 will honestly report if the local embedder
is unavailable, which is itself a talking point (don't hide it).

## Demo data — one-liner

```
tmp/anon/network_data_backup_<date>.tar.gz   (16 weeks, ~100 MB each)
  format:   home/admin.demo/network_data/<command>/<device_fqdn>   (OLAV canonical, NOT RANCID)
  scale:    339 devices · 13 sites · 36 command types
  sites:    alpha beta gamma delta epsilon eta zeta theta iota kappa lambda mu nu
  domain:   net.demo.internal   ·   IPs SHA-256 → 10.x.x.x (topology preserved)
```
**Always pass an absolute path** (`$(pwd)/tmp/anon/...`) — relative paths
fail inside the importer subprocess.

## Ch1 — Install & first run: the software sets itself up (5 min) ★

**Goal**: from `pip install` to a working, self-diagnosed agent — one
install, one question (the API key), nothing else.

```bash
# 1. Install both packages from public PyPI
pip install olav olav-netops

# 2. Just run it. No `olav init`, no editing api.json.
olav
```

On this first bare run OLAV detects an empty project and bootstraps
itself, then asks for the one thing it cannot infer:

```
First run detected — setting up OLAV...
platform ready: created .olav scaffolding · db · workspace · embedder · guides
No LLM API key configured yet.
Paste your LLM API key: ********
✓ API key saved to .olav/config/api.json
```

You land in the interactive TUI. The **welcome screen reflects real
state** — not a generic tip. On this box it will say something true,
e.g.:

```
OLAV ready — explore, audit, or schedule. What's next on the network?
⚠ netops is installed but not initialized yet — run /netops_init to create
  its tables, then import a snapshot or collect from devices.
```

(Or, if the local embedding backend is down, it says *that* instead — let
it; honesty is the point.)

```bash
# 3. Health check — anytime, from shell or inside the TUI
olav doctor              # shell
# /doctor                # same check, inside the TUI, no exit needed
```

```
✓ scaffolding: .olav/ deployed
✓ llm: connected
⚠ embedding: <real status with an actionable fix if degraded>
overall: <healthy | needs attention>
```

```bash
# 4. Deploy the netops + audit agents from the installed package
olav skill install olav-netops       # resolves the pip package's bundle
olav list                            # core, admin, audit, devops, netops, services
```

**Verification**:
* `olav version` → `v0.22.1` (or newer — a bare `pip install` gets the latest)
* `olav list` → 6 agents (core/admin/audit/devops ship in the base wheel;
  netops/audit deploy via `skill install olav-netops`)
* `olav doctor` prints a per-check report; every ⚠ line carries a `fix:`
* No `olav init` was ever typed; no `api.json` was hand-edited

**Talking point**: this is "software understands the human, not the other
way around." Zero-ritual onboarding (bootstrap is automatic, one
irreducible secret is asked for once), a first screen that tells you your
*actual* state instead of a canned tip, and a zero-LLM `doctor` that works
even when the LLM config itself is what's broken. `olav skill install
olav-netops` resolves the pip-installed package — no source tree needed
(dev_docs/99 §7.1/§7.6).

> **Optional fork — pick your embedding backend NOW, before any data (30 s)**
> The default embedding is `BAAI/bge-small-zh-v1.5` (90 MB, auto-downloaded,
> zero-config) — leave it and skip this for the fastest demo. **But if you
> intend to use a local Ollama embedding model, do it here** — before Ch2
> imports data or any memory is built — so you never re-embed later. This is
> the *right time* for it precisely because switching the embedding model
> changes the vector dimension; doing it on an empty store is free, doing it
> after Ch2/Ch4/Ch5 means rebuilding the memory table (`EmbeddingDimMismatchError`
> by design). The switch itself is the full Ch8b flow — validated before it
> commits, one sentence to roll back:
> ```bash
> olav --agent admin "switch embedding to api mode using the local Ollama \
>   model embeddinggemma at http://localhost:11434/v1 (api key 'ollama')"
> olav doctor          # → ✓ embedding: connected (now via Ollama)
> ```
> Keep the zero-config default for the headline recording; take this fork
> only when the story is specifically "runs entirely on your own local
> stack." Full walk-through + the raw-string integration detail: **Ch8b**.

# DATA

## Ch2 — Offline import: a 339-device campus, no SSH (8 min)

**Goal**: zero data → a production-scale network in DuckDB, purely from
offline archives — the same downstream pipeline as live SSH collection.

```bash
# Absolute path to the archive dir. Set it to wherever tmp/anon lives:
#   host demo:      BUNDLE=/home/<you>/Olav/tmp/anon
#   container demo: BUNDLE=/data/anon         (see Appendix F mount)
BUNDLE=/absolute/path/to/tmp/anon           # ← edit this one line
[ -f "$BUNDLE/network_data_backup_2026-02-15.tar.gz" ] || echo "BUNDLE path wrong — fix it before continuing"

# Import the most recent week
olav --agent netops "Import the network backup at $BUNDLE/network_data_backup_2026-02-15.tar.gz"
#  importer pipeline: survey_bundle → validate_bundle (sha256) → ingest_snapshot

# Import an earlier week too — sets up week-over-week drift in Ch6
olav --agent netops "Import the network backup at $BUNDLE/network_data_backup_2026-02-08.tar.gz"

# Confirm scale
olav "How many devices were imported? Show the site distribution."
```

**Verification**:
```bash
olav "How many devices are there?"            # → ~339
olav "List devices grouped by site prefix"    # → 13 sites: alpha … nu
# Chain of custody — every import is a row
duckdb .olav/databases/domain.duckdb -c \
  "SELECT bundle_id, collector, hosts_ingested, ingested_at
   FROM netops.bundle_ingests ORDER BY ingested_at DESC LIMIT 5"
```

**Talking point**: the `importer` sub-agent turns an offline archive into
the same TextFSM → ETL → auto-views path as live SSH — SHA-256 validated,
full audit chain. 339 devices across 13 sites lands with no network
access: air-gapped, trade-show, and archive-replay all work. And note the
welcome screen's Ch1 nudge ("no device data yet") is now satisfied — the
software walked you here.

## Ch3 — Core NL queries (5 min)

**Goal**: natural language → SQL → answer, with AutoRecall injecting
relevant memory so a small model lands correct SQL first try.

```bash
olav "Which devices are access-layer switches?"
olav "Show CDP neighbors for the alpha site core switches"
olav "Which interfaces are down across the delta site?"
```

**Verification**: each answer is backed by one `execute_sql` call (no
schema round-trips — `schema_knowledge` was pre-injected); repeated
query shapes get faster as `query_pattern` memory is captured and recalled.

**Talking point**: memory beats prompt engineering — `<relevant-memories>`
injected on every model call. This is why OLAV targets local small models
(qwen3 7–30B): fix the prompt with memory, not the model.

## Ch4 — Knowledge Base: declarative memory (4 min)

**Goal**: author a team rule in YAML, have AutoRecall surface it.

```bash
cat > .olav/workspace/netops/references/site_naming.guide.yaml <<'EOF'
schema_version: 2
intent: site_naming_convention
agent: netops
source_tier: team
keywords: [site, naming, hostname, prefix, 命名, 站点]
body: |
  Campus device hostnames follow <site>-<role><n>-<model> on
  net.demo.internal (e.g. alpha-as1-3850 = alpha site, access switch 1,
  Catalyst 3850). Sites: alpha beta gamma delta epsilon eta zeta theta
  iota kappa lambda mu nu.
EOF

olav kb import-guides .olav/workspace          # prime into LanceDB
olav kb list-guides --tier team                # inspect the live KB
olav --agent netops "What's our site naming convention and which sites exist?"
```

**Verification**: the answer quotes the guide body; `olav kb show
site_naming_convention` prints the YAML for git-PR promotion.

**Talking point**: declarative `*.guide.yaml` is the version-controlled,
schema-bound, team-shareable memory path — the steering layer. To change
how an agent behaves, author a guide, don't edit a prompt (ADR-0015).

## Ch5 — Conversational memory (R102, HITL) (6 min)

**Goal**: tell OLAV in natural language what to remember; `memory_curator`
shapes it and commits only after explicit confirmation in a separate turn.

```bash
olav --agent core "记住 —— delta 站点的 core 交换机维护窗口是每周日 02:00-04:00"
# → curator renders a YAML preview, waits
# next turn:
olav --agent core "commit the draft: commit_to_memory(from_draft=true, intent='delta_maintenance_window')"

olav --agent core "What's the maintenance window for delta core switches?"
# → quotes the committed rule
```

**HARD HITL**: the curator NEVER commits without a confirmation in a
*separate* turn after the preview. "I've reviewed" inside the first
message does not count.

**Talking point**: three memory on-ramps — implicit L1 capture,
declarative YAML (Ch4), conversational NL (this). Just talk; no schema to
learn.

**Goal**: multi-step analysis across the campus; intent-routed sub-agents;

```bash
# reporter (investigation): "investigate / why / drift / blast-radius"
olav --agent netops "Investigate interface errors across the campus — which sites are worst?"

# analyzer (change planning): "plan / add / change / modify"
olav --agent netops "Plan adding a redundant uplink from alpha-as1 to a second core. \

# → reporter: diff_snapshots → added/removed/modified config lines per device, per section
```

**Verification**: reporter returns a structured diff (`device`, `section`,
`change_type`, `before`, `after`) across the 13-site campus; analyzer's

Mermaid diagram with no DB access of its own.

Optional depth (mention, run if time):
* `olav --agent netops "/learn_cmd cisco_ios 'show spanning-tree'"` — learner drafts+freezes a TextFSM parser (self-healing parse layer)
* `olav --agent netops "Which devices are single points of failure?"` — topology graph analysis
* `olav --agent netops "Does alpha-core's outbound policy permit the 10.0.0.0/8 summary?"` — simulator (Batfish, config-layer, no SQL)

**Talking point**: netops has 8 sub-agents, each ≤7 tools to keep small-model

## Ch8 — Self-configuration, undo, recovery (6 min) ★

**Goal**: change config by talking, safely; undo agent actions; recover
from a runtime failure — all conversational, none requiring a file editor.

```bash
# 1. Conversational config change — validated BEFORE it's saved
olav --agent admin "switch my LLM model to <some-model>"
#   editor: tests the candidate against the live provider first;
#   a bad model/key is REJECTED with the real error, working config untouched.

# 2. Show the safety net with an intentionally bad key
olav --agent admin "update my LLM api key to sk-obviously-invalid-000"
#   → "Rejected — candidate config failed to connect: 401 ... Current config unchanged."

# 3. Roll back the last (good) change in one sentence
olav --agent admin "rollback my LLM config"

# 4. Generalized undo for agent write-actions (files, cron)
olav --agent admin "undo my last change"
#   → reverts the most recent journaled write_workspace_file / manage_cron action

# 5. Runtime-failure recovery hint (optional, dramatic):
#    with a broken key, a normal query fails with a POINTER, not a stack trace
OLAV_LLM_API_KEY=sk-broken olav "how many devices are there?"
#   → "The LLM provider rejected the API key ... run `olav doctor` to diagnose.
#      If this started after a config change, undo it:
#      olav --agent admin 'rollback my LLM config'"
```

### Ch8b — Switch embedding to a local Ollama model (conversational) ★

**Goal**: point OLAV's embedding backend at a **local Ollama** embedding
model, entirely by talking to the admin agent — no `api.json` editing,
validated against the live endpoint before it's saved.

> **Ordering note**: this chapter documents the *mechanism*. If your demo
> actually uses Ollama embedding for the whole run, do it at the **Ch1
> optional fork** (before Ch2 imports data), not here — switching after a
> memory store exists means a dimension change and a rebuild. Run it here
> only to *showcase* safe config change on a store you don't mind
> re-embedding.

**Prereq**: olav **≥ 0.22.1** (the local-embedding raw-string fix + the
`base_url` param landed there; a bare `pip install olav` gets it). Plus
Ollama running with an embedding model, e.g. `ollama pull embeddinggemma`
(verified live from PyPI 0.22.1 at `localhost:11434`, 768-dim).

```bash
olav --agent admin \
  "switch embedding to api mode using the local Ollama model embeddinggemma \
   at http://localhost:11434/v1 (api key can be 'ollama')"
#   editor → update_embedding_config(mode=api, model=embeddinggemma,
#            base_url=http://localhost:11434/v1, api_key=ollama)
#   → probes the real Ollama endpoint FIRST; commits only if it embeds cleanly.

# Confirm it took effect
olav doctor            # → ✓ embedding: connected  (now via Ollama)

# One-sentence rollback to the bundled local model
olav --agent admin "rollback my embedding config"
```

**Verification**:
* success message names the changed keys (mode/model/base_url/api_key);
  `.olav/config/api.json` `embedding.api.base_url` = the Ollama endpoint
* `olav doctor` reports `embedding: connected`
* rollback restores the pre-change `embedding` section

**Talking point**: same validate-before-commit story as the LLM — you
describe the endpoint in plain language, OLAV proves it works against the
real server before writing anything, and one sentence rolls it back.
Note the small integration detail OLAV handles for you: local
OpenAI-compat servers (Ollama/llama.cpp/vLLM) only accept raw-string
embedding input, so OLAV auto-disables tiktoken tokenisation for any
non-`openai.com` endpoint — the user never sees the "invalid input type"
400 that trips up naive OpenAI-client integrations.

**Verification** (Ch8 overall):
* bad candidate → `.olav/config/api.json` byte-identical before/after (rejected, not written)
* good change → previous config snapshotted to `api.json.lastgood`; rollback restores it
* undo → the last file/cron mutation is reverted; `undo_last_action(list_only=True)` previews first

**Talking point**: you never hand-edit JSON and never lose a working setup
to a mistake. Every config change is validate-before-commit; every change
is snapshotted; every agent write-action is journaled and undoable; every
runtime failure points at the fix. This is the recovery half of "software
understands the human" (dev_docs/99 §3.4/§3.5/§7.2/§7.4).

**Recording note**: after the demo, re-run `olav doctor` to confirm the
box is back to a healthy config (the bad-key steps use env override /
rejected candidates, so nothing should have persisted — verify on camera).

## B. Common failure modes + fixes

| Symptom | Cause | Fix |
|---|---|---|
| `olav skill install olav-netops` → path not found | ran before `pip install olav-netops` | install the package first — resolution needs it importable |
| welcome screen shows embedding ⚠ | local embedder backend unavailable on this box | it's honest state; either fix per the `fix:` line or narrate it as the doctor value-prop |
| import fails / relative path | importer runs in a subprocess | always pass absolute `$(pwd)/tmp/anon/...` |
| `--agent netops "find problems"` loops | explorer lives in audit, not netops | use `--agent audit "find issues"` |
| config change "succeeds" but nothing changed | candidate failed validation, was rejected | that's the safety net working — read the rejection reason |
| runtime 401 mid-demo | key expired / bad env override lingering | `olav doctor`; `unset OLAV_LLM_API_KEY`; `rollback my LLM config` |
| agent stops without a tool call | small-model adherence variance | re-run; behavioural steps have LLM variance (N≥3 before calling it broken) |

## F. Recording in a clean container (recommended for "fresh machine" authenticity)

A throwaway container is the most honest vessel for Ch0's "clean machine"
hook — and, verified 2026-07-05, the local embedding model works better in
it than on a GPU-torch dev box (slim images ship CPU torch, so no
`libcudnn` issues; the welcome screen won't show a spurious embedding ⚠).

```bash
cd /path/to/Olav                      # repo root, so tmp/anon is mountable
docker run --rm -it \
  -v "$(pwd)/tmp/anon:/data/anon:ro" \  # demo archives, read-only → BUNDLE=/data/anon in Ch2
  -e OLAV_EMBEDDING_MODE=local \
  python:3.12-slim bash

# —— inside the container: this IS the runsheet ——
pip install olav olav-netops          # Ch1
mkdir /root/olav-demo && cd /root/olav-demo
olav                                  # Ch1: self-bootstrap → paste LLM key (needs the -it TTY)
olav doctor
olav skill install olav-netops
# Ch2: BUNDLE=/data/anon  (the mount above)
olav --agent netops "Import the network backup at /data/anon/network_data_backup_2026-02-15.tar.gz"
```

Notes:
* **`-it` is mandatory** — Ch1's key prompt and the whole TUI need a real TTY.
* **LLM key**: the container has default egress to reach the provider. Either
  paste it live at the Ch1 prompt (best for the "one question" story) or
  pre-set `-e OLAV_LLM_API_KEY=sk-...`.
* **`--rm` = fresh every run** (serves the Ch0 hook). To rehearse then record
  against the same state, drop `--rm`, add `--name olav-demo`, or mount a
  named volume over `/root/olav-demo/.olav`.
* **Optional speed-up**: pre-build an image with `pip install` + the embedding
  model pre-downloaded to skip ~1-2 min of first-run download — at the cost of
  the authentic "from pip install" moment. Pick per what the recording emphasises.
