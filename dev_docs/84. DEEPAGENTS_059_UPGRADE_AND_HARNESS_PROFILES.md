# 84. deepagents 0.5.9 upgrade + tier-based harness profiles

**Date**: 2026-05-16
**Scope**: dependency bump + architectural decisions that came out of it
**Commits**:
* `661006c0` — bump deepagents 0.5.1 → 0.5.9 + jump_to state-leak fix
* `f48ee53d` — harness profile system + P0/P1 follow-ons
* `2270fdfe` — track netops sub-agent definitions in git
* `17c889e0` — refactor profiles per-model → per-tier

This document captures the **why** behind those four commits so
future maintainers don't re-litigate the trade-offs.

## 1. Why bump deepagents 0.5.1 → 0.5.9

Two issues forced the bump and neither is going away:

### 1.1 KeyError 'model' under KB-heavy sub-agents

In KB-heavy explorer / audit runs, when the parent orchestrator
called a sub-agent via the `task` tool, the sub-agent's
model→tools branch occasionally raised `KeyError: 'model'` from
`langgraph.graph._branch.BranchSpec._finish`.

**Root cause** (verified at langchain 1.2.18 / langgraph 1.1.10 / deepagents 0.5.9 — all the same wiring at HEAD):

`langchain.agents.factory._make_model_to_tools_edge`
(`factory.py:1701`) can return `model_destination` (the
`loop_entry_node` name) via two paths:

* **Path 1** (line 1705) — when `state["jump_to"] == "model"`,
  `_resolve_jump` returns `model_destination`.
* **Path 6** (line 1751) — when the AIMessage has tool calls
  that are all already answered (artificial tool messages),
  returns `model_destination` as a "go back to model" signal.

But the conditional-edge destination list at `factory.py:1515-1517`
**only includes `loop_entry_node` when `response_format` is set OR
when `loop_exit_node != "model"`** (i.e. there's an after_model
middleware in the chain):

```python
model_to_tools_destinations = ["tools", exit_node]
if response_format or loop_exit_node != "model":
    model_to_tools_destinations.append(loop_entry_node)
```

For OLAV sub-agents (built via `create_agent` with only
`TodoListMiddleware + SummarizationMiddleware + AnthropicPromptCachingMiddleware`,
none of which declare `before_model` / `after_model` hooks),
`loop_entry_node == loop_exit_node == "model"` and
`response_format is None`. Branch ends dict is `{"tools",
"__end__"}` — `"model"` is **not** a valid destination — so when
the path callable returns it, `KeyError`.

### 1.2 The jump_to state leak that triggers it

`deepagents.middleware.subagents._validate_and_prepare_state`
(`subagents.py:344-350`) copies the parent's
`runtime.state` into the sub-agent's initial state, minus a fixed
exclusion set:

```python
_EXCLUDED_STATE_KEYS = {"messages", "todos", "structured_response",
                        "skills_metadata", "skills_load_errors",
                        "memory_contents"}
```

**`jump_to` is not in that set.** So if the parent ever has
`jump_to="model"` in state (Path 6 trigger from a previous turn,
or an upstream middleware), it leaks into the sub-agent and fires
Path 1.

### 1.3 OLAV's monkey-patch (the actual fix)

`src/olav/agents/agent.py:112-140` patches `_EXCLUDED_STATE_KEYS` at
import time to include `"jump_to"`:

```python
try:
    import deepagents.middleware.subagents as _ds_subagents_for_jump
    if "jump_to" not in _ds_subagents_for_jump._EXCLUDED_STATE_KEYS:
        _ds_subagents_for_jump._EXCLUDED_STATE_KEYS.add("jump_to")
        logger.info("✓ Patched ...")
except (ImportError, AttributeError) as _exc:
    logger.warning("Could not patch ... %s: %s", ...)
```

Verified in vivo: the bake-off in `olav-demo-inbox-prod` previously
crashed at the recall_memory call (the first call after parent
state is propagated into the sub-agent). After the patch, the
exact same scenario ran 22 tool calls cleanly, recorded 3 findings,
and only stopped because gemma4 hit the wall-clock timeout
generating verbose narrative (a separate model-quality issue).

### 1.4 Why not fix upstream first?

The langchain wiring oversight and the deepagents exclusion list
are both unfixed at HEAD as of 2026-05-16 (verified directly via
GitHub `raw.githubusercontent.com`). Filing an issue and waiting
for a release is multi-week. The monkey-patch is 5 lines, has a
docstring explaining the root cause, and degrades gracefully if
the upstream API changes (the try/except logs a warning and the
agent still starts).

### 1.5 Secondary benefits of the bump

* `FilesystemPermission` (0.5.2) is finally importable —
  `src/olav/agents/agent.py:574-612` had a `try/except ImportError`
  that silently no-op'd on 0.5.1. On 0.5.9 the virtual-FS write
  guard is actually live.
* CompiledSubAgent name → `lc_agent_name` metadata (0.5.6) —
  LangSmith traces show sub-agent names properly.
* GP-subagent permission inheritance (0.5.7) — auto-added
  general-purpose sub-agent inherits parent's permissions.

## 2. Why tier-based profiles, not per-model

deepagents 0.5.4 added the `HarnessProfile` system (per-model
prompt-suffix / excluded-tools / excluded-middleware overrides).
The built-in examples are model-specific (`_anthropic_sonnet_4_6.py`,
`_openai_codex.py`) because Anthropic / Codex have published
prompting guidance for those specific models.

The first cut of OLAV's profile (`gemma4.py`, commit `f48ee53d`)
copied that pattern: one profile per model spec. Three days later
we refactored it (`17c889e0`) to tier-based:

```
src/olav/agents/profiles/
├── __init__.py
├── tier_small.py    ← gemma / phi-3 / 7B-8B llama / qwen-7b / haiku / grok-4.1-fast
└── tier_medium.py   ← qwen3.6:27b / qwen2.5:14b-32b / mixtral / mistral-small
```

No `tier_large.py` — large models (gpt-4-turbo / claude-sonnet /
opus) need no OLAV-imposed discipline; deepagents stock behavior
suffices.

### 2.1 Why the refactor was needed

The "Local Small-Model Discipline" suffix + 8 excluded auto-tools
(`write_todos / ls / grep / read_file / write_file / edit_file /
execute / glob`) + `TodoListMiddleware` exclude — **none of these
were gemma4-specific.** They're size-class fixes for:

* Reaching for auto-injected tools the model wasn't asked to use
  (the "plan-loop tail" — R88-A / R89 / R90 in dev_docs/77).
* Multi-paragraph PLAN narratives before tool calls (context-budget
  waste).
* Unreliable parallel tool calling (small models can't reason
  across simultaneous tool invocations).

These apply uniformly to every <=8B-class local model OLAV is
likely to encounter. Putting them in a `gemma4.py` was
miscategorisation.

### 2.2 Why tier is the right axis

OLAV already classifies models via
`olav.core.config._TIER_REGEX_SMALL` /
`_TIER_REGEX_MEDIUM` for:

* `context_budget` (8K / 32K / 200K)
* `recall_top_k` (LanceDB memory injection — 1 for small, more
  for medium/large)
* SummarizationMiddleware trigger threshold (50% / 65% / 80% of
  budget)

Profiles now follow the same axis. Adding a new small model means
appending one spec string to `tier_small._SMALL_MODEL_SPECS`
instead of writing a new profile file.

### 2.3 What's left for per-model profiles

Real model-specific overlays exist:

* **Anthropic prompt caching** — `AnthropicPromptCachingMiddleware`
  only does anything for Claude. Currently injected unconditionally
  in `agent.py:1088-1089` at sub-agent compile time. A proper fix
  is conditional injection based on model identity, but profile
  `extra_middleware` doesn't apply to `CompiledSubAgent` (see §3),
  so this would be a partial fix at best. Deferred (task #537).
* **Codex action bias** — deepagents ships `_openai_codex.py` as
  a built-in. OLAV doesn't need to write its own; when the user
  picks `openai:gpt-5.3-codex`, the built-in profile registers
  itself.
* **Grok OpenRouter routing** — this is `init_chat_model` kwargs
  (model construction), not a `HarnessProfile` concern. Belongs in
  `ProviderProfile` if anywhere, but OLAV's `core/llm.py` bypasses
  deepagents' `resolve_model` entirely, so the registration hook
  doesn't fire. Not solvable via profiles.

## 3. The CompiledSubAgent limitation

`HarnessProfile.extra_middleware`'s scope (deepagents 0.5.4
`harness_profiles.py:687-705`):

> Applied to the main agent, the auto-added `general-purpose`
> subagent, and declarative synchronous subagents created from
> `SubAgent` specs — i.e., the stacks that `create_deep_agent`
> assembles itself.
>
> Not applied to `CompiledSubAgent` runnables or `AsyncSubAgent`
> entries. A `CompiledSubAgent` is passed in pre-built (its
> `runnable` is already a compiled graph with its own middleware
> chain), so `create_deep_agent` has nothing to append to.

**OLAV's sub-agents are all `CompiledSubAgent`**
(`agent.py:1086 runnable = create_agent(...)`, wrapped in a
`CompiledSubAgent` dict at line 1024). This is intentional —
sub-agents are loaded from `.olav/workspace/<agent>/SKILL.md` with
their own tool whitelist, prompt, and middleware, and we want the
exact graph we authored, not a re-build.

So **profile-driven middleware on sub-agents is impossible without
restructuring sub-agent construction to use `SubAgent` dicts**
(declarative, deepagents builds the graph). That's a deeper
refactor than this commit cycle accepted — leaving the existing
ad-hoc middleware logic in `agent.py:1024-1099` in place.

### 3.1 Defense in depth: profile + post-compile prune

Because profile excluded_tools doesn't reach sub-agents, OLAV
keeps the post-compile prune in `agent.py:1151-1153`
(`_DEEPAGENTS_INJECT_TOOLS` frozenset). Two-layer guard:

* **Profile-level** (tier_small.excluded_tools): orchestrator
  never sees the auto-injected tools at all.
* **Post-compile prune** (`_prune_graph_tools`): all sub-agents
  + orchestrator have these tools stripped from the compiled
  graph regardless of model.

The post-compile prune handles non-tier-matched models (anything
not in `_SMALL_MODEL_SPECS` or `_MEDIUM_MODEL_SPECS`) and all
sub-agents. The profile layer is defense for the orchestrator.

## 4. Workspace tracking model

Before commit `2270fdfe`, the rule
`pattern: olav-netops/**` in `ownership_manifest.yaml` was
`git: ignore`. Sub-agent definitions in
`olav-netops/.olav/workspace/netops/<sub-agent>/` (SKILL.md,
prompts, references, @tool wrappers) were on-disk-only — anything
the user edited there never propagated to git.

Today's commit added two rules:

```yaml
- pattern: olav-netops/.olav/workspace/netops/**
  git: track          # 35 new files committed: explorer/, ingest/, ...

- pattern: olav-netops/.olav/workspace/netops/collect/config/nornir/defaults.yaml
  git: secret         # contains real lab credentials (cisco/<redacted-lab-password>)
```

The generator (`scripts/gen_gitignore.py`) emits secret rules
**after** track-negation rules so the secret pattern wins on the
specific path.

### 4.1 Pre-existing secret in history

`olav-netops/.olav/workspace/netops/collect/config/nornir/defaults.yaml`
was added in commit `ad99eee0` (well before this cleanup). The new
`git: secret` rule prevents future re-tracking but does NOT
expunge the existing commit. Rotating + `git rm --cached` +
`git filter-branch` / BFG history rewrite is a separate cleanup
that needs explicit operator sign-off (breaks fresh-clone CLAB UX
and rewrites public history).

## 5. What this session deliberately did NOT do

* **Migrate sub-agents from `CompiledSubAgent` → `SubAgent` dicts.**
  Required to make profile `extra_middleware` apply to sub-agents.
  Touches `_build_subagents` and a dozen sub-agent SKILL.md
  loaders. Out of scope; tracked as a follow-up.

* **deepagents-cli 0.0.41 → 0.0.59.** 12 patches behind. Each
  requires verifying `src/olav/cli/tui_overlay.py` monkey-patches
  still bind (WelcomeBanner constants, DeepAgentsApp.TITLE /
  _handle_command, command_registry). Mostly CLI UX fixes
  (Thinking spinner, HITL approval reason, OSC 9;4 progress) —
  low user-facing impact, high binding-review cost. Closed as
  deprioritized.

* **Capability overlays (Anthropic caching / Codex / Grok).**
  Each has either a deepagents built-in covering it, or a layer
  mismatch that makes the overlay redundant/regressive (see §2.3).
  Closed as deprioritized.

* **Collapse `HAS_SUMMARIZATION` / `HAS_LOCAL_SHELL_BACKEND` /
  `HAS_NAMESPACE_FACTORY` / `HAS_ASYNC_SUBAGENTS`** in
  `_deepagents_bridge.py`. With floor at 0.5.9 these are all
  tautologically True. Kept as defensive scaffolding because
  they cost nothing at runtime and let us drop the floor again
  without rewriting call sites.

## B. Correction (2026-05-16, post-architecture-review)

The original dev_docs/83 §13a-b design had ``promote_finding_to_audit``
generate a v4.0-shaped audit profile YAML from a finding row. **This
was wrong on two counts:**

1. **Performance** — forcing the LLM to emit structured YAML with
   strict frontmatter / job schema burns tokens on schema-adherence
   retries; small models (gemma4) fail this regularly. The audit
   ``author`` sub-agent already exists precisely for shaping
   structured profiles — letting it do its job means the explorer
   can stay in plain markdown mode where it's strongest.

2. **Skips human review** — auto-promoting a finding to a recurring
   audit check pre-empts the operator's judgment about what's worth
   permanent monitoring vs. one-time investigation. The corrected
   flow puts a human between the discovery and the rule:

```
explorer (LLM)
   ↓ format_and_export
exports/reports/explore_<run_id>.md   (free-form markdown)
   ↓
   ↓  human reads, decides which findings warrant permanent monitoring
   ↓
olav -a audit "Read exports/reports/explore_xxx.md and create
              profiles for any finding marked 'should re-monitor'."
   ↓
audit / author sub-agent
   ↓ create_profile_atomic / save_profile / append_jobs
audit/profiles/<name>.md   (v4.0 frontmatter + jobs[])
   ↓
olav -a audit "run <name>"
   ↓
audit / runner → run_map_engine + render_report
```

### What was removed

* ``src/olav/core/explorer/promote.py`` — entire module (also took
  ``read_audit_profile_provenance`` since the provenance block it
  read was a property of the removed YAML schema; no production
  caller existed anyway).
* ``olav-netops/.olav/workspace/netops/explorer/tools/promote_finding_to_audit.py``
  — the @tool wrapper.
* ``promote_finding_to_audit`` from
  ``olav-netops/.olav/workspace/netops/explorer/SKILL.md`` tools
  list.
* Section 0 of explorer ``prompts/system.md`` REPORT phase that
  instructed the LLM to emit ``promote_finding_to_audit(...,
  dry_run=True)`` calls.
* ``tests/unit/test_explorer_promote.py``.
* Updated ``tests/governance/test_explorer_subagent_skill.py`` to
  assert the tool is **absent** (was previously asserted to be
  present).

### What stays unchanged

* ``netops.exploration_findings`` schema — findings still recorded
  with SQL evidence; they're just consumed via the markdown report
  now, not via direct YAML generation.
* Audit runner + author + curator sub-agents — already correctly
  shaped for the corrected lifecycle; no change needed.
* The ``audit_runs.collection_source`` field (v0.22 migration) is
  unrelated and stays.

### What the audit ``author`` sub-agent needs to learn

In principle the author can already shape a profile from any
natural-language description, including "here's a markdown report,
turn finding X into a profile". The author's existing system prompt
+ ``create_profile_atomic`` / ``save_profile`` tools handle this.
A small SKILL.md hint pointing operators at the explore-report → audit
workflow is the only documentation gap remaining — left for a
follow-up if the operator interaction friction proves real.
