## 3. Architecture wins (in priority of impact)

### W1 — Adaptive endpoints (Patches A + B, `ec3f49b`)

Made deployment-tier switching pure-config.  Three tiers
contractually supported:

| Tier | LLM | Embed | Reranker |
|---|---|---|---|
| Layer 1 (full local) | Ollama | `BAAI/bge-base-en-v1.5` SentenceTransformer | disabled |
| Layer 2 (LLM-only minimum) | any | `mode: none` (BM25 fallback) | disabled |
| Layer 3 (full cloud) | OpenRouter | Perplexity / OpenAI | OpenRouter Cohere Rerank |

Required:
* `LlamaCppReranker` extended with optional `model` + `api_key` →
  Bearer header for cloud kinds.
* `LLMConfig.api_key` + `EmbeddingConfig.openai_api_key` precedence
  flipped: per-section first, shared fallback, env last.
  (Was: shared first, which clobbered per-section in heterogeneous
  setups.)
* New `kind` aliases: `openrouter` / `cohere` / `openai_compat` /
  `openai` all dispatch the same `LlamaCppReranker` class with
  cloud parameters.

### W2 — LLM-only minimum mode (Patch C, `95a076b`)

`embedding.mode = "none"` is now a real production path.  Audited
every `embed_text() → store.add_memory()` call site; only
`commit_to_memory.py` was missing the None-vec guard.  Fixed +
added 2 tests.

Memory degrades gracefully:
* Reads: `_gather_candidates` skips vector search, hits
  `search_by_text` (BM25 only) when `query_vector is None`.
* Writes: zero-vector placeholder so the row lands; FTS keeps it
  searchable.

### W3 — Agent re-org Step 1+2 (`950c79b` + `9306c89`)

Ops orchestrator went from 6 sub-agents (analyze/collect/lab/devops/
infra/writer) → 3 (analyze/collect/lab).  `devops` and `infra`
promoted to top-level workspaces.  `core/admin` folded into
`services` (its 5 platform-mgmt tools moved across).

Net: ~5-7 KB of orchestrator prompt budget reclaimed.  Plus the
domain-prefix naming standardization (`netops_ops`,
`netops_topology`, `netops_learner`, `devops_scripts`,
`devops_infra`) makes the agent surface self-documenting.

### W4 — Recursion limit env-tunable (`19cfe3e`)

deepagents stacks 6 middleware (AutoRecall, Skills, SubAgent,
Filesystem, Summarization, TodoList).  Each tool call costs 6-8
recursion units.  langgraph's default 75 was tight at ~10 tool
calls.  Bumped to 200 with env override `OLAV_RECURSION_LIMIT`.

## 4. Architecture mistakes (lessons)

### M1 — Over-aggressive sandbox folding (revealed by Patch D)

`c91a272` folded all 5 analyzer primitives into the
`run_python_simulation` prologue.  4 of 5 (`diff_sql_state`,
`diff_topology_drift`, `diff_routing_drift`, `diff_configs`) are
pure-compute and fit fine.  But `tcf_emit_from_sim` writes a YAML
file to disk — a sandbox-external write target that ADR-0008
condition #2 explicitly carves out for `@tool` placement.  I had
to walk it back via Patch D.

**Lesson:** ADR-0008's 4 conditions for `@tool` elevation are not
optional aesthetic preferences.  The first time a primitive
satisfies any one of (sandbox-external privilege, sandbox-external
write target, critical audit, cross-snapshot DB joins), it belongs
at the @tool layer.

### M2 — "Use mocks as ground truth" anti-pattern (revealed by T1j)

Patches D and E assumed the failure mode was "agent passes Python
list instead of JSON string" / "agent forgets phase" / "agent passes
ASN as string" — based on offline mock scenarios.  4 attempts of
T1 (T1, T1b, T1c, T1d) all failed despite the mocks all passing.

T1j added 1 line of JSONL debug logging inside the @tool wrapper.
The first real-trace record exposed the actual failure modes:
* `post_check_json` blocks shaped like CliBlock instead of
  PostCheck (Pydantic correctly rejected)
* `output_dir` already contained `change_id`, then `tcf_emit_from_sim`
  appended another `change_id` → double-nested path

**Lesson:** Real LLM trace data > offline mock test scenarios for
agent-tool integration debugging.  Always instrument before
guessing.

### M3 — Behavioral nudges have a ceiling (Patch E result)

Patch E added a strong "emit FIRST, refine LATER" decision rule
in system.md + orchestrator.md.  Result: agent went from 0
emit_tcf calls to 4 — but all 4 still hit the post_check shape
mismatch from M2.  The behavioral nudge got the agent moving but
didn't address the actual schema friction.

**Lesson:** Prompt-side imperatives can change *whether* an agent
calls a tool, but not *how correctly* it constructs the call.
Schema friction needs schema-side fixes (Patch F+G coercion +
silent-degrade).

### M4 — Agent variance exceeds patch effects on N=1 runs

T1h (Patch F) returned 0 emit_tcf calls.  T1i (same setup, retry)
returned 31 emit_tcf calls — same code path, different outcome.
DeepSeek's behavior on the same prompt has wide variance.

**Lesson:** Single-run validation is insufficient for agent
behavior questions.  Either run N≥3 or instrument success-rate
tracking before claiming a patch closed an issue.

## 5. Process learnings

### P1 — Closure by accumulation > closure by single patch

Both Ch7 (5 layers) and Ch9 (3 cumulative changes) closed without
a single dedicated "Ch7 fix" or "Ch9 fix" commit.  Each contributing
change was independently motivated and individually small.  The
issues closed when enough mitigations stacked.

This argues against a "design the perfect fix" approach — instead,
ship many small contributing changes and re-test the cumulative
state.

### P2 — Real-trace debug instrumentation is cheap and decisive

The JSONL debug log added inside emit_tcf was 6 lines of code.  It
exposed the actual failure modes within 1 test run after 4 prior
runs of guessing.  Cost: 30 minutes.  Value: revealed two distinct
bugs (Patch G + path-doubling fix) the offline mocks had completely
missed.

Future: add similar debug instrumentation to any tool whose agent-
side success rate is < 80% during validation.

### P3 — Documentation lag was real

System.md changes (e.g. Patch E imperative) were the right surface
to teach the agent — but I first added it to SKILL.md body, which
turns out NOT to be injected into the prompt.  Frontmatter
(name/description/tools) goes in; body doesn't.  System prompt
file (`prompts/system.md`) is the actual injection target.

Documented in section 3 of [42. DEMO_RUNSHEET.md](42.%20DEMO_RUNSHEET.md)
deprecation note → see V2 [71. DEMO_RUNSHEET_V2.md](71.%20DEMO_RUNSHEET_V2.md)
for the working flow.

### Recommended deployment configuration

For demos and production reliability:

```jsonc
{
  "llm": {
    "provider": "custom",
    "model": "deepseek/deepseek-v4-flash",
    "base_url": "https://openrouter.ai/api/v1",
    "model_provider": "openai",
    "api_key": "sk-or-v1-...",
    "context_budget": 64000           // 128000 for headroom
  },
  "embedding": {
    "mode": "local",                  // or api with Perplexity
    "local": {
      "model": "BAAI/bge-base-en-v1.5",
      "device": "cpu"
    }
  },
  "reranker": { "enabled": false }    // R99 evidence: rerank often hurts
}
```

DeepSeek V4 Flash + 64K ctx + local bge embed + reranker disabled
is the **minimum reliable production tier**.  Adding cloud Cohere
Rerank is optional (helps recall on high-volume KB but adds latency).
