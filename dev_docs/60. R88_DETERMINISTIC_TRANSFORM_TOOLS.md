## Origin: small-model tool-arg adherence gap

R87 Phase 1 closed-loop validation surfaced a problem the memory
architecture cannot solve on its own:

**Step 2 v2 observation**: the agent had `clab_topology_srl.expert.yaml`
in its recall block. The body of that YAML literally said "topology
yaml MUST include a `links:` section between data interfaces, otherwise
veth pairs are not created and BGP cannot ARP". The agent's reasoning
trace acknowledged this. **And then the agent called `deploy_lab`
with `yaml_content` missing the `links:` section anyway**, producing
a third FAIL.

This is not a knowledge gap — the knowledge was retrieved, surfaced,
and read. It's a **synthesis gap**: small models reliably understand
imperative facts but unreliably translate them into structured tool
arguments, especially when the structure is non-trivial (multi-line
yaml with cross-references between `nodes:` and `links:`).

The pattern: knowledge → tool-arg synthesis. The failure mode: small
model drops half the constraints during synthesis.

## Type A vs Type B knowledge

R87 Phase 1 packaged everything as `expert_knowledge` YAML. Looking
at the 6 shipped YAMLs after the v2 failure, two distinct shapes
emerge:

| Type | Purpose | Best home | Examples |
|---|---|---|---|
| **A — Semantic interpretation** | "How do I read state X / why is Y failing?" | YAML in memory | `bgp_validation_srl` (SRL `active` ≠ Cisco "trying"), `srl_config_push_gotchas` (commit semantics), `junos_vs_ios_bgp_translation` (cross-vendor mapping) |
| **B — Data transformation** | "How do I produce structured artifact X from data Y?" | Deterministic tool | `clab_topology_srl` (DB topology table → CLAB yaml), spec scaffolding (DB inventory → IP plan), config templating (intent → vendor CLI) |

**Type A** legitimately needs YAML — the LLM has to interpret
semantics, weigh trade-offs, decide what matters. No deterministic
function can substitute.

**Type B** is the wrong fit for YAML. The transformation is
deterministic (input is structured DB data, output format is fixed)
but R87 packaged the transformation rules as prose for the LLM to
synthesize at tool-call time. The synthesis step is the failure
point.

R88 makes Type B a tool, not a memory entry.

## Anti-pattern check: this is NOT LLM-as-judge

The "verifier tool" anti-pattern (Python encoding semantic judgments)
is real but distinct from R88:

| Verifier (anti-pattern) | Generator (R88, OK) |
|---|---|
| Input: arbitrary config / output | Input: structured DB rows + fixed parameters |
| Output: pass/fail judgment | Output: well-formed artifact in fixed schema |
| Failure mode: ossifies LLM judgment in if-else | Failure mode: just bugs in transformation code |
| Better as YAML for LLM to apply | Better as tool to remove synthesis burden |

R88 generators sit in the same family as `format_and_export`,
`build_view`, `take_snapshot` — they shape data, they don't judge
content.

## R88-A — `generate_clab_topology` tool

### Tool signature

```python
@tool
def generate_clab_topology(
    nodes: list[str],
    lab_name: str,
    image: str = "ghcr.io/nokia/srlinux:24.10.1",
    snapshot_id: str | None = None,
) -> str:
    """Generate a complete ContainerLab topology YAML from netops L2 data.

    Reads netops.v_l2_links_auto, normalizes prod interface names to SRL
    container shorthand (e1-N), and emits a ready-to-deploy yaml string
    with both `nodes:` and `links:` sections.

    Args:
        nodes: list of device names from netops inventory (e.g. ["R1", "R4"]).
        lab_name: clab lab name (becomes `name:` in the yaml).
        image: SRL container image tag (default pinned to 24.10.1).
        snapshot_id: optional snapshot to query against (defaults to latest).

    Returns: JSON string with:
        {"yaml_content": "<full yaml>", "links_found": N, "warnings": [...]}
    """
```

### Internal logic

1. Open `~/.olav/databases/main.duckdb` (or the project's main DB)
2. Query:
   ```sql
   SELECT source_device, source_interface, destination_device, destination_interface
   FROM netops.v_l2_links_auto
   WHERE source_device IN (?, ...)
     AND destination_device IN (?, ...)
   ```
3. Dedupe bidirectional links (R1→R4 and R4→R1 are the same link)
4. Normalize interface names with `_normalize_iface_name()`
5. Emit yaml with `nodes:` (one per node) + `links:` (one per dedup'd edge)
6. Validate yaml against `_validate_clab_topology` (existing in `deploy_lab.py`)
7. Return JSON envelope with `yaml_content` + `links_found` count + any warnings

### Interface name normalization

The data transformation core. Maps prod interface conventions to
SRL kernel shorthand:

| Prod pattern | Example | SRL shorthand |
|---|---|---|
| Junos `ge-X/Y/Z` | `ge-0/0/2` | `e1-3` (Y+1 in slot 1) |
| Junos `xe-X/Y/Z` | `xe-0/0/0` | `e1-1` |
| Cisco IOS `GigabitEthernet0/N` | `GigabitEthernet0/2` | `e1-3` (N+1) |
| Cisco IOS `GigabitEthernet0/0/N` | `GigabitEthernet0/0/0` | `e1-1` |
| Cisco IOS-XR `Gi0/0/0/N` | `Gi0/0/0/0` | `e1-1` |
| Cisco IOS short `Gi0/N` | `Gi0/2` | `e1-3` |
| Already SRL slash | `ethernet-1/1` | `e1-1` (CLAB shorthand) |
| Already SRL dash | `e1-1` | `e1-1` (passthrough) |

Rule of thumb: take the **last numeric component**, add 1 (lab
container ports are 1-indexed; prod often 0-indexed), prefix with
`e1-`. SRL containers in CLAB only have line card 1, so the slot
component is always 1.

Edge cases:
* Subinterface (`ge-0/0/2.100`): strip `.X` suffix before numeric
  parse — labs run on the physical layer
* Bundle (`Bundle-Ether10`, `ae0`): not supported in CLAB SRL labs;
  emit warning "bundle interface, skipping link" rather than fail
* LAG members are usually represented as separate physical links
  in `v_l2_links_auto` already (per LLDP), so bundles are a corner
  case

### Output yaml shape

```yaml
name: cab_r1_r4_ebgp
topology:
  nodes:
    R1:
      kind: nokia_srlinux
      image: ghcr.io/nokia/srlinux:24.10.1
    R4:
      kind: nokia_srlinux
      image: ghcr.io/nokia/srlinux:24.10.1
  links:
    - endpoints: [R1:e1-3, R4:e1-1]   # ge-0/0/2 ↔ Ethernet0/0
```

The output is **complete and deploy-ready** — `deploy_lab` should
not need to add anything. The agent's job collapses to:

```python
result = generate_clab_topology(nodes=["R1", "R4"], lab_name="cab_r1_r4_ebgp")
yaml_content = json.loads(result)["yaml_content"]
deploy_lab(yaml_content=yaml_content, ...)
```

No multi-line yaml synthesis step, no constraint to remember.

## R88-B — closed-loop test plan

**Goal**: prove that adding the generator tool resolves the v2 FAIL
that the YAML-only approach couldn't.

**Setup**:
1. Implement R88-A generator tool
2. Update `ops/lab/SKILL.md` or `ops/lab/prompts/system.md` with one
   line: "When deploying SRL lab from a CAB spec, ALWAYS call
   `generate_clab_topology` first to produce `yaml_content`. Do not
   handwrite the topology yaml."
3. Optional: delete `clab_topology_srl.expert.yaml` (Phase 1.5 plan
   says to anyway — it becomes redundant)

**Run**:
* Use the same v2 spec (`exports/reports/cab_r1_r4_ebgp_v3.md`)
* Trigger ops-lab with the same prompt as v2
* Capture the trace and the deploy result

**Expected**:
* Agent calls `generate_clab_topology(nodes=["R1","R4"], lab_name="cab_r1_r4_ebgp")`
* Tool returns yaml with `links: [{endpoints: [R1:e1-3, R4:e1-1]}]`
* `deploy_lab` succeeds with veth pairs created
* BGP reaches `Established` (since spec was already correct in v3)
* Result: CAB PASS or close-to-PASS (one less failure mode)

**Pass criteria for R88-B**:
* `yaml_content` passed to `deploy_lab` contains a non-empty
  `links:` section (this is the literal v2 failure we're fixing)
* `links:` section is correct per v_l2_links_auto data
* No regression: v3 spec correctness still recognized, BGP still
  reaches Established (modulo other failure classes)

**Failure modes for R88-B (and what they teach us)**:
* Agent doesn't call `generate_clab_topology` → prompt update wasn't
  enough; needs upgrade to a usage_guide / format_guide entry forcing
  the call pattern
* Tool produces wrong interface mapping → bug in normalizer; fix
  in code, add test case
* Tool produces correct yaml but agent regresses BGP somewhere else
  → orthogonal issue, document but don't block

## Closed-loop validation results (R88-B)

Four sequential agent runs against the same v3 spec
(`exports/reports/cab_r1_r4_ebgp_v3.md`), each surfacing a different
small-model / infra failure mode:

| run | result | what failed | what we fixed |
|---|---|---|---|
| **v1** | ❌ FAIL | yaml round-trip via JSON envelope: agent re-emitted yaml_content with literal `\n` (escape mismatch) → `deploy_lab` saw single-line yaml → parse error | Tool returns RAW yaml string with `# WARNING:` / `# snapshot_id:` comments at the top instead of JSON envelope (commit referenced as R88-A v2) |
| **v2** | ❌ FAIL | port numbering: tool was preserving prod port numbers (`R1:e1-3` from `ge-0/0/2`) which doesn't match CAB Lab Substitution Table convention | Sequential per-node port numbering starting at e1-1; LLDP port-id-only values ('512') rejected as warnings instead of generating bogus extra links |
| **v3** | ❌ FAIL | node case mismatch: tool emitted `R1`/`R4` (uppercase, prod-style); CLAB's `create_srl_links` workaround does case-sensitive `docker inspect` → veth pair created on different container name → BGP active + ARP empty | Tool lowercases node names (`R1` → `r1`); emits `# prod → lab node mapping:` comment block so the agent knows to use lowercase for `save_lab_config` / `push_node_config` / etc.; prompt updated to reinforce |
| **v4** | ✅ **PASS** | (no R88 issue remained) — agent honored explicit "wait 60s before BGP verification" hint; BGP `established` both sides; 1 route exchanged each direction | n/a — separate timing-race in `deploy_and_push_lab` (post-push convergence wait) tracked as follow-up task |

**v4 PASS evidence** (from agent's CAB report):
* `r1 BGP neighbor: state=established (172.16.99.2, AS65001), [Rx/Active/Tx]=[1/1/1]`
* `r4 BGP neighbor: state=established (172.16.99.1, AS65000), [Rx/Active/Tx]=[1/1/1]`
* `r1/r4 e1-1: up/up, IPv4 172.16.99.{1,2}/30`
* Deploy committed cleanly; lab destroyed

**Manual probe confirming the timing-race**: between v3 and v4 we
deployed a single lab via direct `deploy_lab.invoke()` + manual
`sr_cli` commit, waited, and verified BGP `established` with 3 routes
RX. The veth pair WAS created and L2 WAS working — the agent's
v3 FAIL was verifying too early in the convergence window.

## Architectural lessons from R88-B

1. **Tool I/O format matters more than tool logic for small models.**
   v1's correct-content-but-wrong-format was a 100% deploy block
   despite identical semantics. JSON envelopes are a consistent
   trip-wire — the model has the correct value but loses the
   round-trip when re-emitting it as a tool argument. Default to
   raw strings + comment metadata when the consumer is another tool
   that takes a string.

2. **Generator tools must respect downstream conventions.**
   v2's "preserve prod port numbers" felt rigorous but broke the CAB
   convention. v3's "preserve prod node case" was even worse — it
   broke a downstream workaround tool (`create_srl_links`) silently.
   The generator's job is to produce artifacts the rest of the
   pipeline can consume, not to faithfully mirror upstream data.

3. **Closed-loop validation surfaces silent infra bugs.** Without
   the v3 → v4 diff, the timing-race in `deploy_and_push_lab` would
   have stayed invisible — every CAB lab run would intermittently
   FAIL and look like "spec is wrong". Now it's a tracked task with
   a known mitigation (explicit wait hint).

## Decision log

| date | decision | rationale |
|---|---|---|
| 2026-04-27 | Distinguish Type A (semantic) vs Type B (transform) knowledge | v2 failure showed YAML-encoding of transformation rules doesn't survive small-model synthesis |
| 2026-04-27 | Type B → deterministic tool, not memory | Removes synthesis burden; same family as format_and_export |
| 2026-04-27 | First R88 candidate: clab_topology generator | v2 failure most actionable here; data is in v_l2_links_auto already |
| 2026-04-27 | Generator tool ≠ verifier tool anti-pattern | Generator transforms structured input into fixed output schema; no judgment encoded |
| 2026-04-27 | Tool returns raw yaml string, not JSON envelope | R88-B v1 closed-loop FAIL: small models can't reliably round-trip JSON-encoded yaml strings as tool args |
| 2026-04-27 | Sequential per-node port numbering | R88-B v2: CAB Lab Substitution Table uses `e1-1` regardless of prod port; preserving prod numbers breaks downstream config alignment |
| 2026-04-27 | Lowercase lab node names + emit prod→lab mapping comment | R88-B v3: `create_srl_links` uses case-sensitive `docker inspect`; uppercase prod names produce silent veth-pair creation failure |
| 2026-04-27 | Closed-loop testing as architecture discipline | Each closed-loop iteration revealed a category of problem static unit tests couldn't catch (JSON round-trip, convention mismatch, case sensitivity, timing race) |
