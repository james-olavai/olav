# Hermes Agent — Olav 平台借鉴分析

> 来源: `_legacy_archived/hermes-agent/` (Nous Research)
> 日期: 2026-03-31

## 1. Hermes Agent 概述

Hermes Agent 是 Nous Research 开发的通用 AI Agent 平台，核心特点：

- **45+ 工具**: web搜索、浏览器自动化、terminal、文件操作、视觉分析、TTS、MCP 等
- **6种执行后端**: local / Docker / SSH / Modal (serverless) / Daytona / Singularity (HPC)
- **10+ 消息平台网关**: Telegram / Discord / Slack / WhatsApp / Email / Home Assistant 等
- **自学习**: skills 自动创建与改进、persistent memory (MEMORY.md + USER.md)、FTS5 session 搜索
- **200+ LLM 模型**: OpenRouter、Anthropic、OpenAI、本地端点 (vLLM/Ollama)
- **子代理委派**: 隔离上下文的 delegate_task、最大深度2、并行3
- **Cron 调度**: 自然语言描述、跨平台结果投递
- **安全**: 危险命令审批、prompt 注入扫描、container 隔离

## 2. 与 Olav 的定位差异

| 维度 | Hermes Agent | Olav |
|------|-------------|------|
| 定位 | 通用个人 AI 助手 | 领域专用 AIOps 平台 |
| 编排框架 | 自研同步循环 + OpenAI SDK | LangGraph / DeepAgents + LangChain |
| 状态管理 | SQLite session store | DuckDB OLAP + LanceDB 向量 + LangGraph checkpoint |
| 领域抽象 | 无 (通用工具集) | `DomainAgent` protocol + `BaseIngestTable` + entry points |
| 数据管道 | 无 | Staging-First ingest -> DuckDB -> 拓扑/验证 |
| 扩展性 | MCP + skills (YAML) | PyPI entry points + workspace agents |

**结论: 不应替换 Olav 平台底层为 Hermes，而应从 Hermes 提取高价值模块。**

Olav 的核心价值在于领域数据管道 (设备发现 -> CLI 采集 -> TextFSM 解析 -> DuckDB OLAP -> 拓扑图 -> 变更验证)，
以及 domain package 协议 (`DomainAgent` + `BaseIngestTable` + entry points)。这些 Hermes 完全没有。

## 3. 可借鉴模块

### 3.1 多执行后端抽象

**来源:** `tools/environments/*.py` + `tools/terminal_tool.py`

**Hermes 设计:**
- 策略模式, 通过 `TERMINAL_ENV` 环境变量切换后端
- 统一接口: `execute(command, workdir, timeout) -> (stdout, stderr, returncode)`
- 后端实现: `local.py` / `docker.py` / `ssh.py` / `modal.py` / `daytona.py` / `singularity.py`
- Docker 后端: cap-drop ALL, no-new-privileges, 资源限制 (CPU/内存/磁盘), bind mount
- Modal 后端: serverless 快照持久化, 独立事件循环避免 async 冲突
- SSH 后端: key-based auth, 远程执行

**Olav 借鉴价值:**
- `ops-lab` subagent: ContainerLab 场景需要 Docker/SSH 后端支持远程实验室
- `ops-probe` subagent: ping/traceroute/port_scan 在远程节点执行
- 当前 Olav terminal 工具直接执行，无后端抽象层

**集成方案:**
```
src/olav/platform/execution/
    __init__.py
    base.py          # ExecutionBackend protocol
    local.py         # 直接执行 (默认)
    docker.py        # 容器隔离执行
    ssh.py           # 远程执行
```
在 `@tool` 装饰器层注入后端选择, workspace SKILL.md 中声明 `execution_env: docker|ssh|local`。

### 3.2 危险命令审批流

**来源:** `tools/approval.py`

**Hermes 设计:**
- 正则模式匹配危险命令: `rm -rf`, `dd`, `mkfs`, `chmod 777`, `iptables -F` 等
- 交互审批 (CLI) 或消息确认 (Gateway)
- session 级或一次性审批策略
- sudo 密码缓存

**Olav 借鉴价值:**
- `ops-probe`: 在真实设备执行命令, 错误操作影响生产
- `ops-lab`: 推送配置到 ContainerLab 节点, 可能影响宿主网络
- `execute_cli.py`: 当前无审批层, Nornir 直接执行

**集成方案:**
```python
# src/olav/platform/safety/approval.py

DANGEROUS_PATTERNS = [
    r"rm\s+(-[a-zA-Z]*f|-[a-zA-Z]*r)",  # rm -rf
    r"shutdown",                           # 设备关机
    r"reload",                             # 设备重启
    r"write\s+erase",                      # 清除配置
    r"no\s+router\s+(bgp|ospf)",          # 删除路由协议 <-- 网络领域特有
    r"interface.*shutdown",                # 关闭接口
]

async def require_approval(command: str, device: str) -> bool:
    """在 execute_cli 工具中调用, 匹配危险模式时请求人工确认。"""
```

### 3.3 Prompt 注入扫描

**来源:** `tools/memory_tool.py` 中 `_scan_for_injection()` + `agent/prompt_builder.py`

**Hermes 设计:**
- 正则检测 blocked patterns:
  - 角色劫持: `you are now`, `ignore previous`, `disregard all`
  - 指令覆盖: `new instructions`, `override`, `system prompt`
  - 数据外泄: `curl.*secret`, `wget.*password`, `ssh.*authorized_keys`
  - 不可见 Unicode 字符检测
- 应用场景: memory 写入、context file 加载 (.hermes.md, AGENTS.md)
- 匹配时拒绝写入并返回错误

**Olav 借鉴价值:**
- `recall_memory` 工具: 从 LanceDB 检索的内容直接注入 prompt
- `search_knowledge_lancedb` 工具: KB 检索结果进入 agent 上下文
- `execute_sql` 工具: 用户构造的 SQL 查询 (虽然 DuckDB 本身较安全)
- workspace SKILL.md / AGENT.md: 从文件系统加载的 prompt 配置

**集成方案:**
```python
# src/olav/platform/safety/injection_scanner.py

INJECTION_PATTERNS = [
    r"(?i)ignore\s+(all\s+)?previous\s+instructions",
    r"(?i)you\s+are\s+now\s+a",
    r"(?i)disregard\s+(all|any|your)",
    r"(?i)new\s+(system\s+)?instructions",
    r"(?i)curl\s+.*\b(secret|token|password|key)\b",
    r"(?i)wget\s+.*\b(secret|token|password|key)\b",
]

def scan_content(text: str) -> tuple[bool, str | None]:
    """扫描文本是否包含注入模式。返回 (is_clean, matched_pattern)。"""
```

在以下位置调用:
- `memory/` 写入路径
- `knowledge/` 文档导入路径
- workspace agent/skill 加载路径
- `execute_sql` 工具的 SQL 输入

### 3.4 消息网关架构

**来源:** `gateway/run.py` + `gateway/platforms/` + `gateway/session.py`

**Hermes 设计:**
- 统一 `GatewayMessage` 抽象: platform, chat_id, user_id, text, attachments
- 平台适配器: 每个平台实现 `start()` / `stop()` / `send()`
- 共享 agent 逻辑: 所有平台使用同一个 AIAgent, 仅 IO 适配不同
- SessionStore: SQLite 持久化, 按 platform+chat_id 隔离 session
- PII 脱敏: 电话号码/用户 ID 自动遮蔽
- Pairing: 敏感平台 (WhatsApp) 需要身份绑定

**Olav 借鉴价值:**
- NOC 场景: 通过 Slack/Teams 接收告警, 执行 probe/diff 操作
- 值班工程师: Telegram bot 查询网络状态, 不需要 SSH 到服务器
- Cron 输出投递: drift 检测结果推送到运维频道

**集成方案 (Phase 2, 非当前优先级):**
```
src/olav/platform/gateway/
    __init__.py
    message.py        # GatewayMessage protocol
    session.py        # DuckDB-backed session store (替代 SQLite)
    platforms/
        slack.py      # Slack Bolt adapter
        telegram.py   # python-telegram-bot adapter
        api.py        # HTTP API (webhook receiver)
```

### 3.5 Cron 定时调度

**来源:** `cron/scheduler.py` + `cron/jobs.py`

**Hermes 设计:**
- 文件锁防止并发 tick
- 自然语言描述: `"every weekday at 9am"` / `"every 6 hours"`
- 投递目标: `"local"` / `"origin"` / `"platform:chat_id"`
- 每个 job 独立 agent 实例, 受限上下文
- 输出持久化用于审计
- `[SILENT]` 标记抑制投递

**Olav 借鉴价值:**
- `ops-diff` 定时漂移检测: 每小时对比配置/路由/拓扑快照
- `ops-probe` 定时健康检查: 每5分钟 ping 关键设备
- 快照调度: 定时执行 `netops_snapshot.py` 采集全网状态
- 结果投递到 Slack 运维频道 (配合 3.4 网关)

**集成方案:**
```python
# src/olav/platform/scheduler/
#     scheduler.py   # APScheduler-based (替代自研, 更成熟)
#     jobs.py        # DuckDB job store

# 在 workspace AGENT.md 中声明:
# schedules:
#   - name: drift-check
#     cron: "0 * * * *"        # 每小时
#     subagent: ops-diff
#     query: "检查全网配置漂移"
#     deliver_to: slack:#noc-alerts
```

### 3.6 上下文压缩

**来源:** `agent/context_compressor.py`

**Hermes 设计:**
- 三阶段策略:
  1. **预裁剪**: 移除旧 tool_result (最便宜的压缩)
  2. **保护头尾**: system prompt (头) + 最近 ~20K tokens (尾) 不动
  3. **摘要中间**: 用 LLM 对中间部分生成结构化摘要
- 50% 上下文占用时触发
- 迭代更新: 多次压缩保持信息连贯
- 摘要预算与压缩内容量成比例

**Olav 借鉴价值:**
- OLAVAgent 当前依赖 LangGraph checkpoint 做状态持久化, 但没有显式上下文窗口管理
- 长会话 (反复 probe/diff 操作) 容易超出上下文限制
- DeepAgents 框架可能内置了压缩, 但 Hermes 的策略更透明可控

**集成方案:**
作为 DeepAgents 的 middleware 或 callback 注入, 在 token 计数接近阈值时触发。

## 4. 优先级排序

| 优先级 | 模块 | 改造难度 | 价值 | 依赖 |
|--------|------|---------|------|------|
| P0 | 危险命令审批 (3.2) | 低 | 生产安全 | 无 |
| P0 | 注入扫描 (3.3) | 低 | 安全基线 | 无 |
| P1 | 执行后端抽象 (3.1) | 中 | ops-lab/probe 远程执行 | 无 |
| P1 | Cron 调度 (3.5) | 中 | diff/probe 定时执行 | 无 |
| P2 | 消息网关 (3.4) | 高 | NOC ChatOps | 调度 (3.5) |
| P2 | 上下文压缩 (3.6) | 中 | 长会话稳定性 | DeepAgents 适配 |
