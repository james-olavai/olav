## 1. 核心变更

**之前：** OpenAPI schema → 代码生成器 → N 个 .py 工具文件 → agent 调工具 → 工具内调 service_call()

**之后：** OpenAPI schema → reference markdown → agent 直接调 core `api_request` → service_call()

## 3. core 新增：`api_request` 工具

```python
# .olav/workspace/core/tools/api_request.py

@tool
def api_request(
    service: str,              # 已注册服务名
    method: str = "GET",       # HTTP method
    path: str = "/",           # API path
    params: dict | None = None,
    body: dict | None = None,
    page_size: int | None = None,   # 若设置，自动分页收集全量结果（GET only）
) -> dict | list:
    """Authenticated API request to a registered service.
    Auth handled automatically. Write ops require HITL approval.

    Returns:
        - dict: 单对象响应（GET /api/dcim/devices/1/）
        - list[dict]: 分页列表响应（自动展开 results 字段）
        - dict: 写操作响应（POST/PATCH/DELETE，需 HITL 批准后执行）

    Pagination:
        NetBox / DRF 风格：{"count": N, "results": [...], "next": "..."}
        若 page_size 未设置，仅返回第一页 results（性能保护）。
        若 page_size=-1，自动分页直至 next=null（慎用，大数据集耗时）。
    """
    from olav.platform.services.client import service_call
    # SECURITY: confirmed=False always — let service_call safety layers decide
    result = service_call(
        service, method=method, path=path,
        params=params or {}, body=body or {},
        confirmed=False,
    )
    # 自动展开分页列表响应
    if isinstance(result, dict) and "results" in result and "count" in result:
        if page_size == -1:
            # 全量收集：继续请求 next 直到 null
            items = list(result["results"])
            next_url = result.get("next")
            while next_url:
                page = service_call(service, method="GET", path=next_url,
                                    params={}, body={}, confirmed=False)
                items.extend(page.get("results", []))
                next_url = page.get("next")
            return items
        else:
            # 仅返回第一页 results，调用方可通过 count 判断是否需要分页
            return result["results"]
    return result
```

### 3.1 错误响应格式

`service_call` 层统一抛出异常（不返回错误 dict），`api_request` 不捕获，让 agent runtime 自然处理：

| 场景 | 行为 |
|------|------|
| HTTP 4xx/5xx | 抛出 `ServiceCallError(status=N, body=...)` |
| 写操作未批准 | 抛出 `ApprovalRequired(reason=...)` |
| 服务未注册 | 抛出 `ServiceNotFound(service=...)` |
| hard_block | 抛出 `HardBlockError(reason=...)` — 不可绕过 |

Agent 在 system.md 中被告知：捕获错误后 **报告给用户**，而非静默重试。

## 4. core 增强：`olav registry register`

**之前：** 注册服务 → 解析 OpenAPI → 生成 N 个 Python @tool 文件 → 创建 workspace

**之后：** 注册服务 → 解析 OpenAPI → 生成 reference markdown → 放入 `infra/references/`

```bash
olav registry register http://netbox:8080 --token abc123
# 1. 写入 services.yaml（已有功能）
# 2. 解析 OpenAPI schema → 提取关键 endpoint/参数/返回字段
# 3. 生成 infra/references/netbox_api.md（精简 markdown，不是 Python 代码）
# 4. 确保 infra/ workspace 存在
```

**不需要 `service-onboard` workspace。** 服务注册是 CLI 操作（同 `olav init`、`olav skill install`），不是 agent 工作流。

### 4.1 Reference Markdown 格式规范

生成文件示例：`infra/references/netbox_api.md`

```markdown
# NetBox API Reference
> source: http://localhost:8000  schema: /api/schema/?format=json  generated: 2026-04-08

## DCIM

### GET /api/dcim/devices/
查询设备列表。
**Params:** `site` `rack` `platform` `status` `tag` `limit` `offset`
**Returns:** `[{id, name, display, device_type.model, device_role.name, site.name,
              primary_ip4.address, status.value, tags}]`

### GET /api/dcim/devices/{id}/
**Returns:** 同上 + `interfaces` `config_context`

### GET /api/dcim/interfaces/
**Params:** `device` `device_id` `type` `enabled` `limit`
**Returns:** `[{id, device.name, name, type.value, enabled, ip_addresses}]`

### GET /api/dcim/sites/
**Params:** `status` `region` `limit`
**Returns:** `[{id, name, slug, status.value, region.name, description}]`

## IPAM

### GET /api/ipam/ip-addresses/
**Params:** `device` `interface_id` `vrf_id` `status` `family` `limit`
**Returns:** `[{id, address, family.value, vrf.name, assigned_object_type,
              assigned_object.name, status.value}]`

### GET /api/ipam/prefixes/
**Params:** `vrf_id` `site` `family` `status` `limit`
**Returns:** `[{id, prefix, vrf.name, site.name, status.value, description}]`
```

**裁剪规则（`olav registry register` 实现时遵守）：**

| 规则 | 说明 |
|------|------|
| 只保留 GET 端点 | 写端点由 changeset 模式处理，不放入 reference |
| 只保留注册时指定的 tag 组 | 与现有 `tool_generation.groups` 对齐 |
| 每个端点最多 8 个关键 params | 按 required 优先，余下按 description 中出现频率 |
| 每个端点最多 10 个 return 字段 | 按 `tool_generation.groups` 描述中提及字段优先 |
| 单文件 token 上限 ~4000 tokens | 超出时按 tag 拆分为 `netbox_dcim_api.md` / `netbox_ipam_api.md` |
| 无 OpenAPI schema 时 | 生成骨架文件，header 注明 `⚠️ schema not available — add endpoints manually` |

### 4.2 infra workspace 初始化规则

`olav registry register` 执行时：

```
1. 写入 services.yaml（已有）
2. 从 schema_url 拉取 OpenAPI → 按 tag 裁剪 → 生成 reference markdown
3. mkdir -p .olav/workspace/infra/references/
4. 写入 infra/references/{service_name}_api.md
   - 若文件已存在：覆盖（re-register 即更新 reference）
5. 若 .olav/workspace/infra/ 不存在整体骨架：
   - 复制 platform template → infra/AGENT.md + infra/SKILL.md + infra/prompts/system.md
   - 仅首次执行；后续 register 只更新 references/
```

**不在 `olav init` 创建 infra/**：init 只建核心 workspace（core/config/quick），infra 按需创建（有服务注册才有意义）。

### system.md

```markdown
# Infrastructure Management Expert

You query infrastructure management systems and generate change scripts.

## Read Operations

Use `api_request` for all API queries:
```
api_request(service="netbox", path="/api/dcim/devices/", params={"site": "DC1"})
```

Refer to reference docs in references/ for available endpoints.

## Write Operations

Writes require `--enable-api-write` CLI flag + dry-run + mandatory HITL approval.
See §8 for full security model. Workflow:

1. **Read** current state via `api_request` GET
2. **Diff** compute what will change
3. **Dry-run** simulate in sandbox, verify no conflicts
4. **Approve** HITL confirmation (cannot be skipped)
5. **Execute** `api_request(method="PATCH", confirmed=True)`
6. **Verify** read back to confirm

Without `--enable-api-write`: all write attempts are blocked.

For bulk script generation (50+ operations or offline workflows), use the
**devops agent** instead: `olav --agent devops "generate import script"`.
See doc 40.
```

### 6.1 `format_and_export` 扩展：`subdir` 参数

现有工具签名仅支持 `exports/` 和 `exports/reports/` 两个出口。changeset 工作流需要写入 `exports/scripts/`，需在 **Phase A** 中为工具添加 `subdir` 参数：

```python
@tool
def format_and_export(
    data: Any,
    filename: str | None = None,
    format: str | None = None,
    subdir: str | None = None,   # 新增：相对于 EXPORTS_DIR 的子目录
                                  # 例："scripts" → exports/scripts/
                                  # 例："reports" → exports/reports/（现有行为）
                                  # None → 按现有格式自动判断（向后兼容）

```

    filename=f"changeset-netbox-{date}",
    format="json",
    subdir="scripts",       # → exports/scripts/changeset-netbox-2026-04-08.json

format_and_export(
    data=shell_script_str,
    filename=f"changeset-netbox-{date}",
    format="sh",
    subdir="scripts",       # → exports/scripts/changeset-netbox-2026-04-08.sh

## 8. 安全模型

### 8.1 不可变安全边界

| 域 | 规则 | 可更改？ |
|----|------|:-------:|
| 网络设备 (ops/probe) | 永远只读。execute_cli 仅 show 命令。 | **不可更改** |
| API 服务 (infra) | 默认只读。写入需 `--enable-api-write` + dry-run PASS + 不可跳过的审批 | 可解锁 |

### 8.2 API 写操作三级门控

**Level 1 — 默认锁死**

```bash
olav --agent infra "update devices"
# → "API write mode not enabled. Use --enable-api-write."
# --dangerously-skip-permissions 不影响此拦截。
```

**Level 2 — 显式解锁 + 警告**

```bash
olav --agent infra "update devices" --enable-api-write
# → "⚠️  API WRITE MODE ENABLED
#     • Backup your data before proceeding
#     • All writes require dry-run + manual approval
#     • --dangerously-skip-permissions does NOT bypass write approval"
```

**Level 3 — 强制 dry-run → 通过后才能请求审批**

```
dry-run FAIL → 阻止，不进入审批
dry-run PASS → 展示 diff → 强制 HITL（不可跳过）→ 执行 → 读回验证
```

### 8.3 写操作完整工作流（6 步，prompt 强制）

```
Step 1: Read      — api_request GET 读当前状态
Step 2: Diff      — 计算变更内容，展示给用户
Step 3: Dry-run   — sandbox 模拟验证（冲突检测、字段校验）
Step 4: Approve   — PASS 后强制 HITL 审批（不可跳过）
Step 5: Execute   — api_request PATCH/POST with confirmed=True
Step 6: Verify    — api_request GET 读回验证结果
```

### 8.4 批量操作自动分流

| 操作规模 | 流程 |
|---------|------|
| 1-5 条 | 交互式：read → diff → HITL → write → verify |
| 5-50 条 | 汇总式：read all → 汇总 diff → 单次 HITL → batch write → batch verify |
| 50+ 条 | 脚本式：read → dry-run → 导出 changeset 脚本 → 用户离线审查 → 手动执行 |

### 8.5 `api_request` 实现

```python
@tool
def api_request(
    service: str,
    method: str = "GET",
    path: str = "/",
    params: dict | None = None,
    body: dict | None = None,
    confirmed: bool = False,
) -> dict:
    # 读操作：直接执行
    if method.upper() in ("GET", "HEAD", "OPTIONS"):
        return service_call(service, method, path, ...)

    # 写操作：检查 write mode 标志
    if not os.environ.get("OLAV_ENABLE_API_WRITE"):
        return {"status": "blocked",
                "reason": "API write mode not enabled. Use --enable-api-write."}

    # 写操作：传递 confirmed（HITL 不可跳过）
    return service_call(service, method, path, body=body,
                        confirmed=confirmed)
```

### 8.6 不可跳过的写审批

service_call 中 API 写审批**独立于** `--dangerously-skip-permissions`：

```python
# service_call 内部
if method.upper() in _WRITE_METHODS and not confirmed:
    # 此检查不受 is_bypass_active() 影响
    return {"status": "requires_approval", ...}
```

### 8.7 sandbox 硬边界

`network_isolation=True` 时 HTTP 写操作 hard_block（防 sandbox 内绕过 api_request 直接用 httpx）：

```python
if network_isolation and "HTTP mutation" in reason:
    return ApprovalResult(hard_block=True)  # 不可绕过
```

### 8.8 register_service 安全默认值

```yaml
# 新注册服务默认 readonly_only: true
netbox:
  readonly_only: true
```

### 8.9 纵深防御完整层叠

| 层 | 防御 | `--dangerously-skip-permissions` | `--enable-api-write` |
|----|------|:---:|:---:|
| 1. `--enable-api-write` | 默认锁死写操作 | 不影响 | 解锁 |
| 2. services.yaml `readonly_only` | 服务级读写控制 | 不影响 | 不影响 |
| 3. Dry-run simulation | 写前强制验证 | 不影响 | — |
| 4. HITL 写审批 | 强制人工确认 | **不可跳过** | — |
| 5. sandbox_guard hard_block | sandbox 内 HTTP 写拦截 | **不可跳过** | — |
| 6. Read-back verify | 写后自动验证 | — | — |
| 7. Audit trail | 全链路记录 | — | — |

**网络设备 execute_cli：** 仅白名单 show 命令。无 `--enable-api-write` 等效标志。永远只读。
