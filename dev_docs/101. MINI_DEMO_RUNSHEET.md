# 101. OLAV Mini Demo Runsheet — the 12-minute network-engineer wow

**Date**: 2026-07-18
**Version**: v0.23.1 (public PyPI: `olav` + `olav-netops`)
**Duration**: ~12–15 min (7 beats)
**Companion to**: `dev_docs/100. DEMO_RUNSHEET_V3.md` — that is the full ~50 min
capability sweep; **this is the tight cut**: only the beats that make a network
engineer lean in, each verified end-to-end on a small local model this cycle.

> **Why a mini runsheet.** The full V3 sweep is comprehensive but long. For a
> cold audience (a network engineer who's never seen OLAV), the story lands in
> ~12 minutes if you show exactly seven things: it installs itself, ingests a
> real fleet with no SSH, answers in plain language + exports, draws the core,
> **writes a BGP change and then formally validates it**, pushes the inventory
> into NetBox, and then improves itself overnight. Everything below was run on
> `gemma4-31b` and produced correct output — no frontier model required.

## Setup (off camera)

**LLM backend.** `gemma4-31b-it-qat` at an OpenAI-compatible endpoint
(`http://<host>:11433/v1`, `api_key: local`, `llm.timeout: 600`). This is the
headline claim — a **local ~30B model** runs the whole demo. Do NOT use a
"flash"/tiny model for the agentic beats: in testing `deepseek-v4-flash`
flailed (146 tool calls vs gemma4's 16 on the same task). gemma4-31b or a
frontier model; nothing in between is needed.

**Demo data.** A 339-device campus/DC fleet already imported (Ch1 shows the
import live, or pre-load it). Batfish + NetBox 4.5 images cached locally so the
self-service deploys are fast on camera.

**One health line before you hit record:**
```bash
olav doctor          # must be all ✓ — agents/subagents/tools/memory/recall
```

## Ch0 — A clean machine installs and configures itself (2 min) ★

```bash
pip install olav olav-netops         # from public PyPI, nothing else
olav                                  # just run it — it bootstraps + asks once for the LLM key
olav skill install olav-netops        # deploy the network agents from the installed package
olav doctor                           # 8 zero-LLM checks, all ✓
```
**Why they care.** Zero-touch. No `git clone`, no editing YAML. `olav doctor`
proves the whole stack is wired (agents, sub-agents, tools, experience layer,
recall) before you ask it anything — an ops person trusts a tool that
self-diagnoses.

## Ch1 — Ingest a real fleet, no SSH (2 min) ★

```bash
olav --agent netops "Import the network backup at <path-to-archive>.tar.gz"
olav --agent netops "How many devices and what platforms did we just import?"
```
**Why they care.** You hand it a raw collector dump (a `.tar.gz`); the importer
extracts + normalises + parses (TextFSM) + builds the topology automatically.
339 devices land with zero device access — safe to run against production
backups.

## Ch2 — Ask in English, get a CSV (1.5 min)

```bash
olav --agent netops "List every device with its model, mgmt IP and site, and export it to CSV"
```
**Why they care.** The NL question becomes SQL over the parsed inventory and
drops a real `exports/*.csv` — no query language to learn, but the data is
exact, not hallucinated.

## Ch3 — Draw the core network as a draw.io diagram (1.5 min) ★

```bash
olav "Draw the core network topology as a draw.io diagram"
```
Open the resulting `exports/diagrams/core_topology_*.drawio` in diagrams.net.
**Why they care.** A scoped, correct topology (Cisco stencils, real
adjacencies) they can drop straight into a Confluence page. The agent scopes it
sensibly (the core layer, ~16 nodes) instead of dumping the whole fabric.

## Ch4 — Write a BGP change plan (2 min) ★★

```bash
olav --agent netops "Write a change plan to add a redundant eBGP uplink on the alpha border router, mirroring the existing AARNet peer"
```
**Why they care.** It reads the device's **actual** running-config (not a
template), finds the real `router bgp <asn>` + the existing neighbour's style,
and emits CLI that mirrors it — with a Pre-change verification section. This is
the beat that separates OLAV from a chatbot: grounded in your config.

## Ch5 — Deploy Batfish and formally validate the change (2.5 min) ★★★

```bash
# The platform stands up its own validation engine — no manual docker:
olav --agent services "Deploy batfish/allinone, ports 9996 9997"
# Then validate BGP session compatibility across the fleet:
olav --agent netops "Use Batfish to validate BGP session compatibility across the network; how many sessions are compatible vs broken, and why?"
```
**Why they care.** This is the killer. The agent **deploys its own** Batfish
container, then runs `bgpSessionCompatibility` and reports the real verdict
(e.g. "66 sessions: 52 compatible; 2 NO_LOCAL_IP on the border eBGP to AARNet;
12 UNKNOWN_REMOTE to devices outside the snapshot"). An AI that writes a change
**and then formally proves its blast radius** is a different category of tool.

## Ch6 — Push the inventory into NetBox (2 min) ★★

```bash
olav --agent services "Deploy netbox"                    # app + postgres + redis, self-service
olav --agent netops  "Export the device inventory to NetBox CSV, then import it into NetBox"
```
Open NetBox → Devices. **Why they care.** 317 devices land in NetBox with
sites, roles, device-types and IPs derived from the fleet — the source-of-truth
CMDB populated from a backup, hands-free. (NetBox 4.5's Bearer-token auth,
slug idempotency, and the register-service auth path are all handled.)

## Ch7 — It improves itself overnight (1 min) ★

```bash
olav cron enable reflect     # opt-in: a daily 4am self-reflection job
# (show the mechanism, don't wait for 4am)
olav --agent admin "reflect on today's errors and propose improvements"
olav doctor                  # cron: ✓ 1 scheduled job active
```
**Why they care.** The platform reads its own error logs (a bounded histogram,
never raw dumps), turns recurring problems into KB lessons, and drafts code-fix
proposals under `exports/reflections/` — never touching source. It gets better
while you sleep, and you can audit every proposal.

## Notes / honesty

- Every beat above was run on `gemma4-31b` this cycle and produced correct
  output. Batfish models **BGP** well and EIGRP poorly — keep the change-plan +
  validation beats on **BGP** (Ch4/Ch5), not EIGRP.
- `olav cron enable reflect` writes to the user's crontab (a daily LLM call) —
  it is deliberately opt-in, never auto-enabled at install.
- For the full capability sweep (KB, conversational HITL memory, drift,
  blast-radius, audit profiles, syslog) see `dev_docs/100. DEMO_RUNSHEET_V3.md`.
