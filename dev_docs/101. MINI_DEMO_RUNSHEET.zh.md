# 101. OLAV 迷你演示脚本 — 面向网络工程师的 12 分钟惊艳版(中文版)

**日期**: 2026-07-20
**版本**: v0.24.1(公共 PyPI:`olav` + `olav-netops`)
**时长**: ~10–13 分钟(6 个节拍)
**配套**: `dev_docs/101. MINI_DEMO_RUNSHEET.md`(英文原版)、`dev_docs/100.
DEMO_RUNSHEET_V3.md`(完整 ~50 分钟能力全览)。本篇是**紧凑剪辑版**:只保留
让网络工程师眼前一亮的节拍,每一拍本轮都在本地小模型上端到端跑通。

> **为什么要中文版。** OLAV 现在有**统一的输出语言指令**(主 agent 全局控制):
> 检测用户输入语言,全程同语言回复——**中文提问 → 中文作答**,英文提问 → 英文
> 作答;而代码 / SQL / YAML 键 / 文件路径 / CLI 命令恒为英文。本脚本用中文向
> TUI 提问,现场直接展示这一能力。底层仍是 `gemma4-31b` 本地 30B 模型,无需前沿
> 云模型。

## 准备(不录制)

**LLM 后端。** `gemma4-31b-it-qat`,OpenAI 兼容端点
(`http://<host>:11433/v1`,`api_key: local`,`llm.timeout: 600`)。这是核心卖点
——**一台本地 ~30B 模型**跑完整个演示。agentic 节拍**不要**用 "flash"/超小模型
(实测 `deepseek-v4-flash` 在同一任务上打转:146 次工具调用 vs gemma4 的 16 次)。

**输入法。** 若要现场用中文输入:GNOME 下 `Super+Space` 在英文/中文拼音间切换
(已装 `ibus-libpinyin`)。

**演示数据。** 一份 339 台设备的园区/数据中心网络备份(Ch1 现场导入)。Batfish
镜像本地已缓存,Ch4 自服务部署秒起。

**开录前的一行体检:**

```bash
olav doctor          # 必须 9 项全 ✓ — workspace/agents/subagents/tools/memory/recall
```

---

> **两个上下文,按执行顺序。** 全程一台机器。**在主机终端**只做两件事:导入
> 设备数据、启动 TUI。**其余全在 TUI 内**——用中文提问,用 `/workspace <name>`
> 切换 agent 上下文。每一拍标注 `[终端]` 或 `[TUI]`,操作者一眼知道自己在哪。

## Ch0 — 干净机器自安装、自配置(2 分钟)★ · `[终端]`

```bash
mkdir ~/olav && cd ~/olav
python3 -m venv .venv && source .venv/bin/activate
pip install olav "olav-netops[sim]"   # [sim] = pybatfish,Ch4 形式化验证需要
olav skill install olav-netops         # 首次运行自举(只问一次 LLM key),部署网络 agents
olav doctor                            # 9 项零-LLM 检查,全 ✓
```

**卖点。** 零接触。无需 `git clone`、无需手改 YAML。`olav doctor` 在你提任何
问题之前就证明整个栈(agents、子代理、工具、经验层、召回、工作区完整性)接线
正常——运维人信任一个会自检的工具。

## Ch1 — 导入真实网络,零 SSH(2 分钟)★ · `[终端]`

CLI 上唯一的数据步(解析较久;跑完它,再打开 TUI):

```bash
olav --agent netops "导入 /home/olav/Downloads/network_data.tar.gz 这个网络备份"
olav                        # 启动 TUI —— 从这里开始全在里面操作
```

**卖点。** 你丢给它一个原始采集包(`.tar.gz`);导入器自动解压 + 规范化 + 解析
(TextFSM)+ 构建拓扑。339 台设备零设备访问落地——对生产备份运行是安全的。
(注意:命令本身可以用中文下达,agent 照样理解并执行。)

## Ch2 — 用中文提问,拿到 CSV(1.5 分钟)· `[TUI]`

在 TUI 提示符里直接用中文输入(默认编排器自动路由):

```
我们刚导入了多少台设备?都是什么平台?
列出每台设备的型号和管理 IP,导出成 CSV
```

**卖点。** 中文自然语言问题被转成对已解析库存的 SQL,落一个真实的
`exports/*.csv`——无需学查询语言,数据精确、不是编的。而且**回答是中文的**
(统一语言指令生效),CSV 里的列名等结构化内容仍是英文。

## Ch3 — 把核心网络画成 draw.io 图(1.5 分钟)★ · `[TUI]`

```
把核心网络拓扑画成 draw.io 图
```

在 diagrams.net 打开生成的 `exports/diagrams/core_topology_*.drawio`。
**卖点。** 一张范围合理、正确的拓扑(思科图元、真实邻接),可直接贴进
Confluence 页面。agent 把范围收敛到核心层(~16 节点),而不是倾倒整个网络。

## Ch4 — 写一份 BGP 变更并形式化验证它(3 分钟)★★★ · `[TUI]`

先切到 services agent 起验证引擎,再切到 netops 起草并验证——全在 TUI 内用
`/workspace` 切换:

```
/workspace services
部署 batfish/allinone,端口 9996 9997
/workspace netops
给 alpha 边界路由器写一份变更计划:新增一条到 AARNet 的冗余 eBGP 上联,参照现有 AARNet 邻居的配置风格
```

**卖点。** `/workspace` 在同一 TUI 会话内切换 agent 上下文——不用新开终端、不用
重启。那一句变更计划请求随后扇出成**三段经过验证的内容**,堆叠在回复里:

- **Draft(起草)** — analyzer 读设备的**真实**运行配置(不是模板),找到真实的
  `router bgp <asn>` + 现有邻居风格,产出镜像 CLI + 回滚,存进
  `exports/change_plans/`。
- **Pre-check(reporter 预检)** — 设备/接口/IP 与现网状态核对 + 独立复算的
  爆炸半径("移除它会孤立 N 台设备")。
- **Formal verification(Batfish 形式化验证)** — 子网/重叠冲突、BGP 兼容性、
  可达性——在 agent **自己**部署的 Batfish 上给出真实裁决。

一个能写变更**并从一句话里把它形式化验证到位**(起草 + 预检 + Batfish)的 AI,
是另一个量级的工具。(`部署 batfish` 这步必须先于变更计划命令完成;若 Batfish
未起,工作流仍返回 Draft + Pre-check 并告诉你怎么起。部署会要求一次按键确认——
那是有意的 HITL 关卡。)

## Ch5 — 定时式审计巡检(1.5 分钟)★★ · `[TUI]`

```
/workspace audit
运行 interface_health 审计 profile,把发现给我
```

**卖点。** 这是 Day-2 运维闭环:一个 **Profile**(一份带严重度规则的 SQL 健康
检查 YAML —— `.olav/workspace/audit/profiles/`)对状态库确定性执行,agent 返回
执行摘要 + 落盘报告(`exports/audit_reports/*.md` + findings JSON)。Profile 是
纯文件:工程师可审阅、可让 audit author agent 扩展("加一个检查 X"),可用
`olav cron` 定时——就是你们 NOC 每天早上跑的巡检,但检查项本身是版本化、可审计
的工件。两次工具调用、零-LLM 评估——LLM 只叙述它能引用的发现。

## 注意事项 / 诚实说明

- 以上每一拍本轮都在 `gemma4-31b` 上跑通并产出正确结果。Batfish 对 **BGP** 建模
  好、对 EIGRP 差——Ch4 的变更 + 验证请保持在 **BGP**,不要用 EIGRP。
- **语言**:统一输出语言指令默认 `auto`(镜像输入)。要强制某语言,在 api.json
  写 `"agent": {"output_language": "zh"}`(或 `"English"`)。代码/SQL/路径恒英文。
- **Ch4 顺序要紧**:`/workspace services` + `部署 batfish` 必须在 `/workspace
  netops` 变更计划命令**之前**完成——该命令触发 analyzer→reporter→simulator
  工作流,末步对运行中的 Batfish 做验证。
- **`/workspace <name>` 是 TUI 内切换 agent 的命令**(netops / services /
  audit / admin / core)。只有导入(Ch1)在主机终端跑;其余都在 TUI 里输入。
  未知名字会列出可选项。`/workspace` 与 `/agents` 是同一命令。
- **Ch5 必须用 interface_health**(或 device_inventory):本数据集没有 BGP/OSPF
  的 TextFSM 视图,`bgp_health`/`ospf_health` profile 会报错
  (`v_show_ip_bgp_summary_auto` 不存在);接口/库存视图数据完整。
- 完整能力全览(知识库、对话式 HITL 记忆、漂移、爆炸半径、审计 profile、syslog)
  见 `dev_docs/100. DEMO_RUNSHEET_V3.md`。
