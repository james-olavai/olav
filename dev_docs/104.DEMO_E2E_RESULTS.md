### Issue #2 deep-dive: does deepagents-cli need upgrading? (checked 2026-06-03)

**Yes — but it is NOT a simple version bump; it needs a code port.**

- **The conflict:** `deepagents-cli==0.0.41` (olav's pinned dep) hard-pins
  `deepagents==0.5.3`; olav's code needs `deepagents>=0.6.7`. pip cannot resolve
  both (`ResolutionImpossible`). They coexist ONLY via the `[tool.uv]
  override-dependencies` (uv forces deepagents 0.6.7 alongside cli 0.0.41,
  effectively `--no-deps` on the cli's pin). **So `pip install olav` is broken
  for any non-uv user.**
- **cli version → deepagents requirement (PyPI):** 0.0.41→`==0.5.3`;
  0.0.52-56→`==0.5.8/0.5.9`; 0.0.59→`==0.6.1` (exact, still conflicts with 0.6.7);
  **0.1.0 / 0.1.2 / 0.2.0 → `>=0.6.1`** (range, ALLOWS 0.6.7 — would fix the conflict).
- **BUT cli 0.1.0+ restructured the internal API olav depends on.** Verified
  against cli 0.2.0: `deepagents_cli.app` and `deepagents_cli.command_registry`
  modules are GONE; `config._UNICODE_BANNER` and `config.SessionState` are GONE.
  A bump to 0.2.0 breaks olav's CLI — even a one-shot query fails with
  `cannot import name 'SessionState' from 'deepagents_cli.config'`.
- **olav's cli-integration surface (5 files to port):** `cli/main.py`
  (`deepagents_cli.execution`, `app.run_textual_app`, `config.SessionState`),
  `cli/tui_overlay.py` (`app.DeepAgentsApp`, `command_registry.COMMANDS`,
  `_UNICODE_BANNER/_ASCII_BANNER`), `cli/commands/builtin.py`,
  `cli/commands/registry.py`, `core/utils.py`.
- **Verdict:** Upgrading the cli (to 0.1.0+) is the correct fix for the
  pip-install breakage, but requires PORTING olav's deepagents-cli integration
  to the new package.

### ✅ Issue #2 RESOLVED (2026-06-03) — migrated deepagents-cli → deepagents-code

The interactive REPL/TUI olav integrates with **moved to the `deepagents-code`
package** (cli 0.2.0's `_REPL_REDIRECT_MESSAGE` says so; the `deepagents` cli is
now deploy/init/agents-only). `deepagents-code==0.1.8` requires
`deepagents==0.6.7` (matches olav) and **re-exposes every internal olav uses**:
`config.SessionState`, `config._UNICODE_BANNER/_ASCII_BANNER`,
`app.run_textual_app/DeepAgentsApp(.TITLE/_handle_command)`,
`command_registry.COMMANDS`, `update_check`, `widgets.welcome`, `server_manager`,
`server.generate_langgraph_json/_build_server_cmd`. (Only `execution`
(HITL `prompt_for_tool_approval`) is gone — olav's usage was already gated, so
HITL audit degrades gracefully.)

**Changes:**
- `pyproject.toml`: `deepagents-cli==0.0.41` → `deepagents-code>=0.1.8`.
- `cli/main.py` + `cli/tui_overlay.py`: `deepagents_cli` → `deepagents_code`
  (imports), `_SUPPORTED_VERSIONS` `{0.0.41}` → `{0.1.8}`.
- `server/graph_factory.py`: env var `DEEPAGENTS_CLI_SERVER_ASSISTANT_ID` →
  `DEEPAGENTS_CODE_SERVER_ASSISTANT_ID` (deepagents-code's new name).
- comment refs in server/migrate/agent_install updated.
- `uv sync`: −deepagents-cli==0.0.41, +deepagents-code==0.1.8.

**Validation (fresh venv, NON-editable wheel):**
- `pip install olav-0.20.0.whl` → **exit 0, clean resolution**
  (deepagents-code 0.1.8 + deepagents 0.6.7); deepagents-cli dropped.
- **`pip check`: "No broken requirements found"** — the ResolutionImpossible is GONE.
- olav loads + `olav --agent core` answers via gemma:11433 (SessionState remap works).
- Repo editable env: imports OK; governance re-run (below).

### Assessment

- **The dedup + wheel are sound for the agent runtime.** 236 passed including the
  full LLM agent chain (gemma → delegate → execute_sql → DB → answer) on
  freshly-deployed-from-wheel workspaces with imported real data.
- **No failure is caused by the workspace dedup itself.** The categories are:
  model quality (A, expected), my services-migration test-fallout (B, fixable),
  missing optional deps (C, pylance), and pre-existing/infra (D/E/F).
- **Actionable from this run:**
  1. **(B) Update `test_devops_e2e::TestDevopsServicesStructure`** to the new
     top-level `services/` location — direct fallout of ADR-0014, should fix.
  2. **(setup #2) The deepagents-cli==0.0.41 → deepagents==0.5.3 pin** is the most
     serious — breaks `pip install` for non-uv users. Needs a real dependency fix.
  3. **(C) pylance** — add to install deps (or document `olav[kb]`/extra).
  4. (D/E/F) investigate individually (lower priority).
