# 47. Tool Implementation Separation — v0.19 Architecture

**Date:** 2026-04-15
**Status:** Phase 1 Complete (v0.18.0)
**Principle:** Tool logic lives in Python packages; workspace is thin @tool glue.

---

## Problem

Business logic (SSH, TextFSM, DuckDB queries, API calls) is embedded in `.olav/workspace/*/tools/*.py` files. These files:
- Can only be used through OLAV's workspace system
- Cannot be imported by other agent platforms (LangChain, CrewAI, AutoGen)
- Cannot be unit tested without workspace scaffolding
- Mix `@tool` decorator boilerplate with actual implementation

## Principle

**Implementation in package. Registration in workspace.**

```
Implementation (platform-agnostic)      Registration (OLAV-specific)
─────────────────────────────────      ──────────────────────────────
olav_netops.tools.ssh                  .olav/workspace/ops/tools/execute_cli.py
  def execute_on_device(...)             from olav_netops.tools.ssh import execute_on_device
  def parallel_collect(...)              @tool
                                         def execute_cli(...):
                                             return execute_on_device(...)
```

## Cross-Platform Usage Example

```python
# LangChain (without OLAV)
from olav_netops.tools.ssh import execute_on_device
from olav_netops.tools.snapshot import collect_snapshot

result = execute_on_device("R1", "show version", platform="cisco_ios")
snapshot = collect_snapshot(devices=["R1", "R2"], commands=["show version"])

# CrewAI
from crewai_tools import tool
from olav_netops.tools.ssh import execute_on_device

@tool("Execute CLI Command")
def cli_tool(device: str, command: str) -> str:
    return execute_on_device(device, command)

# AutoGen
from olav_netops.tools.ssh import execute_on_device
# Register as AutoGen function call
```

## Migration Plan

### Phase 1: Extract (non-breaking)
- Create `src/olav/tools/` and `olav-netops/src/olav_netops/tools/`
- Move core logic from workspace .py files to package modules
- Workspace tools become thin wrappers that import from package
- All existing `@tool` signatures unchanged

### Phase 2: Test
- Unit test package tools directly (no workspace needed)
- Verify workspace wrappers still work via Tier 0-2

### Phase 3: Document
- olav-doc: add "Using tools without OLAV" guide
- pypi: olav-netops README shows cross-platform usage

## What Stays in Workspace

| File | Stays in workspace | Why |
|---|---|---|
| `AGENT.md` | Yes | OLAV agent registration |
| `SKILL.md` | Yes | OLAV skill metadata |
| `prompts/*.md` | Yes | LLM-specific prompts |
| `references/*.md` | Yes | API schema docs (generated by registry) |
| `config/*.yaml` | Yes | User configuration |
| `tools/*.py` | Yes (thin wrapper) | `@tool` decorator + parameter schema |
| **Business logic** | **No → package** | Actual SSH/SQL/API/ETL code |

## infra in core

With this separation, the infra question resolves naturally:

```python
# olav_netops.tools.api has no OLAV dependency
from olav_netops.tools.api import query_netbox

# Core workspace can use it:
# .olav/workspace/core/tools/query_service.py
@tool
def query_service(service: str, endpoint: str):
    from olav.tools.api import service_request
    return service_request(service, endpoint)
```

References (NetBox API schema) stay in workspace — they're prompt context, not code.
Core loads them via `static_context` in SKILL.md.

## Not in Scope

- Changing `@tool` function signatures (backward compatible)
- Moving AGENT.md/SKILL.md/prompts out of workspace
- Changing the workspace directory structure
- Breaking `olav skill install` flow
