## 1. Active candidate patches (P3 优化, 不阻塞任何 demo)

详细分析见 `dev_docs/72. V2_VALIDATION_RETROSPECTIVE.md`. 每条都是
独立工作块，可任意顺序施工。

### Patch I — system.md token diet (10 min)

**问题**: `analyze/prompts/system.md` 里有 ~600 char 的"Database
schema cheatsheet" 段 + ~1.5K char 的 "TCF emission emit FIRST" 段，
都跟现已 prime 进 memory 的 guide 重复 (`schema_introspection_via_describe_table`
+ `change_plan_emit_tcf`)。

**修复**: 删除 system.md 中重复部分，只留 "见 memory guide" 的
1-line pointer。AutoRecall 已经会在意图匹配时注入完整内容。

**预期收益**: 每 turn 注入 ~550 tokens (1-1.5% of 64K budget)。
multi-turn 累计 ~10-15K tokens。

**风险**: 极低 — 内容已在 memory，删 system.md 不丢能力。

### Patch J — ROUTING_EXPERT_GUIDE 拆 intent-keyed guides (60 min)

**问题**: `analyze/references/ROUTING_EXPERT_GUIDE.md` 是 368 行的
单文件，agent 触发 BGP intent 时 on_intent 加载整个 ~12 KB。多数
查询只需要其中一段(BGP path selection / community handling / route-map
ordering)。

**修复**: 拆成 6-8 个小 `*.guide.yaml`，关键词区分：
- `bgp_path_selection_attributes.guide.yaml`
- `bgp_community_handling.guide.yaml`
- `bgp_route_map_ordering.guide.yaml`
- `bgp_local_pref_med_decision_tree.guide.yaml`
- `bgp_neighbor_state_machine.guide.yaml` (已有 in memory)
- `bgp_aggregate_summary_route.guide.yaml`
- `bgp_session_types_ebgp_ibgp.guide.yaml`
- `bgp_authentication_md5_ttl_security.guide.yaml`

每个 guide ≤ 2 KB。AutoRecall top-K 召回的精度大涨（不再"为问 community
误注入 path selection"）。

**预期收益**: 0 tokens at base，召回精度从 1/8 → ~3/3 准确。

**风险**: 中 — 拆分要保留语义完整性；建议 LLM 协助拆分 + 人审。

### Patch K — emit_tcf 内容正确性 hard gate (60 min)

**问题**: 当前 emit_tcf 只验 schema 不验 content。Agent 可以 invent
ASN/IP/CLI，spec 写出但跑 lab 失败。详见 `72. V2_VALIDATION_RETROSPECTIVE.md`
section 1 ("TCF correctness" Layer B).

**修复**:
1. emit_tcf 内嵌从 `netops.v_show_ip_bgp_summary_auto` 查实际
   `local_as`，与传入的 `device_asns` 对比，不匹配 → result.warnings
2. 强制要求 agent 先 run_python_simulation 跑
   DESIGN_FEASIBILITY_CHECK.md 里的 feasibility_issues 检查；emit_tcf
   收 `sim_passed: bool` 必填字段（默认 False 时 result.warnings 强提醒）

**预期收益**: 把 "schema 通过" 升级为 "spec 内容跟 prod 数据一致"。
ops-lab 的 verdict 准确率应显著上升。

**风险**: 低 — schema-side 改动，向后兼容（warnings 不阻塞 emit）。

### 2.2 Variance instrumentation

T1h (Patch F) returned 0 emit_tcf calls; T1i (same setup, retry)
returned 31. DeepSeek 同 prompt variance 大。validation 应统计
multi-run success rate，不是 single-run。

实施方案：在 demo7 加个 `tools/v2_chapter_runner.py` 跑同一 prompt
N=3 次，agg success rate 输出 markdown table。
