## 优先级总览（修订 2026-04-02 rev 4）

```
P0  发布就绪                  ← 阻塞 pip publish 的硬性缺口（3项）
P1  平台质量收尾              ← 不阻塞发布但影响文档可信度（5项）
P2  平台功能扩展              ← 有需求但不是必须（4项）
DOC 文档站（6步流程）        ← 依赖 P0+P1 核心项完成后启动
P3  NetOps 专属               ← 不影响平台核心（3项）
```

**排期决策：先修补平台缺口，再进入文档阶段。**

理由：
1. Doc-Driven Testing 会产出针对平台能力的 E2E 测试——如果平台有已知缺口，测试会失败，需要回头修代码，形成低效循环
2. P0 的断测试和打包问题是硬门禁，文档 CI 也依赖测试全绿
3. P1 的 `call_api` 迁移和 probe tool 删除是「清理噪音」——在 Claim 审计前清理，避免把废弃工具写入文档
4. Doc Step A（代码审计）是纯只读操作，可在 P1 并行进行，不阻塞

```
当前可立即执行（无依赖）:
  P0: gap-13, p0-packaging, p0-version
  P1: gap-11, gap-12, gap-14, p1-ghost-audit, p1-cli-todo

P0+P1 核心完成后启动:
  DOC Step A: 代码审计（可与 P1 并行，只读）
  DOC Step B-F: 顺序执行
```
