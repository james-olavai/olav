#### `general-purpose` subagent 映射策略

三个选项：

| 方案 | 做法 | 优缺点 |
|:---|:---|:---|
| A. 映射到现有 subagent | 将 Olav 某个 subagent 命名为 `"general-purpose"` | 破坏语义（网络排障 subagent 不是"通用"的） |
| B. 创建受控通用 subagent | 新建一个 `"general-purpose"` subagent，只给 scratchpad 工具 + `run_python_code` | 最安全，但需要额外维护 |
| **C. 保持现状** | 接受 deepagents 自动注入的 general-purpose（拥有 Olav 全部 orchestrator_tools） | 最简单；该 subagent 的工具和 orchestrator 相同，LLM 用它相当于自己执行，风险低 |

**推荐方案 C**：`general-purpose` subagent 继承了 orchestrator 的全部工具和安全中间件，
LLM 通过 `task("general-purpose", ...)` 调用它等效于 orchestrator 自己执行但在隔离上下文中。
这实际上是有价值的——为长任务提供上下文隔离，不污染主对话。
