| MemoryCapturePlugin | `plugins/middleware/memory_capture.py` | ✅ 已是 middleware | 无需改 |

## 1. 目标

1. 把 `AuditCallbackPlugin`（`AsyncCallbackHandler` 风格）转换为 `AuditMiddleware`（`AgentMiddleware` 风格）
2. 引入 `OlavRunContext` 作为跨 middleware 传递 `run_id` / `recorder` / `agent_id` 的通用载体（替换 `bind_run()` 模式）
3. OLAVAgent 提供 `OLAV_MIDDLEWARE_MODE=callback|middleware` env 切换，v0.20.1 默认 `callback`（用户零感知），v0.20.2 切到 `middleware` 默认
4. 清理：抽取 `parse_subcommand_args()` 助手到 `src/olav/cli/commands/_argparse.py`（P3 的搭车清理项）
5. 端到端验证：callback 模式 vs middleware 模式，audit.duckdb 事件 schema / run_id 绑定 / 父子事件层级 **严格一致**

## 2. 非目标

- 不动其他 4 个已经是 middleware 的 plugin
- 不动 `SecuritySidecarPlugin`（callback 是它的天然形态）
- 不动 `AuditEventRecorder` 的写入格式 / schema / audit.duckdb 表结构
- 不动 CLI TUI 路径（属于 P6）
- 不动 Tool loader / filesystem 布局（属于 P1/P2）

## 3. 设计

### 3.1 OlavRunContext —— 跨 middleware 的运行上下文

```python
# src/olav/plugins/middleware/_context.py
from dataclasses import dataclass
from typing import Optional

@dataclass
class OlavRunContext:
    """Per-invocation context propagated via LangGraph's Runtime.context.

    Replaces the imperative AuditCallbackPlugin.bind_run(run_id) pattern:
    the CLI/API sets run_id + recorder into the context before invoking
    the graph, and every middleware reads it via ``runtime.context``.
    """
    run_id: str | None = None
    recorder: "AuditEventRecorder | None" = None  # noqa: F821  # optional
    agent_id: str | None = None
    user_id: str | None = None
    source_channel: str = "cli"
```

传递方式（LangGraph 1.x 原生）：

```python
# CLI / API 入口
from olav.plugins.middleware._context import OlavRunContext

ctx = OlavRunContext(
    run_id=str(uuid.uuid4()),
    recorder=audit_recorder,
    agent_id=assistant_id,
    source_channel="cli_interactive",
)
result = await graph.ainvoke(
    {"messages": [{"role": "user", "content": prompt}]},
    config={...},
    context=ctx,       # 新增
)
```

Middleware 端：

```python
class AuditMiddleware(OLAVMiddlewarePlugin):
    async def abefore_agent(self, state, runtime):
        ctx: OlavRunContext | None = runtime.context  # 注意可能为 None
        if ctx is None or ctx.run_id is None:
            return None  # 无 run 上下文 → 静默跳过
        ...
```

**为什么不用 state_schema**：run_id 是跨 middleware 共享的只读数据，不是 state。把它塞进 state 会污染 message / memory / agent loop 的状态空间，也会被 checkpointer 持久化（不期望）。context 是 LangGraph 设计用来装这类"只读旁路数据"的。

### 3.2 AuditMiddleware 事件映射

| LangChain callback hook (旧) | AgentMiddleware hook (新) | 备注 |
|---|---|---|
| `on_chat_model_start` | `abefore_model` | 读 state.messages 的 last system/human |
| `on_llm_end` | `aafter_model` | 读 state.messages 里新增的 AIMessage（tokens_in/tokens_out 从 response_metadata 拿）|
| `on_tool_start` | `aafter_tool_call` 的 "started" 路径 | LangGraph 在一次 model turn 后进入 tool-loop；可靠位置是 after_tool_call |
| `on_tool_end` | `aafter_tool_call` 的 "completed" 路径 | 同上 |
| `on_tool_error` | `aafter_tool_call` 的 "failed" 路径（捕获 `state["last_error"]` 或 tool_call_output 里的异常标志）| |
| `on_llm_new_token` | ❌ 不迁 | 流式 token 事件不由 middleware 看到；这条在 middleware 模式里落空。由 CLI/API 层的 streaming handler 独立记录 |

**one-turn 事件对齐**：旧 callback 是 "每个 event 触发一次"；middleware 是 "每个 agent turn 一次聚合"。需要在 AuditMiddleware 里维护 per-turn buffer，`aafter_tool_call` 时 flush。

### 3.3 OLAVAgent 的 dual-path 选择

```python
# src/olav/agents/agent.py（改动片段）
_MODE = os.environ.get("OLAV_MIDDLEWARE_MODE", "callback").lower()

if _MODE == "middleware":
    # middleware 模式：AuditMiddleware 已经通过 load_builtin_plugins 注册，
    # 正常传给 create_deep_agent(middleware=[...])
    # CLI 入口不再调 bind_run，改为把 OlavRunContext 传入 ainvoke(context=...)
    ...
else:
    # callback 模式：保持 v0.19 行为
    # AuditCallbackPlugin 通过 .with_config({"callbacks": [...]}) 挂上
    # CLI 入口在 ainvoke 前调 bind_run(run_id, recorder)
    ...
```

环境变量默认值：
- v0.20.1 发布时 = `callback`（保持行为）
- v0.20.2 发布时 = `middleware`（cutover）
- v0.20.3 发布时 = 只剩 middleware，env var 失效（打印 warning）

### 3.4 callback 模式下的兼容

在 v0.20.1 里两种模式都要能跑：
- `AuditCallbackPlugin` 仍在 `plugins/callbacks/audit.py`（不删）
- `AuditMiddleware` 新增在 `plugins/middleware/audit.py`
- `load_builtin_plugins` 扫描两个目录，按 class 分类
- OLAVAgent 根据 mode 只"启用"一条路径 —— 另一条的 plugin 不会收到事件（callback 模式不挂 middleware；middleware 模式不注册 callback 到 config）

## 8. 风险

| 风险 | 缓解 |
|---|---|
| AgentMiddleware 看不到 streaming token（on_llm_new_token）| middleware 模式下这条事件落空；如果用户依赖此数据 → 在 callback 模式保留；v0.20.2 切换时发 release note 标注 |
| runtime.context 在某些调用路径是 None（e.g. 直接 ainvoke 不传 context） | `abefore_agent` 里检测并静默跳过（AuditMiddleware 不让调用方崩），记一条 debug log |
| 双模式导致 test matrix 翻倍 | 接受，短期一个 minor 的代价 |
| AuditEventRecorder 在 middleware 生命周期里实例化时的线程/事件循环冲突 | 使用 runtime.context 传入的 recorder 实例；避免在 middleware 内部 new 一个新 recorder |
