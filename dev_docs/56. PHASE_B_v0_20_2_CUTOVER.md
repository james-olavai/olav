## 1. 目标

**用户视角**：
- `olav` 命令行看起来一样；`olav agent install` 落地位置改到 `.deepagents/agents/`
- TUI 里 `/agents` 原生命令替代 overlay 的 `/workspace`
- 现有 workspace 可以通过 `olav migrate` 命令一键转换到新布局
- `OLAV_V0_20_LAYOUT=new` 启用新布局；缺省继续 v0.19.x 旧布局（可升级/可回退）

**开发者视角**：
- 新工具开发：`.deepagents/agents/<n>/tools/foo.py` + 重启，自动发现，无 `olav refresh` 调用
- 现有 workspace tools 发现逻辑下沉到 `tool_loader`，graph_factory 消费

**平台视角**：
- `simple_cli` 支持 `OLAV_TUI_MODE=native|overlay`，缺省随 layout 而变（新布局 = native；旧布局 = overlay）
- overlay 从 ~400 LOC 缩到 ~80 LOC（删 `/workspace` 调度器、别名注册、update 拦截）
- `plugins/callbacks/audit.py` 标记 deprecated，P7（v0.20.3）删除

## 2. 非目标

- 不删 `AuditCallbackPlugin` / `olav skill install`（P7 干净清理）
- 不碰 `OLAVAgent.__init__` 里的 LLM / checkpointer / subagents 加载路径
- 不触动 `olav init` 以外的命令行入口（P7 一并收尾）
- 不迁移 netops 仓库的 `.olav/workspace/` → 留给 `olav-netops` 同步提交

## 3. 三个子部分详细设计

### 3.1 P1 — filesystem 对齐

**布局映射**：

```
(旧 v0.19.x)                             (新 v0.20.2+)
.olav/workspace/                        .deepagents/agents/
├── core/                               ├── core/
│   ├── AGENT.md                ─────>   │   ├── AGENTS.md       (rename + content 保留)
│   ├── MANIFEST.yaml                   │   ├── MANIFEST.yaml    (保留 — OLAV 内部消费)
│   ├── tools/*.py                      │   ├── tools/*.py       (不动)
│   ├── prompts/                        │   ├── prompts/         (不动)
│   ├── references/                     │   ├── references/      (不动)
│   └── writer/                         │   ├── agents/
│       └── AGENT.md            ─────>   │   │   └── writer.md   (YAML frontmatter 头 + 正文)
│                                       │   └── skills/
│                                       │       └── <existing-skill>/SKILL.md (不动)
```

**关键新模块**：`src/olav/migrate/v0_20_layout.py`

```python
def plan_migration(root: Path) -> MigrationPlan:
    """Dry-run: return what would change, no side effects."""
def apply_migration(plan: MigrationPlan, *, backup: bool = True) -> MigrationResult:
    """Apply the plan; optionally tar .olav/workspace/ to .olav.bak/ first."""
def already_migrated(root: Path) -> bool:
    """Idempotent check — returns True when .deepagents/agents/ exists
    and contains the expected agent set."""
```

**用户命令**：

```bash
olav migrate --dry-run    # 看会发生什么
olav migrate              # 实际迁移（默认带 backup）
olav migrate --no-backup  # 不带 backup（CI 场景）
```

内部：`olav init` 检测 `OLAV_V0_20_LAYOUT=new`，决定初始化哪种布局。缺省旧布局保护用户（v0.20.2 发布后 release note 提示运行 `olav migrate`）。

**安全措施**：
1. **Dry-run 优先**：`plan_migration` 只读；输出 JSON-serialisable plan
2. **Backup 默认**：`apply_migration(backup=True)` 前 tar cf `.olav.bak/v0.19-backup.tar`
3. **Idempotent**：重复运行不破坏；第二次运行 `already_migrated() → True` 直接跳过
4. **Rollback**：`olav migrate --undo` 读 backup tar 恢复（P7 可能加）

### 3.2 P2 — tool loader

**新模块**：`src/olav/server/tool_loader.py`

```python
def load_tools_for_agent(
    agent_name: str,
    *,
    layout: Literal["legacy", "new"],
    root: Path | None = None,
) -> list[BaseTool]:
    """Return all @tool-decorated callables for *agent_name*.
    
    Scans:
      - new layout: .deepagents/agents/<name>/tools/*.py
                    .deepagents/agents/<name>/skills/*/tools/*.py
                    .deepagents/agents/<name>/agents/<sub>/tools/*.py
      - legacy layout: .olav/workspace/<name>/tools/*.py
                       .olav/workspace/<name>/<skill>/tools/*.py
    """
```

**消费方**：
- `OLAVAgent._load_tools_for_workspace_skills()` 调用 `load_tools_for_agent`，不再手搓 path
- `graph_factory.build_graph` 在 server-subprocess 模式下直接调 `load_tools_for_agent` 把 list 传给 `create_deep_agent(tools=...)`
- `inject_into_core` 在 `agent_install.py` 变成：注册到 OLAV 的全局 tool catalog（内存里），core 构造时通过 catalog 获取

### 3.3 P6 — TUI cutover

**`simple_cli` 改造**（`src/olav/cli/main.py`）：

```python
async def simple_cli(agent, assistant_id, session_state, backend, ...):
    from olav.cli.tui_overlay import apply_olav_overlay
    apply_olav_overlay()
    
    mode = os.environ.get("OLAV_TUI_MODE", _default_tui_mode()).strip().lower()
    if mode == "native":
        # P6: server-subprocess mode; deepagents-cli spawns langgraph server
        # from langgraph.json; /agents handles workspace switching
        server_kwargs = {
            "config_path": str(REPO_ROOT / "langgraph.json"),
        }
        await run_textual_app(
            server_kwargs=server_kwargs,
            assistant_id=assistant_id,
            backend=backend,
            auto_approve=session_state.auto_approve,
        )
    else:
        # Overlay mode — v0.19.x behaviour
        await run_textual_app(agent=agent.graph, ...)

def _default_tui_mode() -> str:
    """New layout → native; legacy → overlay.  Follows current
    .deepagents/agents/ existence."""
    return "native" if (Path.cwd() / ".deepagents" / "agents").is_dir() else "overlay"
```

**overlay 瘦身**（`src/olav/cli/tui_overlay.py`）：

|  保留 | 删除 |

| `_patch_banner()` | `_patch_workspace_command()` — 整个函数 |
| `_patch_title()` | `_register_workspace_aliases()` — 整个函数 |
| `apply_olav_overlay()` 主入口 | `_patch_disable_self_upgrade()` — 保留但 native 模式下空操作 |
| 版本 guard | `_dispatch_workspace()` — 删 |
| `_BLOCKED_COMMANDS` 常量 | `_PENDING_WORKSPACE` / `consume_pending_workspace()` — 保留，但 native 模式下永远 None |

LOC 预估：~400 → ~80，删除 ~320 LOC。

**`run_interactive` 简化**：新 layout 下不再需要 swap-and-relaunch 循环；`/agents` 原生接管。保留旧布局的 swap 循环作为 `OLAV_TUI_MODE=overlay` 回退。

## 10. P6 TUI Cutover 阻塞调查（重要）

**发现时间**：实施 P6 cycle 2 前的可行性验证阶段。

### 10.1 问题

`run_textual_app(server_kwargs=...)` 实际走的路径是
`deepagents_cli.server_manager.start_server_and_get_agent` →
`_scaffold_workspace(work_dir)` → 写一个 **hardcoded** 的
`langgraph.json` 到 tmp dir：

```python
# deepagents_cli/server_manager.py
def _scaffold_workspace(work_dir: Path) -> None:
    server_graph_src = Path(__file__).parent / "server_graph.py"
    server_graph_dst = work_dir / "server_graph.py"
    shutil.copy2(server_graph_src, server_graph_dst)
    ...
    generate_langgraph_json(
        work_dir,
        graph_ref="./server_graph.py:graph",   # ← 写死！
        checkpointer_path="./checkpointer.py:create_checkpointer",
    )
```

`graph_ref` 被硬编码为 deepagents-cli **自己的** `server_graph.py`。
我们放在 OLAV 仓库根的 `langgraph.json`（引用
`olav.server.graph_factory:graph`）**完全不被消费**。subprocess 跑
的是 deepagents 默认图，OLAV 的 plugin / middleware / backend 全部
进不去。

### 10.2 验证

本地实测（session 内）：

```
>>> asyncio.run(start_server_and_get_agent(assistant_id='core', ...))
server OK: RemoteAgent
```

"start 成功"但打开 source tracer 后可见：启动的是 `_scaffold_workspace` 
生成的那份 `langgraph.json` 指向 deepagents 的默认 `server_graph.py`，
不是 OLAV 的 `graph_factory`。

### 10.3 影响

P6 cycle 2（overlay trim）和 cycle 3（simple_cli dispatch）的设计前提
是 "native 模式 = 把 OLAV 图装进 langgraph subprocess"，这个前提
**不成立**。

**原计划无法直接实施**。原生 `/agents` 可用，但切换进的是 deepagents
默认 agent，不是 OLAV 的 ops / audit / topology。

### 10.4 解决方案选项

| 方案 | 实施成本 | 维护成本 | 风险 |
|---|---|---|---|
| **A. Monkey-patch `_scaffold_workspace`** —— 覆盖 `graph_ref` 到 `olav.server.graph_factory:graph`；同时要替换 checkpointer 路径 | 小（~30 LOC） | 中（跟着 deepagents-cli 升级漂移） | 高（deepagents 重构此函数时直接坏掉，和 tui_overlay 同类风险） |
| **B. 向上游 deepagents-cli 提 PR** —— 加 `server_kwargs={"graph_ref": "..."}` 之类的参数 | 小 PR + 等审批 | 低 | 上游可能拒绝；时间不可控 |
| **C. 放弃原生 `/agents`，保持 overlay 路径** —— v0.20.2 只含基础设施（migrate/tool_loader/mode_resolver/olav migrate），TUI 继续走 v0.19.x overlay | 已完成 | 零 | 延迟 `/agents` 原生化到未来版本 |
| **D. Fork deepagents-cli** | 高 | 高 | 脱离上游生态 |

### 10.5 决策（本次 session）

**采纳 C**：v0.20.2 scope 收缩为 **infrastructure-only**。

已交付：
- `olav migrate [--dry-run] [--json] [--no-backup]` —— 用户可以独立
  使用，跟 TUI 模式无关
- `olav.server.tool_loader` —— 公开 API，P6 恢复时可直接消费
- `olav.cli.tui_overlay.resolve_tui_mode` —— 公开 API
- `OLAV_V0_20_LAYOUT` / `OLAV_TUI_MODE` env var 已被模块识别但目前仅
  影响 resolver 返回值；不影响 simple_cli 行为

**推迟**：
- TUI cutover 推到 v0.20.3 或 v0.21.0（取决于方案 A vs B 的进度）
- overlay 的 `/workspace` 和 aliases **保持** v0.19.x 原样
- `OLAV_TUI_MODE=native` 设了也不生效（打印 warning）—— P6 实际切换
  动作进未来版本

### 10.6 v0.20.2 真实价值

不具备原生 `/agents`，但 v0.20.2 仍然有独立价值：

1. **`olav migrate`** 为用户提供显式升级路径。future 版本正式切 native 时，
   用户已经在新 layout 上了
2. **tool_loader + graph_factory 解耦** 为 langgraph dev / LangSmith
   Studio 接入铺路（和 TUI 解耦的价值）
3. **Mode resolver + env var** 是将来 cutover 的 feature flag 的基础
4. **5 个清晰提交** 上了 gitea，每个 cycle 独立可回滚
