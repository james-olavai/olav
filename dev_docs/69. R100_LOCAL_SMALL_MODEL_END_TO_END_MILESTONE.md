## Why this matters

Before this work, OLAV's demo runsheet had a known weak link: **local small models would silently fail on write-class tasks**.  Cloud LLMs (deepseek-v4-flash, grok-4.1-fast, OpenAI) worked fine, but the moment a deployment switched to local Ollama or llama.cpp with a 27B-class model, demo Ch8 (devops scripts) would break in subtle ways:

* Agent describes "I'll write the script" and stops without writing
* Agent calls `format_and_export` with malformed args (nested dict, quote-leaked strings)
* Agent calls deepagents' `write_file` (virtual FS) and gets fake-success, then loops chmod-ing a non-existent file
* Conversation context overflows on multi-turn flows
* AutoCapture embed silently fails on long inputs

Every one of these looked like an LLM adherence problem, suggesting the fix was "use a bigger model" or "tune the prompt better" — neither of which actually scales for on-prem deployments.

The R100 series proves the fix is **at the code layer**, not the prompt or model layer.  ~200 LOC of strict schema typing + defensive coercion + permission gating turns a broken local-small-model demo into a production-quality one.

## The fixes (~200 LOC across 4 commits)

### R100/S2 — strict tool schema + quote-strip (`c2ce4f2`)

`src/olav/data/workspace/core/tools/format_and_export.py`:

```diff
- def format_and_export(data: Any, filename: str | None = None, ...) -> dict:
+ def format_and_export(data: str, filename: str | None = None, ...) -> dict:
```

Removed lenient dict-extraction logic that silently unwrapped `{"content": ...}` / `{"mermaid": ...}` wrappers — that coercion was masking the real adherence bug, letting bad model output produce weird files instead of clear ValidationErrors.

Added `_strip_quote_leak()` defense for short identifier-style fields:

```python
def _strip_quote_leak(s):
    """Strip matching leading/trailing single OR double quotes that
    qwen3.6-27b empirically bakes into short string args."""
    if isinstance(s, str) and len(s) >= 2 and s[0] == s[-1] and s[0] in ('"', "'"):
        return s[1:-1].strip()
    return s
```

12 unit tests pin: dict/list reject with ValidationError; string content variants write byte-for-byte; quote-leak (single + double) stripped; format auto-detected from leading `#`.

### R100/S3 — embed input truncation (`f9b37bf`)

`src/olav/core/embedder.py`: cap input at `OLAV_EMBED_MAX_CHARS=6000` (default) before sending to embed endpoint.  AutoCapture pipeline embeds the growing conversation each turn; without cap, hits llama-server's `--batch-size` ceiling on turn 3-4 of any non-trivial agent flow.

5 unit tests pin: short pass-through; long truncation; env override; env=0 disable; env=invalid fallback to default.

### R100/S4 — FilesystemPermission deny (`42ff7db`)

`src/olav/agents/agent.py:OLAVAgent.__init__`: inject `FilesystemPermission(operations=["write"], paths=["/**"], mode="deny")` to `create_deep_agent(permissions=[...])`.

deepagents' `write_file` writes to `LangGraph state["files"]` virtual filesystem — looks like success but doesn't reach real disk.  Models given open-ended "save to exports/" prompts sometimes pick `write_file` over OLAV's `format_and_export` because the schema is simpler.  Denying virtual-FS writes redirects them to the real-disk tool.

Reads remain allowed (cross-turn data passing via state files keeps working).  Override: `OLAV_ALLOW_VIRTUAL_FS_WRITES=1` (debug only).  Optional dep: deepagents >= 0.5.3.

## Architectural takeaway: code engineering > prompt engineering for small-model adherence

Throughout v1-v9 we tried every prompt/memory-tier intervention available:

* Improve user prompt wording — ❌
* Add directive guide to AutoRecall memory — ❌ (visible in monitor stream, model sees it, ignores it)
* Disable qwen3 thinking — ❌❌ (regression — thinking is load-bearing for ReAct adherence)
* Switch to a "stronger" model (35B-A3B-unsloth, 35B-A3B-Aggressive) — ❌❌❌ (MoE active 3B is *worse* at tool-call adherence than 27B dense)
* Enable LlamaCppReranker for sharper top-K retrieval — ⚠️ (no measurable adherence change; reranker remains valuable for retrieval quality but doesn't fix generation)

What worked:

* `data: Any → str` — gives the LLM an unambiguous JSON schema, removes the "permissive Any → I can pass anything" failure mode
* Defensive input cleaning at the tool boundary — cheap to add, catches systematic LLM-side malformations (quote leakage in short identifiers) that don't go away by saying "don't do that"
* Permission gating that REDIRECTS without destroying the agent flow — when `write_file` fails with PermissionError, the model can re-plan with `format_and_export`; if we'd just removed `write_file` from the toolset, the model would have nothing to fall back to

**The pattern**: small models are confidently wrong about tool args.  Treat them like buggy clients to a strict server — validate inputs, normalize defensively, gate operations narrowly, and make the failure modes loud (ValidationError, PermissionError) rather than silent (write to virtual FS, return weird file).

This is not the same architecture you'd build for cloud frontier-class models.  Cloud models are agile and adherent; the temptation is to design tools for that contract.  But OLAV's deploy story includes on-prem 27B / 14B / 8B local-only setups — the smaller end of which is exactly where the small-model adherence issues bite hardest.  Code-layer rigor is the load-bearing layer.

## What this does NOT solve

* Multi-turn conversation memory pruning — currently relies on docker-compose ctx=65K being big enough; OLAV doesn't yet auto-trim old turns.  Demo7 multi-step flows comfortably fit, but a long debugging session could overflow.
* Cross-agent delegation routing prompts — Ch10 syslog still has an open prompt-tier issue (orchestrator doesn't know to delegate to admin sub-agent for `search_logs`).  Tracked in `ISSUE-CH10-CORE-ORCHESTRATOR-DOESNT-DELEGATE-SYSLOG` (P2).
* Prompt-tier corner cases that ARE genuinely model-dependent — the qwen3 family of GGUFs has known weaknesses around image multimodal, structured JSON output beyond what tool_calls covers, etc.  Not worth solving until we have a real user story for them.

## Decision log

* **Reject "use a bigger model"** — 35B-A3B (both unsloth and Aggressive) was empirically *worse* than 27B dense for tool_call adherence (MoE 3B-active hits a generation-layer wall).  Architectural decision is: prefer dense over MoE for OLAV agent workloads, regardless of total param count.
* **Reject "wait for the qwen3 family to improve adherence"** — could be 6+ months; the bug isn't qwen-specific anyway (smaller llama / mistral derivatives show similar args malformation).  Code fix is universal and shipped immediately.
* **Reject "make `format_and_export` accept `Any` again with smarter coercion"** — that was the v1-v4 bug-masking layer.  Lenient coercion silently produces weird files and the model thinks it succeeded; ValidationError gives a clean retry signal.
* **Reject "force `tool_choice=required` always"** — that closes the door on agents legitimately asking the user a clarifying question.  Better to fix the schema and let the model pick.
