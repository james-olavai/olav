# OLAV — OpenConfig Schema Design v2

**版本**: v2.0 (2026-03-28)
**状态**: 当前设计基准
**取代**: `07. OPENCONFIG_SCHEMA_DESIGN.md`（v0.13.0，已归档）

---

## 0. 设计动机

旧设计（v0.13.0）有5阶段流水线、置信度评分、mapping_cache状态机、LLM自动推断。
过度工程化，维护负担重，核心需求其实很简单：

1. 生产设备数据通过TextFSM采集，数据最丰富
2. Lab需要OC JSON才能通过gNMI推送到SRL
3. 两者之间有gap，gap需要可见但不需要自动消除

**新设计原则：两张表，职责分明，gap自然可见。**

---

## 1. 两张表

### `parsed_outputs` — 原始TextFSM数据（现有，不变）

```sql
-- 现有表，保持不动
netops.parsed_outputs (
    device_name  VARCHAR NOT NULL,
    command      VARCHAR NOT NULL,
    parsed_data  JSON,        -- TextFSM解析结果，原始字段名
    raw_output   TEXT,        -- CLI原始文本，永久保留
    snapshot_id  VARCHAR,
    ingested_at  TIMESTAMP,
    PRIMARY KEY (device_name, command, snapshot_id)
)
```

**写入规则**：TextFSM解析成功就写，不管有没有OC映射。自定义TextFSM模板的数据一定在这里。

### `oc_outputs` — 严格OC数据（新增）

```sql
netops.oc_outputs (
    device_name  VARCHAR NOT NULL,
    snapshot_id  VARCHAR NOT NULL,
    oc_module    VARCHAR NOT NULL,   -- "openconfig-interfaces" | "openconfig-bgp" | ...
    oc_data      JSON    NOT NULL,   -- 该模块的完整OC树，严格遵循OC YANG结构
    source_cmd   VARCHAR,            -- 来源命令，用于追溯
    PRIMARY KEY (device_name, snapshot_id, oc_module)
)
```

**写入规则**：只写`schema_catalog`里有OC路径映射的字段。没有映射的命令不写这张表，不写假数据。

## 2. 数据流

### Sync时（采集 → 存储）

```
生产设备 CLI
    ↓ TextFSM解析
parsed_outputs  ← 无条件写入（数据永不丢失）
    ↓ apply_oc_mapping_cached()
    ↓ 有schema_catalog映射的字段 → 按OC模块分组
oc_outputs      ← 只写成功映射的部分
```

两个写操作在同一次sync中完成。`oc_outputs`写入失败不影响`parsed_outputs`写入。

### Lab时（导出 → gNMI推送）

```
oc_outputs
    ↓ SELECT WHERE device_name IN (...) AND snapshot_id = latest
OC JSON per device per module
    ↓ gNMI Set (json_ietf)
SRL节点
```

Lab agent只读`oc_outputs`，不碰`parsed_outputs`。不需要任何运行时转化。

---

## 3. OC模块覆盖范围

`oc_outputs`按模块分行存储，当前支持的模块由`schema_catalog`的覆盖情况决定：

| oc_module | 来源命令（典型） | 核心域 |
|-----------|----------------|-------|
| openconfig-interfaces | show interfaces, show ip interface | ✅ |
| openconfig-bgp | show bgp summary, show ip bgp | ✅ |
| openconfig-network-instance (OSPF) | show ospf neighbor | ✅ |
| openconfig-lldp | show lldp neighbors | ✅ |
| openconfig-platform | show version, show inventory | ✅ |
| openconfig-network-instance (ISIS) | show isis neighbors | 扩展域 |
| openconfig-vlan / EVPN | show evpn instance | 扩展域 |

覆盖范围随`schema_catalog`内容自动扩展，不需要改代码。

## 4. Gap可见性

自定义TextFSM模板或新命令，若没有`schema_catalog`映射：

- `parsed_outputs`：有数据 ✓
- `oc_outputs`：无数据

Gap检测：

```sql
-- 找出有TextFSM数据但无OC输出的device × command
SELECT DISTINCT p.device_name, p.command
FROM parsed_outputs p
LEFT JOIN oc_outputs o
    ON p.device_name = o.device_name
    AND p.snapshot_id = o.snapshot_id
WHERE o.device_name IS NULL
  AND p.snapshot_id = (SELECT MAX(snapshot_id) FROM parsed_outputs)
ORDER BY p.device_name, p.command;
```

这条SQL就是gap报告，不需要专门的审计脚本。

## 5. schema_catalog的角色

`schema_catalog`是两表之间的桥梁，定义哪些TextFSM字段能进`oc_outputs`：

```sql
schema_catalog (
    platform     VARCHAR,
    source_name  VARCHAR,   -- CLI命令
    fields       JSON,      -- [{name, openconfig_path, ...}]
    PRIMARY KEY (platform, source_name)
)
```

`fields`里`openconfig_path`非空的字段 → 写入`oc_outputs`。
`openconfig_path`为空或缺失 → 留在`parsed_outputs`，不进`oc_outputs`。

---

## 6. 核心域Gate（不变）

核心域OC覆盖率 ≥ 95%，定义不变：

```sql
SELECT
    SUM(CASE WHEN f->>'openconfig_path' IS NOT NULL THEN 1 ELSE 0 END)
        * 100.0 / COUNT(*) AS core_coverage_pct
FROM schema_catalog sc,
     UNNEST(json_extract(sc.fields, '$[*]')::JSON[]) AS t(f)
WHERE lower(sc.source_name) = ANY(CORE_COMMAND_LIST);
-- CORE_COMMAND_LIST: interfaces, lldp, bgp, inventory类命令
```

Gate失败说明核心域有字段未映射，需要补充`schema_catalog`，不需要改代码。

## 7. 新增命令的处理流程

用户新增自定义TextFSM模板，完整流程：

```
1. 写TextFSM模板 → .olav/templates/{platform}_{command}.textfsm

2. 触发sync → 数据进parsed_outputs ← 立即生效

3. 查gap SQL → 发现该命令无OC输出

4. 在schema_catalog里为该命令的每个字段添加openconfig_path
   （手工 或 通过schema_engine向量检索辅助）

5. 下次sync → 数据同时进parsed_outputs + oc_outputs ← 完整打通
```

步骤3到4之间，`parsed_outputs`已有数据，可以通过`execute_sql`直接查询，不影响已有功能。Lab使用需要等到步骤4-5完成。

## 8. 与Lab Agent的接口

Lab agent的`export_oc_snapshot`工具：

```python
def export_oc_snapshot(
    devices: list[str],
    snapshot_id: str | None = None,   # None = 最新
) -> dict:
    """
    从oc_outputs读取指定设备的OC数据。

    返回:
    {
      "r1": {
        "openconfig-interfaces": {...},
        "openconfig-bgp":        {...},
      },
      "coverage_gaps": [
        {"device": "r1", "commands_in_parsed": 8, "oc_modules": 3}
      ]
    }

    coverage_gaps告知agent哪些设备的OC覆盖不完整，
    agent根据gap决定lab实验的可信度范围。
    """
```

`coverage_gaps`是两表对比的结果，不是单独维护的状态。

## 9. 与旧设计的主要差异

| 旧设计 (v0.13.0) | 新设计 (v2.0) |
|-----------------|--------------|
| 单表`parsed_outputs`混存原始+OC | 双表职责分明 |
| Lab时做OC转化（时间敏感） | Sync时做转化，Lab直接读 |
| 5阶段流水线 + 置信度评分 | schema_catalog映射，有就写，没有就跳过 |
| mapping_cache状态机 | 不需要，schema_catalog就是唯一映射源 |
| unmapped_commands专用追踪 | gap = oc_outputs里没有，SQL直接查 |
| LLM自动推断写schema_catalog | 手工或辅助工具，人工确认后写 |
