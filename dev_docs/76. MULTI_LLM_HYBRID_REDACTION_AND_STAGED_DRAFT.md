# R-MULTI-LLM-HYBRID — 多模型 / 混合部署 / 脱敏 / 分阶段 ReAct draft 设计

**Created**: 2026-05-13
**Driver**: 2026-05-12 R-CAB-THREE-STAGE 后续实测发现 — `gemma4:31b` 多阶段编排失稳;
`deepseek-v4-flash` 全栈通但**数据主权 + 成本**两件事没解决;
draft.yaml 出来的"PASS"有假阳 (post_check `expected_pattern` 被静默接受为空).

本文档落 4 个互锁设计:
1. **多 LLM profile** — 每个 sub-agent 单独选模型
2. **混合部署** — 30B 本地 inspector + 200B 在线 reasoning
3. **脱敏层** — draft.yaml 出门前 redact, 回来 derecact
4. **Draft 分阶段 ReAct fill** — 模仿 audit `render_report` 模式, section-by-section 填空 + 立即 lint

---

## 设计 1: 多 LLM profile (P1, ~1-2 天)

### 动机
当前 `.olav/config/api.json` 单一 `llm.model` 配置, 全工作区共用一个模型. 实测:
- 编排器 + analyzer 需要 200B+ (gemma4:31b 多阶段 timeout)
- sim + lab `agent_type: api` 不调 LLM
- inspector 单工具调用, 30B 够用
- freeform_translator 跨厂商翻译, 需 200B+

成本: 让所有人用 200B+ 浪费 (sim/lab 用不到); 让所有人用 30B 编排跪.

### 配置 schema

```jsonc
{
  "llm": {
    // 向后兼容: 不写 profiles 就是旧 single-model 模式
    "default": {
      "model": "deepseek/deepseek-v4-flash",
      "base_url": "https://openrouter.ai/api/v1",
      "api_key": "sk-or-v1-...",
      "model_provider": "openrouter"
    },
    "profiles": {
      "fast": {
        "model": "gemma4:31b",
        "base_url": "http://192.168.100.12:11434",
        "model_provider": "ollama"
      },
      "strong": {
        "model": "anthropic/claude-sonnet-4-6",
        "base_url": "https://openrouter.ai/api/v1",
        "api_key": "sk-or-v1-..."
      },
      "local_redact_safe": {
        "model": "gemma4:31b",
        "base_url": "http://192.168.100.12:11434",
        "model_provider": "ollama",
        "redact_required": true   // 数据出此 profile 必先脱敏
      }
    }
  }
}
```

### SKILL.md 字段

```yaml
---
name: analyzer
agent_type: api          # 不调 LLM → 忽略 llm_profile
llm_profile: strong      # 用 claude-sonnet-4-6
# 未声明 → 用 default
---
```

### 代码改动 (~60 行)

| 文件 | 改动 |
|---|---|
| `src/olav/core/config.py:get_llm_config()` | 加 `profile: str | None` 参数, 选 default 或 profiles[name] |
| `src/olav/core/llm.py:LLMFactory.get_chat_model()` | 加 `llm_profile` 参数 → 传给 get_llm_config |
| `src/olav/agents/agent.py:~991` (sub-agent LLM 重建块) | 读 `metadata.llm_profile`, 传给 factory |

### 推荐生产配置

| 角色 | profile | 理由 |
|---|---|---|
| netops 编排器 | `strong` | 多阶段路由 + tool chaining |
| netops/analyzer | `strong` | inspect 多轮 + schema 填写 |
| netops/sim | (无 LLM) | Python skill-script |
| netops/lab | (无 LLM) | Python skill-script |
| netops/investigate | `fast` | 单工具调用居多 |
| netops/collect | `fast` | 同上 |
| freeform_translator | `strong` | 跨厂商翻译 |

成本估算 (1000 CAB/月): 一刀切 `strong` vs per-profile 优化 ≈ **省 60-70% LLM 费用**.

### 测试要求
1. 同 task 切换 profile 跑两次 — 输出 (除时延外) 等价
2. 子 agent 报告各自所用模型 ID (在 journal 里记)
3. `redact_required: true` 的 profile 收到未脱敏数据应 hard-fail

## 设计 2: 混合部署 — 30B 本地 inspector + 200B 在线 reasoning (P1, 依赖设计 1)

### 动机
设计 1 让 sub-agent 选模型;设计 2 是基于实测能力数据的**具体角色分配**:

#### 30B (gemma4:31b) 实测能力边界 (2026-05-13)

| 任务 | 30B 表现 |
|---|---|
| 单 tool 调用 (inspect_devices) | ✅ |
| Schema 填写 (Pydantic 强制下 retry 几次) | ✅ |
| Intent 选择 (5 个 supported intent 里挑) | ✅ |
| 跟 suggested_alternative 切 intent | ✅ |
| **填 facts_collected.topology_edges (多设备)** | ❌ **经常空** |
| **填 intent_args 子字段精确度** (`expected_pattern` 不是 `expected`) | 🟡 经常错 |
| **多阶段 task() chaining (analyzer→sim→lab)** | ❌ timeout |
| **长上下文 (20+ tool call)** | ❌ 退化 |

#### 200B (deepseek-v4-flash) 实测

| 任务 | 200B 表现 |
|---|---|
| 多阶段 task chaining | ✅ ~10min 完整跑通 R2-R4 OSPF |
| 跟 next_step.action 路由 | ✅ |
| **同样的字段名同义词错** (`expected` vs `expected_pattern`) | 🟡 **也错** |
| **同样依赖 schema 反馈做修正** | 🟡 需要 lint 层 |

### 关键发现 — "字段名精确度"不是 30B vs 200B 的问题

**模型大小解决不了字段拼写问题, schema lint 才解决**. 见设计 4.

### 混合部署目标拓扑

```
本地区域 (数据敏感)                            在线区域 (cloud LLM)
─────────────────────────                  ─────────────────────────
inspector tools                            
  ├─ inspect_devices                       
  ├─ inspect_topology                      
  └─ inspect_routing                       
  (纯 Python query, 不通过 LLM)            
       ↓ raw facts JSON                    
                                           
analyzer (本地 30B 或纯 deterministic)    
  └─ 把 inspector JSON 合并成 envelope     
       ↓ raw draft.yaml                    
                                           
redactor (本地)  ──redact()──→  redacted draft  ───→  在线 analyzer (200B)
                                                       └─ 写 rationale, 选 intent,
                                                          fill intent_args
                                                       ↓ redacted draft (完整)
                                           
                 ←──redacted spec──  在线 sim (200B render + freeform_translator)
                                           
derecact (本地) ──derecact()──→ real spec.tcf.yaml
       ↓                                    
lab (本地 Python, 直接 CLAB API)           
```

### 关键设计
- **inspector 不通过 LLM** — 直接 Python query 返回 typed JSON. 30B 在这一步不会"漏字段"
- **analyzer "envelope 合并"** 可以是纯 Python (拿 inspector JSON 拼 facts_collected)
- **写 rationale + 选 intent + fill intent_args** 这些 reasoning 上云
- **prod data 不出门** (脱敏后才出)

### 实施前提
- 设计 1 (per-subagent profile) 完成
- 设计 3 (redaction) 完成

## 设计 3: 脱敏层 (P1, ~2 周)

### 动机
draft.yaml 当前内容含真实敏感数据:
- 主机名 (`DCN-CORE-01.prod.acme.com`)
- IP (loopback `1.1.1.1`, link subnet `10.1.13.0/30`)
- ASN (`65000`, `65001` — 揭示 BGP 边界)
- 完整 prod CLI

数据出网到 OpenRouter / 第三方 LLM API 有合规问题. 需要脱敏层让"实数据本地, 在线只看占位".

### 映射规则 (确定性 + 可逆)

| Field | 原 | 脱敏 |
|---|---|---|
| Device name | `R1, R3, SW1, DCN-CORE-01` | `DEV_A, DEV_B, DEV_C, DEV_D` |
| Loopback | `1.1.1.1, 3.3.3.3` | `198.51.100.1, 198.51.100.3` (RFC 5737) |
| Link subnet | `10.1.13.0/30` | `192.0.2.0/30` (RFC 5737) |
| ASN | `65000, 65001` | `64512, 64513` (RFC 6996 private) |
| Hostname FQDN | `core-east-1.prod.acme.com` | `dev_a_1.example.local` |
| AS-PATH/community | `65000:100` | `64512:100` |
| Interface name | `ge-0/0/2, Ethernet0/1` | **保留** (vendor 句法依赖) |
| 自由文本 CLI | `set protocols bgp group X` | 原文 (规则化扫描内嵌敏感 ID 替换) |

### 模块结构

```
src/olav/core/cab/redaction/
  __init__.py
  redactor.py         # class DraftRedactor:
                      #   redact(draft) → (redacted_draft, inverse_map)
                      #   derecact(redacted_spec, inverse_map) → spec
  patterns.py         # IP/ASN/hostname regex + 替换函数
  test_redactor.py    # 双向 roundtrip + 不变量
```

### 数据流

```
draft.yaml          → redactor.redact() → redacted_draft.yaml + inverse_map.json
                                           ↓ 出门
                                           ↓ 在线 LLM
                                           ↓ redacted_spec.tcf.yaml 返回
real_spec.tcf.yaml ← redactor.derecact() ←
       ↓ 本地展开真实数据
lab 执行
```

inverse_map 本地存:
```json
{
  "devices":  {"DEV_A": "R1", "DEV_B": "R3"},
  "ips":      {"198.51.100.1": "1.1.1.1", "192.0.2.0": "10.1.13.0"},
  "asns":     {"64512": "65000", "64513": "65001"}
}
```

### 设计约束
- **确定性** — 同 device → 同占位 (per-draft, 跨 CAB 不一致以防 cross-correlation)
- **可逆** — derecact 必须无损还原
- **完整覆盖** — 模糊字段 (rationale prose) 也要扫
- **泄漏检测** — redacted 输出过 detector, 任何 prod-shape IP/ASN 残留就 fail-loud

### Profile 集成
配合设计 1 的 `redact_required: true` 标记:
- 任何 profile 标 `redact_required` 时, factory 在 LLM call 前调 redactor
- 返回后 derecact

### 估时 (~2 周)
| 项 | 天数 |
|---|---|
| redactor.py + patterns.py | 3-5 |
| 单测 (roundtrip + leak detector) | 1-2 |
| submit_draft 集成 | 1 |
| sim/finalize 集成 (从 redacted draft 走) | 1 |
| lab 入口 derecact | 1 |
| e2e R1-R3 OSPF 验证 (redact → online sim → derecact → lab PASS) | 2 |

## 设计 4: Draft 分阶段 ReAct fill (P1, ~3 天)

### 动机 — 一次性 fill 的失败模式

当前 `submit_draft` 是 one-shot 结构化输出:
```python
@tool(args_schema=DraftChangePlan)
def submit_draft(user_prompt, devices_in_scope, proposed_intent, 
                  intent_args, rationale, facts_collected, ...):
```

LLM 在**单个 message** 里要一口气填全部字段. 实测问题:
1. facts_collected 经常漏 (gemma 多设备 topology_edges 0 entries)
2. intent_args 子字段拼错 (`expected` vs `expected_pattern`)
3. 失败信息抽象 (Pydantic ValidationError 一次给好几条, LLM 不知道先改哪个)
4. 整个 envelope 太大, 30B 短上下文 trade-off 内顾此失彼

### 灵感 — Audit `render_report` 模式

读 `src/olav/.olav/workspace/audit/runner/tools/render_report.py`:
```python
# Phase 2 — per-Job section rendering, appended to file
for job_name, findings in jobs.items():
    section_prompt = _get_section_prompt(profile_cfg, job_name)
    prompt = _assemble_prompt(system_envelope, section_prompt, findings)
    section_content = llm.invoke(prompt).content
    _append_to_file(report_path, section_content)
```

LLM 一次只看一个 section + 该 section 的 findings, 输出该 section. 不让它见全文. **section-by-section 流式 fill**.

### Draft 分段填法

把 DraftChangePlan 分成 5 个 fillable section, 每个独立 prompt + 立即 lint:

| Section | 输入 | LLM 任务 | 立即 lint |
|---|---|---|---|
| **S1: scope** | user_prompt | 提取 `user_prompt`, `devices_in_scope` (list)| 必有 ≥1 device |
| **S2: facts** | scope + inspector tool outputs | 合并成 `facts_collected` (devices, topology_edges, ...) | 多设备时 topology_edges 必非空; 每 device 必有 platform |
| **S3: intent** | scope + facts | 选 `proposed_intent` (5-Literal); 给 `rationale` | rationale ≥30 chars; intent ∈ SupportedIntent |
| **S4: intent_args** | intent + facts | 按 intent shape 填 intent_args (per-intent template) | freeform_cli: cli_per_device 覆盖 scope; post_checks 每条有 device+command+expected_pattern |
| **S5: revision_meta** | (optional) | revision_round, previous_blockers — revision 时才填 | revision_round ≥0; previous_blockers list |

每 section 通过 → append 到 in-progress draft → 进下一 section. 任何 section 失败 → ReAct 修该 section, 其他不动.

### 模板文件 (per-intent)

```
src/olav/data/draft_templates/
  freeform_cli.yaml      # 5 section, 每 section 一段 prompt
  ebgp_direct.yaml
  ibgp_direct.yaml
  static_route_add.yaml
  vlan_add.yaml
  _shared/
    scope.yaml           # S1 prompt 通用
    facts.yaml           # S2 prompt 通用 (按设备数选 single/multi 变体)
    intent.yaml          # S3 prompt 通用
```

模板 schema:
```yaml
# freeform_cli.yaml
intent: freeform_cli
sections:
  s4_intent_args:
    description: "Fill cli_per_device + rollback_per_device + post_checks for freeform_cli"
    prompt: |
      Given the chosen intent `freeform_cli` for devices {{devices_in_scope}},
      compose intent_args with this EXACT schema:
        cli_per_device: {<device>: [<cli line>, ...]}
        rollback_per_device: {<device>: [<cli line>, ...]}
        post_checks: 
          - device: <one of devices_in_scope>
            command: "<show command>"
            expected_pattern: "<EXACT regex/substring to match>"  # CANNOT be empty
            description: "<purpose>"
      
      Constraints:
        - Every device in {{devices_in_scope}} MUST appear in cli_per_device
        - post_checks MUST have non-empty expected_pattern (空字符串 = 自动 PASS bug)
        - Field name is "expected_pattern" NOT "expected" — typo will be rejected
      
      Existing facts:
        {{facts_collected_summary}}
    lint:
      - rule: cli_per_device_covers_scope
        message: "cli_per_device 缺设备: {missing}. 加 {missing}: [<CLI lines>]"
      - rule: post_check_has_device_field
        message: "post_check[{i}] 缺 device 字段"
      - rule: post_check_expected_pattern_nonempty
        message: "post_check[{i}].expected_pattern 不能空; 用具体匹配字符串/正则"
      - rule: post_check_no_synonym_typo
        synonyms: ["expected", "pattern", "match"]
        message: "post_check[{i}] 用了 '{found}', 应为 'expected_pattern'"
```

### 流程图

```
analyzer:
  S1 ──fill──→ scope_ok?
        ├─ no  → re-prompt with lint hint (1-2 retry)
        └─ yes ↓
  
  S2 ──fill──→ facts_ok?
        ├─ no  → re-prompt
        └─ yes ↓
  
  S3 ──fill──→ intent_ok?
        ├─ no  → re-prompt
        └─ yes ↓
  
  S4 ──fill──→ intent_args_ok?
        ├─ no  → re-prompt with per-rule lint hints
        └─ yes ↓
  
  (S5 optional)
        ↓
  whole_draft_lint  → 所有 section 一起 cross-check
        ├─ no  → 报告哪个 section 需要重填
        └─ yes ↓
  
  submit_draft (one-shot 写入 disk + 返回 next_step)
        ↓
  sim.finalize_tcf
```

### 与 sim 的关系

`sim/finalize.py` 收到 draft.yaml 后**重跑** lint (防 staged-fill 被绕过). 这是 trust boundary — sim 假设输入不可信.

### 实施 (~3 天)

| 文件 | 改动 |
|---|---|
| `src/olav/core/cab/draft_templates/` (NEW) | 5 个 YAML 模板 + shared prompt |
| `src/olav/core/cab/sim/draft_lint.py` (NEW) | 共享 lint rules (sim 和 analyzer 都用) |
| `olav-netops/.olav/workspace/netops/analyzer/tools/staged_draft_fill.py` (NEW) | 替代 submit_draft 的 staged-fill 工具 (旧 submit_draft 保留为 fallback) |
| `analyzer/SKILL.md` | 加 staged_draft_fill 到 tools list, 说明新工作流 |
| `sim/finalize.py` | finalize 前先跑 draft_lint, 任何 lint 错 → 返回 lint_failed rejection |

### 收益预期
- **30B 可用** — 每个 section 小, 不超 30B 短上下文
- **失败信息精准** — lint 错带 hint + 字段路径, LLM 机械化修
- **假阳消除** — `expected_pattern` 空字符串 lint 拒绝
- **审计可读** — draft.yaml 旁多个 staged_fill_journal.yaml 记每 section 的 prompt/response/lint
- **跨模型一致** — 30B 和 200B 都受益, 不是只救 30B

### 测试目标
1. R1-R3 OSPF 用 30B + staged fill → 落盘 draft.yaml 与 200B 一次性产出**字段完整度**等价
2. R2-R4 OSPF 在 30B 上跑 → lab.verdict 真 PASS (不是 R2-R4 那次的假阳)
3. 故意写错字段名 prompt → lint catch + 自动 retry 修对

## 全局优先级与里程碑

| 设计 | P | 估时 | 依赖 |
|---|---|---|---|
| 1. 多 LLM profile | P1 | 1-2 天 | — |
| 4. Draft 分阶段 ReAct fill | P1 | ~3 天 | — (独立) |
| 3. 脱敏层 | P1 | ~2 周 | 1 (用 profile 标 redact_required) |
| 2. 混合部署 | P1 | 集成天 (~3 天) | 1 + 3 完成后即水到渠成 |

**最小可见收益顺序**: 4 → 1 → 3 → 2

1. **先做 4 (staged fill)** — 立即解决 30B 字段精度 + 假阳, 不需要换模型也能用
2. **再做 1 (profile)** — 让不同 sub-agent 可独立配模型, 解锁混合
3. **再做 3 (redact)** — 数据合规, 解锁在线模型
4. **最后 2 (混合)** — 1+3 完成后就是配置题
