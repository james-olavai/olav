## Ch4 — Knowledge Base (declarative memory, 5 min)

**Goal**: hand-author team rules in YAML and have AutoRecall surface
them.

```bash
# 1. Author a rule — drop anywhere under .olav/workspace; the importer
#    rglob's *.guide.yaml (no fixed `guides/` directory required).
#    Recommended locations:
#      .olav/workspace/<agent>/guides/    — agent-scoped
#      .olav/workspace/<agent>/<skill>/references/  — per-skill (portable
#                                                    via SKILL.md
#                                                    `dynamic_context`)
cat > .olav/workspace/netops/guides/netbox_naming.guide.yaml <<'EOF'
schema_version: 2
intent: netbox_naming_convention
agent: netops
source_tier: team        # vendor | platform | team | user (dev_docs/79).
                          # Team-tier (priority 6 → weight 1.33) beats
                          # user-tier R102 commits (priority 3 → 0.83).
keywords: [netbox, naming, hostname, 命名, 规范]
body: |
  Device hostnames in NetBox follow <site>-<role>-<n> pattern.
  Example: us-west-border-01.  Status defaults to active.
EOF

# 2. Prime into LanceDB
olav kb import-guides .olav/workspace
# → "✓ guides primed: N (K skipped, P orphan(s) pruned)"
#   The orphan-prune phase deletes memory entries whose source YAML
#   was removed — keeps AutoRecall in sync with disk truth.

# 3. Inspect the live KB (new in dev_docs/79)
olav kb list-guides --tier team
# → table of team-tier guides; --tier user surfaces R102 commits
olav kb show netbox_naming_convention
# → prints the YAML; copy/paste for git PR promotion to platform tier

# 4. Verify recall
olav --agent netops "What's our NetBox naming convention?"

# 5. Decommission a guide (audit-trail mandatory) — dev_docs/79
olav kb remove netbox_naming_convention --reason "moved to org-wide repo"
# → tombstone YAML (<intent>.guide.yaml.removed) + LanceDB row deleted
#   + kb_audit/<ts>_remove_<intent>.yaml row written (actor + body_sha256
#   + reason + timestamp).  Reprime will not resurrect.
```

**Verification**:
```bash
python -c "
import lancedb
db = lancedb.connect('.olav/databases/memory.lance')
df = db.open_table('memory').to_pandas()
print(df[df['id']=='guide_netops_netbox_naming_convention'].iloc[0]['text'][:120])
"
# → echoes the body
```

**Talking point**: declarative `*.guide.yaml` is the **version-controlled,
schema-bound, team-shareable** memory path — pairs with R102
conversational ingestion (Ch5) and L1 implicit capture. Per-skill
`references/` (2026-05-13) keeps guides portable across agent
frameworks while OLAV's rglob importer still finds them.

#
# NOTE 2026-05-15: bare "可以" / "y" / "入库" without intent name does NOT work

## Ch10 — Services (CSV-intermediate sync to NetBox)

**Goal**: demo the canonical netops ↔ services handoff via CSV
intermediate.  netops (read side) shapes the data; services (write
side) handles NetBox API quirks.  The CSV is the audit-friendly
contract between them — git-diff-able, replayable across
environments, human-reviewable before any push.

**Two phases**:
* **Ch10a (default, no external dep, ~5 min)** — netops exports
  NetBox-shaped CSV.  Validates the read pipeline + column mapping
  without needing a real NetBox.
* **Ch10b (full path, ~30-40 min, optional)** — `olav --agent
  services "deploy netbox"` starts the official netbox-docker
  stack; services agent imports the CSV via NetBox REST API.
  Skip unless you're validating the write side end-to-end.

### Ch10a — netops → CSV (no external services)

```bash
# 1. netops exports devices via the deterministic slash command
#    (no LLM in the loop — the script wraps the SQL + CSV write atomically
#    so gemma4 nothink doesn't have to chain execute_sql + format_and_export,
#    which it does unreliably).
olav --agent netops "/export_netbox_csv"
# → writes exports/netbox_devices.csv in <1s
# Optional: --filename my_export, --tenant team-xxx

# 2. Inspect the CSV — operator's HITL gate
head -5 exports/netbox_devices.csv
wc -l exports/netbox_devices.csv     # 1 header + N device rows
```

The slash command is a thin Python wrapper (`netops/export_netbox_csv/run.py`);
the canonical column mapping + SQL + tenant resolution lives in the
`netbox_csv_export.guide.yaml` platform-tier guide (source-of-truth for
operators who want to edit the export shape).

**Verification**:
* `exports/netbox_devices.csv` exists, ≥ 7 lines (header + 6 devices)
* Header includes `name, device_role, manufacturer, device_type,
  primary_ip4, platform, site, status, tenant, snapshot_id,
  exported_at` (exact column set determined by `netbox_csv_export`
  guide)
* `tenant` column = `acme-network-ops` on every row (sourced from
  the team-tier `netbox_tenant_default` guide written in Ch4)
* `snapshot_id` matches the latest `netops.v_snapshots_auto` row

**Talking point**: CSV-as-contract decouples the two agents.
netops only knows OLAV's `netops.devices` schema + the column
mapping (lives in `netbox_csv_export.guide.yaml`, source_tier:
platform).  services only knows NetBox's API + foreign-key order
(site → device_type → device).  Neither sees the other's quirks;
a single CSV change-set is the unit of review + git audit.

### Ch10b — services → NetBox container (full path, optional)

```bash
# 1. Start a local NetBox docker stack via OLAV's deploy_service
olav --agent services "Deploy NetBox container locally with default
admin token"
# → uses .olav/config/services.yaml.netbox stanza, starts
#   netbox + postgres + redis via docker-compose, prints token

# 2. Register the local instance + verify health
olav --agent services "Is NetBox healthy?"

# 3. services imports the CSV produced by Ch10a
olav --agent services "Import exports/netbox_devices.csv into NetBox.
Ensure sites, manufacturers, device_types exist (create if missing).
Idempotent on device.name+site.  Report per-row status."

# 4. Round-trip verify — query NetBox back, compare against
#    netops.devices, expect zero diff on (name, site, primary_ip4).
olav --agent services "Compare NetBox device list vs netops.devices;
show any gap rows."

# 5. Stop the container
olav --agent services "Stop NetBox container"
```

**Verification**:
* `docker ps | grep netbox` shows running container during the run
* Round-trip diff is empty (NetBox == netops.devices on the mapped fields)
* `audit.duckdb` has `register_service` + `deploy_service` rows

**Why deferred**: the netbox-docker stack pulls ~700MB across 3
images and adds ~3 min cold-start latency.  Ch10b is the "real
production sync" demo — useful for a stakeholder review, overkill
for the day-to-day platform smoke run.
