## Ch3 — Core agent NL queries (5 min)

**Goal**: natural-language → SQL → answer, with AutoRecall injecting
relevant memories.

```bash
olav "What devices are border routers?"
olav "Show BGP neighbors on R1"
olav "Which interfaces on R3 are down?"
```

**Verification**:
* Each call emits 1 `execute_sql` tool call (no introspection
  round-trips — schema_knowledge memory was pre-injected)
* Recurrent queries get faster: query_pattern memory captures
  successful SQL and AutoRecall surfaces it next time
* Weight-based ranking (2026-05-14): `usage_guide` (priority 5 → weight 1.0,
  priority ≥ 8 → weight ≥ 1.5) outranks `operational_event` (weight 0.5)
  in mixed AutoRecall results — policy beats prior-example noise.

**Talking point**: memory beats prompt engineering — `<relevant-memories>`
auto-injected on every model call lets a 27B-dense model land
production SQL on first try.

## Ch4 — Knowledge Base (declarative memory, 5 min)

**Goal**: hand-author team rules in YAML and have AutoRecall surface
them.

```bash
# 1. Author a rule — drop anywhere under .olav/workspace; the importer
#    rglob's *.guide.yaml (no fixed `guides/` directory required).
#    Recommended locations:
#      .olav/workspace/<agent>/guides/    — agent-scoped
#      .olav/workspace/<agent>/<skill>/references/  — per-skill (portable
#                                                    via SKILL.md
#                                                    `dynamic_context`)
cat > .olav/workspace/netops/guides/netbox_naming.guide.yaml <<'EOF'
schema_version: 1
intent: netbox_naming_convention
agent: netops
keywords: [netbox, naming, hostname, 命名, 规范]
priority: 7  # 1..10; default 5 → weight 1.0; high-priority guides
             # outrank operational_event noise (weight 0.5) in recall.
body: |
  Device hostnames in NetBox follow <site>-<role>-<n> pattern.
  Example: us-west-border-01.  Status defaults to active.
EOF

# 2. Prime into LanceDB
olav kb import-guides .olav/workspace
# → "✓ guides primed: N (K skipped, P orphan(s) pruned)"
#   The orphan-prune phase deletes memory entries whose source YAML
#   was removed — keeps AutoRecall in sync with disk truth.

# 3. Verify recall
olav --agent netops "What's our NetBox naming convention?"
```

**Verification**:
```bash
python -c "
import lancedb
db = lancedb.connect('.olav/databases/memory.lance')
df = db.open_table('memory').to_pandas()
print(df[df['id']=='guide_netops_netbox_naming_convention'].iloc[0]['text'][:120])
"
# → echoes the body
```

**Talking point**: declarative `*.guide.yaml` is the **version-controlled,
schema-bound, team-shareable** memory path — pairs with R102
conversational ingestion (Ch5) and L1 implicit capture. Per-skill
`references/` (2026-05-13) keeps guides portable across agent
frameworks while OLAV's rglob importer still finds them.

**Goal**: tell OLAV in natural language what to remember; have

```bash

# Case 2 — verify recall

# → answer quotes 'acme-network-ops' from the new rule

# Case 3 — long-doc dual-track (summary guide + N document chunks)

# → reads file, proposes 1× summary + N× chunks, asks user to confirm

# Case 4 — Mermaid topology source
olav --agent core <<'EOF'
记一下这个拓扑：
graph TD
  R1 -->|eBGP| R3
  R3 -->|iBGP| R4
EOF
# → category=topology, metadata.media_type=mermaid auto-detected
```

**Verification**:
```bash
python -c "
import lancedb
db = lancedb.connect('.olav/databases/memory.lance')
df = db.open_table('memory').to_pandas()
print('usage_guide:', len(df[df.category=='usage_guide']))
print('document:', len(df[df.category=='document']))
print('topology:', len(df[df.category=='topology']))

"
# Expect (post 2026-05-13 references/ migration + 4-case demo):
#   usage_guide      ≥ 22  (was ≥ 13 — count grew with per-skill guides)
#   document         ≥ 8
#   topology         ≥ 1
#   operational_event ≥ 0   (grows over time via L1 capture; weight 0.5)

**HARD HITL**: memory_curator NEVER commits without explicit
confirmation in a SEPARATE user turn after rendering the YAML
preview. "I've reviewed" / "我已审阅" embedded in the initial
request DO NOT count — render preview, wait for next turn.

**Talking point**: R102 closes the third memory load path —
conversational on-ramp completes the trio (L1 implicit / declarative
YAML / NL ingestion). User experience: just talk; no schema to
learn, no CLI to remember.

  Emit a change plan markdown under exports/reports/."

```

**Verification**:
* `execute_sql` against `v_bgp_neighbors_auto` returns rows
* Analyzer emits a structured topology table inside the change plan
  (so downstream renderers can transform it without re-querying)
* Writer subagent polishes the markdown and embeds a Mermaid block
  under `### Diagram` via `render_topology_mermaid` (pure transformer
  — no SQL access from writer, by design)
* `olav --agent netops "list snapshots"` shows new snapshot id
* `inspect_drift_{sql,topology,routing,configs}` available on `analyze`
  for snapshot-vs-snapshot deltas (4 single-tool files, post 2026-05-15 split)

**Talking point**: netops agent has 7+ sub-agents (collect / analyzer
[default] / analyze / sim / investigate / writer / topology /
learner); the analyzer is the dispatcher, sim is Batfish-backed
config-layer eval, writer is a pure-transformer polish stage with
no DB access. Lab/CAB now lives in `olav-ent`.

## Ch7 — Layered fault diagnosis (NEW, 10 min)

**Goal**: validate the L1→L4 layered diagnostic guide
(`troubleshoot_layered_l1_to_l4.guide.yaml`) against injected faults.
Demonstrates that AutoRecall → guide → agent behaviour really
changes ops investigation order.

### 7.1 — Interface shut → BGP Idle (L1 root cause)

```bash
# Inject: shut ge-0/0/0 on R1 → BGP goes Idle, link-down syslog
python /home/yhvh/Olav/scripts/fault/interface_shut.py inject --device R1

# Take fresh snapshot capturing the fault state
olav --agent netops "Take a snapshot of R1"

# Diagnose — agent should hit L1 BEFORE L4 BGP attributes
olav --agent netops "R1 上 BGP 邻居 down 了，帮我排查根因"

# Revert
python /home/yhvh/Olav/scripts/fault/interface_shut.py revert --device R1
```

**Verification — agent followed layered guide**:
* First tool call: `execute_sql` against `v_show_interfaces_terse_auto`
  (L1 check) — NOT `v_bgp_neighbors_auto` first
* Or: `search_logs(host='R1', query='link', hours=2)` for syslog evidence
* Final answer mentions "interface down → BGP Idle is downstream"

### 7.2 — BGP wrong peer IP → Active state (L3 reachability)

```bash
python /home/yhvh/Olav/scripts/fault/bgp_wrong_peer_ip.py inject --device R1
olav --agent netops "Take a snapshot of R1"
olav --agent netops "R1 BGP 邻居 stuck Active，为什么连不上？"
python /home/yhvh/Olav/scripts/fault/bgp_wrong_peer_ip.py revert --device R1
```

**Verification**:
* Agent does `ping`/`show route <peer-ip>` (L3) before BGP attribute
  introspection
* Answer cites layered guide: "BGP Active = TCP 179 not establishing
  → L3 reach failure"

### 7.3 — OSPF area mismatch → Init state (L7 protocol params)

```bash
python /home/yhvh/Olav/scripts/fault/ospf_area_mismatch.py inject --device R1
olav --agent netops "Take a snapshot of R1"
olav --agent netops "R1 OSPF 邻居一直 Init，怎么回事？"
python /home/yhvh/Olav/scripts/fault/ospf_area_mismatch.py revert --device R1
```

**Verification**:
* Agent rules out L1/L2/L3 (interface up + ping OK)
* Then checks OSPF area config — finds mismatch

**Talking point**: this is the proof that memory guides change
agent behaviour. Without `troubleshoot_layered_l1_to_l4.guide.yaml`
in AutoRecall, 27B-dense agents dive straight to BGP attribute
introspection on `BGP Idle` — wasted turns. With the guide
surfaced as top-K, agents follow OSI bottom-up.
