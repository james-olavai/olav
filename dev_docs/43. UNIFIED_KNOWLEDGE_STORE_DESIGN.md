## 一、问题陈述

### 1.1 当前架构：两条死胡同

OLAV 的知识存储分裂为两个完全隔离的子系统：

```
管道 A — Long-Term Memory (自动，不可见)
  AutoCaptureMiddleware
    → LLM 提取 ≤3 条 ≤120 字 fact/decision
    → 存入 LanceDB memory 表
  AutoRecallMiddleware
    → 只搜 memory 表
    → 注入 <relevant-memories> 到 prompt
  用户无法查看、编辑、管理 memory 内容

管道 B — Knowledge Base (手动，无人使用)
  用户手动放文件到 .olav/knowledge/
    → 1024 字符定长切块 (无语义感知)
    → embed 存入 LanceDB kb_chunks 表
  search_knowledge tool
    → 只搜 kb_chunks 表
  实际状态: .olav/knowledge/ 为空，无人使用
```

### 1.2 具体缺陷

| # | 缺陷 | 代码位置 | 后果 |
|---|---|---|---|
| D1 | recall 只搜 memory 表 | `middleware.py:168` `hybrid_search(..., table_name=MEMORY_TABLE)` | 文档知识永远不被 recall |
| D2 | KB search 只搜 kb_chunks 表 | `knowledge/__init__.py:324` `table_name=KB_TABLE` | 运维经验永远搜不到 |
| D3 | 切块无语义感知 | `knowledge/__init__.py:276` `_split_chunks()` 按 1024 char 硬切 | 完整段落被截断 |
| D4 | 无文档目录 | `get_indexed_sources()` scan 10000 行 | 无法快速列出已索引文件 |
| D5 | 删除靠 LIKE '%' | `knowledge/__init__.py:395` `LIKE '%{source_safe}%'` | 误删风险 |
| D6 | 无版本追踪 | 默认模式下重复索引产生重复块 | 数据膨胀 |
| D7 | 用户不可见 | memory 表无导出/浏览功能 | agent 积累的知识是黑箱 |
| D8 | 两套 schema | memory 表有 scope/access_count，kb_chunks 有 source_file/chunk_index | 无法统一搜索 |

### 1.3 核心洞察

**KB 永远是空的，因为没有人会主动写 KB。** 但 agent 已经在通过 AutoCapture 持续积累运维知识——这些知识被锁在 memory 表里，用户看不到，KB search 搜不到。

**解法不是修补两个子系统，而是合并为一个。** Agent 捕获的运维经验就是知识，文档导入只是知识的另一个来源。它们应该在同一张表、同一条搜索路径、同一个管理界面中。

## 二、设计目标

| # | 目标 | 验收标准 |
|---|---|---|
| G1 | 统一存储 | 所有知识（agent 捕获、文档导入、用户手写）存入同一张 LanceDB 表 |
| G2 | 统一搜索 | AutoRecallMiddleware 一次搜索命中所有来源的知识 |
| G3 | 运维即 KB | agent 运行自动积累知识，无需用户手动写 KB |
| G4 | 用户可见 | 用户可以浏览、编辑、确认、删除 agent 积累的知识 |
| G5 | 第三方工具兼容 | 导出为 markdown 文件，Obsidian / Logseq / VS Code 可直接编辑 |
| G6 | 双向同步 | 文件编辑后可同步回 LanceDB（显式命令，非实时） |
| G7 | 知识质量管理 | 通过 confidence + access_count + time_decay 自然淘汰低质量知识 |
| G8 | LanceDB 原生图 | 利用 LanceDB 向量相似度作为隐式图边，tags 共现作为显式图边，不引入外部图引擎 |
| G9 | 知识图谱可视化 | vis.js + Obsidian wikilinks 提供交互式图谱浏览 |

### 不做什么

| 排除项 | 理由 |
|---|---|
| 实时双向同步 | 复杂度过高，显式 export/sync 命令覆盖需求 |
| 内建 KB 浏览 UI | Obsidian + vis.js HTML 做得更好，不重造 |
| 引入 Graphify 作为依赖 | OLAV 的 LanceDB 向量空间比 Graphify 的静态 NetworkX 图更强（见 §11 分析）|
| 构建独立 NetworkX 图 | LanceDB `search_by_vector()` 已经是动态图邻接查询，不需要维护第二份图 |

### 3.2 统一 Schema

在现有 `memory` 表基础上新增三个列：

```python
# 现有列 (保持不变)
("id",           pa.string()),          # UUID: "cap-xxxx" | "doc-xxxx" | "usr-xxxx"
("text",         pa.string()),          # 知识正文
("vector",       pa.list_(pa.float32(), dim)),  # embedding 向量
("category",     pa.string()),          # fact | decision | preference | audit | kb
("scope",        pa.string()),          # global | agent-specific
("metadata",     pa.string()),          # JSON: source_file, chunk_index, importance, ...
("timestamp",    pa.timestamp("us")),   # 最后更新时间
("created_at",   pa.timestamp("us")),   # 创建时间
("access_count", pa.int32()),           # recall 命中次数
("weight",       pa.float32()),         # 时间衰减权重

# 新增列
("origin",       pa.string()),          # NEW: "agent" | "document" | "user" | "audit"
("confidence",   pa.float32()),         # NEW: 0.0-1.0, 知识可靠度
("tags",         pa.string()),          # NEW: JSON array, e.g. '["spine01","bgp","mtu"]'
```

### 3.3 Origin 与生命周期

| origin | 写入方 | confidence 默认值 | 时间衰减 | ID 前缀 |
|---|---|---|---|---|
| `"agent"` | AutoCaptureMiddleware | LLM importance (0.0-1.0) | 正常衰减 half_life=60d | `cap-` |
| `"document"` | `olav kb import` / `olav kb sync` | `1.0` | 不衰减 | `doc-` |
| `"user"` | 用户在文件系统手动创建 | `1.0` | 不衰减 | `usr-` |
| `"audit"` | GuardrailInjector / 失败记录 | `1.0` | 慢速衰减 half_life=365d | `aud-` |

### 3.4 时间衰减策略改进

当前 `apply_time_decay()` 对所有记忆一视同仁。统一后需要差异化：

```python
def apply_time_decay(store, half_life_days=60, weight_floor=0.1):
    memories = store.get_memories(limit=100000)
    
    for mem in memories:
        origin = _get_origin(mem)  # 从 metadata 或 origin 列读取
        
        # 文档和用户知识不衰减
        if origin in ("document", "user"):
            continue
        
        # 审计记录慢速衰减
        if origin == "audit":
            effective_half_life = 365.0
        else:
            effective_half_life = half_life_days
        
        # 高频使用的知识衰减更慢 (access_count boost)
        access_count = mem.get("access_count", 0)
        if access_count >= 5:
            effective_half_life *= 2.0  # 被频繁使用 → 更持久
        
        age_days = _age_in_days(mem)
        new_weight = max(weight_floor, 0.5 + 0.5 * exp(-age_days / effective_half_life))
        store.update_weight(id=mem["id"], weight=new_weight)
```

### 3.5 搜索统一

AutoRecallMiddleware 当前只搜 `memory` 表。统一后 `memory` 表就是唯一知识表，**不需要改 recall 代码**——它已经在搜正确的表。

- `KnowledgeBase.search()` — 被 `hybrid_search()` 替代
- `search_knowledge_lancedb.py` tool — 被 `recall_memory.py` tool 替代

### 4.2 Frontmatter 字段规范

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | export 时必填，新文件可省略 | 省略时 sync 自动生成 |
| `origin` | enum | 否，默认 `"user"` | agent / document / user / audit |
| `category` | enum | 否，默认 `"fact"` | fact / decision / preference / audit / kb |
| `confidence` | float | 否，默认 `1.0` | 0.0-1.0 |
| `scope` | string | 否，默认 `"global"` | 作用域 |
| `created` | ISO datetime | 否，默认当前时间 | 创建时间 |
| `access_count` | int | 否，只读 | export 时写入，sync 时忽略（由系统管理） |
| `weight` | float | 否，只读 | export 时写入，sync 时忽略 |
| `tags` | string[] | 否 | 实体/主题标签 |

```python
def kb_sync(knowledge_dir, dry_run=False):
    """markdown files → LanceDB (差量同步).
    
    同步规则:
    1. 有 frontmatter.id 且 id 存在于 LanceDB
       → UPDATE: text, confidence, tags, category 从文件更新

       → SKIP: 不导入
    """
```

### 7.1 现有 memory 表迁移

现有 memory 表条目需要补填新列：

```python
def migrate_memory_table(store):
    """为现有 memory 条目补填 origin, confidence, tags 列."""
    memories = store.get_memories(limit=100000)
    for mem in memories:
        meta = json.loads(mem.get("metadata", "{}"))
        
        # 推断 origin
        source = meta.get("source", "")
        if source == "auto_capture":
            origin = "agent"
            confidence = meta.get("importance", 0.5)
        elif source == "failure_record":
            origin = "audit"
            confidence = 1.0
        elif source == "network_event":
            origin = "agent"
            confidence = 0.7
        else:
            origin = "user"
            confidence = 0.8
        
        store.update_memory(mem["id"], origin=origin, confidence=confidence, tags="[]")
```

## 十一、LanceDB 原生知识图谱

### 11.1 核心洞察：LanceDB 向量空间就是图

传统知识图谱需要显式构建节点和边。OLAV 不需要——**LanceDB 的向量空间本身就是一个动态知识图谱**：

```
传统图引擎 (Neo4j / NetworkX / Graphify):
  显式构建节点 → 显式构建边 → 静态图 → 查询
  边是预先计算的，每次数据变更需要重建

LanceDB 向量空间:
  每条 memory = 一个节点 (自带 embedding 向量)
  search_by_vector() = 动态邻接查询
  边是按需计算的，永远反映最新数据，零维护成本
```

| 图操作 | 传统图引擎 | OLAV LanceDB 原生 |
|---|---|---|
| 存储节点 | `G.add_node()` | `store.add_memory()` — 已有 |
| 查询邻居 | `G.neighbors(n)` | `store.search_by_vector(mem.vector, limit=K)` — 已有 |
| 边权重 | 静态 `weight` 属性 | `1.0 - _distance` (余弦相似度) — 动态计算 |
| 显式关系 | 需要维护边表 | `tags` 共现查询 — 无需维护 |
| 全局搜索 | 图遍历 | `hybrid_search()` (vector + BM25 + RRF) — 已有且更强 |
| 数据更新 | 重建图 | 写入即更新，搜索自动反映 |

### 11.2 两种边

统一知识表上有两类关系边，都不需要单独的边表：

**隐式边 — 向量相似度（OLAV 已有）：**

```python
# 给定一条 memory，找到语义最相关的 K 条
similar = store.search_by_vector(
    query_vector=mem["vector"],
    limit=5,
)
# 每个 result 都是一条隐式边，weight = 1.0 - distance
# 动态计算，永远反映当前全量数据，零维护
```

**显式边 — Tags 共现（新增）：**

```python
# 给定一个 tag "spine01"，找到所有包含该 tag 的 memory
# LanceDB SQL filter:
results = tbl.search().where("tags LIKE '%spine01%'").limit(100).to_list()
# 这些 memory 之间通过 "spine01" 显式关联
```

**两者互补：**
- 向量相似度发现**语义相关**但用词不同的知识（"MTU 不匹配" ↔ "jumbo frame 问题"）
- Tags 共现发现**实体相关**的知识（都提到 "spine01" 的条目）
- Graphify 只有后者（静态 tag 边），没有前者

### 11.3 图物化（用于可视化）

日常搜索/recall 直接用 LanceDB 查询，不需要物化图。只有在生成可视化时才需要物化：

```python
# src/olav/core/memory/knowledge_graph.py

def materialize_graph(
    store: LanceDBStore,
    similarity_threshold: float = 0.5,
    max_similar_edges: int = 3,
) -> dict:
    """将 LanceDB 隐式图物化为 nodes + edges（用于导出/可视化）.
    
    Returns:
        {"nodes": [...], "edges": [...], "entities": [...]}
    """
    memories = store.get_memories(limit=10000)
    
    nodes = []
    edges = []
    entities = {}  # tag → set of memory ids
    
    for mem in memories:
        # ── Node ──
        nodes.append({
            "id": mem["id"],
            "label": mem["text"][:60],
            "full_text": mem["text"],
            "origin": mem.get("origin", "agent"),
            "category": mem.get("category", "fact"),
            "confidence": mem.get("confidence", 0.5),
            "access_count": mem.get("access_count", 0),
        })
        
        # ── 显式边: tags 共现 ──
        tags = json.loads(mem.get("tags", "[]"))
        for tag in tags:
            entities.setdefault(tag, set()).add(mem["id"])
        
        # ── 隐式边: 向量相似度 ──
        vector = mem.get("vector")
        if vector:
            similar = store.search_by_vector(
                query_vector=vector,
                limit=max_similar_edges + 1,  # +1 排除自身
            )
            for s in similar:
                if s["id"] != mem["id"]:
                    dist = s.get("score", 1.0)
                    if dist < similarity_threshold:
                        edges.append({
                            "source": mem["id"],
                            "target": s["id"],
                            "type": "similar",
                            "weight": round(1.0 - dist, 3),
                        })
    
    # ── 实体节点 + 实体边 ──
    entity_nodes = []
    for tag, mem_ids in entities.items():
        entity_nodes.append({
            "id": f"entity_{tag}",
            "label": tag,
            "type": "entity",
            "reference_count": len(mem_ids),
        })
        for mid in mem_ids:
            edges.append({
                "source": mid,
                "target": f"entity_{tag}",
                "type": "tagged",
                "weight": 1.0,
            })
    
    return {
        "nodes": nodes + entity_nodes,
        "edges": _deduplicate_edges(edges),
        "entities": entities,
    }
```

### 11.4 可选聚类

社区检测只在可视化时有用，且只需要 graspologic 一个调用：

```python
def cluster_knowledge(graph_data: dict) -> dict[int, list[str]] | None:
    """对物化图做 Leiden 社区检测（可选）.
    
    Returns:
        {community_id: [node_id, ...]} or None if graspologic unavailable
    """
    try:
        import networkx as nx
        from graspologic.partition import leiden
    except ImportError:
        return None  # 聚类不可用，降级为无社区分组
    
    G = nx.Graph()
    for n in graph_data["nodes"]:
        G.add_node(n["id"])
    for e in graph_data["edges"]:
        G.add_edge(e["source"], e["target"], weight=e.get("weight", 1.0))
    
    if len(G) < 3:
        return None
    
    partition = leiden(G)  # 一行调用，核心算法在 graspologic 中
    
    # 转换为 {community_id: [node_ids]} 格式
    communities = {}
    for node_id, comm_id in partition.items():
        communities.setdefault(comm_id, []).append(node_id)
    
    return communities
```

### 11.6 Obsidian 导出

直接写 markdown + frontmatter + `[[wikilinks]]`，无需中间格式转换：

```python
def export_obsidian(store: LanceDBStore, output_dir: Path, communities=None):
    """将知识图谱导出为 Obsidian vault."""
    memories = store.get_memories(limit=10000)
    entities = {}  # tag → [memory_ids]
    
    for mem in memories:
        tags = json.loads(mem.get("tags", "[]"))
        for tag in tags:
            entities.setdefault(tag, []).append(mem)
        
        # 确定输出目录 (按 community 或 origin)
        if communities:
            subdir = _community_dir(mem["id"], communities)
        else:
            subdir = mem.get("origin", "agent")
        
        out_path = output_dir / subdir / f"{mem['id']}.md"
        out_path.parent.mkdir(parents=True, exist_ok=True)
        
        # 直接写 markdown — 不经过任何中间 schema
        wikilinks = "\n".join(f"- [[entity_{t}|{t}]]" for t in tags)
        out_path.write_text(
            f"---\n"
            f"id: {mem['id']}\n"
            f"origin: {mem.get('origin', 'agent')}\n"
            f"category: {mem.get('category', 'fact')}\n"
            f"confidence: {mem.get('confidence', 0.5)}\n"
            f"tags: {json.dumps(tags)}\n"
            f"access_count: {mem.get('access_count', 0)}\n"
            f"---\n\n"
            f"{mem['text']}\n\n"
            f"## Related\n{wikilinks}\n"
        )
    
    # 实体索引页
    for tag, mems in entities.items():
        ent_path = output_dir / "_entities" / f"entity_{tag}.md"
        ent_path.parent.mkdir(parents=True, exist_ok=True)
        links = "\n".join(f"- [[{m['id']}]] — {m['text'][:60]}" for m in mems)
        ent_path.write_text(f"# {tag}\n\n{len(mems)} entries reference this entity.\n\n{links}\n")
```

### 11.7 与 Graphify 的关系

Graphify (https://github.com/safishamsi/graphify) 评估结论：**不集成。**

| 维度 | Graphify adapter 方案 | OLAV 原生方案 |
|---|---|---|
| 图的边 | 静态 (tags 共现) | **动态 (向量相似度) + 静态 (tags)** |
| schema 适配 | 250 行 adapter，有损转换 | **零转换，直接读写 LanceDB** |
| 依赖 | graphify + graspologic + networkx | **graspologic (可选)** |
| 数据更新 | 需要重新构建 NetworkX 图 | **写入即更新，搜索自动反映** |
| 导出格式 | 多 (Obsidian/JSON/GraphML/Cypher) | Obsidian + vis.js (按需加) |
| 代码量 | 250 行 adapter + 依赖 ~2000 行 | **~200 行直接代码** |
| 可维护性 | 受 Graphify API 变更影响 | **完全自控** |

**Graphify 的真正价值在 `extract.py`（Tree-sitter AST 抽取）——那恰好是我们不需要的部分。** 它的 build/cluster/export 层都是 thin wrappers，底层是 NetworkX 和 graspologic。OLAV 直接调用底层库比通过 Graphify 绕一圈更简洁。

**保留的未来接口：** 如果将来需要对 `src/olav/` 代码做结构分析，Graphify 的 AST 抽取是有价值的。但这是独立的代码智能功能（`olav graph` 命令），与知识存储无关。

**支持的格式 (via MarkItDown):**

|---|---|---|

| `.pdf` | `markitdown[pdf]` | 保留标题/表格结构 |
| `.docx` | `markitdown[docx]` | Word 文档 |
| `.pptx` | `markitdown[pptx]` | PowerPoint，每页一段 |

| `.html` | 无 (内置) | 网页，保留结构 |
| `.csv` / `.json` / `.xml` | 无 (内置) | 数据文件 |
| `.epub` | 无 (内置) | 电子书 |
| `.zip` | 无 (内置) | 递归处理内部文件 |
| 图片 | `markitdown` + LLM client | OCR + LLM 描述 |
| 音频 | `markitdown[audio-transcription]` | Whisper 语音转文字 |
| YouTube URL | `markitdown[youtube-transcription]` | 字幕提取 |

**导入管道实现:**

```python
def kb_import(file_path: str | Path, chunk_size: int = 1500) -> dict:
    """导入任意格式文件到知识库."""
    path = Path(file_path)
    
    # .md / .txt 直接读取 (不需要 MarkItDown)
    if path.suffix.lower() in (".md", ".txt"):
        text = path.read_text(encoding="utf-8", errors="replace")
    else:
        # 所有其他格式 → MarkItDown → markdown
        from markitdown import MarkItDown
        mid = MarkItDown()  # 可选: llm_client=... 用于图片 OCR
        result = mid.convert(str(path))
        text = result.text_content
    
    if not text or not text.strip():
        return {"status": "error", "message": f"Empty content: {path}"}
    
    # 统一管道: chunk → embed → store
    chunks = smart_chunk(text, file_type=path.suffix.lstrip("."), chunk_size=chunk_size)
    stored = 0
    for i, chunk_text in enumerate(chunks):
        vector = embed_text(chunk_text)
        store.add_memory(
            id=f"doc-{uuid4().hex[:8]}",
            text=chunk_text,
            vector=vector or [0.0] * embedding_dim,
            category="kb",
            origin="document",
            confidence=1.0,
            tags="[]",
            metadata=json.dumps({
                "source_file": str(path),
                "chunk_index": i,
                "total_chunks": len(chunks),
            }),
        )
        stored += 1
    
    return {"status": "success", "file": str(path), "chunks": stored}
```

### 12.4 切块策略详解

替代旧 KB 的 `_split_chunks()` 1024 char 硬切：

```python
def smart_chunk(text: str, file_type: str, chunk_size: int = 1500) -> list[str]:
    """按文档结构切块，而非定长硬切."""
    
    if len(text) < chunk_size:
        return [text]  # 短文件不切
    
    if file_type == "md":
        # 按 ## 标题分块 — 保留文档结构
        sections = re.split(r'\n(?=## )', text)
        chunks = []
        for section in sections:
            if len(section) < chunk_size:
                chunks.append(section)
            else:
                # 超长 section 按段落再切
                chunks.extend(_split_by_paragraphs(section, chunk_size))
        return chunks
    
    elif file_type == "pdf":
        # 已经按页分割 (pdfplumber), 页内按段落
        pages = text.split("=== PAGE ")
        chunks = []
        for page in pages:
            if len(page) < chunk_size:
                chunks.append(page)
            else:
                chunks.extend(_split_by_paragraphs(page, chunk_size))
        return chunks
    
    else:
        # fallback: 按段落 (双换行) 分块
        return _split_by_paragraphs(text, chunk_size)


def _split_by_paragraphs(text: str, max_size: int) -> list[str]:
    """按段落边界切块，尊重自然语义单元."""
    paragraphs = text.split('\n\n')
    chunks = []
    current = ""
    for para in paragraphs:
        if len(current) + len(para) > max_size and current:
            chunks.append(current.strip())
            current = para
        else:
            current += "\n\n" + para if current else para
    if current.strip():
        chunks.append(current.strip())
    return chunks
```

**与旧 KB 的区别：**

| | 旧 KB | 新管道 (MarkItDown + smart_chunk) |
|---|---|---|
| 格式支持 | .md + .pdf (pdfplumber) | 15+ 格式 (via MarkItDown) |
| 切割策略 | 1024 char 硬切 | 按标题/段落边界切 |
| 重叠 | 128 char overlap | 无需 overlap（按语义单元切不会丢上下文）|
| 短文件 | 也会切 (产生 <1024 的尾块) | 不切 (整篇作为一条) |
| 结构保留 | 否 (标题和正文可能被切开) | 是 (MarkItDown 保留标题/表格结构 → `##` 作为分块点) |
| PDF 表格 | pdfplumber extract_text() 丢失表格结构 | MarkItDown 转为 markdown table |

```python
# src/olav/api/routes/kb.py (新增)

from fastapi import APIRouter, Query
from olav.core.memory import get_store

router = APIRouter(prefix="/api/kb", tags=["knowledge"])


@router.get("/nodes")
async def get_nodes(
    origin: str | None = Query(None),
    limit: int = Query(500, le=5000),
):
    """返回知识节点列表."""
    store = get_store()
    memories = store.get_memories(limit=limit)
    
    if origin:
        memories = [m for m in memories if m.get("origin") == origin]
    
    nodes = []
    entities = {}
    
    for mem in memories:
        tags = json.loads(mem.get("tags", "[]"))
        nodes.append({
            "id": mem["id"],
            "label": mem["text"][:60],
            "full_text": mem["text"],
            "origin": mem.get("origin", "agent"),
            "category": mem.get("category", "fact"),
            "confidence": mem.get("confidence", 0.5),
            "access_count": mem.get("access_count", 0),
        })
        for tag in tags:
            entities.setdefault(tag, 0)
            entities[tag] += 1
    
    # Entity nodes
    for tag, count in entities.items():
        nodes.append({
            "id": f"entity_{tag}",
            "label": tag,
            "origin": "entity",
            "access_count": count,
        })
    
    return nodes


@router.get("/edges")
async def get_edges(
    similarity_threshold: float = Query(0.5),
    max_per_node: int = Query(3, le=10),
):
    """返回知识边列表 (向量相似度 + tags 共现)."""
    store = get_store()
    memories = store.get_memories(limit=5000)
    
    edges = []
    
    for mem in memories:
        # 显式边: tags
        tags = json.loads(mem.get("tags", "[]"))
        for tag in tags:
            edges.append({
                "source": mem["id"],
                "target": f"entity_{tag}",
                "type": "tagged",
                "weight": 1.0,
            })
        
        # 隐式边: 向量相似度
        vector = mem.get("vector")
        if vector:
            similar = store.search_by_vector(vector, limit=max_per_node + 1)
            for s in similar:
                if s["id"] != mem["id"] and s.get("score", 1.0) < similarity_threshold:
                    edges.append({
                        "source": mem["id"],
                        "target": s["id"],
                        "type": "similar",
                        "weight": round(1.0 - s["score"], 3),
                    })
    
    return _deduplicate_edges(edges)


@router.get("/stats")
async def get_stats():
    """返回知识库统计信息."""
    store = get_store()
    memories = store.get_memories(limit=100000)
    
    by_origin = {}
    by_category = {}
    for m in memories:
        origin = m.get("origin", "agent")
        by_origin[origin] = by_origin.get(origin, 0) + 1
        cat = m.get("category", "fact")
        by_category[cat] = by_category.get(cat, 0) + 1
    
    return {
        "total": len(memories),
        "by_origin": by_origin,
        "by_category": by_category,
    }
```

```python
async def import_file(file: UploadFile):

    用户从浏览器上传 PDF/DOCX/XLSX/PPTX/MD 等文件,
    后端: MarkItDown 转 markdown → smart_chunk → embed → store.
    """
    tmp_path = Path(f"/tmp/olav_import_{file.filename}")
    tmp_path.write_bytes(await file.read())
    
    try:
        result = kb_import(tmp_path)
        return result
    finally:
        tmp_path.unlink(missing_ok=True)

@router.put("/entries/{entry_id}")
async def update_entry(entry_id: str, body: EntryUpdate):
    """编辑知识条目 — 远程替代 Obsidian 中的文件编辑."""
    store = get_store()
    vector = embed_text(body.text) if body.text else None
    store.update_memory(
        entry_id,
        text=body.text,
        tags=json.dumps(body.tags),
        confidence=body.confidence,
        vector=vector,
    )
    return {"status": "updated", "id": entry_id}

@router.post("/entries/{entry_id}/promote")
async def promote_entry(entry_id: str):
    """晋升: agent 捕获 → 用户确认 (停止衰减, confidence=1.0)."""
    store = get_store()
    store.update_memory(entry_id, origin="user", confidence=1.0)
    return {"status": "promoted", "id": entry_id}
```

### 14.3 实现：`olav kb watch`

```python
# src/olav/cli/commands/kb.py — watch 子命令

def kb_watch(knowledge_dir: Path, open_obsidian: bool = False, interval: float = 2.0):
    """双向文件监听: Obsidian ↔ LanceDB 自动同步.
    
    方向 A (LanceDB → 文件):
      - 每 interval 秒检查 LanceDB 是否有新 capture
      - 新条目自动写入 .olav/knowledge/{origin}/{id}.md
      - Obsidian 会自动检测到新文件并显示
    
    方向 B (文件 → LanceDB):
      - 监听 .olav/knowledge/ 目录的文件变更 (inotify/kqueue)
      - 文件修改 → 重新 embed + 更新 LanceDB
      - 文件删除 → 从 LanceDB 删除
      - 新文件创建 → embed + 导入 LanceDB
    """
    import time
    from watchdog.observers import Observer  # pip install watchdog
    from watchdog.events import FileSystemEventHandler
    
    store = get_store()
    
    # ── 方向 B: 文件 → LanceDB (via watchdog) ──
    class KBFileHandler(FileSystemEventHandler):
        def on_modified(self, event):
            if event.src_path.endswith(".md") and not _is_generated(event.src_path):
                _sync_file_to_lancedb(event.src_path, store)
        
        def on_created(self, event):
            if event.src_path.endswith(".md") and not _is_generated(event.src_path):
                _import_file_to_lancedb(event.src_path, store)
        
        def on_deleted(self, event):
            if event.src_path.endswith(".md") and not _is_generated(event.src_path):
                _delete_from_lancedb(event.src_path, store)
    
    observer = Observer()
    observer.schedule(KBFileHandler(), str(knowledge_dir), recursive=True)
    observer.start()
    
    # ── 初始 export ──
    kb_export(knowledge_dir)
    
    # ── 可选: 打开 Obsidian ──
    if open_obsidian:
        _open_obsidian_vault(knowledge_dir)
    
    # ── 方向 A: LanceDB → 文件 (polling) ──
    last_check = datetime.now(UTC)
    try:
        while True:
            time.sleep(interval)
            new_memories = _get_memories_since(store, last_check)
            if new_memories:
                for mem in new_memories:
                    _write_memory_as_markdown(mem, knowledge_dir)
                last_check = datetime.now(UTC)
    except KeyboardInterrupt:
        observer.stop()
    observer.join()


def _open_obsidian_vault(knowledge_dir: Path):
    """通过 obsidian:// URI scheme 打开 vault."""
    import subprocess, sys
    vault_name = "olav-knowledge"
    uri = f"obsidian://open?vault={vault_name}"
    
    if sys.platform == "linux":
        subprocess.Popen(["xdg-open", uri])
    elif sys.platform == "darwin":
        subprocess.Popen(["open", uri])
    elif sys.platform == "win32":
        subprocess.Popen(["start", uri], shell=True)
```

## 十五、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Schema 迁移导致现有 memory 数据丢失 | 高 | Phase 1 只加列（有默认值），不改现有列。迁移前自动备份 .lance 目录 |
| AutoCapture tags 提取质量差 | 中 | Tags 是增值信息，不影响 text/vector 搜索质量。质量差只影响 entity 索引页和图谱 |
| sync 删除逻辑误删未导出的新 capture | 高 | 只删 metadata._exported=true 的条目。未导出过的条目不受 sync 影响 |
| kb_chunks 迁移后旧代码仍引用旧表 | 中 | Phase 4 在所有引用清理完毕后才删表。保留一个版本周期 |
| LanceDB 单表行数增长影响搜索性能 | 低 | 文档规模 (千-万级行) 在 LanceDB 承受范围内。百万级行才需要考虑分片 |
| graspologic 不可用 | 低 | 可选依赖。不可用时跳过 Leiden 聚类，按 origin 分组代替 community 分组 |
| Leiden 对少量节点 (<50) 聚类效果差 | 低 | 设最小节点数阈值，低于时跳过聚类 |
| 图物化对大量 memory (>5000) 的 O(n×K) 向量查询开销 | 中 | 物化是离线操作 (`olav kb graph`)，不影响在线 recall。可设 `--limit` 参数 |
| 用户不用 Obsidian | 低 | `olav kb graph` 提供 vis.js HTML (浏览器)；`olav kb report` 提供终端报告 |
