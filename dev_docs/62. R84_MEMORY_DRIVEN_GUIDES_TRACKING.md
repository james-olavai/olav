## Writer-subagent regression — investigation (2026-04-26)

### Symptom

C4-topo bench:
* Phase 1.5 N=5 (05:25): file landed 5/5 → correctness 100%
* Phase 1.5b N=5 (06:46): file landed 0/5 → correctness 0%
* Pristine `a6d3437` retest (16:55): file landed 0/5 → reproduces

Same code, same demo, same model.  Failure boundary is not flaky-noise; once the demo enters the broken state, it stays broken across retries.

### What's happening (verified via `--verbose` trace)

Orchestrator path is intact:
1. Memory recall surfaces the right 3 guides (`topology_visualization` + `save_artifact` + `simulation_what_if`) at distances 0.41 / 1.15 / 1.42 — all inside any reasonable threshold.
2. Orchestrator pulls L2 links, builds the Mermaid diagram, calls `olav_delegate(subagent_name="writer", task_description="report_type: topology_diagram\n<json>")`.

Writer subagent boots correctly:
```
INFO ✓ SubAgent 'writer' (5 tools): ['web_search', 'recall_memory',
                                      'execute_sql', 'format_and_export',
                                      'read_file']
INFO Injected 7 static_context file(s) from writer
```

So writer has `format_and_export` available and the `topology_diagram.md` reference is in its system prompt.

But: in failing runs, writer's response to the orchestrator is just the Mermaid block + summary table as **text** — no `format_and_export` tool call, no file path returned.  The orchestrator then prints what writer returned and stops.

### Why the safety net (SaveAssertion) doesn't catch this

`src/olav/plugins/middleware/save_assertion.py:114` `_looks_like_save_claim` is the cheap pre-filter.  In the failing runs the orchestrator's final message is the Mermaid + table — **no "saved to" / "saved as" / "保存到" phrase**.  Pre-filter returns False; SaveAssertion exits early; no recovery.

There's also `_SAVE_DELEGATIONS = {"writer", ...}` at `:96` which counts the orchestrator's `olav_delegate("writer", ...)` call as save-evidence.  Even if the pre-filter fired, this rule would trust the delegation regardless of whether writer actually saved.  Two-layer hole.

### Root cause

Writer is a small-model agent (grok-4.1-fast inherits the orchestrator's tier).  Its prompt + reference both say "ALWAYS call format_and_export — never only display in chat" — but small models drop tool calls when they can answer in text alone.  The 5/5 success in Phase 1.5 N=5 was a lucky streak; the 0/5 failure is the unlucky streak of the same coin.

Why "environmental" looks correlated with re-priming: re-prime adds new `query_pattern` / `schema_knowledge` rows.  These don't displace usage_guide hits (we verified — guides still top-3 in diversifier output) but they DO compete for top-13 slots overall.  The injected `<relevant-memories>` block grows, and writer (which inherits the orchestrator's recall middleware) sees a longer block, which biases the small model toward "answer in text" over "call tool" — same general pattern as Phase 1's wall-clock cost.

### Fix candidates (none committed yet)

| approach | effort | trade-off |
|---|---|---|
| **A**: extend SaveAssertion — when delegation to writer happened but the orchestrator's final message contains a Mermaid block AND no path, run the auto-recovery path (`_extract_mermaid` + direct `format_and_export`) | small (~30 LOC) | safety net catches all writer failures; doesn't fix writer itself |
| **B**: orchestrator-level post-check — after `olav_delegate(writer)` returns, scan the result for a path; retry once if missing | medium | doubles the writer call cost on failure; still relies on writer to eventually comply |
| **C**: bypass writer for "save mermaid" path — orchestrator calls `format_and_export` directly when topology_visualization guide is the top recall hit | medium-large | violates the "writer owns file writes" architecture; ad-hoc per intent |
| **D**: stronger model for writer | trivial config | costs $$$, makes write path slow, doesn't address the core "small models drop tool calls" issue |
| **E**: shrink writer's recall block (skip injection on writer's turn) | small | recall middleware already has `_should_skip_for_budget` for ARCH-19; just gate it on subagent_name |

**Recommendation**: A (deterministic safety net) + E (shrink writer's recall) together.  A is the immediate user-facing fix; E is the architectural improvement that should unblock the broader "writer skips tool calls" pattern.

## Writer-subagent regression — FIX (2026-04-26, `24778df`)

### Approach taken

Approach **A** from the investigation: extend `SaveAssertionMiddleware` so its pre-filter ALSO triggers when:

1. The orchestrator delegated to a save-owning subagent (writer / audit-auditor / ops-lab), AND
2. The final assistant content has a recoverable artifact (Mermaid block / report-shaped Markdown).

In `_save_evidence_in_history`, the unconditional trust on `olav_delegate(writer)` was tightened: a delegation only counts as evidence when the corresponding `ToolMessage` result contains a path-shaped string.  Bare delegation (writer skipped the tool call) no longer trusted.

When recovery runs, the helper extracts the Mermaid block from the orchestrator's printed message and writes it directly to `exports/diagrams/recovered_<ts>.mmd` — same path the writer would have used had it called `format_and_export`.

### Code changes

`src/olav/plugins/middleware/save_assertion.py`:
* New `_DELEGATION_RESULT_PATH_RE` regex
* New helper `_delegation_result_has_path(messages, tool_call_id)`
* New helper `_delegated_to_writer(messages)`
* Tightened `_save_evidence_in_history`'s `olav_delegate` rule
* `aafter_agent` pre-filter now `claim or (delegated and recoverable)`
* Recovery note phrasing distinguishes claim-path vs delegate-path failures

### CC-1b: structural diagnosis — query_pattern starvation (2026-04-26)

**Investigation finding**: probed the diversifier directly for Q3
("Which interfaces are down across all devices?") on demo6 with
21 captured query_patterns in LanceDB (5 of them Q3-specific).
Result:

```
diversifier returned 13 memories — by category:
  {'schema_knowledge': 5, 'value_distribution': 5, 'usage_guide': 3}
query_pattern hits: 0
```

`_CATEGORY_QUOTAS` (`src/olav/core/memory/middleware.py:195`) reserves
**5 schema + 5 value + 3 usage_guide = 13 slots** — exactly fills
the large-tier `recall_top_k=13`.  `query_pattern` has NO quota and
the diversifier's Pass 3 (global ranking fill) never runs because
the limit is already saturated by Pass 2.

**Implication**: captured SQL templates from `query_pattern_capture`
**never reach the agent prompt**.  The agent re-discovers query
strategies every run, with no learning between sessions.  The
+113%/+167% Q2/Q3 spike is **pure model variance** — today's agent
fragments the SQL across 6 views; postfix's agent did one UNION.

Today's manual Q3 trace (8 tool calls):
```
🔧 execute_sql({'sql': "SELECT device_name, interface, status, proto, ..."})       # v_show_interfaces_status_auto
🔧 execute_sql({'sql': "SELECT device_name, interface, admin_state, ..."})         # v_show_interfaces_terse_auto
```

The agent saw 5 schema_knowledge entries about interface views and
queried each individually — exactly what `query_pattern` retrieval
should have prevented.

**Real fix candidates**:

* **A — re-quota** (smallest, most surgical):
  ```python
  _CATEGORY_QUOTAS = {
      "schema_knowledge": 4,    # was 5
      "value_distribution": 4,  # was 5
      "query_pattern": 2,       # NEW
      "usage_guide": 3,
  }
  # Total: 13 (unchanged)
  ```
  Trade-off: lose 1 schema + 1 value slot to gain 2 query_pattern slots.
* **B — bump top_k**:
  ```python
  _CATEGORY_QUOTAS["query_pattern"] = 3
  recall_top_k: 13 → 16
  ```
  Trade-off: +3 entries × ~300 chars ≈ +900 tokens per turn.

Recommendation: **A** — preserves the existing token budget and
gives query_pattern a guaranteed 2-slot foothold.  query_pattern
entries are cheap (single SQL line each, ~150 chars), so 2 slots
is enough for the bench's 6 query intents.

CC-1b is the bigger discovery from this investigation than CC-1
itself.  Filed as next priority.

* Q1/Q2 saw their captured pattern → fewer calls + correctness.

**Architectural finding** (drives R85 below):

Writer is not the only delegation target: ops-analyze (sim, drift) and ops-lab (config save) have the same shape.

**Verdict**: CC-1c is a real fix for query_pattern starvation (Q2 evidence) but exposes a deeper architectural issue.  Ship it, then refactor.

## R85 candidate — Inline-save refactor (proposal δ)

**Insight from user**: cross-agent delegation as a save-bottleneck was a workaround for unreliable small-model multi-step.  Now that memory works, it's an unnecessary middle layer that creates the memory-poisoning vector seen in CC-1c.

**Proposed direction**:

1. Make `format_and_export` a **shared core tool** instead of writer-only.  Add to ops/audit/lab agents' SKILL.md tool list.
2. Convert writer's 7 reference docs (`device_table.md`, `topology_diagram.md`, …) into a new memory category `format_guide` (one entry per report_type).
3. Add `format_guide: 1` to `_CATEGORY_QUOTAS` (borrow 1 slot from schema_knowledge).
4. Rewrite the 4 ops `*.guide.yaml` so the workflow is **single-step inline-save**:
   * Old: "delegate to writer with `report_type: topology_diagram`"
   * New: "call `format_and_export(data, format='mmd', subdir='diagrams')`"
5. Simplify `SaveAssertion`: drop `_SAVE_DELEGATIONS` writer entry, keep claim-detection as the only trigger.
6. Demote `writer` to optional **polish/edit subagent** (its original spec) — invoked only on user "润色" / "edit this report" intents, not as a save bottleneck.

**Expected outcomes**:
* `query_pattern_capture` captures a single-agent multi-tool sequence faithfully → re-injection of the captured pattern teaches the **correct** full workflow → C4-topo correctness back to 100% with fewer total calls.
* SaveAssertion's auto-recovery becomes a true safety net rather than the primary save mechanism.
* Eliminates one cross-agent indirection per save → demo wall-clock drop.
* Aligned with `dev_docs/200`: memory + format references = "users inject experience" — including format conventions.

**Risks**:
* Migration scope: every agent that delegates to writer needs SKILL.md tools update + corresponding guide rewrite.
* Test coverage: spreading file-write across N agents = N paths to verify.
* Existing workflows (ops audit reports, lab config saves) need migration.

To start when CC-1c is committed.
