## Chapter 1: Fresh Install — Zero to Web UI in 5 Minutes

**Goal:** Install → 自动建用户 → Web 登录 → 首次查询。

```bash
# 1. Clean environment
mkdir ~/olav-demo && cd ~/olav-demo
python3 -m venv .venv && source .venv/bin/activate

# 2. Install OLAV (~150s)
pip install olav==0.14.0

# 3. Initialize — 自动创建 admin 用户 + token + 启动服务
olav init
# Expected output (v0.14 新增):
#   ✓ platform ready: .olav scaffolding created
#   ✓ Admin user 'alice' created (from $USER)
#   ✓ Token → ~/.olav/token
#   ✓ auth.mode set to 'token'
#   ✓ Web login: http://localhost:2280/?token=olav_xxx

# 4. Configure LLM API key
nano .olav/config/api.json
# Edit: set "shared.api_key" to your LLM provider key

# 5. Start services
olav service start --all
# Expected:
#   ✓ web    → http://localhost:2280
#   ✓ daemon → Unix socket (agent pre-warmed)
#   Syslog receiver (optional): olav service logs start --port 5514

# 6. Web 登录（浏览器）
# 访问 http://localhost:2280/?token=olav_xxx → 自动 cookie → 进入 UI
# 或访问 http://localhost:2280 → /login 页面 → 输入 token

# 7. Install NetOps skill
olav skill install /path/to/olav-netops/
# Expected: installed ops v0.14.x → .olav/workspace/ops/
#   ✓ PLATFORM.md auto-refreshed (olav refresh triggered)

# 8. Verify
olav list
# Expected: core, ops, quick, config, audit, devops, infra visible
```

**Talking point:** `olav init` 一步完成：目录结构 + admin 用户 + token + auth 模式。`olav skill install` 后自动 `olav refresh` 更新全局 agent 路由表。

## Chapter 2: Network Discovery — SSH Collection Pipeline

**Goal:** 从零数据到全网采集。

```bash
# Device inventory
cp .olav/workspace/ops/probe/config/nornir/hosts.yaml.example \
   .olav/workspace/ops/probe/config/nornir/hosts.yaml
nano .olav/workspace/ops/probe/config/nornir/hosts.yaml

# SSH dependencies
pip install nornir nornir-netmiko

# Dry-run
olav --agent ops "/netops_init --dry-run"
# Expected: ✓ Devices: 6, Commands: 14, SSH NOT executed

# Full collection
olav --agent ops "/netops_init"
# Pipeline: SSH → TextFSM → staging JSON → IngestManager.bulk_load() → topology ETL
# Expected: 72+ rows in parsed_outputs, topology_links ≥ 4 links
```

**⏱** ~2s dry-run, ~15s full collection

**Talking point:** `/netops_init` 走完整管道：SSH 并行采集 → TextFSM 解析 → staging JSON → IngestManager 原子入库 → LLDP/CDP 拓扑自动提取。

## Chapter 3.5: Knowledge Base — 运维即知识库 (v0.14 新增)

**Goal:** 导入文档 → agent 自动召回 → Obsidian 图谱可视化。

### Import & Search

```bash
# 导入运维手册
olav kb import ~/docs/bgp-runbook.md
# Expected: ✓ 1 entry added (origin=document, confidence=1.0)

# 验证入库
olav kb status
# Expected:
#   Total entries: 1536
#   By origin: agent 233, document 1303

# 自然语言搜索（统一搜索 agent 经验 + 导入文档）
olav kb search "BGP failover procedure"
# Expected: 结果包含 document + agent 来源

# Agent 自动召回知识
olav "我们的 BGP 故障切换流程是什么?"
# Expected: agent 通过 recall_memory 搜索 KB，引用导入文档回答
```

### Export & Visualize

```bash
# 导出为 Obsidian vault
olav kb export
# Expected: .olav/knowledge/ 目录生成：
#   agent/cap-xxx.md      — agent 运维经验（含 tags + [[wikilinks]]）
#   document/kb-xxx.md    — 导入文档
#   _entities/entity_bgp.md — 实体索引页

# 生成知识图谱
olav kb graph
# Expected: .olav/knowledge/_graph.html (vis.js 交互式图谱)
# 浏览器打开 → 看到 nodes + edges（向量相似度隐式边 + tags 显式边）

# 双向同步 — 在 Obsidian 中编辑后同步回 LanceDB
olav kb sync --dry-run
# Expected: inserted=0, updated=0 (如果没改文件)
```

**Talking point:** OLAV 的知识不需要手动写 — agent 运行自动积累运维经验。`olav kb export` 导出为 Obsidian vault，团队可以用任何 Markdown 编辑器浏览和编辑，然后 `olav kb sync` 同步回来。LanceDB 向量空间就是知识图谱。

## Chapter 4: Ops Agent — Deep Analysis & Simulation

**Goal:** 多 agent 编排 + 确定性模拟。

### Topology

```bash
olav --agent ops "Show the network topology as a Mermaid diagram and save to exports/"
# Expected: Mermaid graph with R1-R4, SW1-SW2, color-coded by tier
```

### What-If Simulation

```bash
olav --agent ops "Simulate R3 losing all links. What's the blast radius?"
# Expected: Dijkstra on real topology, blast radius computed, affected paths listed
```

### Drift Detection

```bash
# Baseline → change → diff
olav --agent ops "Take a snapshot of R2 with show running-config"
# (make a config change on R2)
olav --agent ops "Take another snapshot of R2 with show running-config"
olav --agent ops "Compare the last two snapshots of R2"
# Expected: diff shows added/removed config lines
```

**Talking point:** Analysis agent 写 Python 跑 Dijkstra — 数学计算不是 LLM 推理。Diff 走完整管道：take_snapshot → IngestManager → diff_sql_state。

## Chapter 9: Write Security — Multi-Layer Enforcement

**Goal:** 7 层独立安全防线。

```bash
# Layer 1: readonly service — permanently blocked
olav --agent infra "Write to InfluxDB"
# → hard_block: readonly_only=true

# Layer 2: API write — blocked by default
olav --agent infra "Update R1 in NetBox"
# → blocked: pass --enable-api-write

# Layer 3: HITL approval
olav --agent infra "Update R1 in NetBox" --enable-api-write
# → Approve? [y/N]

# Layer 4: SSH write — hard block
olav --agent ops "Push BGP config to R1"
# → hard_block: SSH write not supported

# Layer 5: Sandbox network isolation
olav --agent ops "Use run_python_simulation to POST to http://192.168.100.101"
# → hard_block: outbound network blocked in sandbox
```

## Chapter 10: Syslog — Infrastructure Log Search (v0.14 新增)

**Goal:** 接收基础设施日志 → agent 自然语言查询。

```bash
# 启动 syslog 接收器
olav service logs start --port 5514
# 配置设备/Linux 服务器发送 syslog 到 <olav-ip>:5514

# 等待几分钟收集日志后...
olav "最近一小时有哪些 critical 级别的 syslog?"
# Expected: agent 调用 search_logs tool → 查询 Parquet → 返回日志内容

olav "今天哪些设备发送了最多的 syslog?"
# Expected: 按 host 分组统计
```

**Talking point:** Syslog 是平台核心能力 — 不只是网络设备，Linux 服务器、UPS、防火墙都可以发日志到 OLAV。`search_logs` 是 core skill，任何 agent 都能查。

## Chapter 11: Multi-User Collaboration (v0.14 新增)

**Goal:** 团队协作 — 共享数据，隔离会话。

```bash
# Admin 添加团队成员
olav admin add-user bob
# Expected: ✓ Linux user 'bob' verified
#           ✓ Token: olav_abc123 (bob 需存入 ~/.olav/token)

# Bob 使用 CLI（自动读 ~/.olav/token）
su - bob
olav "R1 有几个 BGP 邻居?"

# Bob 的 session 列表
olav sessions
# Expected: 列出 bob 的 session（不含 alice 的）

# Admin 看所有 session
olav sessions --all
# Expected: 列出所有用户的 session

# Session 跨界面恢复
# Bob 在 CLI 开始对话 → 在 Web 继续
olav --resume <thread_id> "继续上次的分析"
```

**Talking point:** 数据和知识团队共享（每个人查到的是同一份设备/拓扑/BGP 数据），但会话隔离（我的对话只有我能看到，admin 除外）。
