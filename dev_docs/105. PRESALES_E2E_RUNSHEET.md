**Status**: Runsheet + validation log

**Companion to**: [101. MINI_DEMO_RUNSHEET](101.%20MINI_DEMO_RUNSHEET.md) (netops mini demo)

The full presales pipeline, end to end, on a **real public IT tender**:

```
surveyor (ingest) → analyst (requirement analysis + tech/device selection)
   → [HITL approve → confirmed requirements] → architect (HLD)
   → engineer (LLD + validation) → publisher (deliverables)
```

Everything below ran on **`gemma4-31b`** (a local ~30B model) — no frontier model.
This runsheet is both the reproducible script (numbered steps + pass criteria)
and the validation log of the real run (§Validation).

---

## Setup (off camera)

- **LLM backend**: `gemma4-31b-agent` at an OpenAI-compatible endpoint
  (`http://192.168.100.12:11433/v1`), `reasoning=off`, `ctx-size≥65536`,
  `llm.timeout: 600`.
- **Embedder**: local Ollama `embeddinggemma` (768-dim) at
  `http://192.168.100.50:11434` (`OLAV_EMBEDDING_MODE=local` / API).
- **Packages**: `olav` + `olav-netops` + `olav-presales` installed
  (`olav init && olav agent install olav-presales`).
- **HITL**: `--dangerously-skip-permissions` bypasses approval gates for the
  automated run; a real engagement keeps them on.
- **Automated e2e** is gated `PRESALES_RUNSHEET_ENABLED=1`; each agent turn is
  bounded + the process TREE is killed on timeout (orphaned grandchildren hold
  the DuckDB lock and cascade-block the next turn).

## The tender (real, public)

**Pershing County (NV) — 2019 Network Infrastructure RFP.** A county-government
multi-site network modernization: **10 locations** interconnected today by
site-to-site IPSec VPNs; aging **Cisco ASA 5500** firewalls + **ISR** routers +
HP/Netgear switches to refresh; four server rooms; **VLAN + QoS + strict
inter-VLAN** security required; **1 Gb** internet / **10 Gb** internal; fiber or
fixed-wireless site interconnect. 26 pages, extracted to
`extracted/RFP-network-infra.md`.

> A genuine public procurement document — used to prove the pipeline handles
> real, messy tender prose, not a hand-tuned fixture. `network_type = campus`
> (per-site LAN with VLAN/QoS/segmentation dominates; the multi-site interconnect
> is a WAN dimension of the HLD).

## Runsheet

### Step 0 — project + ingest
```bash
olav --agent presales "project new pershing --customer 'Pershing County IT' --region US"
# drop the tender PDF in .olav/presales/projects/pershing/input/ ; surveyor
# convert_documents produces extracted/*.md (Docling). Here the text was
# pre-extracted (Docling optional in this env).
```
**Pass**: project active (`region=US`), `extracted/*.md` present.

### Step 1 — requirement / tender analysis  → `task("analyst")`
```
"分析 pershing 招标需求 (network_type=campus)：做需求分析，列出合规矩阵与阻塞缺口。"
```
Analyst runs `analyze_tender(network_type="campus")`.
**Pass**: compliance matrix over the campus dimensions (sites/scale/redundancy/
ip_space/segmentation/vendor); `blocks_topology_open` lists the real gaps;
`ready_for_hld=false` while blocking dims are unconfirmed.

### Step 2 — technology + device selection  → `task("analyst")`
```
"做技术选型 (compare_approaches) 和设备选型 (select_devices)，生成完整选型报告。"
```
Analyst runs `compare_approaches` + `select_devices` (region US → NDAA
eligibility) + `generate_selection_report`.
**Pass**: report at `exports/selections/SELECTION_pershing.md` with an approach
comparison + a device matrix (chosen + alternates) + any excluded-with-reason;
`complete=true`.

### Step 3 — HITL approve → confirmed requirements (the bridge)
On approval each resolved dimension is persisted so the architect's gap analysis
sees it:
```
record_design(kind="requirement", dimension=<...>, value=<...>, status="confirmed")
```
**Pass**: `presales.requirements` has the confirmed dimensions; the architect's
`inspect_requirements` no longer reports them missing.

### Step 4 — HLD  → `task("architect")`
```
"为 pershing 起草 HLD (network_type=campus)：开 design run，做三桶 gap 分析，
 提出章节骨架，逐章起草（每个决策带 WHAT+WHY+来源），最后 finish_hld。"
```
Architect: `create_design_run(hld)` → `inspect_requirements` → `propose_structure`
→ chapter loop (`query_project_docs` grounding + `record_design(kind="decision")`)
→ `finish_hld(constraints={...})`.
**Pass**: an HLD document with the expected chapters (context, requirements,
logical topology, addressing, security/segmentation, …); decisions carry a
rationale; `design_runs.phase = hld_approved` with a structured constraint set.

### Step 5 — LLD  → `task("engineer")` (validation-driven, dev_docs/106)
```
"根据 HLD 约束为 pershing 生成 LLD：为 Lovelock 中心机房路由核心设计一个
 topology-agnostic skeleton（devices+roles、links、p2p/loopback 池、routing.asn
 按 RFC 7938），用 generate_lld 一次产出并落库；再 inspect_topology_health 校验。"
```
Engineer **designs a generic skeleton** grounded in the references (RFC 7938 ASN
scheme, oversubscription sizing), then `generate_lld(skeleton=…, output_filename=…)`
self-writes the LLD, computes the exact IP/BGP allocation, and **persists the
structured `to_be` topology**. Validation = **networkx** (`inspect_topology_health`)
— presales's only rung. NO Batfish in presales (dev_docs/106 — config-layer
validation is netops implementation).
**Pass**: `exports/designs/LLD_pershing.md` with IP allocation + BGP matrix +
interface spec + reversibility + an **inline Mermaid topology**; `topology_nodes`
carry `loopback_ip`/`bgp_asn`, `topology_links` carry `source_ip`/`destination_ip`
(the structured, field-aligned handoff); networkx health connected/redundant.

> **Scope**: the LLD path is **topology-agnostic** (skeleton-driven) — not a
> spine-leaf-only generator. For this campus/WAN tender it instantiates the
> **Lovelock hub routed core** as a small fabric (server rooms + 10 Gb internal);
> the same path serves 3-tier/hub-spoke. Deployment (config synthesis / Batfish /
> lab) is out of scope — the structured LLD hands off to netops (dev_docs/106).

### Step 6 — deliverables (optional)  → `task("publisher")`
```
"生成 dossier + BOM，导出 HLD/LLD 为 docx/PDF。"
```
**Pass**: `wiki/` dossier + BOM; `render_deliverable` ok / `needs_pandoc`.

### Step 2 — technology + device selection ✅ (device caveat)
`SELECTION_pershing.md` written with all three approach matrices, scored +

- **dc_fabric → Spine-Leaf (Clos)** (39 vs 27)
- **underlay_routing → eBGP** (37 vs OSPF 28 vs IS-IS 27)
- **wan_connectivity → SD-WAN** (40 vs MPLS 27) — the right call for a 10-site
  county interconnect.
- **Device selection (re-run 2026-07-23, post-merge — now works)**: with the

  **core → Cisco C9500-48Y4C** (3200 Gbps, 48p; Aruba CX-8360 alt),

### Step 3 — HITL approve → confirmed requirements ✅
Simulating the reviewer's approval, the six dimensions were persisted with

knowledge bridge (dev_docs/104 §5) closed on real data.

### Step 4 — HLD ✅
Agent routed → `task("architect")` → `create_design_run(hld)` →
`inspect_requirements(campus)` (ready) → chapter drafting with
`record_design(kind="decision")` → `finish_hld(constraints={…})` →
`format_and_export`. Result:
- **run_id** `run-aa1b8087cc24` (re-run 2026-07-23), **`design_runs.phase =
  hld_approved`** with a structured constraint set; decisions recorded.
- **HLD** at `exports/reports/pershing_hld.md` — an 8-chapter document:
  Executive Summary · Business Requirements · Logical Topology · Physical
  Topology · Redundancy & HA · Address Planning · Segmentation & Policy · Risks
  & Constraints.
- **Design judgement**: the architect chose a **3-tier hierarchical core + star
  WAN topology + collapsed-core at remote sites** — contextually *better* for a
  10-site county than the analyst's generic spine-leaf recommendation. This is
  the dev_docs/104 §12 Q4 boundary in action (analyst proposes; architect grounds

  architect refine the topology decision rather than blindly inherit it.

The engineer designs a **topology-agnostic skeleton** (Lovelock hub core: 2
core-spine + 4 srv-leaf, full mesh, `routing.asn` per RFC 7938) and calls

- **LLD** at `exports/designs/LLD_pershing.md` — 6 devices, 8 P2P /31 links

- **Structured handoff persisted** (dev_docs/106): `topology_nodes` carry
  `loopback_ip` + `bgp_asn` (e.g. core-spine-1 = 10.0.255.1/32, AS 65000;

Real public tender → **all phases green on `gemma4-31b`**: ingest → requirement
analysis → tech/device selection (datasheet-verified, NDAA-excluded) → HLD
(3-tier, approved) → **validation-driven LLD** (networkx-validated, structured

## Known limitations (found by this run — honest)

1. **LLD networkx rung is DB-fed, `generate_lld` does not DB-persist.**
   ✅ **CLOSED**: `generate_lld` now upserts the `to_be` fabric to
   `presales.topology_*` (via `save_topology`) when given a `db_path`; the
   engineer script resolves + passes it. Verified through the real entry point:
   `generate_lld.py` persists 6 nodes/8 links → `inspect_topology_health.py` →
   `connected=True, node_count=6, link_count=8, spof=None, min_degree=2` (a
   healthy redundant fabric — was empty before). Persistence is gated on an
   explicit `db_path`, so direct unit callers never touch a DB.
2. **Device catalog + `select_devices` roles are DC-fabric vocabulary.**
   ✅ **ADDRESSED (2026-07-23)**: added campus `core`/`distribution`/`access`
   devices to `device_catalog.yaml` (Cisco Catalyst 9500/9300, Aruba CX). Re-run
   validated: a campus tender now selects core → Cisco C9500-48Y4C (Aruba alt),
   access → Cisco C9300-48P (+ C9300-48UXM / Aruba alts). Approach selection was
   already vocabulary-agnostic.
3. **LLD generator is spine-leaf-only.**
   ✅ **ADDRESSED (redesign, dev_docs/106)**: the hardcoded spine-leaf generator
   (`plan_fabric`) is **deleted**. The LLD is now **validation-driven +
   experience-grounded**: the LLM designs a topology-agnostic *skeleton* (devices +
   links + addressing + routing.asn) grounded in the reference corpus (RFC 7938 /
   oversubscription); generic deterministic math allocates addresses; and the
   generic simulators (networkx now, Batfish/CLAB next) validate. Spine-leaf,
   3-tier campus, and hub-spoke WAN all use the same path — topology knowledge is
   data (skeleton + references), not Python. Phase 1 (networkx-validated generic
   path) implemented; per-site VLAN/overlay config synthesis is Phase 2/3.
4. **analyst `dc_fabric` decision on a campus tender.**
   ✅ **CLOSED (deterministic)**: added a `campus_topology` decision
   (3-tier / collapsed-core / routed-access, **site-count driven** —
   `{sites:10}→three_tier`, `{sites:1}→collapsed_core`; `_check_applicability`
   honours `min_/max_sites`) AND made the decision set **resolve deterministically
   from `network_type`** — `generate_selection_report` calls
   `decisions_for_network_type()` (map in `design_patterns.yaml`:
   `network_type_decisions`), so a known network_type is **authoritative**: the
   LLM no longer passes `decisions` and cannot get it wrong. Verified through the
   real entry point — the agent passing `decisions=['dc_fabric']` on a `campus`
   tender still produces `{campus_topology: three_tier}`. Removes the soft-steering
   dependency entirely (no N≥3 needed).
