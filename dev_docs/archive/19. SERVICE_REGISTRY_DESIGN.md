# Service Registry — 声明式服务管理 (无 MCP)

> 日期: 2026-03-31
> 依赖: api_registry.py, tool_discovery.py, authz.py, config.py

## 1. 问题

当前 Olav 对外部服务的管理存在以下问题：

1. **连接硬编码**: ContainerLab URL/密码写死在 `lab/config/config.json`，SSH 主机写死在工具代码中
2. **无生命周期管理**: clab-api-server、netbox 等服务需要手动启停
3. **无统一权限**: 谁能操作 lab？谁只能查看 netbox？没有控制
4. **每加一个服务就要手写工具**: netbox 有 200+ API endpoint，手写 @tool 不现实
5. **MCP 过于复杂**: 需要为每个服务维护一个 MCP server 进程，有 stdio/HTTP 传输开销，还要适配 LangChain

## 2. 核心洞察：Olav 已有全部基础设施

```
api_registry.py     →  DuckDB 存储 OpenAPI schema (operations + definitions)
tool_discovery.py   →  自动发现 @tool 装饰函数
authz.py            →  (agent_id, skill_name, action) 权限模型
config.py           →  单例 ConfigLoader，文件 + 环境变量覆盖
auth/               →  可插拔身份提供者 (os/token/ldap/oidc)
```

**缺的只是一座桥**：从 api_registry 中的 OpenAPI schema 自动生成 @tool 函数，
让 tool_discovery 接管，authz 控制权限。不需要 MCP。

## 5. 工具自动生成机制

### 5.1 为什么不是 per-endpoint 生成

Netbox 有 200+ endpoint，ContainerLab 有 30+。如果每个 endpoint 一个 @tool：
- Agent 的 tool list 爆炸，LLM 选择困难
- Token 浪费在 tool schema 描述上
- 大部分 endpoint 永远不会被调用

**grouped 模式**: 将相关 endpoint 合并为一个 @tool，内部路由。

### 5.2 生成的工具结构

```python
# 自动生成: .olav/workspace/ops/tools/_generated/clab.py

from olav.platform.service_registry import service_call, require_service_permission

@tool
def clab_deploy(action: str, topology_yaml: str = "", lab_name: str = "") -> dict:
    """部署或销毁 ContainerLab 拓扑。

    Args:
        action: "deploy" 或 "destroy"
        topology_yaml: 拓扑 YAML 内容 (deploy 时必填)
        lab_name: 实验室名称 (destroy 时必填)
    """
    # 1. 权限检查 (自动注入)
    require_service_permission("containerlab", "clab_deploy", "mutate")

    # 2. 路由到具体 endpoint
    if action == "deploy":
        return service_call("containerlab", "POST", "/api/v1/labs",
                           json={"topologyContent": yaml.safe_load(topology_yaml)})
    elif action == "destroy":
        return service_call("containerlab", "DELETE", f"/api/v1/labs/{lab_name}")

@tool
def clab_query(lab_name: str = "", include_nodes: bool = False) -> dict:
    """查询 lab 状态和节点信息。"""
    require_service_permission("containerlab", "clab_query", "use")

    if lab_name and include_nodes:
        return service_call("containerlab", "GET", f"/api/v1/labs/{lab_name}/nodes")
    elif lab_name:
        return service_call("containerlab", "GET", f"/api/v1/labs/{lab_name}")
    else:
        return service_call("containerlab", "GET", "/api/v1/labs")

@tool
def clab_exec(lab_name: str, node: str, command: str) -> dict:
    """在 lab 节点上执行命令。"""
    require_service_permission("containerlab", "clab_exec", "mutate")

    return service_call("containerlab", "POST", f"/api/v1/labs/{lab_name}/exec",
                       json={"nodeFilter": node, "command": command})
```

### 5.3 service_call 内部流程

```python
def service_call(service_name: str, method: str, path: str, **kwargs) -> dict:
    """统一服务调用入口。"""

    # 1. 从 ConfigLoader 获取服务配置
    svc = service_registry.get(service_name)

    # 2. 健康检查 (如果 lifecycle.managed=true 且服务不健康，尝试启动)
    if svc.lifecycle.managed and not svc.is_healthy():
        svc.start()
        svc.wait_healthy(timeout=30)

    # 3. 认证 (自动获取/刷新 token)
    headers = svc.auth_headers()  # JWT: 自动 login; Bearer: 直接注入; Basic: 编码

    # 4. 发起请求
    url = f"{svc.endpoint}{path}"
    response = httpx.request(method, url, headers=headers, timeout=svc.timeout, **kwargs)

    # 5. schema 感知的响应解析
    #    从 api_registry.operations 查询该 path 的 response_200_def
    #    用 definition schema 验证并提取关键字段 (而非返回全部 JSON)
    operation = api_registry.find_path(service_name, method, path)
    if operation and operation.response_200_def:
        return _extract_by_schema(response.json(), operation.response_200_def)

    return {"status": response.status_code, "data": response.json()}
```

### 5.4 schema 感知的响应提取

这是 api_registry 真正发挥作用的地方：

```python
def _extract_by_schema(data: dict, definition_name: str) -> dict:
    """根据 api_registry 中的 definition schema 提取关键字段。

    目的: Netbox GET /api/dcim/devices/ 返回 50+ 字段,
    但 agent 只需要 name, role, site, primary_ip, status。
    api_registry.definitions 表知道哪些字段是必填的。
    """
    fields = api_registry.field_names(service_name, definition_name)
    required_fields = [f for f in fields if f.required]

    # 优先返回 required 字段，减少 token 消耗
    if isinstance(data, list):
        return [_pick(item, required_fields) for item in data]
    return _pick(data, required_fields)
```

```python
def require_service_permission(service_name: str, tool_name: str, action: str):
    """在 @tool 函数开头调用。"""
    identity = get_current_identity()  # 从 context 获取
    allowed = check_permission(
        role=identity.role,
        agent_id="ops",              # 当前 agent
        skill_name=tool_name,        # clab_deploy, netbox_query_devices
        action=action,               # use, mutate, admin
    )
    if not allowed:
        raise PermissionDeniedError(
            f"用户 {identity.username} (role={identity.role}) "
            f"无权执行 {tool_name}.{action}"
        )
```

## 8. 与 MCP 的对比

| 维度 | MCP | Olav Service Registry |
|------|-----|----------------------|
| 协议 | JSON-RPC over stdio/HTTP | 直接 HTTP 调用 |
| Schema 来源 | MCP server 自己声明 | 服务的 OpenAPI spec (业界标准) |
| Schema 存储 | 内存 (每次启动重新发现) | DuckDB (持久化，可查询) |
| 工具注册 | MCP adapter 层转换 | 直接生成 LangChain @tool |
| 进程模型 | 每个服务一个 MCP server 进程 | 无额外进程，直接 HTTP |
| 权限 | 无 (MCP 不管权限) | 复用 authz.py RBAC |
| 生命周期 | 无 | managed: start/stop/health |
| 响应优化 | 无 (返回全部) | schema-aware 提取关键字段 |
| 可审计性 | 日志 | DuckDB audit_recorder |
| 依赖 | mcp SDK + 每个服务的 adapter | httpx + 现有基础设施 |

**本质区别**: MCP 是通用协议，适合连接任意 AI 工具。Olav 的场景是连接有 OpenAPI spec 的 REST 服务
（ContainerLab、Netbox、Grafana、Oxidized 等），直接用 OpenAPI 比绕道 MCP 更简单、更强。

### 9.1 register 内部流程

```python
def register_service(service_name: str):
    """完整注册流程。"""

    # 1. 读取 services.yaml
    config = load_services_yaml()
    svc = config["services"][service_name]

    # 2. 拉取 OpenAPI spec
    spec = httpx.get(svc["spec_url"]).json()

    # 3. 写入 api_registry (已有能力)
    api_registry.load(service_name, spec)  # 解析 Swagger/OpenAPI → operations + definitions

    # 4. 根据 tool_generation.groups 生成 @tool 文件
    groups = svc["tool_generation"]["groups"]
    code = generate_tool_code(service_name, groups, svc)
    write_file(f".olav/workspace/ops/tools/_generated/{service_name}.py", code)

    # 5. 注册权限规则
    rules = generate_permission_rules(service_name, svc["permissions"])
    save_permission_rules(rules)

    # 6. 验证 (生成的工具是否能被 tool_discovery 发现)
    tools = discover_tools(Path(".olav/workspace/ops/tools/_generated/"))
    expected = {g["name"] for g in groups}
    found = {t.name for t in tools}
    assert expected <= found, f"Missing tools: {expected - found}"
```
