# 46. Agent Boundary Specification — v0.18.0

**Date:** 2026-04-14
**Status:** Implemented (v0.18.0 — 3 agents + tool separation Phase 1)
**Breaking Change:** Yes — 9 top-level agents → 3

---

## Motivation

v0.17.0 has 9 top-level agents registered via `workspace/*/AGENT.md` directory scanning. This creates:
- User confusion (`olav --agent audit-auditor` vs `olav --agent audit`)
- Duplicate standalone copies of subagents (ops-lab = ops/lab, audit-auditor = audit/auditor)
- Config agent tools that belong in core or ops
- Devops/infra agents with no tools (only prompts + references)

## Target Architecture

**3 top-level agents. No standalone shortcuts.**

```
.olav/workspace/
├── core/                    ← Platform core (ships in olav wheel)
│   ├── AGENT.md
│   ├── SKILL.md
│   ├── prompts/system.md
│   └── tools/               14 tools
│
├── ops/                     ← Network operations (ships in olav-netops)
│   ├── AGENT.md
│   ├── SKILL.md
│   ├── prompts/orchestrator.md
│   ├── tools/                8 shared tools
│   ├── analysis/             subagent: simulation, topology
│   ├── probe/                subagent: SSH collection, liveness
│   ├── diff/                 subagent: drift detection
│   ├── lab/                  subagent: ContainerLab digital twin
│   ├── devops/               subagent: script generation (was top-level)
│   └── infra/                subagent: service registry queries (was top-level)
│
└── audit/                   ← Learning & compliance (ships in olav-netops)
    ├── AGENT.md
    ├── SKILL.md
    ├── prompts/orchestrator.md
    ├── designer/             subagent: profile creation + schema learning
    ├── auditor/              subagent: profile execution + reporting
    └── learner/              subagent: /learn_cmd + trace analysis (NEW)
```

## Agent Responsibilities

### core (olav wheel)

**Role:** Platform operations, quick queries, system management.
**Default agent** — `olav "query"` without `--agent` uses core.

**Orchestrator (5 tools — what the LLM sees directly):**

| Tool | Responsibility |
|---|---|
| `execute_sql` | Query DuckDB (schema-aware, dynamic hints) |
| `recall_memory` | Knowledge retrieval (LanceDB) |
| `web_search` | External web search |
| `format_and_export` | Output formatting + file export |
| `olav_delegate` | Delegate to subagents (below) |

**Subagents (via olav_delegate):**

| Subagent | Own tools | Responsibility |
|---|---|---|
| `db_query` | execute_sql, recall_memory, web_search, format_and_export | Complex multi-step database workflows |
| `api_query` | api_request, service_health, web_search, format_and_export | External API queries (NetBox, Grafana, Jira) |
| `remote` | remote_execute, run_shell | SSH to servers, local shell commands |
| `admin` | workspace_health, bulk_ingest, analyze_logs, manage_cron, deploy_service, stop_service, write_workspace_file + more | Platform management |

**Key design:** `execute_sql` and `api_request` are in **different** subagents — LLM cannot confuse them. `run_python_code` removed from core entirely.
All shipped in olav wheel. No netops dependency.

### ops (olav-netops)

**Role:** Network operations — data collection, analysis, change management, lab validation.
**Invoked via:** `olav --agent ops "query"`

**Orchestrator tools (shared, always loaded):**

| Tool | Source | Responsibility |
|---|---|---|
| `execute_cli` | existing (ops root) | SSH command execution |
| `execute_cli_parallel` | existing | Parallel SSH collection |
| `take_snapshot` | existing | Snapshot + auto-ingest |
| `search_commands` | existing | Command discovery |
| `diff_configs` | existing | Quick config comparison |
| `run_python_simulation` | existing | Topology analysis (networkx sandbox) |
| `record_network_event` | existing | Event recording |
| `register_service` | existing | Service registration |

**Subagents (routed by orchestrator):**

| Subagent | Tools | Responsibility |
|---|---|---|
| `analysis` | run_python_simulation | Dijkstra, What-If, topology viz |
| `probe` | execute_cli_parallel | Active liveness, latency |
| `diff` | diff_routing_drift, diff_sql_state, diff_topology_drift, diff_configs | Drift detection |
| `lab` | deploy_lab, push_node_config, exec_on_node, destroy_lab, create_srl_links, fix_srl_topology, save_lab_config, deploy_and_push_lab | ContainerLab digital twin |
| `devops` | *(no own tools — uses orchestrator's execute_sql + prompts/references)* | Script generation |
| `infra` | *(no own tools — uses core's api_request + references)* | Service queries |

**devops and infra** become subagents of ops. They have no unique tools — they're prompt-engineering wrappers that guide the LLM to use existing tools (execute_sql, api_request) with domain-specific context.

### audit (olav-netops)

**Role:** Learning, compliance, quality assurance — teach the system to understand data better.
**Invoked via:** `olav --agent audit "query"`

**Subagents:**

| Subagent | Tools | Responsibility |
|---|---|---|
| `designer` | analyze_thresholds, save_profile, read_profile, append_jobs, database_introspection, test_map_query | Profile creation + schema exploration |
| `auditor` | anomaly_engine, baseline_engine, incident_engine, map_engine, render_report | Profile execution + Markdown reports |
| `learner` | schema_learner (NEW: merge discover_view_schemas + fuzzy_map_schema + sync_schema_reference), scaffold_domain_agent, trace_learner, /learn_cmd | TextFSM learning, schema discovery, trace analysis |

**`learner`** is a new subagent that consolidates all "teach the system" tools:
- `/learn_cmd` — learn CLI output patterns → TextFSM templates
- `schema_learner` — discover DB schema → map fields → sync references
- `trace_learner` — analyze past runs → improve prompts
- `scaffold_domain_agent` — generate new agent from learned patterns

## User-Facing Changes

| Before (v0.17) | After (v0.18) |
|---|---|
| `olav --agent audit-auditor "run profile"` | `olav --agent audit "run profile"` (orchestrator routes to auditor) |
| `olav --agent audit-designer "create profile"` | `olav --agent audit "create profile"` |
| `olav --agent ops-lab "deploy lab"` | `olav --agent ops "deploy lab"` (orchestrator routes to lab) |
| `olav --agent config "health check"` | `olav "health check"` (core handles it) |
| `olav --agent devops "write script"` | `olav --agent ops "write backup script"` |
| `olav --agent infra "query NetBox"` | `olav --agent ops "query NetBox"` |
| `olav list` → 9 agents | `olav list` → 3 agents: core, ops, audit |

## Verification

After migration, `olav list` must show exactly:

```
Available Agents:
  • core   — Platform operations, queries, system management
  • ops    — Network operations, analysis, change management, lab validation
  • audit  — Learning, compliance, health reporting
```

CI Tier 0 Phase A: `/agents` returns exactly 1 (core only).
CI Tier 0 Phase B: `/agents` returns exactly 3 (core + ops + audit).
