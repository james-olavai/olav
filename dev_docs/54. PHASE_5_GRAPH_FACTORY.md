## 1. 目标与非目标

### 1.1 目标

1. 写一个 `langgraph.json`，`langgraph validate` 通过
2. 写一个 `src/olav/server/graph_factory.py`，提供一个可被 `langgraph` 加载的 compiled graph
3. 能够通过环境变量 `DEEPAGENTS_CLI_SERVER_ASSISTANT_ID` 选择 5 个顶层 agent（`core` / `ops` / `audit` / `topology` / `command_learner`）之一
4. `langgraph dev --config langgraph.json` 能启动一个 API server，能响应一次简单 query
5. 集成测试：子进程启动 + ping
6. 顺手注册 `olav agent install` subparser（内部转发到现有 `olav skill install`）为 P1 铺路

### 1.2 非目标

- **不动 TUI**：`simple_cli` 继续走 `run_textual_app(agent=<graph>)`
- **不动 plugin registry**：callback plugins 仍然是 callback，`AgentMiddleware` 改造在 P3（v0.20.1）
- **不动 skill install 路径**：`.olav/workspace/` 保持现状
- **不改 overlay**：`/workspace` / `/ops` alias 原样
- **不切 LangSmith Studio**：只是让可能，不强制

### 1.3 成功指标

| 指标 | 阈值 |
|---|---|
| `langgraph validate -c langgraph.json` | exit 0 |
| `langgraph dev` 启动 | 20 秒内 /health 返回 200 |

## 3. `langgraph.json` 设计

```json
{
  "graphs": {
    "agent": "./src/olav/server/graph_factory.py:graph"
  },
  "dependencies": ["."],
  "python_version": "3.12",
  "env": ".env"
}
```

字段说明：

| 字段 | 值 | 理由 |
|---|---|---|
| `graphs.agent` | `graph` 变量 | langgraph CLI 约定 key `"agent"` 是默认 graph 名；deepagents-cli 的 `_server_kwargs` 也假设这个名字 |
| `dependencies` | `["."]` | 依赖当前仓库（pyproject.toml），自动跟 OLAV 版本走 |
| `python_version` | 3.12 | 和 CI / demo venv 一致 |
| `env` | `.env`（可选） | 支持用户在 .env 里注入 `ANTHROPIC_API_KEY` 等，langgraph dev 会自动加载 |

## 4. `graph_factory.py` 接口

```python
"""LangGraph graph factory for OLAV agents.

Imported by ``langgraph dev`` / ``langgraph up`` subprocesses via
``langgraph.json``.  The subprocess reads the agent name from the
``DEEPAGENTS_CLI_SERVER_ASSISTANT_ID`` environment variable (set by
deepagents-cli when spawning the server) and builds the corresponding
OLAV compiled graph.

Why this exists (Phase 5, v0.20.0):
  This factory lets the OLAV agent tree be consumed by anything that
  speaks langgraph-server — `langgraph dev` for local debugging,
  LangSmith Studio for UI debugging, and (starting v0.20.2) the
  deepagents-cli TUI in server-subprocess mode.  Until v0.20.2 the TUI
  still uses the in-process `agent=<graph>` path; this module is
  additive only.

Contract:
  - Must expose a module-level ``graph`` variable whose type is
    ``CompiledGraph`` (langgraph requirement).
  - Read ``DEEPAGENTS_CLI_SERVER_ASSISTANT_ID`` at import time; missing
    env → fall back to ``"core"``.
  - Unknown agent name → raise ``ValueError`` loudly so misconfigured
    subprocesses fail fast instead of silently serving the wrong graph.
  - Do NOT read any interactive config (no prompts, no TTY) — the
    subprocess runs headless.
"""

from __future__ import annotations

import logging
import os
from typing import Any

logger = logging.getLogger(__name__)

_DEFAULT_ASSISTANT_ID = "core"
_ENV_ASSISTANT_ID = "DEEPAGENTS_CLI_SERVER_ASSISTANT_ID"


def build_graph(assistant_id: str | None = None) -> Any:
    """Construct a compiled OLAV graph for *assistant_id*.

    Thin wrapper around
    :func:`olav.cli.main.create_olav_agent_with_backend` so tests can
    inject an assistant_id directly without touching the env var.

    Args:
        assistant_id: Which top-level agent to build (``core`` /
            ``ops`` / ``audit`` / ``topology`` / ``command_learner``).
            Defaults to ``DEEPAGENTS_CLI_SERVER_ASSISTANT_ID`` env or
            ``"core"``.

    Returns:
        A compiled LangGraph object (``langgraph.graph.CompiledGraph``).
        The exact type is ``Any`` because langgraph's type aliases
        differ between 1.x versions; at the langgraph-server layer
        ducktyping is sufficient.

    Raises:
        ValueError: When the requested agent has no workspace or no
            AGENT.md (misconfigured deployment — fail loudly rather
            than serve a default).
    """
    name = (assistant_id or os.environ.get(_ENV_ASSISTANT_ID) or _DEFAULT_ASSISTANT_ID).strip()
    if not name:
        name = _DEFAULT_ASSISTANT_ID

    # Deferred import so merely importing this module doesn't drag in
    # the full OLAV agent stack at collection time.
    from olav.cli.main import create_olav_agent_with_backend

    logger.info(
        "Building OLAV graph for assistant_id=%r (env=%s)",
        name,
        os.environ.get(_ENV_ASSISTANT_ID, "<unset>"),
    )
    try:
        compiled, _backend = create_olav_agent_with_backend(name)
    except FileNotFoundError as exc:
        raise ValueError(
            f"No workspace found for agent {name!r}. "
            "Set DEEPAGENTS_CLI_SERVER_ASSISTANT_ID to one of: "
            "core, ops, audit, topology, command_learner."
        ) from exc
    return compiled


# Module-level graph for ``langgraph.json`` to discover.
# Evaluated at import time inside the subprocess so the graph is
# ready by the time langgraph-server starts.
graph = build_graph()
```

### 4.1 边界情况

| 情况 | 行为 |
|---|---|
| env 变量未设置 | 默认 `"core"` |
| env 变量为空字符串 | 默认 `"core"` |
| env 变量指向不存在的 agent | 抛 `ValueError` 失败快 |
| workspace 目录存在但 `AGENT.md` 缺失 | `create_olav_agent_with_backend` 内部已处理，会回落 default prompt |
| plugin_registry 加载失败 | callback 层自己 try/except（不影响 graph 构造） |

### 4.2 为什么不做懒加载

一个理论上更干净的设计是让 `graph` 是一个 `LazyGraph` 代理对象，首次被调用时再实例化。但 langgraph-server 在 `/health` 检查时会访问 graph 的一些元属性（如 `get_input_schema()`），提前失败总比运行时 500 友好。所以在 import 期就 fully compile。

### 4.3 开销

- `create_olav_agent_with_backend("core")` 目前冷启动 ~1.5s（含 LangGraph 编译 + plugin 注册）
- 子进程总启动时间大约 3-5s（比直接 `olav` 慢，因为 langgraph server 框架本身 1-2s）
- 可接受，因为 TUI 模式下子进程只启动一次，此后会话内复用

## 5. 与现有 OLAV 代码的粘合

```
┌──────────────────────────────────────┐
│ langgraph dev / langgraph up          │  ← subprocess
│   ├─ reads langgraph.json             │
│   ├─ imports graph_factory:graph      │
│   └─ exposes /threads, /runs, /health │
└──────────────────────────────────────┘
             │
             │ import-time
             ▼
┌──────────────────────────────────────┐
│ olav.server.graph_factory             │
│   build_graph(assistant_id)           │
│     → create_olav_agent_with_backend  │  ← existing, unchanged
│       → OLAVAgent(...)                │
│         → plugin_registry             │
│         → LocalShellBackend           │
│         → create_deep_agent(...)      │
└──────────────────────────────────────┘
```

**关键不变量**：`olav.cli.main.create_olav_agent_with_backend` **一行都不改**。factory 只是个 thin 封装。如果 factory 能成功构造图，说明 P5 成功；如果失败，说明是 plugin_registry 或 backend 或 checkpointer 层有子进程不兼容问题，需要先修那一层。

## 6. 集成测试设计

# tests/integration/test_graph_factory.py

def test_graph_factory_core() -> None:
    """Default agent (core) builds without env var."""
    from olav.server.graph_factory import build_graph
    g = build_graph()
    assert g is not None
    assert hasattr(g, "ainvoke")  # LangGraph Pregel-like surface

def test_graph_factory_each_agent(monkeypatch) -> None:
    """Each top-level agent builds cleanly."""
    for name in ["core", "ops", "audit", "topology", "command_learner"]:
        monkeypatch.setenv("DEEPAGENTS_CLI_SERVER_ASSISTANT_ID", name)
        from olav.server import graph_factory
        # Reload module so env is re-read at import-time
        import importlib
        importlib.reload(graph_factory)
        assert graph_factory.graph is not None, f"{name}: graph is None"

def test_graph_factory_unknown_raises() -> None:
    """Unknown agent → ValueError, no silent default."""
    from olav.server.graph_factory import build_graph
    import pytest
    with pytest.raises(ValueError, match="No workspace found"):
        build_graph("definitely-not-a-real-agent-xyz")

def test_langgraph_validate(tmp_path) -> None:
    """`langgraph validate` accepts our config."""
    import subprocess, sys
    result = subprocess.run(
        ["langgraph", "validate", "-c", "langgraph.json"],
        capture_output=True, text=True, cwd="/home/yhvh/Olav",
    )
    assert result.returncode == 0, f"validate failed: {result.stderr}"

```python
# src/olav/cli/commands/agent_install.py
class AgentInstallCommand(BaseCommand):
    """v0.20.0 shim — delegates to SkillInstallCommand until P1."""

    async def execute(self, args) -> str:
        from olav.cli.commands.skill import SkillCommand
        forwarded = ["install", args.source]
        if getattr(args, "merge_into", None):
            forwarded.extend(["--merge-into", args.merge_into])
        # --copy honoured starting v0.20.2 (P1)
        return await SkillCommand().execute(" ".join(forwarded))
```

v0.20.0 行为：两个命令对同一份输入产生同样的输出，只是名字不同。P1（v0.20.2）里 `agent_install.py` 会吸收 `skill.py` 的实现，`skill install` 变成只打 error 的占位 stub。
