## 一、设计原则

**运维 agent 输出永远用 Mermaid。不给 agent 格式选择权。**

理由：
1. Mermaid 是纯文本 — 终端、GitHub、Obsidian、VS Code 都能渲染
2. 工程师能直接读懂（不需要 draw.io 或 PlantUML 工具链）
3. agent 不需要决策"该用哪种格式" — 减少 token 浪费和错误选择
4. 报告格式统一 — 所有 ops/audit/devops 输出都是 Markdown + Mermaid

**润色是独立步骤。** 如果用户要 CAB 级报告（Cisco 图标 + infographic KPI + draw.io 可编辑图），调用 `writer` skill 对已有文档进行升级。

```
运维 agent → Markdown + Mermaid（快速、稳定、工程师看）
     ↓ 用户："润色这份报告"
writer skill → PlantUML 网络拓扑 + Infographic KPI + draw.io XML（正式、可编辑、CAB 用）
```

## 三、Writer Agent 设计

### AGENT.md

```yaml
---
name: writer
description: "Report Writer — 将运维报告升级为 CAB 级文档，添加专业拓扑图、KPI 卡片和格式优化"
system_prompt_file: prompts/system.md
---
```

### system.md 核心指令

```markdown
You are a technical report writer for IT operations.

## Your Role
- Take existing Markdown reports (from ops/audit/devops agents) and polish them
- Upgrade Mermaid diagrams to PlantUML with Cisco device icons
- Add Infographic KPI cards for quantitative data
- Generate draw.io XML for diagrams that need human editing
- Improve structure: Executive Summary → Findings → Evidence → Recommendations

## Input
- User provides a file path (exports/reports/*.md) or pastes Markdown content
- The content already contains Mermaid diagrams and data tables from other agents

## Output Formats
- Polished Markdown with PlantUML code blocks (```plantuml)
- Infographic YAML code blocks (```infographic)
- draw.io XML files via format_and_export(format="drawio")
- ALWAYS keep the original Mermaid as fallback (in <details> block)

## References
- viz_plantuml_network.md — Cisco/network stencil icons + PlantUML syntax
- viz_drawio.md — draw.io XML generation rules
- viz_infographic.md — KPI card templates (score-card, timeline, table)
- viz_mermaid.md — Mermaid syntax rules (for fixing original diagrams)

## Rules
- NEVER change the factual content of the report — only format and visualize
- Keep original data tables alongside infographic versions
- PlantUML and draw.io share mxgraph.* stencil IDs — same icon set
```

## 七、用户工作流

### 日常运维（90% 场景）

```bash
olav --agent ops "show topology"
# → Mermaid 图直接显示在终端 / 导出为 .mmd
# 工程师直接看，够了
```

### CAB 报告准备（10% 场景）

```bash
# Step 1: 运维 agent 生成原始报告
olav --agent ops "分析 R3 变更的影响，生成报告"
# → exports/reports/r3_change_impact.md（Mermaid 拓扑 + 数据表格）

# Step 2: writer 润色
olav --agent writer "润色 exports/reports/r3_change_impact.md，加专业拓扑图和 KPI"
# → exports/reports/r3_change_impact_polished.md（PlantUML + Infographic）
# → exports/diagrams/r3_topology.drawio（可在 draw.io 编辑）

# Step 3: 人工精修（可选）
# 用 draw.io Desktop 打开 .drawio → 调整布局 → 导出 PNG
# 嵌入到 CAB 提案文档
```

## 九、不做什么

| 排除项 | 理由 |
|---|---|
| 让 ops/audit agent 输出 PlantUML/draw.io | 增加决策负担 + 格式不统一 |
| 引入 PlantUML/draw.io 渲染服务 | OLAV 只生成源代码，渲染由外部工具完成 |
| Writer 修改报告事实内容 | Writer 只做格式升级，不改数据 |
| 自动触发 Writer | 润色是用户显式请求，不是默认流程 |
| 将 viz reference 注入所有 agent | PlantUML/draw.io/Infographic 只在 writer 中，防止其他 agent 被诱导 |
