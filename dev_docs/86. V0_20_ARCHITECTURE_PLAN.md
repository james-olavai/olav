# 86. v0.20 架构规划 — deepagents 升级 + 工作流稳定性

**版本**: 0.20.0  
**分支**: `0.20.0`  
**前版本**: 0.19.0（`0.11.0` 分支）  
**规划日期**: 2026-06-01  
**目标完成**: 2026-07 前

---

## 0. 背景与目标

v0.19 及之前的版本通过大量 prompt 工程和 CLI 层补丁来维持复杂工作流的稳定性：

- **Rule 7**（"L1-L4 全覆盖后才停"）是文字约束，模型可忽略
- **Forced Synthesis**（`main.py:1329`）是 CLI 层事后注入，根因未消除
- **read-file-before-write** 是手工防护，依赖模型遵守系统提示
- **`_DEEPAGENTS_INJECT_TOOLS` 静态白名单**是脆弱的后置剪枝

v0.20 的目标是：**用 deepagents 0.6.x 的架构机制取代这些 prompt 补丁**，让稳定性来自框架层而不是 LLM 遵从性。

### v0.20 核心方向

| 方向 | 描述 |
|---|---|
| **deepagents 升级** | 0.5.9 → 0.6.7，解锁 `RubricMiddleware`、`state_schema`、`ContextHubBackend`、`DeltaChannel` |
| **Open Issues 清零** | 修复所有 P1/P2 open issues（8 个，见第 1 节） |
| **工作流架构重构** | explorer、analyzer、orchestrator 三条复杂链路用框架机制替代 prompt 规则 |
| **淘汰自造轮子** | 识别并删除被 deepagents 原生机制覆盖的代码 |

## 1. Open Issues 清零计划（前置条件）

升级前先消除现有技术债，确保升级在干净基础上进行。

### P1 Issues（必须先解决）

#### ISSUE-FORCED-SYNTHESIS-IS-PATCH
**根因**：小模型（gemma4-31b）完成工具调用后认为任务结束，不发出 AIMessage。  
**v0.20 修复**：在 LangGraph 图内加 `synthesis_node` 条件边，不在 CLI 层打补丁。

```
tool_executor
    → (has_text_output?) → agent          # 正常路径
    → (empty + has_tool_results?) → synthesis_node → END
```

`synthesis_node` 拿到完整消息历史，质量优于 CLI 层截断版本。删除 `main.py:1329` FORCED-SYNTHESIS 块。

**影响文件**：`src/olav/agents/agent.py`（graph 编译），`src/olav/cli/main.py`（删除 fallback）

#### ISSUE-HARNESS-PROMPT-CACHING-PROVIDER-BLIND
**根因**：`HAS_PROMPT_CACHING = True` 硬编码，Anthropic middleware 注入到所有 sub-agent。  
**v0.20 修复**：`_deepagents_bridge.py` 加 `should_use_prompt_caching()` 函数（代码已有框架，完善注入点）。

```python
# agent.py _build_subagents() 注入点改为：
if should_use_prompt_caching():
    _middleware.append(AnthropicPromptCachingMiddleware(...))
```

## 3. 工作流逐一分析

### 3.1 Explorer 多层调查（最复杂，最受益）

**当前问题汇总**：
- Rule 7 是文字约束，fragile
- 每层写报告前手动 `read_file` 检查，4 层 = 4 次额外 round-trip
- 调查结果只写 markdown，不进 DB，下次 session 从零开始
- `thinking_mode: enabled` × 6 层调查 × 40s/turn ≈ 需要 700s 超时

**v0.20 改造**：

```
RubricMiddleware（替代 Rule 7）
  rubric = {
    "L1-interface": "## L1 存在于报告且有证据 SQL",
    "L2-security":  "## L2 存在于报告且有证据 SQL",
    "L3-routing":   "## L3 存在于报告且有证据 SQL",
    "L4-bgp":       "## L4 存在于报告且有证据 SQL",
    "summary":      "## Summary 和 ## Recommendations 存在",
  }
  max_iterations = 2  # 未满足则自动重试当前层
```

```
state_schema（替代 read_file 状态推断）
  class ExplorerState(TypedDict):
      run_id: str
      report_path: str
      layers_written: list[str]   # ["L1", "L2", ...]
      report_content: str          # 当前报告内容，跨 tool call 保持一致
```

**删除**：SKILL.md 中的 Rule 6（read before write 文字规则）、Rule 7（L1-L4 文字约束）。由 RubricMiddleware + state_schema 接管。

**SKILL.md 变化**：`tools:` 删除 `read_file`（状态由 state_schema 维护），`metadata:` 加 `rubric_middleware: true`。

### 3.2 Orchestrator 上下文膨胀

**当前问题**：explorer 报告以 markdown 文本形式流入 orchestrator 上下文，长任务链后 orchestrator context 线性增长。

**v0.20 改造**：
- **DeltaChannel**：checkpoint 改为差量存储，200 turn 会话内存占用从 ~5 GB → ~130 MB
- **数据流改造**（与 deepagents 升级独立）：orchestrator 通过 `execute_sql` 查 `netops.exploration_findings` 获取摘要，不在上下文携带完整报告。这部分 0.5.9 阶段已有 scratchpad 支撑，0.20 继续完善

### 3.3 Analyzer 变更分析

**当前问题**：analyzer 靠 system prompt 指令驱动多步骤变更分析，中途可能跳步或过早结束。

**v0.20 改造**：
- `RubricMiddleware`：rubric = "变更计划包含：影响设备列表、每批次行动步骤、回滚步骤"
- `TodoListMiddleware`（已支持，仅需在 SKILL.md 加 `enable_todo_list: true`）

### 3.4 Reporter 综合报告

**当前问题**：reporter 的 read-first-then-write 靠手工系统提示约束，模型可忽略。

**v0.20 改造**：
- `state_schema`：`report_sections_written: list[str]`，跨 tool call 维护已写章节集合
- `RubricMiddleware`：rubric = "最终报告包含：摘要、设备清单、关键发现"
- 删除 SKILL.md 中的"Read before write"手工规则

### 3.5 Collector 批量采集

**当前问题**：`tools: []` 导致 LLM 无法调用脚本（ISSUE-AGENT-SCRIPT-REGISTRATION-GAPS A 类）。

**v0.20 改造**：明确 collector 是 pipeline-only（Python 侧调用），在 SKILL.md 加 `pipeline_only: true` 注释，不加 `execute_skill_script`。新增 governance test 对 pipeline-only 豁免白名单做断言。

### 3.6 Forced Synthesis（跨所有 agent）

**当前问题**：CLI 层补丁，每次触发 +30-60s 延迟，根因未消除。

**v0.20 改造**：LangGraph 图内 `synthesis_node`，对所有 agent 生效，删除 `main.py:1329` 的 `FORCED-SYNTHESIS` 块及相关 `_SILENT_DELEGATE` / `_WRITE_TOOLS` 过滤逻辑（约 60 行）。

def _should_synthesize(state) -> Literal["synthesis_node", END]:
    last = state["messages"][-1]
    if (isinstance(last, AIMessage) and not last.content
            and state.get("_tool_results")):
