# 102. Workspace SSOT Consolidation

**Issue:** ISSUE-ARCH-AUDIT-WORKSPACE-DUAL-COPY-DEBT (P2)
**Opened:** 2026-06-02 (architecture audit batch)
**Status:** Phase 1 done (diagnosis + tooling); Phase 2+ gated on new e2e suite
**Owner:** olav (platform)

## Problem

Workspace agent content (`SKILL.md`, `AGENT.md`, `MANIFEST.yaml`,
`prompts/`, `references/`) exists in **up to three committed copies per
domain**, kept in sync only by a partial script (`sync_netops_workspace.py`,
ops-only) plus a byte-identical governance test. The audit found the
copies have **actually drifted** — this is no longer just maintenance
overhead, it is live divergence, and the wheel ships stale content.

### Copy roles

| Domain | Authoritative *source* (target) | Generated mirrors (git-ignored) |
|---|---|---|
| core   | `src/olav/data/workspace/core`  | `.olav/workspace/core` |
| audit  | `olav-netops/.olav/workspace/audit` (audit's home — bundled w/ netops) | `.olav/workspace/audit` + `src/olav/data/workspace/audit` (wheel init-fallback) |
| netops | `olav-netops/.olav/workspace/netops` | `.olav/workspace/netops` |
| devops | `olav-netops/.olav/workspace/devops` | `.olav/workspace/devops` |
| ops    | `olav-netops/.olav/workspace/ops`    | `.olav/workspace/ops` |

**audit belongs to netops.** Per `ownership_manifest.yaml`, audit ships
bundled with the netops workspace via `olav skill install`; the wheel copy
`src/olav/data/workspace/audit` is only an `olav init` fallback "when no
skill pack is installed yet". So the netops copy — not the wheel — is the
authoritative source.

At runtime the agent **always** reads `.olav/workspace/`. The source dirs
are copied in by `olav init` (`importlib.resources` walk of
`olav.data.workspace.*`, see `cli/commands/init.py:386`) and by
`olav skill install <olav-netops-url>`.

## Diagnosis (2026-06-02)

### The wheel source is stale 0.17-era content

Per the maintainer: `src/olav/data/workspace/` was "casually coded during
earlier development"; PyPI is at 0.17.0; the correct content target is the
newer (0.18+) revision. The **live/correct content currently sits in the
runtime copies** (`.olav/workspace/*`, edited directly during dev), and in
`olav-netops/` for the netops domains — NOT in the wheel source.

Evidence — `core/AGENT.md`:
- runtime `.olav/workspace/core` → `version: "4.0.0"`, `prompts/core.md`
- wheel  `src/olav/data/workspace/core` → `version: "3.2.0"`, stale
  `prompts/system.md`, still references the removed `admin` sub-agent.

90-day commit frequency (how "live" each copy is):

| copy | core | audit | netops |
|---|---|---|---|
| `.olav/workspace/*` (runtime) | 75 | 55 | 15 |
| `src/olav/data/workspace/*` (wheel) | 75 | 13 | — |
| `olav-netops/.olav/workspace/*` | — | 31 | 104 |

→ Active dev for core/audit happens in the runtime copy; for netops it
happens in olav-netops. The wheel source is the laggard for core/audit.

### Full drift map

Generated by `scripts/workspace_drift.py` (read-only). Summary:

- **core** — 13 metadata files drift between wheel source and runtime.
  Runtime has `prompts/core.md`, `guides/viz_drawio.guide.yaml`,
  `writer/prompts/writer.md`; wheel has stale `prompts/system.md` and a
  `remote/SKILL.md` not present in runtime.
- **audit** — initially looked like an unmergeable three-way fork, but
  applying the "latest deepagents workflow wins" rule **resolves it
  mechanically** (it is NOT a real fork):
  - **wheel** `src/olav/data/workspace/audit` — 0 `rubric_middleware`
    markers → objectively stale 0.17-era. Has old `curator/`, no `explorer/`.
  - **netops** `olav-netops/.olav/workspace/audit` — latest workflow
    (rubric markers in `audit-author/SKILL.md`, `explorer/SKILL.md`).
    Clean: `explorer`, no `curator`, orchestrator prompt = `prompts/audit.md`.
    References resolve (`prompts/audit.md`, `audit-runner/prompts/system_envelope.md`).
  - **runtime** `.olav/workspace/audit` — byte-identical to netops on all
    shared files (0 differ); it is netops **plus pre-consolidation leftovers**:
    `curator/` (dead — `audit/AGENT.md:12` records "Removed curator sub-agent
    — all scripts were dead code", 2026-05-27), `prompts/orchestrator.md`
    (still references the removed curator), `prompts/system.md`,
    `audit-*/prompts/system.md`. These are stale, not active.
  → Resolution: **netops is the clean authoritative latest.** Regenerate
  runtime + wheel from netops; drop the runtime-only leftovers. Mechanical,
  not a human merge.
- **netops** — in sync except the waived `analyzer/references/ROUTING_EXPERT_GUIDE.md`.
- **devops** — 4 drift; runtime has a `services/` sub-agent the source lacks.
- **ops** — fully in sync.

### Git-tracking drift (secondary)

`.olav/` uses a whitelist model, but several runtime dirs marked
`git: ignore` in `ownership_manifest.yaml` still have leftover **tracked**
files committed before the ignore rule landed (e.g. `.olav/workspace/netops`
= 38 tracked files; `.olav/workspace/audit` = 31). These cannot be blindly
untracked because some hold the live content (audit runtime is the most
active copy). Untracking is coupled to the content reconciliation below and
is therefore also Phase 2.

## Target steady-state model

**One authoritative editable source per domain; runtime `.olav/workspace/`
is a generated, git-ignored mirror that is never hand-edited.**

- Edit + commit in the **source** column above.
- `.olav/workspace/*` is regenerated from the source (by `olav init` /
  skill install, or a `--direction to-runtime` sync, or a dev symlink).
- Governance test asserts runtime == source (regenerate, don't hand-edit),
  replacing the current bidirectional byte-compare SSOT tests.

This eliminates the structural duplication: there is exactly one place to
edit, and the mirror is derived.

## Reconciliation plan

### Phase 1 — Diagnosis + tooling ✅ (2026-06-02)
- `scripts/workspace_drift.py` — read-only N-way drift reporter across all
  domains (supersedes ops-only `sync_netops_workspace.py` for diagnosis).
  `--apply` is guarded: requires explicit `--direction` + `--domain`, no
  default write direction (wrong direction would overwrite live with stale).
- This document.

Authority is now deterministic (latest deepagents workflow wins), so every
step below is mechanical. Execution + release blessing remain gated on the
new e2e suite per the maintainer directive.

### Phase 2 — Content reconciliation (GATED on new e2e suite) ⏳
1. Build / finish the new e2e suite that exercises every sub-agent.
2. For **core**: promote runtime (v4.0.0) → wheel source
   (`workspace_drift.py --apply --domain core --direction to-source`),
   replacing the stale v3.2.0 content. Review the diff before commit.
3. For **audit**: netops is authoritative.
   - Drop the runtime-only stale leftovers (`curator/`,
     `prompts/orchestrator.md`, `prompts/system.md`, `audit-*/prompts/system.md`)
     so runtime matches netops.
   - Regenerate the wheel fallback from netops
     (`workspace_drift.py --apply --domain audit --direction to-runtime`
     pushes source→runtime; the wheel extra_mirror is written per target).
4. For **devops**: decide the fate of the runtime-only `services/` sub-agent
   (does the shipped devops agent include a `services` sub-agent?), then
   converge.
5. **netops/ops**: already aligned; no action beyond the model switch.
6. Only after e2e passes on the reconciled content may it be tagged as the
   new released workspace (0.18+).

### Phase 3 — Make runtime a true generated mirror ⏳
1. Untrack the leftover tracked files under git-ignored runtime dirs
   (`git rm --cached`, keep on disk).
2. Switch the governance test from bidirectional byte-compare to
   "runtime is regenerable from source" (or "runtime is a symlink to source"
   for the monorepo dev layout).
3. Update `ownership_manifest.yaml` so the runtime copies are uniformly
   `generated` / `git: ignore`, and the source dirs are the sole tracked
   authority.
4. Retire `sync_netops_workspace.py` in favour of `workspace_drift.py`.

## Why gated, not done now

The maintainer's directive: the live content must NOT be blessed as the
latest released version until the new e2e suite passes. The authority
direction is now deterministic — "the copy using the latest deepagents
workflow (`rubric_middleware`/`enable_todo_list`) is the current one" — so
every reconciliation step is mechanical (latest overwrites stale; no risky
human merge). What remains genuinely gated is *validation*: the regenerated
content must pass the new e2e suite before it ships as 0.18+. Phase 1 is
therefore strictly non-destructive: it makes the drift visible and provides
the guarded tool, so Phase 2/3 execution is a sequence of reviewed
`--apply` runs once e2e is green.
