# 96. CLAB redesign — native-image fidelity tiers, scan-only image policy, deterministic twin

**Status**: Draft / proposed 2026-06-17. Phase 1 scoped; awaiting build authorisation.
**Supersedes**: the **SR-Linux-as-universal-target** assumption in dev_docs/73 §3-§4
and dev_docs/74 (Twin Builder + Runner *split* is kept; its *SRL-translation
content* is replaced). dev_docs/73 §2 (sim / Batfish) remains valid and is the
designated **primary** validator here.
**Builds on**: shipped `sim` agent (`batfish_q`), shipped clab REST integration
(`service_call("containerlab", ...)`), the deterministic-transform principle
(R88), and the small-model-first governance in CLAUDE.md.
**Owners**: netops + lab maintainers

---

## 0. Why the previous design was wrong

Two operator-observed failure modes drove this redesign:

1. **Translating prod config to SR Linux gives poor results.** The shipped path
   (`olav-ent/.../cab/postcheck_translate.py` — 11 regex rules — plus
   `freeform_translator.py` LLM fallback) produces low-confidence, often-wrong
   SRL config and command/pattern translations.
2. **Simulator vs. real device divergence.** Even when translation "succeeds",
   the lab runs SR Linux's protocol state machines, timers, and quirks — not the
   production vendor's. The lab answers *"does this work on SRL?"*, which is the
   wrong question.

**Both complaints share one root cause: forcing every device through SR Linux as
a universal target.**

- Config-layer correctness is better served by **Batfish** (vendor-faithful
  parsers, zero translation, offline, sub-second) — the `sim` agent, already
  shipped.
- Behavioural truth — the *only* thing a live lab adds over Batfish — requires
  running **the device's own OS**. Translating to SRL throws away exactly the
  vendor quirks behavioural validation exists to test. SRL-as-universal sits in a
  no-man's-land: neither config-faithful (needs lossy translation) nor
  behaviour-faithful (it is a different OS).

A second, compounding root cause: **the LLM was placed in a config-*authoring*
role.** Config transformation is deterministic; an LLM asked to emit config text
will hallucinate, forget across retries, and "fill gaps". This produced the
observed multi-attempt instability. (Contradicts R88 / the deterministic-transform
principle in CLAUDE.md.)

### The governing principle of this redesign

> **The LLM never authors config. All transforms are deterministic Python with
> per-line receipts. Ground truth comes from the device (or Batfish), never from
> the LLM's judgement. The lab target is the device's *own* OS, never a
> universal stand-in.**

This single principle dissolves all three observed problems:
translation (deleted — same-vendor needs none), fidelity (native image), and
LLM instability (LLM removed from the build loop).

## 2. Image policy — scan-only, never distribute (legal firewall)

OLAV **never downloads, stores, packages, or moves any proprietary vendor image.**
The operator supplies images they are licensed for (Cisco IOL, n9kv, …) onto the
clab host. OLAV only **discovers** what is present and decides eligibility from
that. This is the legal firewall and a hard architectural boundary, consistent
with the repo's ownership philosophy.

```
Image catalog = discovery, not distribution
  ├── scanner    enumerate images actually present on the clab host
  │              (docker image inventory / CLAB REST available kinds)
  ├── resolver   device(model, os_version) → desired (clab kind, image, version)
  └── gate       desired image present in scan? → eligible (T1)
                 absent?                        → fall back to Batfish (T0),
                                                  labelled "image not available"
```

OLAV ships only the **mapping rules + scanner + gate** — code, not images. A
device is lab-eligible only because the scan proved its image exists; otherwise
it degrades honestly to formal analysis. No hardcoded "assume image X exists".

## 3. Fidelity tiers

| Tier | Mechanism | Answers | Translation | Cost | Default? |
|---|---|---|---|---|---|
| **T0 Formal** | Batfish (`sim`, shipped) | reachability, BGP/OSPF session compat, ACL, route-policy, what-if differential | none (native parsers) | sub-second | **Yes — primary** |
| **T1 Native** | device's **own** OS image, scanned-present | real convergence, timers, protocol state machines, control-plane behaviour | **none** (same vendor) | minutes; scope-limited | only when behaviour adds value beyond T0 |
| ~~T2 SRL approximation~~ | ~~translate to SR Linux~~ | — | **REMOVED** | — | — |

Rules:
- **T0 is the primary validator.** Most pre-flight questions (especially for an
  access/campus switching fleet: VLAN/ACL/port changes) are config-derived and
  never need a live lab.
- **T1 is a narrow, high-fidelity add-on**, reserved for what Batfish genuinely
  cannot prove (real convergence/timing, protocol state-machine behaviour). It
  runs **only the change-scope devices** (typically 2–4), not the whole network.
- **T2 is deleted.** Cross-vendor → SRL translation is an unsolvable, false-
  confidence path. SR Linux is a T1 target **only when the device is actually
  Nokia** (none in this fleet today).
- **Honest degrade:** no scanned image and no Batfish parser → output
  "behavioural validation unavailable; here is the formal analysis we can do."
  Never fake a PASS.

## 4. Tier mapping for this fleet

Because the lab target is the device's **own vendor OS**, there is **zero CLI
translation** — IOS config is pushed to an IOS image, NX-OS to an NX-OS image.
This is the core win: the original "translation" complaint disappears entirely.

| Device class | Operator-supplied image | clab kind | Fidelity | Approx count |
|---|---|---|---|---|
| Catalyst access/dist (IOS/IOS-XE, L2) | **IOL-L2** | `cisco_iol` `type: l2` | medium — VLAN/Trunk/STP/SVI + L3 control-plane; **not** ASIC/PoE/stacking | ~220+ |
| Routed IOS/IOS-XE (L3) | **IOL** | `cisco_iol` | medium — OSPF/BGP/EIGRP control-plane | part of 9k/4500X |
| Nexus 9000 | **n9kv** | `cisco_n9kv` | high — native NX-OS | 34 |
| anything not scanned | — | — | — → T0 Batfish | remainder |

**Why IOL changes everything for this fleet:** IOL (IOS-on-Linux) is a
process-level, lightweight (~hundreds of MB) Cisco IOS image; the L2 variant
models switching control-plane (VLANs, trunks, STP, SVIs) plus routing
(OSPF/BGP/EIGRP). It is the **same vendor CLI** as prod, so config pushes
verbatim — no translation. It covers the bulk of the fleet at low resource cost.

## 5. Deterministic config normalization (no LLM, with receipts)

Same-vendor prod→lab is ~identity plus a small, enumerable rule set. **No LLM
authors any config line.** Parse with a real parser (reuse Batfish's parse tree /
hierarchical config), not regex line-munging.

| Rule class | Action | Source |
|---|---|---|
| Interface remap | `GigabitEthernet1/0/1 → Ethernet0/1` (IOL) etc. | `topology_links` / LLDP — deterministic table |
| Hardware-stanza strip | denylist: `hardware`, `platform`, `transceiver`, breakout, `speed forced`, PoE, stacking, QoS-hardware | versioned ruleset |
| Management neutralize | swap mgmt IP → lab mgmt; strip unreachable TACACS/RADIUS/SNMP servers; keep local auth | ruleset |
| Keep verbatim (default) | BGP, OSPF/EIGRP, route-map, prefix-list, VRF, ACL, VLAN, SVI | — — **this is what we test** |

Hard constraints:

1. **Lossless-with-receipts.** Every removed/changed line carries a reason code,
   emitted as a `normalization diff` sidecar. **No silent drops.** A line that
   cannot be classified → flagged `unclassified`, surfaced, never guessed.
2. **Idempotent + content-addressed.** `twin_id = hash(scope, snapshot_id,
   ruleset_version)`. Re-running yields a byte-identical artifact. "Multiple
   attempts" stops being a concept — there is no LLM state to forget, no variance
   to re-roll.
3. **Keep-ratio metric.** Percent of lines kept verbatim. Same-vendor native
   should be high; a low ratio or many `unclassified` lines → mark the twin
   low-fidelity and degrade. Fidelity is measured, not assumed.

## 6. Round-trip fidelity validation (device as judge)

The twin is not trusted because the transform "looks right"; it is validated
empirically:

> After deploy, dump running-config **from the lab device**, normalize it the
> same way, and diff against the intended config. Result should be empty modulo
> the known interface remap. Non-empty diff = lines that did not take (version
> gap, unsupported feature) — exposed automatically.

This closes the loop with the device's own parser as ground truth and is the
honest answer to "version drift" (IOL may track an older IOS than prod 17.x):
incompatibilities surface as round-trip diffs, are recorded, and feed the
eligibility gate (§2) — they are never hidden behind an LLM guess.

## 7. Build/run split (kept from dev_docs/74, de-LLM'd)

The Twin Builder / Experiment Runner *split* from dev_docs/74 is retained — slow
cacheable build, fast on-demand run — but the **twin content changes** from
"SRL-translated" to "native image + verbatim config + interface map", and the
**LLM is removed from the build**:

- **Twin Builder** (deterministic, no LLM): collect snapshot config + topology →
  normalize (§5) → render startup-config + clab YAML with the scanned native kind
  → emit `normalization diff` + manifest. The dev_docs/74
  `translation_confidence` / `translation_review.md` machinery is **gone** (no
  translation ⇒ nothing to score or review).
- **Experiment Runner**: load twin → `containerlab_deploy --startup-config` →
  push change delta (**same-vendor CLI, verbatim**) → run prod post-check
  commands directly (no command/pattern translation) → round-trip validate (§6) →
  emit markdown lab report → destroy.

The LLM's only roles remain: routing (which agent), narration (turn the
deterministic diff / report into prose), and judgement over Batfish results
(PASS/FAIL). It authors no config.

## 8. What gets deleted

- ❌ Cross-vendor → SRL translation (the whole goal).
- ❌ `olav-ent/.../cab/postcheck_translate.py` command/pattern translation.
- ❌ `olav-ent/.../cab/freeform_translator.py` LLM translator.
- ❌ dev_docs/74 `translation_confidence` scoring + `translation_review.md`.
- ❌ Any LLM step inside twin construction.

SR Linux assets are retained only for (a) genuine Nokia devices and (b) existing
platform self-test labs — not for production config behavioural validation.

## 9. Phase 1 scope (deliberately narrow)

Eligibility gate per device (all must hold): vendor/model resolves to a kind;
**scanned image present**; version close (same major.minor preferred, small gap
flagged); normalization yields near-identity (high keep-ratio, zero blocking
`unclassified`). Else → T0 Batfish.

Phase 1 deliverables:

1. **scanner + resolver + gate** (deterministic, zero LLM).
2. **Same-vendor normalization** (§5): interface remap + hardware denylist +
   keep-verbatim; emits startup-config + clab YAML + normalization diff.
3. **Round-trip validation** (§6) as the fidelity acceptance criterion.
4. First line: **IOL-L2 access switches** (largest count, lightest, best
   demonstration of the no-translation win). Second line: **n9kv** (high fidelity,
   heavier; gated on operator-supplied image).
5. Retire the SRL translation path (§8).

**Acceptance:**
- For an eligible device, round-trip diff is empty modulo known interface remap.
- An ineligible device (no scanned image / large version gap / low keep-ratio)
  degrades to Batfish with an explicit, logged reason — no faked PASS.
- Build pipeline contains zero LLM calls (re-run is byte-identical).

## 10. Open questions

1. **IOL interface-map determinism for stacked / modular Catalyst**: prod
   `Gi1/0/1` (stack member/slot/port) → IOL `Ethernet0/x` flat. Map rule needs a
   stack-aware policy; or mark stacked devices ineligible in Phase 1.
2. **Scanner transport**: docker socket on clab host vs. a CLAB REST
   "available kinds/images" endpoint vs. an operator-declared catalog file.
   Prefer live scan; allow declared-catalog override for air-gapped hosts.
3. **n9kv resource governance**: VM-class RAM; need subnet pool + concurrency cap
   (carried over from dev_docs/74 open Q#6) before enabling at scale.
4. **Keep-ratio threshold**: what verbatim-% / unclassified-count flips a twin to
   "low-fidelity / ineligible"? Calibrate against the first IOL-L2 batch.
5. **Juniper vSRX (1 device)**: out of Phase 1; revisit with `juniper_vjunos*`
   only if the fleet grows.
