# 46. Data Pipeline Self-Healing & Raw Fallback

**Date:** 2026-04-17
**Status:** Design — guides v0.19 implementation
**Motivation:** R1 (Junos) BGP/Interface data 采集成功但 TextFSM 解析失败，导致 `parsed_outputs` 缺失，拓扑不完整，查询漏设备。

---

## 问题链

```
1. TextFSM 模板不匹配 → parsed_outputs 缺失
2. parsed_outputs 缺失 → Topology ETL 缺少 Junos 链接
3. Topology ETL 不完整 → 拓扑图缺 R1 链接
4. execute_sql 只查 parsed_outputs → "BGP邻居" 漏掉 R1
5. raw_output_store 有完整数据但无人查询
```

实测：R1 的 11 个命令中 4 个解析失败（show bgp summary, show interfaces, show interfaces terse, show configuration），但 raw 数据完整存在。

---

## 三层解决方案

### Layer 1: raw_output_store 覆盖更新 + 查询 Fallback

**数据模型：**

| 表 | 更新策略 | 语义 | 查询优先级 |
|---|---|---|---|
| `raw_output_store` | **UPSERT**（覆盖） | 最新设备状态 | fallback |
| `parsed_outputs` | **APPEND**（追加） | 时间切片快照 | primary |
| `devices` | **UPSERT** | 最新设备信息 | — |
| `topology_links` | **UPSERT** | 最新拓扑 | — |

**raw_output_store 必须覆盖更新。** 每次采集 UPSERT on `(device_name, command)`——只保留最新一次的 raw 输出。否则每次 init 都追加 81 条记录，增长不可控。

**查询 Fallback 链路：**

```
用户: "R1 的 BGP 状态"
  → execute_sql: SELECT FROM netops.parsed_outputs WHERE device_name='R1' AND command LIKE '%bgp%'
  → 结果为空
  → Fallback: SELECT raw_output FROM netops.raw_output_store WHERE device_name='R1' AND command LIKE '%bgp%'
  → LLM 直接读 raw 文本，提取 BGP 信息
```

**实现位置：**
- `core/prompts/system.md` 或 `db_query/SKILL.md`: 添加 fallback 规则
- `ops/SKILL.md`: Database Schema 段添加 raw_output_store 说明和 fallback SQL 模式
- `execute_sql` 工具的 schema hints: 自动包含 raw_output_store

**Topology ETL 也需要 fallback：** 当前 Topology ETL 从 `parsed_outputs` 的 LLDP/CDP 数据提取链接。如果 Junos LLDP 解析失败，应该从 `raw_output_store` 的 `show lldp neighbors` raw text 提取。

### Layer 2: Pipeline 内自动学习（Stage 3.5）

**在 init pipeline 内部**，TextFSM 解析失败后立即触发学习，不等到 pipeline 结束。

```
Stage 1: Environment check
Stage 2: Device inventory
Stage 3: SSH collection (per platform)
  → TextFSM 解析尝试
  → 成功 → parsed_outputs
  → 失败 → Stage 3.5

Stage 3.5: 自动学习（仅对解析失败 + 非假阳性的命令）
  → 假阳性排除
  → 检查自定义模板
  → learn_cmd 学习（≤5 次）
  → 成功 → 存入 custom template + parsed_outputs
  → 失败 → 存入 raw_output_store 作为 fallback

Stage 4: Ingest → Topology ETL → Device ETL（此时 parsed_outputs 完整）
```

**时序关键：** Stage 3.5 必须在 Stage 4（Topology ETL）之前完成。Topology 依赖 LLDP/CDP 的 parsed_data。如果学习成功，Stage 4 就能用完整数据构建拓扑。

### Layer 3: 自定义模板持久化与共享

```
.olav/workspace/ops/templates/custom/
  juniper_junos/
    show_bgp_summary.textfsm
    show_interfaces.textfsm
    show_interfaces_terse.textfsm
  cisco_nxos/
    show_ip_bgp_summary.textfsm
```

- 模板在 workspace 中 → `git add` 可跟踪 → 团队共享
- 下次 init 优先使用 custom 模板 → 不需要重新学习
- learn_cmd 生成的模板带元数据注释（生成日期、基于哪条 raw output）

## 假阳性排除

不是所有解析失败都应该触发学习。

| 情况 | raw_output 特征 | 动作 |
|---|---|---|
| **有效输出 + 模板失败** | >100 chars，含表格/数据行，无错误标记 | **触发 learn** |
| 设备不支持该命令 | 含 `% Invalid`, `error`, `unknown command` | 跳过，不学习 |
| 空/极短输出 | <20 chars 或纯空行 | 跳过 |
| 命令超时 | 含 `timeout`, `timed out` | 跳过 |
| 备份型命令 | `show running-config`, `show configuration` | **存入 raw，不学习**（配置文本不需要 TextFSM） |
| 权限不足 | 含 `permission denied`, `access denied` | 跳过 |

```python
BACKUP_COMMANDS = {
    "show running-config", "show startup-config", "show configuration",
    "show running-config | display set",
}

ERROR_PATTERNS = [
    "% invalid", "% unknown", "syntax error", "not found",
    "command not recognized", "% incomplete", "permission denied",
    "access denied", "% authorization",
]

def should_learn(command: str, raw_output: str) -> bool:
    """Determine if a parse failure should trigger learn_cmd."""
    text = raw_output.strip()
    
    # Too short — likely error or empty
    if len(text) < 20:
        return False
    
    # Backup commands — store raw, don't parse
    if command.lower().strip() in BACKUP_COMMANDS:
        return False
    
    # Device error messages
    first_lines = "\n".join(text.split("\n")[:3]).lower()
    if any(p in first_lines for p in ERROR_PATTERNS):
        return False
    
    # Timeout
    if "timeout" in text.lower() or "timed out" in text.lower():
        return False
    
    # Valid output — trigger learning
    return True
```

## learn_cmd 集成流程

```python
def stage_3_5_auto_learn(
    parse_failures: list[dict],  # [{device, platform, command, raw_output}, ...]
    custom_template_dir: Path,
    max_retries: int = 5,
) -> list[dict]:
    """Auto-learn TextFSM templates for failed parses. Returns newly parsed results."""
    
    newly_parsed = []
    
    for item in parse_failures:
        device = item["device"]
        platform = item["platform"]
        command = item["command"]
        raw = item["raw_output"]
        
        # 1. 假阳性排除
        if not should_learn(command, raw):
            logger.info(f"skip learn {device}/{command}: false positive or backup")
            continue
        
        # 2. 检查已有自定义模板
        custom = load_custom_template(custom_template_dir, platform, command)
        if custom:
            result = parse_with_template(raw, custom)
            if result:
                newly_parsed.append({**item, "parsed_data": result, "source": "custom_template"})
                continue
        
        # 3. learn_cmd 学习（最多 max_retries 次）
        for attempt in range(max_retries):
            template = learn_cmd(platform, command, raw)
            if template is None:
                continue
            
            result = parse_with_template(raw, template)
            if result and len(result) > 0:
                # 验证：解析结果字段数 ≥ 2 且行数 ≥ 1
                if validate_parsed_result(result):
                    save_custom_template(custom_template_dir, platform, command, template)
                    newly_parsed.append({**item, "parsed_data": result, "source": f"learned_attempt_{attempt+1}"})
                    logger.info(f"✓ learned {platform}/{command} in {attempt+1} attempt(s)")
                    break
        else:
            logger.warning(f"✗ learn failed after {max_retries} attempts: {device}/{command}")
    
    return newly_parsed
```

## raw_output_store 覆盖更新

当前 `raw_output_store` 可能每次 init 都追加记录。必须改为 UPSERT：

```sql
-- 创建或更新（覆盖）
INSERT OR REPLACE INTO netops.raw_output_store 
    (device_name, command, raw_output, snapshot_id, updated_at)
VALUES (?, ?, ?, ?, NOW())
ON CONFLICT (device_name, command) DO UPDATE SET
    raw_output = EXCLUDED.raw_output,
    snapshot_id = EXCLUDED.snapshot_id,
    updated_at = NOW();
```

**主键：** `(device_name, command)` — 同一设备同一命令只保留最新输出。

**存储量对比：**
- 覆盖: 6 devices × ~20 commands = ~120 行（固定）
- 追加: 每次 init +81 行 → 10 次后 810 行，100 次后 8100 行

## 查询层 Fallback 规则

### execute_sql / db_query

在 `ops/SKILL.md` 和 `core/prompts/system.md` 添加：

```markdown
## Query Fallback (重要)

`parsed_outputs` 是结构化数据（TextFSM 解析后的 JSON）。
`raw_output_store` 是原始 CLI 文本输出（始终存在，覆盖更新）。

**查询优先级:**
1. 先查 `parsed_outputs`（结构化，快速）
2. 如果某设备/命令在 parsed 中为空 → 查 `raw_output_store`（原始文本）

**Fallback SQL 模式:**
```sql
-- 先查 parsed
SELECT device_name, parsed_data FROM netops.parsed_outputs 
WHERE command LIKE '%bgp%';

-- 如果某设备缺失，fallback 到 raw
SELECT device_name, command, raw_output FROM netops.raw_output_store 
WHERE command LIKE '%bgp%' 
  AND device_name NOT IN (
    SELECT DISTINCT device_name FROM netops.parsed_outputs WHERE command LIKE '%bgp%'
  );
```

**raw_output_store schema:**
| Column | Type | 说明 |
|---|---|---|
| device_name | VARCHAR | 设备名 |
| command | VARCHAR | CLI 命令 |
| raw_output | TEXT | 原始 CLI 文本输出 |
| snapshot_id | VARCHAR | 最后采集的 snapshot |
| updated_at | TIMESTAMP | 最后更新时间 |

**主键:** (device_name, command) — 覆盖更新，只保留最新。
```
