# 97. Loop-engineering review — deterministic graders, active verification, scheduled hill-climbing

**Status**: Draft / proposed 2026-06-18. Finding + first refactor landed
(db-query deterministic grader); remaining items scoped, not yet built.
**Trigger**: review of LangChain's "The Art of Loop Engineering" (four-loop
stack: agent → verification → event-driven → hill-climbing) against OLAV's
actual agent fleet.
**Builds on**: ADR-0015 (memory steering), the small-model-first governance in
CLAUDE.md, R88 (deterministic transforms), dev_docs/87 (rubric middleware).
**Owners**: platform + netops maintainers

---

## 0. Framing

The article models production agent systems as four nested feedback loops:

1. **Agent loop** — model calls tools until done (`create_agent`).
2. **Verification loop** — a grader (deterministic *or* LLM) checks output
   against a rubric and loops back on failure (`RubricMiddleware`).
3. **Event-driven loop** — schedules / webhooks run the agent continuously.
4. **Hill-climbing loop** — production traces feed an analysis pass that
   improves the harness "and reaches inside and updates the agent loop directly".

Plus: human-in-the-loop is a first-class primitive at every level; "human
judgment + token capital compound" into a hard-to-copy advantage.

OLAV already touches all four — but in a small-model-first idiom, and with two
load-bearing gaps this review surfaces.

## 2. Finding — the sub-agent verification loop is dead two ways over

Investigating to wire the first deterministic grader surfaced **two stacked
defects**, either of which alone makes the sub-agent verification loop inert.

**Defect A — the flag is read at the wrong nesting level (never instantiated).**
Sub-agent `SKILL.md` files nest their flags under a `metadata:` block, so
`python-frontmatter`'s `post.metadata` exposes top-level keys
`['name','description','scripts','tools','references','metadata']` and the actual
flags one level **down**. But `agent.py:_build_subagents` does
`metadata = post.metadata` and then `metadata.get("rubric_middleware")`
(`agent.py:1332`) — reading the **top level**, which is always `None`. Verified:
`post.metadata.get("rubric_middleware") → None`;
`post.metadata["metadata"]["rubric_middleware"] → True`. **So the RubricMiddleware
branch never fires for any sub-agent — the grader is never even constructed.**
(The netops *orchestrator* escapes this: its `rubric_middleware` is declared
top-level on line 8 and loaded via the orchestrator config path.)

**Defect B — even if instantiated, it would no-op.** `RubricMiddleware` activates
only when `state["rubric"]` is set (`deepagents/middleware/rubric.py:409-412,
482-483`). The only populator is `agent.py:1537`, gated on `synthesis_rubric:
true`, writing to the **top-level** invocation input; sub-agents get fresh state
via the `task` tool and never inherit it.

Net effect:
- **Active verification loop:** only the **netops orchestrator**
  (top-level `rubric_middleware` + `synthesis_rubric`).
- **Dead on ~18 sub-agents + admin/audit/services orchestrators:** the flag reads
  as "verification on"; in production it is off — a textbook
  "shipped-but-unreachable" loop (CLAUDE.md DoD failure mode), here doubly so.

Neither is a deepagents bug. Defect A is a pure OLAV frontmatter-nesting wiring
gap; Defect B is the activation-key gap. The deterministic-grader refactor (§4)
reads **both** nesting levels so it actually fires, and documents Defect A so the
rubric branch can be fixed deliberately (activating 18 graders is a behavioural
change, scoped separately in §5).

## 3. Recommendation — deterministic graders, reserve LLM graders for prose

The article explicitly allows **deterministic** graders. OLAV uses LLM rubrics
exclusively, which for small models is the wrong default:

- An LLM grading an LLM costs an extra model round-trip (latency + tokens) and
  burns scarce context budget — on **every** natural stop.
- Most OLAV agents emit **structured / deterministically-checkable** output
  (row counts, schema match, service-health 200, SQL parse/empty, snapshot
  exists, graph connectivity). These do not need an LLM judge.
- The one criterion the active netops rubric actually enforces —
  *"prose synthesis present, not pure raw output"* (ISSUE-NO-SYNTHESIS) — is
  itself a deterministic predicate.

**Rule going forward:**
- **Data-flow / structured-output agents** (db-query, collector, topology,
  importer, services, the CLAB experiment-runner) → **deterministic grader**
  (zero LLM).
- **Prose-output agents** (analyzer, reporter, writer, audit-author, explorer)
  → keep an LLM rubric *only if it is actually activated* (it currently is not —
  §2), else also start with the deterministic synthesis check.

The CLAB redesign (dev_docs/96) already fits: the experiment-runner's
**round-trip diff is a deterministic grader**.

## 4. The deterministic synthesis grader (implemented)

`src/olav/agents/deterministic_grader.py` — `DeterministicSynthesisMiddleware`:
a zero-LLM `AgentMiddleware` whose `after_agent` runs a Python predicate
(`has_prose`) over the final AI message. On failure it injects one feedback
`HumanMessage` and `jump_to="model"` (capped iterations); on pass it falls
through. It is a faithful, deterministic port of the netops synthesis rubric's
sole criterion — same contract, zero model calls, zero added context cost.

Activated by `deterministic_synthesis_grader: true` in a SKILL.md frontmatter,
wired in `agent.py` alongside the (existing) `rubric_middleware` branch.

**Second criterion — grounded result (2026-06-19, ISSUE-LE-GRADER-SYNTHESIS-ONLY).**
The prose floor alone passes prose-but-fabricated answers (a confident result on
top of tool calls that all failed). Opt-in via `grader_require_tool_success:
true`, the grader adds a second check: fail (loop back once) only in the
unambiguous case — tools were called, **all** failed, and the answer does **not**
acknowledge the failure. Pass-biased elsewhere (no tools / any tool succeeded /
honest "I could not …"). `_tool_failure_stats` reads `ToolMessage.status` + an
error-envelope marker; `_acknowledges_failure` is EN+CN. Enabled on the
data-flow agents api-query / collector / topology / importer. Zero-LLM, bounded.
**Honest limit:** catches "fabricated success on all-failed tools", not
api-query's earlier "right data via the wrong tool (execute_sql httpfs)" masking
— that was fixed by the script-recipe injection (§8), not the grader.

**First refactor:** `core/db-query` — `rubric_middleware: true` (dormant LLM
no-op) → `deterministic_synthesis_grader: true` (active, zero-LLM). Both
workspace copies synced.

Wiring also required fixing **Defect A** (§2): the branch now reads the flag from
both the top level and the nested `metadata:` block.

### Before / after — same question

Question (same both runs): *"netops.devices 表里一共有多少台设备？给出数字并用一句话说明。"*

| Signal | BEFORE (`rubric_middleware`, nested) | AFTER (`deterministic_synthesis_grader` + nesting fix) |
|---|---|---|
| Build-time wiring | Deterministic branch fired: **False**; Rubric branch fired: **False** — grader **never instantiated** (Defect A) | `→ 'db-query' DeterministicSynthesisMiddleware enabled (zero-LLM grader)` ✓ |
| Runtime grader firings (db-query) | **0** (no `*_evaluation agent=db-query` line in the full baseline run) | grader **fires** (`agent=db-query` evaluation logged), verdict satisfied (answer carried prose) |
| LLM calls added by the grader | 0 (dormant) | **0** (deterministic predicate) |
| Verification actually present? | **No** | **Yes**, at zero LLM cost |

Plus a model-independent unit proof of the predicate + loop: `has_prose` returns
False for pure table/JSON/tool-echo/code/empty and True for EN/CN prose; the
middleware returns `jump_to="model"` + feedback on a no-prose final message,
falls through on prose, and is bounded (no jump once `max_iterations` is hit).

**Honest caveats.**
- With the active model (deepseek) the *visible answer* is prose either way, so
  the win is not a different answer on the happy path — it is that a real
  verification loop now **exists and fires** where before it was structurally
  dead, and it does so with **zero added LLM cost** (vs. the LLM-grader path,
  which would add a full grader round-trip per natural stop).
- The demo also exposed a **pre-existing, unrelated db-query capability bug**:
  it could not locate a SQL-runner script (`execute_skill_script` found no
  `scripts/` for the query) and returned an apology. The grader correctly
  **passed** that answer — its contract is "prose present", not "answer
  correct". The db-query SQL-execution gap is logged separately, not addressed
  here.

## 5. Remaining scope

1. **Activate verification fleet-wide via deterministic graders.** — **DONE for
   leaf sub-agents (2026-06-18).** Flipped `rubric_middleware` →
   `deterministic_synthesis_grader` on **12 leaf sub-agents** (writer, api-query,
   db-query, ops, installer, editor, infra, audit-author, explorer, collector,
   topology, learner, simulator), all copies synced + verified wired via
   build-time log. **Deferred:**
   - **analyzer, reporter** — **DONE (2026-06-18).** They declare `subagents:`
     (→ `create_deep_agent` recursive path). `create_deep_agent` rejects
     *duplicate* built-in middleware, but accepts a custom one via its
     `middleware=` param — so the recursive branch now passes
     `[DeterministicSynthesisMiddleware]` only. Verified: build ok, grader wired
     on analyzer + reporter, **no "duplicate middleware" error**, and a runtime
     probe confirmed the grader **fires** inside the reporter deep-agent
     (`rubric_evaluation agent=reporter` logged). Flags flipped on both copies.
   - **netops orchestrator — DONE (2026-06-19).** Converted its one genuinely-
     active **LLM** synthesis rubric (`rubric_middleware` + `synthesis_rubric`) to
     the **deterministic** grader: added an orchestrator-level branch in
     `agent.py` that appends `DeterministicSynthesisMiddleware` to
     `effective_middleware` (create_deep_agent accepts the custom middleware; no
     duplicate). SKILL.md flags replaced with `deterministic_synthesis_grader:
     true` (both copies). Verified twice at build: `build_ok=True, det=True,
     rubric=False`, no duplicate-middleware. **Net win:** removes one LLM grader
     round-trip per netops call (the rubric spawned a `rubric_grader` sub-agent);
     same "prose-present" guarantee, zero LLM cost.
   - **audit/services orchestrator** rubrics stay dormant (a synthesis grader on a
     verbatim-return router is usually wrong — orchestrators should not
     re-synthesise; netops is the exception because it does synthesise).
   - **Per-agent structured post-checks** (row counts, health 200, graph
     connectivity) beyond the universal synthesis-present floor — future
     refinement.
2. **Close one L4 loop through L3 — DONE (2026-06-19, propose path).**
   Context: the *auto-commit* trace-learn loop already exists and is reachable
   (`trace_learner._run_learn_cycle` → reflection rows, scope=global, fired per
   run by `AuditMiddleware` + `/trace-review`). What was missing is the
   **HITL, per-agent, scheduled** variant. Added:
   - `trace_learner._run_review_cycle(propose_only)` — groups failures **per
     agent**, extracts per-agent lessons (reuses `_analyze_failures` +
     `_extract_constraints`), and writes them as **drafts** to the memory-curator
     drafts dir (`.curator_drafts/trace_lessons_<agent>.draft.json`, category
     `usage_guide`, scope=`<agent>`). **It does NOT commit** — a human reviews and
     runs `commit_to_memory(from_draft=True, intent=trace_lessons_<agent>)`.
   - New **cron-friendly CLI verb** `olav trace-review [--propose|--learn]`
     (`cli/commands/trace_review.py` + `main.py` registration/dispatch). `--propose`
     (default) = HITL drafts; `--learn` = legacy auto-commit reflections.
   - **Reachability test** (`tests/integration/test_trace_review_propose.py`,
     production-default config): seeds a one-failure `audit.duckdb`, invokes the
     real `handle_trace_review_command`, asserts a per-agent draft is written AND
     the store received **no** `add_memory` (HITL gate). Plus a verb-registration
     test. 2 passed. (Honors the DoD rule — the old trace-learn loop was once
     "wired" under a scope no production caller used.)
   - **Schedule (L3):** add a crontab line —
     `0 2 * * * cd <repo> && olav trace-review --propose --hours 24 >> ~/.olav/logs/trace_review.log 2>&1`.
   OLAV-specific: it updates the **memory/guide layer, not code**. **Deferred:**
   "repeated *successful* pattern" mining (current = failures only); routing the
   cron through `manage_cron` (its job shape is agent+instruction, not a verb —
   the crontab line above is the interim).
3. **Feed L2 failures into L4.** Persist grader verdicts (now that they actually
   fire) so "which agent fails synthesis most" becomes an improvement signal.
4. **Use the idle cron for L3.** idle twin-builder (dev_docs/96), nightly
   distillation (item 2), scheduled freshness collection.
5. **Cap fixes as loop quality.** Split infra (9→≤5 tools); decide on a netops
   `data-ops` sub-router (collector+importer+topology) vs. the extra-hop context
   cost.

## 6. The small-model filter on "more loops"

The article frames stacking loops as advantage. For OLAV, **every loop is also a
context tax**. So the order of preference is deliberate:

- deterministic grader **>** LLM grader,
- memory/guide injection **>** prompt/code rewrite,
- HITL proposal **>** auto-commit.

This is exactly where OLAV differs from a generic large-model agent stack, and
it is the lens applied to every item above. (See also ARCH-16 anti-fan-out,
dev_docs/95.)

## 8. Coda — the sub-agent script-invocation bug (db-query deleted, api-query fixed)

Demoing the db-query deterministic grader (§4) surfaced that **db-query could not
run a single query**. Investigation (a tool-call capture probe) found the agent
made **76 `execute_skill_script` calls, 0 with the correct `skill_name`** —
call [1] used `skill_name="lab"`, copied verbatim from the `execute_skill_script`
tool docstring's example — then guessed `netops/ops/admin/...` and gave up.

**Root cause (code-level):** sub-agents' system prompt is just their SKILL.md
body (`agent.py:_build_subagents`); the **`SkillsMiddleware` section is
orchestrator-only**. A sub-agent whose only tool is `execute_skill_script` must
translate "run X" into `execute_skill_script(skill_name="<self>", script_name=
"X.py", ...)`, but the SKILL.md never states the recipe or the agent's own
`skill_name`, and the tool docstring's `skill_name="lab"` example actively
misleads. The script + path-resolution were both fine (direct call returns 348).

**Why no test caught it:** db-query is **practically unreachable** — core answers
DB questions with its own (larger) `execute_sql` @tool per its routing table, so
db-query was never the routed path; and every test touching "db-query" exercised
the *script* directly or the *structure*, never the sub-agent through a real
delegation with a (small) model. Same shipped-but-unreachable class as §2.

**api-query has the same bug — confirmed:** 0/8 correct `skill_name` (again
copied `"lab"`), but it **masked the failure** by abusing its `execute_sql` tool
to `read_text()` the service URL over HTTP — producing a superficially-correct
health report while bypassing `api_request.py` and its auth/read-only path.

**Verdict + fix (2026-06-19):**
- **db-query → deleted** (redundant with core `execute_sql`, never routed, broken).
  Removed from `core/SKILL.md` subagents + workspace dirs; `tier0_packaging.sh`
  A3b/A18 assertions corrected (they were already stale — read a nonexistent
  `core/AGENT.md`, asserted 3 tools / 5 subagents incl. nonexistent remote/admin).
- **api-query → fixed** (unique external-API path, cannot delete).
- **Systemic fix** (`agent.py:_inject_script_recipe`): every script-bearing
  sub-agent (has `scripts:` + `execute_skill_script` in `tools:`) now gets the
  exact call shape — `execute_skill_script(skill_name="<this-skill>",
  script_name="<file>", ...)` — injected into its prompt. One change fixes
  api-query and every future sub-agent.
- **Docstring fix:** `execute_skill_script` example `skill_name="lab"` →
  `"<your-skill>"` + "do NOT copy the example value".
- **Tests:** `tests/unit/test_subagent_script_recipe.py` (recipe injects own
  skill_name; skipped without execute_skill_script/scripts; db-query removed).

Lesson (added to the §2 family): **a redundant sub-agent that is never the routed
path rots silently** — and a sub-agent whose only tool is `execute_skill_script`
needs the call recipe in its prompt, because it gets no SkillsMiddleware section.
